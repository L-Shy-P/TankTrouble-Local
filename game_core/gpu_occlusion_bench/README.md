# GPU 离线基准：单帧遮蔽角评分

独立于 `index.html` 游戏加载的 WebGPU 基准页面。GPU 只做“单帧遮蔽角评分”
中的 f32 遮蔽弧段生成；**不写回游戏，不接最终决策**。

## 打开方式

1. 启动任意静态文件服务器，例如在仓库根目录运行：
   `python server.py`（或 `python -m http.server 8000`）。
2. 浏览器打开：
   `http://localhost:8000/gpu_occlusion_bench/index.html`
3. 需要支持 WebGPU 的浏览器（Chrome 113+ / Edge 113+）。
   若不支持，页面会显示“WebGPU 不可用”，但仍会说明原因。

## 基准内容

- 输入：`操作数 × 帧数` 个坦克位姿（默认 9×75=675）+ `帧数 × 每帧子弹数`
  个子弹位置（默认 75×20=1500）。
- GPU：`occlusion.wgsl` 对每个位姿执行与 JS `exactOcclusion` 相同的
  解析几何粗筛与弧段生成（R_ABS / R_SEMI、asin 半角、sin/cos 角带求交），
  输出原始遮蔽弧段到 storage buffer。
- CPU：对 GPU 输出的原始弧段做区间合并与 gap 宽度平方和，得到每帧分数。
- 对照：JS 精确 f64 版本 `jsExactScore()`（页面内自包含，与
  `js/vantage_scoring.js` 拷贝区2 同源）。
- 指标：最大误差、平均误差、最优操作一致性（按 75 帧合计比较 9 操作中
  总分最大的帧）。

## 预期输入规模

- 默认：9 操作 × 75 帧 × 每帧 20 弹 = 675 位姿，约 1.7 MB 弧段缓冲。
- 可调范围：操作数 1..64，帧数 1..300，每帧子弹数 0..128。
  更大批量（例如 64×300×128）弧段缓冲约 100 MB 量级，需注意浏览器
  显存/内存上限。

## 已知限制

1. **f32 精度**：WGSL 使用 f32 计算几何与反三角函数，存在舍入误差；
   JS 对照使用 f64。误差会随距离/角度边界命中情况变化。
2. **区间合并留在 CPU**：GPU 只生成原始弧段，区间合并、gap 评分与
   最终分数计算由页面 JS 完成，不是纯 GPU 流水线。
3. **每帧子弹数固定**：为简化 storage 布局，每帧子弹数固定；空闲子弹
   需由生成器置于远处（当前基准生成器全部为有效位置）。
4. **不回写游戏**：本页面的 GPU 结果只用于离线基准显示，不写入
   `VantageScoring` / `VantageTree` / 任何游戏状态。
5. 本目录不参与 `index.html` 游戏加载，不影响默认 AI 行为。
