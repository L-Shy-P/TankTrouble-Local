# 阶段③ 树结构 · 细化方案（第二版，2026-08-15 重写，待主人检查）

## 2026-08-23 最终语义定稿（软死 / 真死 / 3 层回退）

> v52 修正（2026-08-23，主人实测定调）：**最新一层选路不再比“本段平均分”，
> 改比“节点自身 75 帧全累积总分（rolloutTotal）”。** 预测 75 帧的全部累积
> 必须参与比较；死亡帧停止累计。新弹出现后全树重评分并逐层重算 next，
> 不能只刷新最外层。v49 为防止长链累计自锁而引入的“本段平均分”口径退役，
> 仅保留在 3 层范围回退/全局回退的路线平均分中。

### 候选死亡定义

- `fullDeathFrame = -1`：没死。
- `fullDeathFrame = 1`：操作真死。
- `fullDeathFrame >= 2`：软死。

软死候选与存活候选在选路上一视同仁；软死只停止累计分数，分数低所以自然
不易被选，但绝不因“死过”被跳过。树图可以用颜色标记软死。

### 执行帧数与计分

- 没死：执行计划帧数。
- 操作真死：执行 1 帧。
- 软死且死亡帧 <= 计划帧数：执行到“死亡帧 − 1”为止。
- 软死且死亡帧 > 计划帧数：执行计划帧数。
- 分数只累计实际执行过的帧，死亡帧不加分。
- 路线平均分只在 3 层回退/全局回退兜底使用，分母永远用计划帧数。

### 节点真死

某节点所有 active 可选子节点都 `fullDeathFrame <= 1`，该节点才真死。
单条路线软死不构成真死，单条路线真死但仍有其他路线也不构成节点真死。
只有节点真死才标 exhausted 并回退。

### 3 层范围回退

1. 从真死节点向根走 3 条边得到祖先 A；不足 3 层则 A=树根。
2. 在 A 的子树内按“整条路线平均分”重新选路，软死路线正常参与。
3. 找不到候选则 A 逐级上移；到根仍没有才走根层兜底。
4. 根节点真死：不重新展开、不特殊回退，直接在所有真死候选里选最高平均分者。

## 2026-08-23 选路死锁事故记录（重要）

### 现象

带子弹实测时，AI 几乎一直站在原地，偶尔才动一下然后死亡。检查提交记录发现：

- “静止”路线累计分 16462；
- 其余 8 个候选都只有 2960。

所以每次提交都选静止，不是评分并列，而是静止路线的长链累计分碾压了其他浅候选。

### 根因

路线累计分是“各段得分之和”。一条路线被连续选中、连续延伸后，会积累大量历史段分；
未延伸的兄弟只有一段分。提交时把长链和浅候选直接比，长链永远赢，
于是继续被选中、继续积累，形成自锁。子弹真正逼近时已经来不及换路。

### 定案规则

1. 正常延伸：只在最新延伸出的 9 个节点中比较“节点自身 75 帧全累积总分”，
   选最高者继续延伸；不比祖先历史累计。
2. 正常提交：直接沿用当前路线已经选定的下一个节点，不重新全局比较。
3. 真死回退或当前路线失效：才做全局比较。
4. 全局比较使用“整条路线平均分 = 路线累计得分 ÷ 路线累计计划帧数”。
5. 死亡时，计划帧数保持不变，得分停止累计，所以死亡路线平均分自然更低。
6. 全局最优平均路线在 500 节点规模内直接 DFS 穷举所有叶路径，不走动态规划。

### 2026-08-23 v52 选路事故记录（新弹后仍执行旧操作）

主人实测：管道内子弹从后方来，候选重评分后“静止 21 帧死、前进 70 帧死、
前进总分更高”，树却继续提交静止；静止执行到快死后才紧急重选前进，已失去
躲避窗口。定位结果：

1. `refreshCandidateScores` 只刷新当前比较层分数，不重算父节点 `next`；
   正常提交仍沿用旧 `next`，软死 `fullDeathFrame>=2` 不会被跳过。
2. 最新层选路用“本段平均分”，死亡点落在本段之外时 75 帧后半段完全
   不参与比较，等于把 75 帧预测的累计浪费掉。
3. 新弹影响不限于最外层；深层旧 rollout 也必须按新弹重评分。

v52 修复（tree `?v=60`）：
- 新增 `rolloutTotal` 字段，选路只比节点自身 75 帧全累积总分；
- `refreshCandidateScores` / 新弹剪枝后同步重定向受影响 `next`；
- 新弹 emergency 触发 `rerouteTreeForCurrentThreats`：全树重评分 +
  逐层重算所有 `next` + 一次后序回传 `subtreeBest`；
- 删除 `pickBestWithThreatBias` 人工“非位移死则强制前后”兜底，
  新鲜根层与新根层回退均使用自然总分比较。

### 需要补充的节点物理量

- 本段计划帧数：探段决定，死亡时不缩短。
- 本段实际执行帧数：死亡时可缩短到死亡帧。
- 本路线累计得分。
- 本路线累计计划帧数。
- 本路线平均每帧得分。
- `rolloutTotal`（v52）：本节点自身 75 帧全累积总分，死亡帧停算；
  最新一层与新鲜根层选路用它自然比较。

`subtreeBest` 仍保留给渲染和旧诊断；最新一层选路不再以它或本段平均分为准。

## 2026-08-23 最终口径更新（优先于下文中一切“整根重来/全弃/重建”表述）

- **换路线绝不删除节点。** 一个 rollout 一旦算出来就是可复用资产。未选中的兄弟分支、
  回退后离开的分支都进入储备/保留集；将来从同一状态继续搜索时直接复用。
  “整根重来”“其余全弃”“换路线 = 下次 commit 整根重来”全部作废。
- **全局最优路线是标准题。** 不变量：
  `subtreeBest = segmentScore + max(baseExt, max(children.subtreeBest))`。
  满足该不变量时，从根逐层选最大 `subtreeBest` 的孩子就是全局最优路径。
  当前实现的 bug 是 `refreshCandidateScores()` 用单段 `totalScore` 覆盖
  `subtreeBest`，把后代价值抹平，使提交退化成只看下一段。
- **生长不能只沿金线末端。** 应从存活叶子集合中选择扩展目标（subtreeBest 或
  上置信修正），让回退到上一节点换兄弟继续延伸成为可能；预算满了只停止生长，不删节点。
- **正常坍缩保留。** 提交节点升为新根、旧根 8 兄弟离开活动树是可以的；但换道时
  不得把未选中路线及其整棵子树 detach。
- **死亡状态与分数必须同步刷新。** `scoreRollout` 返回的 dead/deathFrame 必须回写
  status/fullDead/fullDeathFrame。
- 历史 v6/v7 中“旧延伸链全弃”“从新根重展开 9 候选”等描述只代表当时为修复
  “链分偏置”而采取的过激手段，现降级为历史记录，不再作为架构依据。

## 〇、核心概念：评估深度与提交粒度解耦

| 量 | 语义 | 取值 | 来源 |
|---|---|---|---|
| **评估深度** | 树在时间上往未来铺多远 | 目标 ≥75 帧视界，受预算约束 | 节点数 × 段长 |
| **提交粒度（=基准时间）** | 一个节点代表的实际执行时长 | 自适应 3~30 帧 | 分化点探测（二节） |

两个已验证的经验注入本设计：
1. **长评估 + 软死**（A/B 两全勾）：多帧累积分比单帧分更能定方向——单帧是瞬时量
   （转向中间帧朝向落在遮蔽区是假劣势），累积是路径积分（噪声被摊薄、持续劣势
   每帧都在扣、隐含时间效率）。
2. **恒定操作直评 = 只有 1 层的退化树**：两全勾的强度是"1 步决策"形态的上限，
   树的增量 = 解锁两段组合解（先后退 8 帧再转向 15 帧之类），并把"提交点之后的
   假设"从"恒定到底"换成真实分叉。

## 一、段长机制（新基准时间的定义与计算，本版核心）

### 1.1 段长该切在哪：信息分化点

节点切在"操作之间开始分出高下"的时刻，而不是均匀网格：

- **无威胁期**：9 操作分数曲线几乎重合（遮蔽≈0、无车道压分）——此时细切节点
  是浪费：切出来的子节点分数全同，白耗预算。该用**长段**长驱直入，省下节点
  铺远处 → 直接服务"更少节点预测更远"。
- **贴脸/岔路期**：操作间分数剧烈分化——此时该用**短段**细换挡，否则错过
  换挡点 = 预测错 = 回退。

### 1.2 分化点探测（divergence probe）——零新增计算

关键红利：探测所需的 rollout **就是现在两全勾模式每轮已经在跑的 9 操作 × 75 帧
模拟**，分化曲线是它的免费副产品：

```
probeSegment(adapter, tankState, threats):
    对 9 操作各跑 scorePath(75帧, 软死cfg)          // 现有计算，零新增
    cum[i][k] = 操作 i 前 k 帧累计净分              // perFrameScores 前缀和
    spread(k) = max_i cum[i][k] − min_i cum[i][k]   // 每帧的操作间分差
    t_div = 最小的 k 使 spread(k) > ε               // 分化点
    段长 = clamp(t_div, T_min=3帧, T_max=30帧)
    ε 初始 = 1.0 × 遮蔽满分(4π²≈39.5)               // "操作间已分出一整档安全差"
```

三条性质（直接编码可验证）：
1. **无威胁**：spread 恒 < ε → t_div=75 → 段长=30 上限 → 节点最省；
2. **死亡威胁**：软死下死操作分数冻结、活操作继续涨 → spread 自动拉大 →
   t_div 前移 → 段长自动缩短——**威胁越大换挡越细，无需专门逻辑**；
3. **车道压分参与**：占道操作的持续扣分也推动 spread → 段长对"该让道了"
   同样敏感。

### 1.3 段长的预算视角

树的预测时长 ≈ Σ(沿链段长)。同样节点预算下：无威胁 30 帧/段 → 3 层即 90 帧
已超视界；贴脸 3 帧/段 → 同预算铺不远，但贴脸时远处本就无信息（弹幕只看眼前），
预算天然该省着近处花。**段长自适应 = 预算的时间分配器**。

### 1.4 每节点独立段长

树中每个节点的段长按**该节点时刻的态势**探测（子节点的 threats 时间平移即可，
折线是全局函数）。同一层兄弟节点段长可以不同——树的"层"是**时间深度不齐**的，
全量层的判定按时间深度而非层数（见四节）。

> 探测成本注记：每节点一次 9 操作 rollout 听起来贵，但第一层探测与"提交前的
> 9 操作对比"是同一次计算（复用）；更深层若预算紧，可用父节点段长 ×0.5 的
> 粗略近似跳过探测，实测再定（待确认项 2）。

### 1.5 死亡语义定稿（主人 2026-08-15 定调：还需要，但只在两处）

死亡在树时代的完整角色清单——**评分零特殊处理**：

| 角色 | 机制 | 备注 |
|---|---|---|
| ① 结构约束 | 死处即叶子：dead 节点不分叉——"60 帧死就不能在 60 帧后建节点" | 已是既有规则（四节），无新增 |
| ② 回退信号 | 九兄弟全死 = 04 回退判定输入；死亡时刻 = 全死兜底排序 | 04 填判定，协议见六节 |
| ③ 评分 | **无**——软死=死处停算，累积分天然编码"活多久×活多好" | −10万 退役（见下） |

**−10万 正式退役的论证**（两个原目的均不成立）：
- 一票否决 → A/B 证伪：把"优解在死亡边缘"（第 70 帧死 vs 第 5 帧死）一起淹没；
- 全死选最长 → 与 −10万 无关：软死下死得晚 = 积累帧多 = 分数自然高，
  argmax 自动选出"活最久"，无需专门逻辑。

**连带推论——提交不筛 alive**：段制下节点的远端死亡是"恒定操作假设"的
产物，不是死刑（只执行它的头部段然后重规划）；"选最高的 alive 者"这类
偏好 = 变相一票否决，一并废除。纯 argmax + 死亡时刻平局裁定（五节）。

## 二、数据结构（段制版）

```
Node = createNodeValues() + {
    // —— 已有（02 四又二）——
    id / parentId / depth / inputs / simState / baseTime / score / status
    // —— 段制增补 ——
    children: []            // 子节点引用（叶子空）
    parent: null
    segmentFrames: number   // 本节点段的帧数（= 本节点的基准时间）
    segmentScore: number    // 本段累计净分（软死：死处停算不倒扣）
    subtreeBest: number     // 自段分 + 最优后代链分（回传，见五节）
    tEndSec: number         // 节点末时刻 = simState.tGlobal + segmentFrames×FRAME_DT
}

Tree = {
    root, leaves,           // 根=当前真实状态；存活叶子按 subtreeBest 降序
    budget,                 // 本帧剩余预算（模拟节点数）
    fullDepthSec: 0.3,      // 全量层的时间深度（秒）——替代旧 fullLevels（层数制废弃）
    commitNode: null,       // 当前正在执行的节点（提交后设，见五节）
    probeCache: null,       // 根层的 9 操作 rollout 缓存（探测+第一层复用）
}
```

status 三值不变（pending/alive/dead）；dead 节点留在树上（04 死路间比相对最优），
不再分叉。子弹状态不进节点（折线全局函数原则，阶段①既定）。

## 三、树循环总览（每帧做一点，段末提交）

```
每帧（挂在 ai_vantage.update，预算制）：
    1. 现实对齐：根状态 vs 真实坦克（执行中每帧刷新根的 simState）
       偏差超容差 0.5m/5° → 触发重规划（04 的判定 1，本阶段先整树重建）
    2. 生长（花预算）：按四节补层/延伸
    3. 段末检查：真实时间 ≥ commitNode.tEndSec → 走五节提交流程
```

与现 testbench 自动模式的关系：**自动模式 = 本循环的最简退化形**（一层树 +
固定轮询周期提交）。迁移路径：vantage_tree.js 落地后自动模式的"9 操作对比表"
直接吃 probeCache，行为无缝升级。

## 四、生长：时间深度制的全量与延伸

```
全量（时间深度 < fullDepthSec≈0.3s 的所有存活叶子）：
    每帧取"时间深度最浅"的一批叶子，各生成 9 子节点
    每子节点：probeSegment 定段长 → scorePath(段长, 软死) → 段分
    （simulateNode 与 scorePath 合并：simState 从 scorePath 的 samples 末态取，
     初版待确认项 3 已问，本版按合并设计）
    dead 子节点：留树不分叉
延伸（全量带之外）：
    沿 subtreeBest 最高叶子（延伸尖）每帧 +1 段（9 兄弟全模拟全挂树，
     只延最优——04 回退判定的数据源，初版既定决策保留）
    预算：9 节点/帧 固定小开销
停止：预算耗尽 或 尖时间深度 ≥ 1.5s（视界=折线威胁计算边界）
```

与初版的差异：层数制（9/81/729）→ 时间深度制。贴脸段短时全量带内节点自然
变多（细切）、无威胁段长时自然变少（粗切）——全量带宽度按秒计恒定，
节点数按态势伸缩，仍是"近全量、远单线"的纺锤形。

## 五、提交与剪枝（段末，MPC 心跳）

```
提交条件：真实时间 ≥ commitNode.tEndSec
提交流程：
    1. 在根的 9 子节点中选 subtreeBest 最高者 → 新 commitNode
       （纯 argmax 不筛 alive——远端死亡是恒定操作假设的产物，只执行头部段，
        1.5 节定稿；分数并列时死亡时刻晚者优先；九兄弟全死置 stalled flag 给 04）
    2. inputState ← commitNode.inputs（写死，执行整个段）
    3. 树剪枝：commitNode 成为新根，其子树保留，其余全弃
    4. 新根层跑 probeSegment（段长探测 + 新第一层，一次计算两用）
    5. 预算重置，继续生长
```

复用的干净性：固定评估视界（1.5s）+ 时间戳全在节点上 → 剪枝后整树时间基准
自然平移，无动态 depthLimit 跳变问题（初版二节的"深度对齐"难题消解）。

## 六、回退的段长配合（04 的钩子，本版定协议）

主人点名"回退可能也有回退基准时间"——是的，回退本身就是段长选错的信号：

```
回退发生（04 的两条判定：现实偏差 / 执行段内死亡逼近）：
    重规划 + 段长上限衰减：T_max ← max(T_min, T_max × 0.5)
    （连续回退 → 段长指数收紧到 3 帧 = 最细换挡）
稳定恢复：连续 3 段无回退 → T_max ← min(30, T_max × 1.5)
（渐进放松，回到长段省节点状态）
```

协议：vantage_tree 暴露 `onRetreat()`（衰减+重规划）与 `onStableCommit()`（计数恢复），
04 的判定逻辑到时填，段长机制不用改。

## 一二、树决策点的 NN 化预留（主人 2026-08-15 提出，远期路线）

主人定调：树的一系列操作（段长/选择/回退等）全可 NN 化，训练不算太难，
效果可能优于手写规则。本版接口不为此改动，只记录路线与难度分级。

**为什么可行（Neko 认同，两条结构性理由）**：
1. 树操作全是"状态→决策"的**局部**决策点，不是整局博弈 RL——难度量级
   完全不同；
2. **树循环天然自带标注**（自标签系统）：每次提交的事后结果（该分支实际
   活了多久 / 有没有回退 / 事后哪条最优）就是现成训练标签，跑着跑着
   训练集自己长出来，无需专门造数据。

**决策点难度分级（诚实评估）**：

| 决策点 | 类型 | 难度 | 备注 |
|---|---|---|---|
| 提交选择 | 监督学习 | 最易 | 标签=事后哪条分支活得最久/分最高；行为克隆即可起步 |
| 段长选取 | contextual bandit | 中 | 需要探索；但 probe 是精确数学+单参数 ε，NN 须证明比这更强（自适应 ε 按态势浮动）才有意义 |
| 回退判定 | 延迟含噪标签 | 最难 | 但规则同样难写对——"比自己写的好"概率最大的一格 |
| 延伸方向 | 同提交选择 | 易 | 与提交选择共享特征与标签 |

**实施纪律**：
