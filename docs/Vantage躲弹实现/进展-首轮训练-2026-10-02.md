## 三、Python ↔ JS 一致性

```
★ JS vs 原始训练网络  logits 最大绝对误差: 8.583e-06
★ 选路一致: 200/200
```

## 四、实现过程中踩到的坑（都记下来）

| # | 坑 | 症状 | 修法 |
|---|----|------|------|
| 1 | ReLU 掩码写错 | 梯度校验 100% 误差 | 用激活值本身 `a>0` 做掩码，别重算 pre-activation |
| 2 | MSE 过 sigmoid 漏导数因子 | 梯度校验 100% 误差 | 补 `s(1−s)` |
| 3 | float32 精度导致梯度校验假失败 | 数值梯度被量化成 0 / 4.77e-3 | 用 float64 校验；**不是梯度错** |
| 4 | 全连接层学不会"在 256 槽位里选 commit 的子节点" | Top1 停在 11% | 改成 **9 个候选的固定槽位**，任务变成"9 选 1 比较" |
| 5 | 把"夹角余弦"当特征喂进去 | — | **那是直接喂答案**，删掉，让网络自己算 |
| 6 | 导出权重转置方向不一致 | JS 与 Python 输出完全不同 | numpy 侧 `(in,out)` → JS 侧 `[out,in]` 行优先，导出时 `.T` |

## 五、一个重要的设计发现

**256 个节点槽位 vs 9 个候选槽位**

第一版把"选路"放进 256 个节点槽位里（架构文档 §一 的原设计），
结果**全连接层学到了 11%（等于随机）**。

原因：「找出 commit 的子节点」是**逐行选择操作**，全连接层不擅长。

改成 **9 个候选的固定槽位**后，任务变成"9 选 1 的比较"，立刻学到 95%。

**结论**：观测里**必须有一个"当前决策点的 9 个候选"专用段**，
不能指望网络从 256 个散乱槽位里自己找。

> 这与架构文档不冲突：整棵树的摘要仍然要给（A 用它决定往哪长），
> 但**B 的选路需要一份"候选段"**。

## 八、端到端打通（补记）

### 8.1 新增的两个文件

| 文件 | 作用 |
|------|------|
| `game_core/js/vantage_nn_obs.js` | **观测编码器**：树的 9 个候选 → 120 维张量 |
| `game_core/js/vantage_nn_agent.js` | **NN 智能体**：实现接口的 `decide()`，只做选路 |

### 8.2 关键性质：**这个智能体在结构上不可能输出非法动作**

```
候选 → 算合法掩码 → 网络出 9 个 logits → 【在合法掩码里取最大】→ 返回节点编号
                                          ↑
                                    非法候选在这里就被排除了
```

这就是主人说的"**能直接做到让智能体不输出非法最好**"。
所以对这个智能体来说，**帧内重试永远用不上**（它输出的一定合法）。

### 8.3 端到端实测（2000 个随机局面）

```
智能体就绪     = true
选出合法节点   = 2000 / 2000
无合法候选     = 0
★ 选中非法节点  = 0        （结构上不可能）
★ 平均瞄准余弦  = 0.753    （随机≈0，理想≈1）
```

**"瞄准余弦 0.753"的含义**：给它一个期望位移方向，它选出的那条路
平均与目标方向夹角约 41°。随机挑是 90°（余弦 0）。
