# 四、深层批判（主人要求：看似理由充分的设计，少了什么致命因素）

## 1. ★「暂不限制数量上限」+ 9 叉分叉 + 时间上限 = 最坏指数爆炸

- 节点 = 75 帧模拟终点；树时间上限 10（单位待确认，若为秒 = 500 帧 ≈ **7 层**）。
- 最坏情况（开阔图、无子弹、全活）：**9⁷ ≈ 478 万节点**。注意力 N² 直接炸；内存也炸。
- 规则版的 `maxNodes=500` + 性能闸门**正是为这堵墙存在的**（它不是"AI 幻觉"，是真实机制；
  幻觉的是"496"这个实测值被当成设计约束——见 §五）。
- 而"树满禁止生长"（D9）需要一个"满"的判定：**若无数量上限，"满"只能 = 全部分支到时间上限**——
  安全局面下树会朝着时间上限无界铺开，**永远"不满"，A 永远在生长，树无限膨胀**。
- 【建议】哪怕不叫"数量上限"，也需要一个**预算机制**（节点数 / 每秒模拟帧数 / 内存）作为性能闸门；
  这属于规则系统（四层结构 ①），不给智能体加负担，与 D9 不冲突。**这条不定，第一版训练环境可能跑不起来。**

## 2. ★「路线是规划，给智能体看」⟹ 规划必须能回到输入

D3 裁决说长路线是"规划"，让智能体思考更深入。
**但规划是 B 的【输出】，不是输入**——下一帧 B 看到的是新摊开的树，看不到自己上帧选的路线。
⟹ "看到规划"要成立，**上一帧的计划（路线 + 射击帧）必须作为事实直传进下一帧观测**
（§七"程序记录实际发生什么传给下一帧"正是这个管道，建议把"上帧计划"明确列入）。
否则"规划促进思考"只是美好的愿望。

## 3. ★ 全场子弹进观测：承载方式决定可不可行

几十发 × 5+ 维，平铺进节点 token = 节点数 × 几十 × 5，数据量爆炸且 99% 是无关弹。
【建议】**子弹 token 序列**（与节点 token 并列的第二种 token）：每弹 1 个 token × (位置,角度,速度,类型,剩余寿命)。
- 注意力原生支持可变数量（0~几十发）；
- 节点与子弹之间的"谁威胁我"让注意力自己学，不需要人工 K 截断、不需要排序补零；
- 与 §9.5"树里已有"的撤销也自洽了：全局不再单列子弹槽，子弹就是子弹 token。

## 4. 根滞后（D1）与「看到最新数据」（D4）之间的接缝

D1 说根只在误差 ≥ 1 帧操作量时才对齐 ⟹ **树的根可能滞后真实"现在" 0~K 帧**。
D4 说智能体看到的永远是最新数据 ⟹ **场面是最新的，树是稍旧的**。
⟹ B 的观测里，"树"和"场面"存在一个小的时间差。智能体可以学会容忍，但：
【建议】**把"根滞后几帧"作为一个数值进观测**（或等价的：根对应的真实时刻），
否则 B 无法判断"树说子弹 3 帧后到这里"里的"3 帧"从哪算起。成本 = 1 个数。

## 5. D7「只选叶子」的代价与两个坑

**收益**（主人判断正确）：所有路线都是叶子路线的子集，格式最简；叶子列表带路线长度 ⟹ 射击帧不易超限。
**代价分析**：
- 候选数没有数量级改善（满 9 叉树叶子 ≈ 0.89N），但这不是问题——格式简化才是目的；
- B 不能再表达"停在中间"——但每帧滚动执行下该能力本就隐含（下帧换个叶子选即可），**损失可接受**。

**坑 1**：A 可以在 B 上帧选中的叶子上生长（合法）⟹ 该叶子**消失**（变成内部节点）。
B 下帧重选即可，无逻辑问题；但如果配合"上帧计划进观测"（§四-2），
执行层要能处理"上帧计划引用的叶子已不存在"——**计划失效的自然语义要有定义**（建议：静默作废，B 反正每帧重出）。

**坑 2**：「只选叶子」+「终点真死不能禁」（#2 裁决）= B 的候选里**必然混着"死前 1 帧的叶子"**。
B 要靠"路线长度"等字段自己判断这条路的存活时长——这又把 #2 顶到了眼前（见下条）。

## 6. ★ #2 的新形态：不变量②死了，但"路线存活时长"的问题活着

主人的裁决链：
- 不能禁 B 选终点真死的路线（可能相对最优）；
- 不能让 B 回避"叶子快死"的路线（同理由）；
- **叶子的死亡情况可能误导 B**（原话）。

⟹ 不变量②（有非真死不选真死）作为**硬约束确实不存在了**——我 v2 说"内化"只对了一半：
结构上 B 选不出"立即死"，但选得出"很快死"，而"很快死"**有时是正确答案**。
**真正剩下的问题是：B 怎么知道一条路线能活多久？**
- 叶子的死亡信息是**相对其父的局部信息**；B 需要的是**整条路线的存活时长 = 沿途各分支死亡帧的最小值**——这是个派生量。
- 给 = 辅助判断（撞"别做太多辅助"红线？）；不给 = B 从各节点位置自己推（可学，但学习难度上去了）。
- 【建议】不给派生量，但**保证每个节点的"距死帧数"可从观测推出**（节点位置 + backMax 已够），
  让 B 自己学。若实测发现 B 学不会"这条路其实很快死"，再回来讨论。

## 7. D4 时序的一个隐含推论（无冲突，但执行层要守）

"智能体选好 → 下一帧智能体思考**之前**执行" ⟹ 每帧的实际输入窗口 = 1 帧；
"按住"（加特林）= 连续帧都输出同一操作。**执行层要保证输入只在该帧有效、不被游戏侧自锁存**——
否则 B 一帧的"点射"会变成"长按"。（`_tools/headless/clock.js` 的 `setInputState` 钩子已是每帧喂一次的模式，一致。）

# 六、#8 实验：炮口顶墙发射能否 0 帧自杀（2026-10-10）

> 实验脚本：`_tools/headless/_probe_wall_suicide.js`（真实 game_core + 虚拟时钟，确定性）。
> 方法：坦克朝墙开直到推不动（真物理贴墙），只按 1 帧 fire，逐帧记录子弹轨迹与存亡。

## 结果：✅ **0 帧自杀确认存在**

| 实验 | 情况 | 结果 |
|---|---|---|
| 格(6,4) 朝 +x | rot 未生效（异常，见下），弹未出膛即消失（弹数恒 0） | 未死 |
| 格(5,2) 朝 -x | rot 未生效（同一异常值 4.08162），弹朝远离墙方向飞出 | 60 帧未死 |
| **格(5,4) 朝 +y** | rot 正常（π），怼墙停点 (55,46.892) | **开火当帧（第 0 帧）死亡** |

**致死机制**（按帧数据推断）：开火输入生效的同一帧内，子弹出膛 → 与墙接触 → 反弹 → 命中自己 →
子弹与坦克同帧销毁（场上只剩上一实验残留的远弹）——**单物理步内完成，正是"0 帧死"的定义**
（子弹射出瞬间就命中自己 / 坦克还没开始动就死了）。

**⟹ 按主人的决策规则：顶墙能 0 帧自杀 ⟹ 检测值得做。**
检测方式的候选仍按细化方案选项 A（几何判据：炮口点贴墙/在墙内 + 反弹指向自己），
但主人已定**过滤不做 100% 确认就不做**——所以只做检测、不做过滤。

## ⚠️ 实验的副产品（比实验本身更重要）：teleport 在倒计时阶段会**静默整个失效**

实验中 3 次 teleport 有 2 次"没生效"（x/y/rot 全是出生值）、1 次完全生效（rot=π 分毫不差）。
用 3 个微探针（`_probe_rot.js` / `_probe_rot2.js` / `_probe_rot3.js`）逐环定位，根因已查明：

**根因**：`GameController.setTankState` 有守卫（探针抓到的源码原文）：

```js
function(tankState){
  if(this.model.getState()!=GameModel._STATES.IN_ROUND){ this.log.warn(...); return false; }
  if(!this.model.isPlayerActive(tankState.getPlayerId())){ this.log.warn(...); return false; }
  ...
```

**回合开始前的倒计时阶段（游戏 state='Game' 但还没 IN_ROUND），`setTankState` 静默 return false——
整个 teleport 无效（x/y/rot 都不生效），只在 log 里 warn 一句。**
倒计时相当长（实测：进入 Game 状态后 62 帧仍在倒计时，~280 帧时才 IN_ROUND）。

**这解释了实验 1/2 的"rot 异常"**：那两次 teleport 整个被丢弃，坦克一直在出生点、用出生朝向
（所以两次 rot 都是同一个 4.08162，x/y"看起来动了"其实是它自己从出生点开出去的）。

**影响面（严重）**：`match.js` 的 `teleport()` 不检查返回值、不等 IN_ROUND——
**训练阶段 1/2/3 的"随机给可达位姿"如果在倒计时内 teleport，位姿就是出生点，训练数据全错。**
`_probe_fire.js` 没踩中只是因为它的前置移动检查烧掉了几百帧，恰好等过了倒计时。

**修复建议**【待主人确认后动 match.js】：
1. `Match` 加 `waitForRound()`：`pump` 直到 `gc` 报 `IN_ROUND`，`open()` 末尾自动调；
2. `teleport()` 返回 `setTankState` 的真实返回值，被拒时响亮报错（不静默）。
