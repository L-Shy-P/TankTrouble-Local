## ① ⭐⭐ `agentSelectOverride` 在 `commit()` 坍缩路径上**【结构性永远匹配不到】**

**现象**：
`B` 每帧选一条路线（`_agentRoute`），**而段末坍缩/对齐仍锚在 `commitNode`** ⟹
**`B` 换了目标后，坍缩结果与 `B` 的意图脱节** —— **最终仍走规则分选**。

**真因（这条是新的）**：
```
:4211  function agentSelectOverride(tree, children) {
:4222      var _routePath = agentRoutePathOf(t, id);
:4223      id = _routePath[0].id;              // ← 把 B 的目标【归约到路线首节点】（深度 1）
:4226      if (!c || c.id !== id) continue;    // ← 只匹配 id 相同的那个
```
**而 `commit()` 坍缩时传进来的是 `prev.children`**（`prev = tree.commitNode`，**它是根的孩子** ⟹ **`prev.children` 是【深度 2】**）
⟹ ⭐ **`path[0]`（深度 1）永远不可能是 `prev.children` 的成员** ⟹
**该 override 在这个调用点上【结构性地永远匹配不到】** ⟹ **`keepBest` 最终走 `prev.next`（规则分选）** ✓

**为什么算"新"**：
- ⚠️ **施工侧 `3-5 §七-4:172` 登记过"commit 侧仍是旧机制"** —— **但没记"为什么结构上匹配不到"** ✓
- ⭐ **外部 AI v1 的引文是假的（`pickCommitMove` 不存在），但它的【结论方向】意外成立；真因是核查时挖出来的** ✓

**归属**：`B` 与段末坍缩的衔接 —— **设计问题**（`commitNode` 该不该跟 `B` 的路线走）。

## ⑤ ⭐⭐ `M_t` 的【权重依赖】= PPO 的 `recurrent state staleness`（**训练侧必解**）

**这是核查 `答 1` 时挖出来的**（**不是它的发现，是它论证的缺口**）：

外部 AI 主张「**每局清零 ⟹ `M₀=0` ⟹ 从 `t=0` 前向一遍就能精确算出任意 `M_t` ⟹ 磁盘 `0` 且无损**」——
⚠️ **不成立**：**`M_t` 是【权重的函数】**：
```
M_t = F(θ; o_{0:t}, a_{0:t}, M_0=0)
```
**"每局清零"只固定了【起点 `M₀=0`】，没固定【中间轨迹】**
⟹ **用训练中不断更新的当前 `θ` 去重放，得到的是"当前网若重演这局会写出的记忆"，不是采集/行为策略当时写的记忆** ⚠️
**训练早期权重变化最大，偏离也最大** ⟹ **标准 PPO 的重要性修正对不上，代理目标有偏** ✓

⭐ **一条救法（外部 AI 没写、施工侧提出）**：
**在线 rollout 时，产生动作的那次前向【同时产生 `M_t`】，把 `M_t` 留在【内存 rollout buffer】** ⟹
**那才是"磁盘 `0` 且无损"** —— **代价只有 `4 KB/帧`（批量 `256` 帧 = `1 MB`）** ✓

**归属**：**训练架构必须解决** —— **它决定"采集格式要不要改"**。
