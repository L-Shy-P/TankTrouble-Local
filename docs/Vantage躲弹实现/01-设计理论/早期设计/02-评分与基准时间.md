## 2026-08-23 最终口径更新（弹簧绳距离评分定稿，优先于下文中冲突描述）

### 1. 为什么需要距离分

单帧角度分在安全时容易取满：无子弹或子弹都在黄圆外时，
`剩余角² = (2π)² ≈ 39.48`，大量存活候选整帧满分，角度项失去区分度。
角度分仍是主评分；距离分只作次级排序，用来在“几条都活着的路”里选更宽敞的那条。

### 2. 距离的定义：弹簧绳长度（墙距）

对 rollout 的第 i 帧：

- 坦克端点 A = `samples[i]`（该帧模拟出来的坦克位置）；
- 子弹端点 B = `threatBulletPos(threat, tGlobal_i)`（同一时刻子弹的弹道位置）；
- 距离 = 从 A 到 B、**允许贴墙边但不进入墙内部**的最短路径长度。

这就是“拉一根绳、让墙把绳顶起来”的长度。它是可见图最短路径问题，结果是精确的，
不是近似。最短路径一定由若干直线段组成，拐点只可能出现在墙矩形的角上。

### 3. 弹簧绳算法

1. 每局开始时，把迷宫墙整理成轴对齐矩形列表；贴在一起且共线的矩形先合并。
2. 每帧、每对 (A, B)：
   - 如果直线 AB 不穿墙，墙距就是欧氏距离；
   - 否则取 A、B，以及“离 A 或 B 不超过 30 米”的所有墙矩形角作为候选节点；
   - 任意两个候选节点之间，只要连线不进入墙内部，就有一条边，边长=欧氏距离
     （允许贴墙边、贴墙角通过）；
   - 在这个小可见图上跑 A*，A 到 B 的最短路长就是弹簧绳长度。
3. 30 米范围限制是安全的：任何绳长不超过 30 米的最优路径，其拐点不可能离
   A 或 B 超过 30 米。范围外的墙直接忽略。
4. 擦角连续：路径长度随 A/B 连续变化；换侧绕墙只会在两条绕法长度相等时发生，
   不会产生二值跳变。

### 4. 把墙距换算成分数

每帧、每颗子弹：

```
w_j = clamp((d_ref − d_j) / (d_ref − d_near), 0, 1)
```

默认参数：

```
d_near = 4m    # 更近则危险权重饱和为 1
d_ref  = 30m   # 三格；更远不算威胁，权重为 0
```

多颗子弹用概率式合成，避免“弹越多分越高”和无限累加：

```
p = 1 − Π(1 − w_j)
单帧距离分 = clearanceCap × p
clearanceCap = 8.0    # 约角度满分 39.48 的 20%
```

不做额外短窗口平滑：每帧分数在 75 帧总分里自然稀释；单帧尖峰不会直接左右路线。
真正是否碰撞仍由死亡检测负责。

> 已实现 v25，开关默认开启。
> 2026-08-23 第四波修正：距离分是**负贡献（扣分）**，近弹 w=1 时扣 `clearanceCap`。

### 5. 车道压分与死亡语义

- 车道压分默认关闭：树配置 `lanePenaltyRatio` 默认 0；开关必须真正接到树，
  testbench 面板开关与树共用同一配置。
- 死亡仍是软死：死亡帧停止累计、不倒扣、不否决；死亡判定本身必须换回
  游戏同源碰撞（见 01 最终口径）。

### 6. 实现边界

- 本方案不要求对“当前是否隔墙”做布尔判断；墙完全由弹簧绳几何处理。
- 算法涉及基础计算：矩形合并、线段与矩形求交、小图 A*，范围 30 米内墙很少，
  性能与车道压分同量级。
- 全部参数（d_near / d_ref / clearanceCap）进入 cfg，不写死。
- 子弹真实弹道只用于死亡检测；距离评分不需要预测子弹未来最近点。

## 一、模块接口契约（红线区，定了就不许变）

本模块对外只有四类交换点。阶段③的树、阶段⑤的输出层，都只认这些接口：

### 1. 常量输入（只从沙箱适配器拿，本模块零硬编码）

```
输入：adapter.constants（阶段①已建好的常量表）
用到：坦克前进/后退速度、子弹速度、子弹半径、坦克宽高、迷宫格宽、帧时长、
     折线采样步长（本版新补进常量表：MAZE_TILE_SIZE、PATH_STEP_SIZE）
规矩：评分与基准时间公式里出现的每一个物理数，都必须能在常量表里找到出处；
     常量表没有的 → 先补常量表（走阶段①的接口），不许在本模块写死
例外：拷贝区（成品几何系统）内部直接读游戏全局 Constants——它本来就是游戏代码，
     与游戏同源是它的正确性来源，不强行改造成走适配器
```

### 2. 数据输入（只从沙箱适配器拿，不碰游戏全局对象）

```
输入：adapter.getTankState()          → 坦克位姿（x、y、朝向）
     adapter.getProjectiles()       → 子弹列表（位置、速度）
     adapter.getProjectilePaths(反弹次数, 最大长度)
                                      → 批量取所有子弹反射折线（本版新加的对接点，
                                        威胁倒计时的数据源，一次取全，不逐颗调）
     adapter.bulletPosAt(折线, 速度, 时刻) → 沿折线按时间取子弹位置
     adapter.simulateTank(位姿, 操作, 帧数) → 坦克运动模拟（路径评分用）
```

### 3. 死亡检测（唯一权威 = 游戏同源判定，本模块不自造）

```
调用：adapter.checkDeath(坦克位姿, 子弹位置列表) → 死/活
规矩：评分里的死亡判定一律走这个接口（Box2D 克隆世界，与游戏同款碰撞逻辑）；
     遮蔽角只负责打分，永远不用来判死亡（大文档 L311 原话：游戏是唯一权威）
```

### 4. 输出（交给阶段③的树消费）

```
输出甲：基准时间 → { 基准秒数, 基准帧数, 基准子弹编号, 密集权重和, 圈内威胁数 }
       基准帧数 = 本帧预测树的延伸深度上限
输出乙：单帧评分 → { 是否死亡, 单帧分, 遮蔽总弧度, 剩余角区间列表 }
输出丙：路径评分 → { 路径总分, 是否死亡, 死亡帧号, 逐帧分数列表 }
       （阶段③每长出一个新叶子，调一次路径评分）
```

**拼接方式**：阶段③拿到「输出甲」决定长多深，长出叶子后拿「输出丙」打分排序。
本模块不知道树的存在，树也不知道评分怎么算——只认接口。

## 二、基准时间计算流程（V6 纯时间定稿）

物理意义：场上子弹那么多，先找出"最火烧眉毛的那颗"，以它的到达时间定预测深度；
如果好几颗子弹挤在差不多的时间到达，说明场面复杂，预测深度要压短一点，先顾眼前。

### 第 1 步：算每颗子弹的"威胁倒计时"和"最近距离"

对每颗子弹：

```
① 取它的反射折线（子弹沿墙反弹的未来路线，游戏物理引擎现成给的）
② 沿折线一小段一小段取点（步长与游戏原版威胁图绘制同源）
③ 对每个点算两个时间视角：
   · 子弹飞到这个点要多久 = 累计路程 ÷ 子弹速度
   · 同一时刻坦克在哪 = 坦克当前位置沿朝向以"净速度"前移后的位置
     （净速度 = 前进速度 − 后退速度 = 3.15 米/秒，
       含义：坦克前后键抵消后缓慢前移，这是大文档 L154 的约定）
   · 这个点与当时坦克位置的距离
④ 全折线上距离最小的那个点：
   · 它的到达时间 = 这颗子弹的"威胁倒计时"
   · 这个最小距离 = "最近距离"（折线隔坦克多近，不是子弹飞了多远）
   · 特殊（2026-08-14 补）：最小点恰好是折线起点（t=0，子弹正在远离）→
     标记"已过"，不参与基准时间（见第 2 步）；威胁表仍显示，标"已过"
```

### 第 2 步：外圈过滤（扔掉假威胁）

```
最近距离 > 外圈半径 → 这颗子弹根本蹭不到坦克，不算威胁，不参与后续
"已过"子弹（最小点=折线起点）→ 一并跳过（倒计时≈0 无意义，会把基准压到下限）
（外圈半径初始 30 米 ≈ 3 格，待标定：
  太大 → 超远子弹的短倒计时会白白压短基准时间；
  太小 → 漏掉"坦克主动追击后会撞上"的真威胁）
```

### 第 3 步：选基准子弹（纯时间，不掺距离）

```
圈内所有威胁子弹里，倒计时最小的那颗 = 基准子弹
基准倒计时 = 它的倒计时
（不做任何距离修正——距离的事归评分管，基准时间只管时间，主人 2026-08-09 拍板）
```

### 第 4 步：密集权重（其他子弹挤不挤）

```
对每颗其他圈内子弹：
  时间差 = 基准倒计时 − 它的倒计时（必然 ≥ 0）
  密集权重 = a × e^(b × 时间差)
  含义：到达时间与基准子弹越接近 → 权重越接近 a（挤在一起，场面复杂）；
       时间差越大 → 指数衰减趋近 0（各来各的，互不干扰），衰减连续不突变
密集权重和 = 所有其他子弹的权重相加
```

### 第 5 步：合成基准时间

```
基准时间 = 基准倒计时 ÷ (1 + 密集权重和)
  · 只有一颗子弹 → 权重和为 0 → 基准时间就是它的倒计时
  · 多颗挤在一起 → 权重和变大 → 基准时间缩短（密集 → 更短，主人定论）
钳制：不小于 1 帧（0.02 秒），不大于 3 秒
特殊：圈内一颗子弹都没有 → 基准时间 = 固定默认值（初始 1.5 秒，待标定，
     用于无威胁时的未雨绸缪探索）
输出：基准帧数 = 基准时间 ÷ 帧时长（四舍五入），交给树当延伸深度上限
```

### 接入点

- 每帧开局算一次（用坦克当前真实位姿）
- 树往深处延伸时，可按"当前节点的坦克位姿"重算（滚动时域）——接口签名里坦克位姿是参数，天然支持，阶段③直接用

### 二·五、基准时间设计问题诊断与修改方案（2026-08-14 第二稿，待主人审查）

**代码与设计一致性核对结论**：逐条比对 vantage_scoring.js 的 computeThreats/computeBaseTime
与本文档第二节流程——倒计时=折线最近点到达时间 ✓、外圈过滤（含 passed 跳过）✓、
基准子弹=纯时间最小 ✓、密集权重 a·e^(b·dt) ✓、合成 tBase/(1+W) 与钳制 ✓。
**代码完全符合 V6 设计。问题出在设计本身，缺陷有二：**

**缺陷① 纯时间倒计时把"远距掠过弹"当最早威胁（主因）**

倒计时 = 子弹到"折线最近点"的时间，**与该点的距离无关**。一颗从 25m 外掠过的子弹，
它的最近点（哪怕在 25m 外）可能 0.3 秒后就到达 → 倒计时 0.3s → 它成为基准子弹 →
基准 = 0.3/(1+W) → 几帧。外圈过滤拦不住：外圈半径 30m，25m 外的弹在圈内。
主人观察"该长的时候只给几帧"皆源于此。

**缺陷② 密集权重衰减太慢，且方向反了**

时间差 dt = tBase − 该弹倒计时 ≤ 0（基准最小），权重 w = e^(0.5·dt)：
晚到 1s → 0.61、晚到 2s → 0.37，圈内四五颗晚到弹 W 就到 1.5~3，基准再被砍 2.5~4 倍；
且倒计时比基准还小的弹 dt > 0 → w > 1，方向反了。

#### 修改方案 v4（膨胀危险区，2026-08-14 第三稿：修复 v3"参考轨迹"致命缺陷）

> v3 被主人质询戳穿的两个问题：
> 1. "威胁时间"命名歧义——实为"从现在到威胁窗口结束的**时长**"（现在=0，数值等于穿出时刻）。
> 2. **致命缺陷：判定锚在假想漂移轨迹（净速 3.15 前移的点）上，与真实坦克无关。**
>    实算漏判（15m 正对来弹）：v3 基准=漂移点穿出 ≈0.83s=42 帧；而"后"操作
>    （12.8 m/s 逃离，弹以 17.2 m/s 追）真实死亡于 0.87s=**44 帧**——死亡在窗口外，
>    必死路线被树看成"活着且每帧高分的优选"。盲区还是持续性的：追击场景里
>    "后"一直被高估，直到弹距 ≤10.8m（解 (D+10)/33.15 ≥ D/17.2）树才翻脸，
>    距命中仅剩 ~0.36s，侧闪（需 0.3~0.6s）来不及。
>    另"穿出=威胁结束"语义在穿心场景不成立：弹过圈心=穿过坦克，威胁没结束，
>    是坦克结束了；圈内成员判定从未区分"会撞"与"路过"。

```
v4 核心：危险区跟着坦克的真实能力膨胀，而不是跟着一条假想轨迹漂移

膨胀危险区：以坦克【当前位置】为圆心、半径 R(t) = D_hit + 最大车速×t 的扩张圆盘
（最大车速 = 前进 15.95 m/s；D_hit = 10m = 1 格）
  物理含义：t 时刻无论执行哪种操作，坦克位置都逃不出"当前位置 + 15.95t"圆盘
  （旋转不位移、后退更慢、墙壁只会压缩可达范围 → 圆盘是安全的外包）
  判定：子弹在 t 有危险性 ⟺ dist(折线位置(t), 坦克当前位置) ≤ R(t)
  可靠性（v4 的关键保证）：若某时刻该距离 > D_hit + 15.95t，则子弹到【任何】
  可达坦克位置的距离 > D_hit ≥ 撞击包络(~2.4m) → 此刻不存在任何操作会被撞。
  外包不漏判：可能多算危险，绝不漏算死亡。

威胁窗口（每颗弹，沿折线 1m 采样；参考点=当前位置，不再漂移——膨胀已吸收运动）：
  窗口 = { t : d(t) ≤ D_hit + 15.95t }
  t_end = 序列最后一个满足时刻（撞墙弹回的弹重新满足，窗口自动保持打开；
  穿越边界处线性插值精确化）
  永不满足 → 非威胁"无关弹"（v3 的远掠过/已过/圈外三分支被这一个条件统一吸收）

基准时间（时长语义，从现在量到窗口结束）：
  基准 = clamp( max(所有威胁弹的 t_end), 1帧, T_max=1.5s )
  · 取 max 不取 min：任何一颗弹窗口还开着，就存在"某操作死于窗口尾部"的可能，
    深度必须盖住所有开着的窗口——min 会重新打开 v3 那个漏看死亡的洞
  · 反直觉但正确的一点：远处追击弹的窗口比贴脸弹更长（贴脸弹穿过后很快甩开
    膨胀圈；远处弹飞过来时圈已胀大，甩开它更晚）——深度问的是"多久后命运
    才定"，不是"多紧急"；紧急程度由树选操作来响应，不由深度来响应
```

#### A. 遮蔽角 4 段 = 单弹过渡环带的正确输出（定案，不改代码）

主人疑问：一直认为单弹遮蔽只有 2 段。

精确法判定式（拷贝区2 同源，调试器 L955 注释）：遮蔽 ⟺ `|sin(θ−ψ)|·D < 有效半宽` 且
`|cos(θ−ψ)|·D < 有效半高`（θ=来弹方位角、ψ=弧段角、D=矩形几何中心到弹距离；
有效半宽=1.5+0.25=**1.75m**、有效半高=2.35+0.25=**2.60m**，车 3×4m + 炮管前伸、
弹半径 0.25m——尺寸以本文档〇节源码实测为准）。

**单弹段数随 D 分档**（两约束角带求交的几何结果）：

| 弹距 D（几何中心） | 遮蔽结构 |
|---|---|
| ≤ 1.75m（红圆 R_ABS） | 全遮蔽 |
| 1.75 ~ 2.60m | **2 段**：跨坐来弹轴 θ 与 θ+180° 的宽弧（宽 2·asin(1.75/D)，越近越宽）——主人记忆中的形态 |
| 2.60 ~ 3.04m（黄圆 R_SEMI 门限） | **4 段**：交集从轴上滑脱成 4 条等宽细弧，对称偏置在 θ 与 θ+180° 两侧 ±ε（ε=(acos(2.60/D)+asin(1.75/D))/2，弧宽=asin−acos），对径配对 |
| > 3.04m | 0 段 |

主人数据验证：剩余角 4 区间 → 遮蔽细缝 4 条各 **10.6° 等宽**，缝心 126.5°/189.4°/306.5°/9.4°，

#### B. 基准时间 v7：角色从「威胁窗深度」换成「决策段长」

**主人定调（2026-08-15）**：基准时间不完全 是几何学问题，是**半个统计学问题**——算法得知道
什么时候要 1 帧精度、什么时候可以几秒省性能；最简衡量标准 = **尽可能减少预测中的死亡的
同时提升预测时间**；多用实测预测死亡数据帮助优化。AI 已开始涌现躲弹能力，当前瓶颈就是
基准时间精度。

**v4.x 结构性缺陷（max(tEnd) 到头了的根因）**：
1. **max 合成被远弹绑架**：任何一颗出圈时刻 >1.5s 的正对弹把基准钳满 75 帧，贴脸弹的
   短窗口在 max 里毫无发言权 → 贴脸仍上限（主人实测"子弹贴脸都还是上限"）。
2. **恒定操作 × 长窗**：9 操作从 t=0 恒定执行到窗尾，"先 A 后 B"两段解不在解空间；
   恒定前进死于第 40 帧 → 整条路径被判死跳过，前 15 帧的优秀部分被淹没
   （假死亡淹没真优秀——主人实测"必须中途换操作的解法被忽略"）。

**v7 公式**：

```
t_in(i) = 第 i 颗弹未来首次进入 D_hit 圈的时刻（穿入段线性插值；t=0 已在圈内 → 0）
T*      = clamp( min_i t_in(i) + K_post , T_floor , baseTimeMax(1.5s) )
          视界内无任何弹将入圈 → T* = 1.5s（走位自由期）
基准弹  = 最早入圈者（黄圈标记；它决定当前决策段的倒计时）
初值    K_post = 12 帧（0.24s）  T_floor = 6 帧（0.12s）——待实测标定
```

- **K_post 的物理意义**：只算到 t_in 会漏"躲进弹道延长线"式死亡（碰撞发生在弹抵达
  原位置之后）与追尾撞；多看 12 帧 ≈ 弹清空坦克局部区所需时长（弹速 18m/s × 0.24s
  = 4.3m ≈ 车长 2 倍），又不至于回到 75 帧老路。
- **为什么 min 而非 max**：基准时间的服务对象是"当前这步选什么操作"。第一颗弹到达前
  是自由走位期（各操作分化小），到达后才开始考试；恒定操作假设在短窗内重新成立。
  滚动时域每帧重算，"先 A 后 B" = 段末自动重选（AI 已涌现的躲弹行为正好接上）。
- **防漏不靠窗口靠 checkDeath**：迎头场景（坦克朝圈外弹冲）段内相遇由 checkDeath
  逐帧权威判定——窗口只决定模拟多长，不决定死活。圈外防漏（弹速 18 > 车速 15.95）
  继承 v4.2。
- **自适应精度表**（弹速 18、D_hit=10m、FRAME_DT=0.02s）：

| 场景 | v4.4 | v7 | 精度语义 |
|---|---|---|---|
| 贴脸弹（已在圈内） | 被远弹拉到 75 帧 | 0+12 = **12 帧** | 微操窗，段末姿态即结果 |
| 17m 正对来弹 | 75 帧 | (7/18s≈19 帧)+12 = **31 帧** | 段末=弹穿过局部区，比姿态 |
| 贴脸 + 30m 远弹 | 75 帧 | **12 帧** | 先解贴脸，远弹滚动接管 |
| 无弹将入圈 | 75 帧 | 75 帧 | 走位自由期（无死亡可能，评分近常量，开销极低） |

- **段末盲区（已知，接受）**：段末只看 t_in+K_post 时刻的姿态分，"躲第一弹恰好送进
  第二弹路径"的贪心盲区由滚动时域兜底，显式双段规划留给 03 树结构。

**实测死亡数据闭环（主人目标函数的形式化，testbench 计数器）**：
- **误杀** = 沙箱预测某操作死、实际执行该操作未死 → 窗过长信号（恒定操作假设破产）

  随漏杀率升而增，T_floor 同理；数据面板直显两计数，标定不拍脑袋。

**神经网络备忘（主人 2026-08-15）**：本反馈调参机制 = 低配版神经网络（特征=威胁几何量、

### 二·十一、神经网络基准时间研究（主人交办 2026-08-15："如何设置奖励比较好"）

主人定性：训练基准时间纯粹是基于子弹估算操作所需时间——很简单的网络，容易训，
参数量小，计算量与直接算差不多。以下为奖励与结构的完整设计，**未实施**，待
手工 v7 数据攒够后启动。

#### 1. 网络定位与结构（输出 K_post，不输出 T* 本身）

T* 的 min(tIn) 部分是几何硬约束（不该学也学不会）；网络只学**余量 K_post**——
学的东西少 → 收敛快、参数小，符合主人判断。

```
输入特征 s（约 8 维，全部归一化）：
  ① minTIn / T_max          最早入圈时刻（滚动逼近的威胁节奏）
  ② minTEnd / T_max         首窗结束（最短交会时长）
  ③ 将入圈弹数 / 9          威胁密度
  ④ 最近弹距 / D_hit        贴脸程度
  ⑤ 遮蔽率 occludedRad/2π   姿态受困程度
  ⑥ 上轮死亡操作数 / 9      反馈信号（网络可感知自己上一段的后果）
  ⑦ 上轮死亡位置均值        同上（无死亡取中性 0.5）
  ⑧ 是否自由期（0/1）       门控特征
隐层：1 × 8 tanh（参数 ≈ 100）
输出：高斯头（μ, σ）→ 采样 K_post = σ(·) × 1.2s（sigmoid 门控到 [0, 1.2s]）
前向成本：两次小矩阵乘，与 computeThreats 单弹采样同量级——"计算量差不多"成立
```

#### 2. 奖励函数（主人三信号的公式化）

每决策段（= 9 操作一轮）结束时打分：

```
r = w_T · T*/T_max                       # 长度项：基准越长越好（0~1）
  − w_D · relu(死亡数 − 3)/6             # 分化项：超过 3 种才罚（"以内"不罚）
  + w_E · 死亡位置均值                    # 边缘项：死亡贴窗尾=窗没白算（0~1）
门控：无弹将入圈（自由期）→ 死亡数/边缘项无效，r = w_T（T*=T_max 满分）
初始权重：w_T=1.0, w_D=1.0, w_E=0.5（边缘项是软信号，弱于硬约束）
```

三项的力学：
- **长度 vs 分化对抗**：拉长 T* 得长度分，但恒定操作长跑死亡数超 3 被罚——
  平衡点即"恰好开始大面积死亡之前"的窗长（信息量归零点，与二·六结论同构）
- **边缘项防两头骗**：短窗刷死亡数=0 骗分化项 → 边缘项也没了（0）+ 长度项低；
  死亡集中窗中段 → 说明窗尾白算，边缘项跌——三项互锁，无单点可 hack
- **自由期门控**：无威胁时死亡数=0 是物理事实不是"砍窗骗来的"，必须免罚，
  否则网络学会在无威胁时也输出短窗（灾难性错误）

#### 3. 训练法（在线 REINFORCE，参数少不需要重型优化器）

- REINFORCE with moving-average baseline：Δθ = α·(r − b)·∇log π(K_post|s)
- Adam lr 0.01；baseline = r 的滑动平均（窗 100 段）
- 样本节奏：每 9 操作轮一个样本（节流间隔 30~200ms → 每秒 5~30 样本），
  几千样本可收敛（参数 ~100，样本/参数比 10:1+）
- 备选 CEM（每代 20 组参数 rollout）——更稳但离线批量，在线场景 REINFORCE 优先

#### 4. 实施前置条件与坑

- **先攒数据**：手工 v7 的死亡统计行（已落地面板）跑出分布——若死亡数常态 ≤3
  且位置贴尾，K_post=0.24 已近优，NN 收益有限；若场景间最优 K_post 差异大，
  NN 才有实质收益。**数据说话，不为上 NN 而 NN**（主人上轮定调）
- **非平稳性**：对局节奏变化（开局试探/终局混战）使 s 分布漂移——靠特征⑥⑦
  （上轮反馈）+ 小 lr 缓解；必要时按场景分桶训练
- **探索安全带**：K_post 采样下界不跌破 T_floor（6 帧）——再小的探索也不许
  把微操窗砍没
- **回退路径**：网络输出可随时被 cfg.kPostSec 手工值覆盖（一个开关），
  NN 挂了不影响主流程

### 二·六、v4 极端情况核查 + 对树效率的影响（2026-08-14，主人交办分析；膨胀圈部分随 v4.2 作废，树效率结论仍成立——固定圈窗口同样单调收缩）

#### 极端情况逐项核查

| # | 场景 | 行为 | 结论 |
|---|---|---|---|
| 1 | 子弹绕坦克转（永不远离） | 窗口一直开着，tEnd=折线末端（10s）→ 钳 1.5s | 安全：持续威胁=持续深算，物理上反弹折线不构成真绕圈，最多多反弹几波 |
| 2 | 多次反弹反复接近 | 窗口开关多次，tEnd 取**最后**一次穿出 | 安全：基准偏长（保守方向），不漏死亡 |
| 3 | t=0 已在圈内且正在远离 | f(0)≤0 且单调升 → tEnd=穿出插值（短） | 正确：贴脸刚过的弹窗口很快关 |
| 4 | 弹速极快的贴脸擦过 | 窗口极短（毫秒级）→ clamp 1 帧 | 正确：真"擦弹"本来就只能看 1 帧内 |
| 5 | 坦克贴墙（真实可达 << 膨胀圆盘） | 圆盘按无墙膨胀 → 窗口偏长 | 安全但浪费：墙挡住的方向坦克到不了，基准虚高。已知保守项，见下"优化空间" |
| 6 | 所有弹窗口都 >1.5s | tRaw>上限 → clampedHigh，基准=1.5s | 安全：滚动时域每帧重算，弹进 1.5s 圈内那帧起窗口自然覆盖 |
| 7 | 0 颗子弹 | 无窗 → 1.5s | 正确 |
| 8 | 折线末端仍在圈内（长追击） | tEnd=末端时刻（300m/30 =10s → 钳 1.5s） | 同 6 |
| 9 | 采样步长 1m vs 窗口边界 | 穿出处线性插值，误差 <1m 飞行时间 ≈0.03s（1.5 帧） | 可接受；不够可加密步长，代价线性 |

**边界情形的数学保证**：膨胀圆盘是坦克可达集的**外包**（墙只压缩可达、后退/旋转更慢），
因此"窗口外 ⟲ 无任何操作可被该弹撞上"恒成立——极端情况只会**多算危险**（基准虚长），
不会漏算死亡。这是 v4 全部安全性的根。

#### 对树执行效率的影响（主人问：减少回退 + 更高利用时间）

**1. 回退（旧设计的主要浪费源）被结构性消除**

旧 V6：参考点漂移 → 基准在"几帧↔默认值"间跳变 → 树深度剧变，上一帧算的 9 叉树
下一帧大部分作废重算 = 实质回退。v4：窗口只由几何（折线 vs 膨胀圆盘）决定，
- 窗口内每推进一帧，所有 tEnd 同步 −1 帧 → 树深度**单调收缩**，收缩的 1 帧
  正好是已验证过的那帧——新树的深度 = 旧树深度 − 1，**前一层结论全部可复用**
  （阶段③若实现"上帧树降级为子树根"可复用到 O(1)，未实现也有复用语义）
- 新威胁入窗 → 该弹窗口独立加入 max，不干扰其他窗口的连续性

**2. 时间利用率：深度从"拍脑袋"变成"恰好盖住威胁"**

- 旧：无弹=1.5s、单弹 perigee≈0.5s、多弹被 W 砍半——深度与威胁结构无关
- v4：深度 = 最长窗口 ⟵ 每一帧都可能有操作分化（生/死、分叉），
  窗口关闭后各操作分数趋同（弹远了大家都是满分）→ **窗口结束 ≈ 信息量归零点**，
  深度恰好停在"再算也没新信息"的边界。多弹密集 → max 自动加深（旧设计反而砍半）。

**3. 单帧成本上限（性能模式的实测预期）**

9 操作 × 基准帧数(≤75) 次模拟+评分。注意 9 操作模拟**共享同一组折线**
（子弹不因坦克操作而变），折线采样每帧只做一次（computeThreats 已做）；
每操作每帧 = 一次坦克推进 + N弹位置插值 + 遮蔽角评估（精确法，纯算术）。
预估：无弹 9×75×轻量；有弹 9×窗口×中量。性能面板（B 键运行态）直接给实测数，
超预算的应对预案（按优先级）：
  a. 死亡早停——操作判死后不再继续模拟（scorePath 已 break，天然有）
  b. 分数提前收敛停——连续 K 帧操作排名无变化即停（阶段③加）
  c. 步长减半（采样 2m/点）——精度降，代价减半
  d. hitRadius 调小（10→8m）——窗口变短，深度变浅

**4. 保留的优化空间（不阻塞当前，记录备查）**

- 墙壁感知的可达集：用迷宫把膨胀圆盘裁成真实可达形（射线/格距），消"贴墙虚高"
- 无关弹剔除：hasWindow=false 的弹不进 9 操作模拟的评分输入（现在仍全弹参与
  单帧评分——遮蔽角会自动给 0，但 bulletPosAt 插值白算；小优化）

**结论**：v4 把基准时间从"经验参数堆砌"变成"威胁结构的函数"——回退消除靠
（深度单调收缩+复用语义），时间利用靠（深度=信息量归零点），两者都是结构性质，
不依赖调参。唯一系统性浪费是贴墙虚高（保守方向，安全无损，优化项 1 可消）。

## 三、评分计算流程（V5 每帧求和定稿）

物理意义：站在坦克的位置环顾四周，每颗子弹都会"挡住"一圈方向里的一段——
朝那段方向动就是送死。被挡的方向越少、剩下的安全方向越完整，这一帧的处境就越好。

### 第 1 步：死亡判定（走接口，不用角度算）

```
调 adapter.checkDeath(坦克位姿, 所有子弹位置)
死 → 路径总分扣 10 万分，这条路径停止延伸
    （但不丢弃：万一所有路都死，死路之间也要比出个相对最优）
```

### 第 2 步：算遮蔽角（直接用拷贝区2 的精确解析法，不自己写几何）

```
物理图景（与《无墙壁子弹危险区域调试器.html》同源）：
  坦克是对称矩形（宽 3m × 高 4.75m），站在坦克中心看每颗子弹：
  子弹会挡住哪些朝向？挡住 = 转到该朝向时矩形够得着子弹（含弹半径）
计算流程（拷贝区2 现成函数）：
  ① 每颗子弹算两个遮蔽半角：asin(有效半宽/距离)、asin(有效半高/距离)
     （有效半宽 = 1.5+0.25，有效半高 = 2.375+0.25）
  ② 两个半角张出四组 sin 角带 × 四组 cos 角带，求交 → 该弹的遮蔽弧段
     （正前方/正后方/左右两侧完全对称——主人 2026-08-14 定调）
  ③ 距离 > 黄圆半径（外接圆+弹半径 ≈ 3.06m）的子弹不产生任何遮蔽
     距离 < 红圆半径（内切圆+弹半径 = 1.75m）→ 全圆遮蔽
  ④ 所有子弹的遮蔽弧段做区间并集合并（处理跨 0/2π 回绕）
  ⑤ 合并后的空隙 = 剩余角区间（安全朝向）
角度 convention：区间角度 = 游戏 rot（矩形宽轴角），与朝向断言/渲染直接通用
```

### 第 3 步：全圆合并，算剩余角

```
① 所有子弹的遮蔽区间放到全圆（360°）上合并（区间并集，重叠只算一次）
② 剩余角 = 全圆 − 遮蔽并集（一段或多段安全方向）
③ 单帧分 = 每段剩余角的弧度² 再求和
   · 平方加权的意义：一整段大安全区（0.8² = 0.64）
     优于四段等大的零散安全区（4 × 0.2² = 0.16）→ 奖励集中完整的安全区
   · 必须全圆都算，不能只看坦克朝向所在的那段——
     防止两颗子弹左右夹击时漏掉外部威胁（大文档 L318 原话）
④ 上限：完全无子弹时单帧分 = (2π)² ≈ 39.5
   （注：大文档 L323 写"上限≈π²"，那是"双轴对称取一边"折叠到半圆后的口径，
     实现时两种口径选一种并全程一致即可，见下方待确认项）
```

### 第 4 步：路径总分

```
路径总分 = 各帧单帧分直接求和（不除帧数）
  · 活得久的路自然分高：死亡最晚的路线积累的帧数多
  · 1 帧完全安全 vs 10 秒比较安全 → 选 10 秒（总分高，大文档 L333 定论）
死亡路径 = 前面活着的帧照加 − 10 万 → 永远垫底，但死路之间仍可排序
```

### 一致性断言（测试用）

- 坦克朝向必须落在某段剩余角内——不在 = 子弹已糊脸，第 1 步应已判死；
  出现"没判死但朝向不在剩余角内" = 遮蔽角算错，测试直接失败
- 无子弹 → 单帧分 = 满值；子弹正撞 → 判死且扣 10 万；子弹逼近 → 分数单调下降

### 三·二、v7.2 车道压分（主人设计 2026-08-15，已实施 ?v=11）

**主人实测反馈**：12 帧版精度提升但 AI 躲弹能力反而变差——普遍预测时间短，
子弹到跟前时已无解；1 帧版恐更近视。主人提出叠加评分机制：子弹轨迹穿过
坦克时每帧累积扣分，轨迹离坦克中心越近、穿越部分越长扣得越多，单帧影响
在角度遮蔽的 0.5~1.0 倍之间。

**近视根因分析**：短窗内（弹到达前的自由走位期）各操作的遮蔽分几乎相同
（弹远→角遮蔽≈0）→ 9 操作无分化 → AI 贪心选位，等弹进圈才慌，但墙/角
已把退路封死。缺的不是更长的窗，而是"**别待在弹道上**"的长程压力信号。

**实现（lanePenaltyFrame + scorePath 集成）**：
- 子弹**未来折线**（起点 = 弹在当前模拟帧时刻的位置，弧长 speed×t 截断）
  与坦克膨胀矩形（同遮蔽角几何：几何中心 + 有效半宽/半高含弹半径）求交：
  - 穿越弦长 L（Liang-Barsky 裁剪，纵贯=2×有效半高）
  - 折线到矩形中心最近距 dMin
- 不穿车 = 0；穿车：`p = ratio × (2π)² × (0.5·贴心率 + 0.5·弦率)`，
  贴心率 = 1 − dMin/R_SEMI，弦率 = L/(2×有效半高)；
  `lanePenaltyRatio = 0.75`（主人定标区间 [0.5, 1.0] 的中值，cfg 可调）
- **每帧叠加**进 scorePath 的 perFrameScores（死亡帧不变仍 −deathPenalty）；
  占道越久扣越多，"提前让道"从第 0 帧就有梯度——折线本身编码子弹远期未来
  （最长 300m），与模拟帧坦克位置求交 = **不延长模拟窗就获得长视界压力**，
  短窗近视的结构性根治。多弹穿车分别扣分求和。
- 面板新增「车道压分: X/帧（N 弹穿车）」行（双态）；沙箱步进面板
  「本帧分(含车道压)」。
- 踩坑记录：Liang-Barsky 裁剪 p=0 且 q<0（线段平行且界外）必须置废标志，
  只 return 布尔不置标志 → 擦边线段漏判穿车（离线断言抓出）。

**离线断言（node，10/10）**：纵贯中心 p=29.6=0.75×遮蔽满分 ✓；侧偏 1.4m
p=22.6（贴心率降）✓；擦边 1.9m 不穿 p=0 ✓；弹已飞过（未来段不含车）p=0 ✓；
旋转 90° 不变性 ✓；横穿弦率 0.7 p=23.9 ✓；梯度单调（中心>横穿>侧偏>不穿）✓；
最重压分 0.75× ∈ [0.5,1.0] ✓；双弹求和 ✓。

**v7.3 修订（主人三轮实测打回，2026-08-15）**：
1. **未死亡大负分 / AI 宕机**——v7.2 两处超纲：多弹穿身**求和**（3 弹 =
   2.25×遮蔽满分）+ ratio 0.75。主人定标"单帧影响 0.5~1.0 倍"指**总**影响，
   且"轨迹只是稍微赋予提前看路能力"。修：**多弹取 max**（最危险弹道定价）+
   ratio **0.5**（区间下限）。断言：单弹纵贯 19.7=0.5×满分；三弹穿身 max
   19.7（求和版 55+）；自由期最坏净分 19.7>0（未死亡帧不再大负）；梯度
   中心 19.7>横穿 15.9>侧偏 15.1>擦边 0 保持。
2. **折线渲染瞬态**（"旧反弹点指向子弹位置"）——位置双源不同步：折线起点
   用物理体 GetPosition()，黄圈/威胁表用模型 getX()，反弹瞬间错位。修
   （sandbox ?v=8）：威胁弹 x/y 统一改与折线起点同源（path[0]）+ 折线健康
   校验（首段与物理速度方向点积 <0.1 → 整条丢弃，本帧不进渲染/评分）。
   注：原版 calculatePath 每轮迭代末尾有 closestFraction 重置，非残留 bug。
3. **运行态面板点击失效**（无法展开沙箱 9 项）——数据区每帧 innerHTML 重建，
   mousedown→mouseup 之间元素被替换 → click（要求同元素配对）不触发。
   修（testbench ?v=16）：委托改 **mousedown**（select/input/label 保持原生）
   + 数据区刷新节流 80ms（perfTick 高频源节流，交互路径即时刷）。

**已知边界**：车道压分只编码"弹道穿越"这一种远期危险；墙角困局类危险
仍需树结构的多段规划。窗口长度维持 v7.1（压分补偿近视）；若实测仍近视，
优先调 lanePenaltyRatio（→1.0）而非拉长窗。

## 四又二、节点数值结构（未雨绸缪，主人 2026-08-14 要求）

未来阶段③的每个树节点，把基准时间、评分、沙箱模拟状态**作为一个整体存取**。
本阶段先定好容器结构（`VantageScoring.createNodeValues()`），阶段③直接填：

```
节点数值 = {
    id:        节点编号（阶段③分配）
    parentId:  父节点编号
    depth:     深度（帧数）
    inputs:    产生本节点的操作（9 种之一）
    simState:  沙箱节点状态 {tank:{x,y,rot}, tGlobal}   ← 阶段①的 createNodeSimState 产物
    baseTime:  本节点重算的基准时间结果（滚动时域）     ← 本模块 computeBaseTime 产物
    score:     路径评分结果（总分/生死/死亡帧/逐帧分）  ← 本模块 scorePath 产物
    status:    pending / alive / dead（阶段③维护）
}
```

设计要点：
- 三类数值（基准时间、评分、模拟状态）挂在同一个对象上，节点存取 = 对象存取，不拆散
- 子弹状态不进节点（确定性折线由全局时间决定，阶段①已定此原则）
- 本模块只负责"算出数值填进去"，节点的增删/树的形状归阶段③管
