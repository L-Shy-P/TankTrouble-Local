# 树决策 NN 接管方案（2026-10-02）

> 口径修正：本文取代《FlyWire果蝇脑接入调研》§5~§6 的接入部分。
>
> 主人原话：「树是数据结构，要替换的是评分、选路、生长、回退等一系列树操作，
> 由神经网络或者大脑操控这些决策，而树只需要做物理模拟 + 增量预测即可，
> 也就是说类似于 Hybrid 的机制，物理精算 + 神经网络决策的混合体。」
>
> 这个口径和《Rust移植与NN对接方案-初稿》§4.1（"树动态，NN 输入必须固定"）、
> §八（"NN 最终目标是处理树的几乎全部工作，规则树只用于学习前期和兜底"）
> 是一致的。本文把它**落到具体函数**上。

## 0. 一句话架构

```
        ┌──────────────────────────────────────────────────────┐
        │  树 = 物理模拟器 + 增量预测引擎（不可学习，要绝对准）  │
        │                                                        │
        │   simulateFusedBatch   9 操作 × 75 帧融合世界 rollout  │
        │   scanNodeDeath        几何/接触判死（只许假阳不许假阴）│
        │   threatCoarseBox      时空盒粗筛                      │
        │   confirmNodeDeath…    JS 融合世界权威判死              │
        │   invalidateStaleNodes 新弹增量失效（只负责"找出嫌疑"） │
        └───────────────────────┬──────────────────────────────┘
                                │  候选特征张量（不是分数！）
        ┌───────────────────────▼──────────────────────────────┐
        │  NN = 决策器（可学习，允许犯错，靠死亡检查兜底）        │
        │                                                        │
        │  ★ 统一形式：给出候选集合 → 每个候选一个分数           │
        │    选路 = argmax(分数)，执行层做，不是 NN 的输出头      │
        │                                                        │
        │   D1 候选评分  9 个操作       → 9 个分                  │
        │   D2 选路      = argmax(D1)   ← 无独立头（主人定案）    │
        │   D3 段长      段长档位       → n 个分                  │
        │   D4 生长      L 个叶 + 不生长 → L+1 个分               │
        │   D5 回退      0..10 层       → 11 个分                 │
        │   D6 失效裁决  作废 / 不作废   → 2 个分                 │
        └───────────────────────┬──────────────────────────────┘
                                │  分数向量
        ┌───────────────────────▼──────────────────────────────┐
        │  执行层（JS 侧）= argmax + 硬约束                       │
        │   · argmax 只在通过硬过滤的候选里取                     │
        │   · 红（fd<=1）绝对不能选 —— 不可被 NN 覆盖的安全底线   │
        │   · 段长 <= evaluatedFrames —— 不能超出实际模拟范围     │
        │   · 粗筛只许假阳不许假阴 —— NN 只能收紧不能放宽          │
        └──────────────────────────────────────────────────────┘
```

> **架构要点（2026-10-02 主人定案）**：选路不需要网络，`argmax` 就够了。
> 网络只负责**给候选打分**，`argmax` 是执行层一行代码。
> 本文档原先把"排名"当成一个独立输出头，是多余的——**排名就是分数的排序**。
> 这条同时满足《Rust移植与NN对接方案》§4.4 的要求（"死亡检查失败时按排名试下一个，
> 无需重新推理"）：拿 9 个分数排序，按序试，效果完全一样。
>
> 推论：四个决策点（生长/回退/段长/失效）**都能化成同一个形式**——
> 给候选集合打分，argmax。见 §3.4。

**和 Hybrid 的对应关系**：

| Hybrid | 本方案 |
|--------|--------|
| 物理精算（Rust 沙盒推演 18 个动作） | 树（融合世界 rollout 9 操作 × 75 帧） |
| 神经网络决策（PPO 策略输出动作） | NN 决策器（评分/选路/生长/回退） |
| 观测 1028 维固定张量 | 同一思路，见 §3.1 |
| 终局奖励 | 逐段自举 + 终局校正，见 §4 |

## 2. 为什么树不能被砍掉

主人说"树只需要做物理模拟+增量预测"，这句话的关键在于
**rollout 本身就是 NN 最大的输入来源**，不是可以省掉的开销：

```
一帧的真实计算量分布（当前实现）：
  rollout（9 操作 × 75 帧融合世界）   ← 这是"算力"，也是 NN 的"眼睛"
  ├─ 产出 perFrameScores[75]          → 直接进 NN 特征（每候选 75 个数）
  ├─ 产出末态位姿 / 速度              → 直接进 NN 特征
  ├─ 产出 deathFrame                  → 进 NN 特征（软死信息）
  └─ 产出弹道采样 samples[]           → 渲染 + 粗筛复用
```

所以正确的说法不是"砍掉树的智能，保留树的计算"，
而是**"树的智能（评分/选路/生长/回退）换成 NN，树的物理与特征提取全留"**。
树从"会思考的结构"降级成"物理 oracle + 特征工厂"，但它一帧都不能省。

## 3. 张量接口

### 3.1 每次推理的固定形状

对齐《Rust移植与NN对接方案》§4.1 的既有口径：

```text
批次维度   B = 9                     （9 个操作，固定）
子弹槽位   K = 16                    （最紧迫的 16 颗，超过截断——已有 MAX_EVAL_BULLETS=64 可调）
叶候选     L = 8                     （生长决策的候选叶数，固定；不足补 mask）

全局标量   G = 24
候选特征   C = 32   × B
子弹特征   S = 12   × K
叶特征     F = 16   × L
```

### 3.2 特征清单

**全局 G（24）**

| 特征 | 来源 |
|------|------|
| 累积时间 `_timeAcc` / 段末剩余 | `tree` |
| 当前节点 depth / nodeCount / 预算占用 | `tree.stats` |
| 真死候选数 / 红候选数 | `isTerminalDead` 统计 |
| 本 tick growMs / rolloutMs（性能反馈） | `tree.stats` |
| 自身位姿 (x,y,rot,vx,vy) | `simState.tank` |
| 被吃/击杀数、剩余弹药、弹种 | 游戏接口 |
| **果蝇反射张量（8 维）** | **见 §5.A** |

**候选 C（32）**——9 个操作各一份

| 特征 | 来源（已有） |
|------|-------------|
| 输入 one-hot (5) | `c.inputs` |
| 预测末态位姿 (3) | rollout 末帧 |
| 段长 `segmentFrames` / `plannedFrames` | 有 |
| `fullDeathFrame`（软死信息，红=-1 特判） | 有 |
| `rolloutTotal` / `segmentScore` / `subtreeBest` | 有（可当 baseline 特征） |
| `perFrameScores` 的统计量：均值/最小/末值/斜率 (4) | 有 |
| 与最近子弹的相对位置/速度 (4) | 可算 |
| 是否贴墙 / 弹簧绳距离 | 有 |
| 被遮蔽角 | 有 |
| 该操作的卡墙黑名单剩余 `_stuckOps` | 有 |
| 历史选中频率 | 可加 |

**子弹 S（12）**——对齐既有草案 §4.3：相对位置(2)、相对速度(2)、距离、到达危险圈时间、
是否在墙后、轨迹包围盒(2)、弹种、半径、剩余寿命。

**叶 F（16）**——生长决策：叶 depth、叶所在路径的 `subtreeBest`、叶的
`fullDeathFrame`、叶的孩子数、该叶距根的段长累计、该叶的 opName one-hot 等。

### 3.3 输出头

**全部是分数向量，没有一个是 one-hot、没有一个是"排名"、没有一个是连续回归。**

```text
D1 score_ops[B=9]        9 个操作的分数          → 执行层 argmax = 选路
D3 score_seg[n]          段长档位的分数          → 执行层 argmax = 本段帧数
                          档位建议 [1, 2, 4, 8, 16, 32, 75]（n=7，夹到 evaluatedFrames）
D4 score_grow[L+1]       L 个叶 + 1 个"不生长"   → 执行层 argmax = 生长决策
D4 score_layers[6]       扩 1~6 层的分数         → 执行层 argmax = 本 tick 层数
D5 score_boost[11]       补偿 0~10 层的分数      → 执行层 argmax = 补偿层数
D6 score_stale[2]        {作废, 不作废} 的分数   → 执行层 argmax + §3.4 护栏
```

> **没有 D2 头。** 排名不是要"输出"的东西，它是分数的排序结果，执行层一行 `sort` 就有了。
> 本文档早先把 `rank[B]` 列为独立输出头是多余的，已按主人定案删除。

### 3.4 统一形式：一棵树只有一个原语

四个决策点形式完全一样，只是候选集合不同：

| 决策 | 候选集合 | 候选数 | 打分依据（特征） |
|------|---------|--------|-----------------|
| 选路 | 9 个操作 | 9 | rollout 75 帧累积分 / 末态位姿 / deathFrame |
| 段长 | 段长档位 | 7 | 当前威胁紧迫度 / 该档位内的死亡帧 |
| 生长 | 待扩展叶 + 不生长 | L+1 | 叶 depth / subtreeBest / 性能余量 |
| 回退 | 补偿层数 | 11 | 失效原因 / 栈深度 / growMs |
| 失效裁决 | 作废 / 不作废 | 2 | 新弹轨迹 vs 节点粗盒 |

**实现建议**：共享 trunk（吃 §3.1 的全局 + 子弹特征），
每个决策点一个小的打分头（输出候选数那么多个标量）。
候选数变了只换头，trunk 不动。

**执行层伪代码**：

```js
function decide(head, features, hardFilter) {
    var scores = net.forward(head, features);      // 长度 = 候选数
    var best = -Infinity, pick = -1;
    for (var i = 0; i < scores.length; i++) {
        if (hardFilter && !hardFilter(i)) continue;   // 红过滤 / 预算闸门 / evaluatedFrames
        if (scores[i] > best) { best = scores[i]; pick = i; }
    }
    return pick;
}
```

**训练时例外**：探索需要采样，所以**训练时用 softmax 采样，部署时 argmax**。
这是训练器和部署器的差别，不是两个输出头。

### 3.5 D6 的安全护栏（重要）

粗筛的铁律是"只许假阳不许假阴"。NN 接管 D6 之后**不能破坏这条**：

```text
NN 输出 score_stale[2]（作废 / 不作废）
执行层规则：
    argmax == 作废  → 作废（保守，可能多作废，只是浪费算力）✅
    粗盒几何命中但 NN 说"不作废" → ❌ 不行
```

正确做法：**NN 只能"追加作废"，不能"免除作废"**。
即 `最终作废集合 = 几何粗盒 ∪ NN 判定集合`，
实现上就是给 `hardFilter` 加一条：几何命中者直接强制"作废"分支。
这样 NN 的价值是"提前抓住几何漏判的（比如 v137 那种子弹状态陈旧导致的漏判）"，
而不是"放宽几何"。等实测证明 NN 的漏判率确实低于几何，再谈放开。

### 3.6 网络到底怎么"操作树"——用代码说清楚

**先破除一个误解：网络碰不到树。** 树是 JS 代码里的对象，网络不能调用它，
也没有任何东西在"操作树"。树一直在自己操作自己。

真实接口只有两件事：

```
树 → 网络 ：一串数字（特征）
网络 → 树 ：一串数字（分数）
中间的"操作"：我们写的 JS 拿着这些分数去做的
```

**原来的 `pickBest`（`vantage_tree.js` 4904）**：

```js
for (var i = 0; i < children.length; i++) {
    var c = children[i];
    if (!c || c.exhausted || c.invalid) continue;
    if (!onlyImmediateDead && isTerminalDead(c)) continue;   // 红过滤
    var cScore = c.subtreeBest + objectiveBonus(c, ...);     // ← 手写公式算分
    if (cScore > bScore) { best = c; bScore = cScore; }
}
return best;
```

**换网络之后**：

```js
var feat   = buildFeatures(children);              // 树 → 数字
var scores = vantageNet.forward('ops', feat);      // 网络 → 9 个数字
for (var i = 0; i < children.length; i++) {
    var c = children[i];
    if (!c || c.exhausted || c.invalid) continue;
    if (!isTerminalDead(c)) continue;              // 红过滤原样不动
    if (scores[i] > bScore) { best = c; bScore = scores[i]; }   // ← 唯一差别
}
return best;
```

**除了 `cScore` 那一行，其它代码一模一样。** 遍历、节点、父子关系、invalidate、
grow——全是原来的。网络把"这个候选值多少分"从**一行公式**换成了**一次推理**。

生长同理：

```js
var leaves = collectGrowableLeaves(tree);       // 树提供候选（L 个）
var scores = vantageNet.forward('grow', feat);  // 网络出 L+1 个数字
var idx = argmax(scores);
if (idx === L) { /* 本 tick 不生长 */ }
else { growStep(tree, leaves[idx]); }           // ← 原有生长函数，一行没改
```

> **准确表述**：网络不"操作树"，网络是**决策函数的替代品**。
> 原来那 40 行 if-else 是决策函数，现在换成 `net.forward()`。
> **调用者还是原来的树。网络替换的是函数体，不是调用者。**

类比：网络是打分员，树是棋盘。**打分员不会动棋子，他只给每个候选打分；
动棋子的手是我们自己的代码。**

**推论**：既然接口只是"数字进、数字出"，那么"大脑能不能操作树"根本不是问题
（能，通过数字）。真正的问题是 **"大脑打的分比手写公式好吗"**——那是 §5 的对照实验。

## 4. 训练口径

### 4.1 逐段自举（沿用既有文档结论）

```
节点 A 被选中，执行 L 帧到达节点 B
训练目标(A) = L 帧内真实结果 + NN(B)
```

对齐《NN树决策讨论精华》§4.2：稠密信号，每个节点执行完学一次，不等回合结束。
终局胜负做低频校正。

### 4.2 预热：先模仿规则树

对齐《Rust移植与NN对接方案》§八第 3 条：
"NN 训练前期先模仿树的基本操作，之后再做自主规划和策略学习。"

具体：把现在 `pickBest` / `pickBestChildByRolloutTotal` 的选择当标签，
先训 D1+D2 到 ≥95% 一致率，再放开 PPO。

**这一步有个额外好处**：可以先在**不改动任何游戏逻辑**的前提下，
把 NN 决策器接成影子模式（shadow mode），跑几百局对比
"NN 会选什么 vs 树实际选了什么"，零风险验证接口正确性。

### 4.3 训练管线

直接复用 `参考AI/killfield-main` 的 PPO 管线 + 导出成浏览器可跑的权重
（复刻 Hybrid 的 `hybrid.bin` + 纯 JS 推理那套，见
`game_core/js/external_ai_hybrid.js` 的既有实现）。

> connectome 当**归纳偏置**、端到端训练，"同一条蒸馏配方、60k 步"：

> 即：**接线让训练慢 22 倍，一分钱没买到。**
>
> **③ 无训练版对照（166,700 神经元吐脉冲，n=20）**
>
> | 系统 | 存活 | 击杀 |
> |---|---|---|
> | 真连接组 | 53.3 s | 12.10 |
> | 打乱连接 | 6.7 s | 0.67 |

>
> 原因：**真脑的输出几乎是常数**——turn 0.80±0.56 度/帧、forward 19.2±1.2、94% 时间按住开火。
> 对照报告原话："**The fly brain isn't what's playing DOOM.**"
>
> **④ 但连接组是真科学——只是要问对问题**
> 同一份接线，换个问题：Shiu et al. 的全脑模型（无 AI），
> 糖 → 进食运动神经元 MN9 = **真接线 66 Hz / 打乱 0 Hz**。
> 原话："**connectomes are for asking questions like the second one.**"
>
> **⑤ 为什么"把数据转成它的感官输入、再把它的反射转成树操作"不够**
>
> 这个思路（2026-10-02 主人提出）看起来很美，但它踩了两个坑：
>
> **坑一：根本没有"已经训练好的模型"。**
> "训练好的模型" = **权重**。连接组给的是**结构**。
>
> | 连接组给了 | 连接组没给 |
> |---|---|
> | 谁连谁（`pre_root_id → post_root_id`） | 突触效能（释放概率、受体密度、电导） |
> | 递质符号（ACH 兴奋 / GABA·GLUT·HIST 抑制） | 时间常数、适应性、爆发特性 |
> | 突触条数（强度的**粗糙代理**） | 神经调质状态 |
> | 神经元的形态/位置 | **针对任何具体任务的"训练结果"** |
>
> 类比：连接组是**电脑的布线图**，不是**软件**。你拿到了主板原理图，但没有程序。
>
> **坑二（更致命）：树操作的输入是"反事实"的，果蝇脑只能接收"实际"的。**
>
> ```
> 树决策的依据：如果走这条路、75 帧后会怎样？
>               ↑ 这是 rollout 模拟出来的未来，从来没发生过
>
> 果蝇感光细胞接收：真实落在复眼上的光
>               ↑ 只能是此刻、实际发生的事
> ```
>
> **你没法给果蝇看"还没发生的未来"。**
> 若硬把 rollout 结果编码成视觉刺激喂进去，那你喂进去的东西里
> **已经包含了你想问它要的信息**——输入是你算的，输出再要回来，是循环的，
> 果蝇脑在其中没有增加任何信息。
>
> 而且这两种计算的性质不同：
>
> | | 输入性质 | 输出性质 | 果蝇能做吗 |
> |---|---|---|---|
> | **反射** | 实际的（眼前的光） | 连续低维运动指令 | ✅ 这是它的专长 |
> | **树操作** | **反事实的**（没发生的未来） | 跨时间可比的 9 个价值分 | ❌ 不同的计算 |
>
> **反射 = 反应，评分 = 评估。这不是"转化"能弥合的差距，是两套计算。**
>
> **⑥ 而且这个思路已经被完整实现过了**
> DOOMFLY 做的就是"正确转化输入输出"：
> ```
> 游戏帧 → R1–R6 亮度(3335) + R8 颜色(811)   ← 转成它的感官输入
> 166,700 神经元吐脉冲
> DNp20 → 转向 / DNpe017 → 前进+开火          ← 转成游戏操作
> ```
> 结果：输出是常数，无脑自动驾驶打得一样好。
> **不是转化没做对，是转化对了也就这样。**
>
> **⑦ 我们自己跑的第一轮对照（2026-10-02，在 Vantage 项目内）**
>
> `tools/flywire/reflex_experiment.py`，900 场景、8 个逃逸方向、70/30 划分。
> 任务：给多方向子弹逼近的场面，预测"哪个方向活得最久"。
> 读出器：**冻结连接组，只训最后一层岭回归**（reservoir computing）。
> 指标：Spearman 秩相关（排序任务不用 argmax，因为平局会毁掉分类指标）。
>
> | 臂 | Spearman | 后悔值(帧) | 特征数 |
> |---|---|---|---|
> | **手写公式**（远离平均威胁） | **0.269** | 24.32 | 0 |
> | 手写公式（远离最近威胁） | 0.247 | 26.66 | 0 |
> | 真连接组 · 只读下行神经元 | 0.077 | 26.13 | 328 |
> | 随机重连 · 只读下行神经元 | 0.071 | 25.37 | 328 |
> | 真连接组 · 分组平均 | 0.088 | 27.31 | 696 |
> | 随机重连 · 分组平均 | 0.114 | 25.32 | 696 |
>
> **判决：真连接组 ≈ 随机重连（Δ=+0.007 / −0.026），手写公式好 3 倍。**
>
> ⚠️ **但这个结果不能证明"果蝇脑不行"**，它只证明了**"当前这个接法不行"**。
> 必须说清楚的三条局限：
> 1. **感觉编码是我手写的且粗糙**——只有 327/971 个种子有 T4/T5 方向调谐谱，
>    其余 713 个退回左右侧别。**如果编码错了，果蝇就没收到正确信息，失败的是我。**
> 2. **生理参数是我瞎设的**——τ=20ms、阈值 1.0、不应期 3ms、噪声 0.01、
>    权重归一化 99 分位×0.35。连接组本身不提供这些。
> 3. **只测了线性读出、只有一个随机种子。**
>
> **所以下一步必须做参数扫描**，把"我的接法不行"和"果蝇不行"分开：
> 输入增益 × τ_m × 抑制强度 × 读出方式 × 编码方式。
> 扫完整个网格 real 仍 ≈ shuffled，结论才站得住。
>
> **⑧ 第二轮：用 NN 学习"最优接法"（主人假说，2026-10-02）**
>
> 主人假说：「用 NN 学习最优接法就行……只要数值凑成一次，就能有很好的效果。」
> 这是**该做的实验，而且正是 doomfly-rl 做的事**。但裁判必须是
> 「同样的训练、同样的编码器结构、**只换中间那张图**」real vs shuffled，
> 而不是「接上了能跑」——因为 reservoir computing 的既有结论是：任何足够大的
> 随机循环系统配训练过的读出层都能逼近目标，"有效果"只能证明编码器好。
>
> 实现：`tools/flywire/learned_interface.py`（速率模型 + 手写 BPTT + Adam）
> ```
>   h_t = tanh( g·(h_{t-1} W) + u W_in + b_in )
>   y   = h_T[:,R] W_out + b_out
>   冻结 W = 连接组（真 / 随机重连 / 全零）  ；可学 W_in 编码器 + W_out 解码器
> ```
> **方法学（这次的可信度）**：
> · BPTT 梯度经 float64 数值校验，最大相对误差 **1e-8** ✅
> · 早停（验证集）+ 权重衰减——修掉了第一轮的过拟合（6 轮 0.155 → 250 轮 0.117）
> · 1800 场景，train/val/test = 55/25/20
>
> **结果（Spearman 秩相关，越高越好）**：
>
> | 臂 | Spearman | 后悔值(帧) |
> |---|---|---|
> | 手写公式（远离最近威胁） | **0.226** | 25.51 |
> | 手写公式（远离平均威胁） | 0.210 | 23.44 |
> | 真连接组 + 学习接口 | 0.166 | 23.61 |
> | **随机重连** + 学习接口 | 0.158 | 22.14 |
> | **完全不要连接组** + 学习接口 | 0.150 | 22.43 |
>
> **判决：real − shuffled = +0.008，real − noconn = +0.016 → 无差异。**
> 手写公式仍然最强。
>
> **但主人的直觉对了一半，而且这半很重要**：
> 学习接口确实大幅有效——**冻结读出只有 0.077，学了编码器/解码器后到 0.166（翻倍）**。
> 所以"接法可以学出来，不必手调"是对的。
>
> **错的是另一半**：学出来的接口**并没有让果蝇脑变得有用**。
> 因为一旦接口可学，信息就被压进编码器/解码器了，中间的动力学不需要提供任何东西
> ——而且中间那层还增加优化难度（real 反而略低于 shuffled 和 noconn）。
>
> **两次完全不同的接法，同一个结论**：
> | 接法 | real | shuffled | 结论 |
> |---|---|---|---|
> | 冻结连接组 + 线性读出 | 0.077 | 0.071 | 无差异 |
> | 冻结连接组 + **学出来的**编码器/解码器 | 0.166 | 0.158 | 无差异 |
>
> **还没被否掉的只剩一条**：以上都是**速率模型（tanh）**，不是脉冲。
> 脉冲动力学可能在起作用，而速率近似把它抹掉了。
> 要验它得上代理梯度（surrogate gradient）跑脉冲 SNN，或用进化策略直接优化脉冲网络
> （脉冲不可微）。这是唯一还站得住的下一步。
>
> ### 对 Vantage 的直接含义
>
> | 想用果蝇脑做的事 | 对照实验的判决 |
> |---|---|
> | 取代传统 NN 做评分 | ❌ 真连接组 18.6 / 随机 19.0 / 无连接组 18.3 —— 一样，且慢 22 倍 |
> | 做观测特征 | ❌ 上表第一行已经证明：反正要训，接线不提供信息 |
> | 当结构先验初始化 | ❌ 这正是 doomfly-rl 做的事，结论是"carries no measurable inductive bias" |
> | **做感觉运动反射**（LPLC2→DNp01 逃逸） | ⚠️ **唯一还站得住的用法**，但先验概率低，必须实测 |
>
> **结论：不要把它当主线。** 主线是传统 NN（Hybrid 已实测 90.7%）。
> 果蝇脑降级成一个**便宜的实验臂**——数据已下好、子图已抽好、代码已写好，
> 跑一次对照就能用自己的基准回答"它到底有没有用"。**别赌它。**

**它做不了主角，但能做三件传统 NN 给不了的事。**

### 5.1 果蝇脑到底是什么（回答主人的问题）

它不是神经网络模型，是**接线图**。139,255 个神经元、386 万条连接、3415 万个突触，
每条只有"谁连谁、连几根、什么递质"。**没有权重、没有激活函数、没有输入输出定义。**

那它"能不能训练"？严格说：

| 方式 | 是否可训练 | 说明 |
|------|-----------|------|
| 直接反传 | ❌ | 脉冲是离散事件，没有可微路径 |
| **线性读出（reservoir computing）** | ✅ | **冻结连接组，只训最后一层线性分类器**。便宜、有理论保证 |
| 局部可塑性（STDP/Hebbian） | ⚠️ 半 | HalfLife 用的 3-factor STDP。无监督、慢、难导向"赢" |
| 代理梯度训 SNN | ✅ | 但这时你训的是一个**普通脉冲网络**，连接组只剩下"初始化"的意义 |

**会比我用传统 NN + RL 更好吗？——在这个任务上，几乎肯定不如。** 三个理由：

1. **数据效率这个优势在我们这儿是废的。** 果蝇脑的价值在于"不用海量数据就能有行为"，
   而我们有一个**可无限重置的模拟器**——这正是 RL 碾压的领域。
2. **行为带宽不匹配。** 果蝇的全部动作空间约 10 块肌肉（走/转/跳/飞）。
   Tank Trouble 需要的是"75 帧后的子弹在哪、哪条路能绕墙"——果蝇大脑里
   没有这种表征，接不上。
3. **demo 的效果主要来自手写的那两端。** 我读了 FlyBrain-HalfLife 的架构：
   它的"战斗反击 180° 甩头"是手写 FSM、"虚拟平衡棒"是弹簧阻尼器、
   "Helmholtz 视觉对准"是手写光流公式。连接组只占中间一层。
   Eon Systems 那波"上传大脑"的说法也已被学界质疑夸大。

### 5.2 但它有三件传统 NN 给不了的东西

| 价值 | 说明 | 在本架构里放哪 |
|------|------|---------------|
| **不可遗忘的硬反射** | RL 会灾难性遗忘；连接组是固定的，永不变质 | §5.3 B：安全否决 |
| **极低延迟** | 3508 神经元 / 11.5 万边，<0.5ms/帧；RL 推理要 1~2ms | §5.3 A：观测特征 |
| **结构先验** | 可能有用的归纳偏置，理论上能让 PPO 收敛更快 | §5.3 C：网络初始化 |

### 5.3 具体放法

**A. 作为观测特征（推荐，最先做）**

用已抽出的 `tools/flywire/_data/reflex_core.*`（3508 神经元，fafb）：

```
每帧：子弹几何 → 8 扇区逼近强度 → 注入 LPLC2/LC4 群（种子神经元）
      ↓ 跑 LIF（1 帧 1 步，或 1 帧 5 步 @ 1ms）
      ↓ 8 类下行神经元（DNp01/DNp04/DNp09/DNp20/DNpe017/MDN/DNg12_b）放电率
      ↓ 8 维"本能张量"
      → 进全局特征 G 的第 17~24 维
```

实测这条链路是通的（`lif_probe.py`）：刺激 0.6 不动、1.0 起爆，
下行群从 0 → 29 → 197 → 346 发放。**这个阈值是连接组自带的**，
正好对应"子弹逼近到一定程度才触发闪避"。

**B. 作为安全否决头（中风险，需要 A 的实测支撑）**

DNp01 群在 N 帧内爆发超过阈值 → **直接否决 NN 选出的操作**，强制换排名第二。
这条路径不可学习、不会被 RL 遗忘，正好补 RL 最脆的地方。

对应现有代码：`enforceNonRedPrefer` 的机制可以直接复用（它已经是"选中后强制改选"）。
区别是判据从"红"换成"果蝇说这个不行"。

**C. 作为决策网络的初始化（研究向，可选）**

把 3508 神经元的连接矩阵当 GNN 的消息传递骨架，D1 的评分头接在后面，
然后 PPO 微调。**这条路是可证伪的实验**：如果它比随机初始化收敛快，
说明连接组确实提供了有用的归纳偏置；如果一样，就说明对这类任务没用。

> 这个实验值得做——它花不了多少时间，但能给"果蝇脑到底有没有用"一个我们自己的数据。

## 6. 工程量与风险

| 项 | 估算 | 风险 |
|----|------|------|
| D1+D2 接管（评分/选路）+ 影子模式 | 3~5 天 | 低。接口清晰，可影子验证 |
| D3 段长 | 1~2 天 | 低。有 `evaluatedFrames` 硬夹 |
| D4 生长 | 3~5 天 | **中**。叶数动态，mask 处理容易错 |
| D5 回退补偿 | 2~3 天 | 中。栈语义要保住 |
| D6 失效裁决 | 3~5 天 | **高**。碰保守性铁律，护栏必须先写 |
| LIF 反射层（JS + Worker） | 2~3 天 | 中。格式已与 `flybrain/sim-worker.js` 兼容 |
| 训练管线 | 1~2 周 | 中。可复用 killfield PPO |

**最大的风险不是技术，是"训不出来还看不出来"**。
所以务必按 §4.2 先做**影子模式**：NN 只出决策不执行，跑几百局对比一致率，
一致率上不去就说明接口或特征有问题，此时绝不能上生产。

## 7. 建议的推进顺序

1. **D1+D2 影子模式**（先不接果蝇，纯把规则树的选择当标签训一个评分/选路网络）
2. **接 LIF 反射层**（`reflex_core.bin.gz` → Web Worker → 8 维本能张量进 G）
   —— 对比影子模式一致率有没有提升，这是果蝇脑有没有用的第一个硬数据
3. **D3+D4+D5**（段长/生长/回退）
4. **D6**（失效裁决，护栏先写）
5. **可选实验**：A（随机初始化）vs C（连接组初始化）的 PPO 收敛速度对比
