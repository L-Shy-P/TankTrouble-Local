## 1. 项目是什么

**Tank Trouble 的本地克隆**，跑在浏览器里（`game_core/`，用 Box2D + Canvas）。

**Vantage** = 给这个游戏做的 AI 的名字。它的核心是一棵「**操作预测树**」：

- 树做 **物理模拟 + 增量预测**；
- 现在跑的是 **规则版**（打分选路）；
- 正在做的是 **智能体版**：把树上的**决策操作**（评分、选路、生长、回退）**换成神经网络智能体**，
  **树只保留物理模拟 + 增量预测**；
- 长期目标：智能体换成 **FlyWire 果蝇脑**；整体形态想做成 **「像 Hybrid」**。

## 3. 主人定案（**原文级，最高优先级**）

### 3.1 架构

- 「树是数据结构，**要替换的是评分、选路、生长、回退等一系列树操作**，由神经网络或者大脑操控这些决策，
  而**树只需要做物理模拟+增量预测**即可」
- 「**智能体直接选出路线**，而没有明面上的打分过程，这才正确。」
- 「**不能让智能体给节点评分，然后我们用算法直接找分最高的路径**」
- 「现有那些机制**不是删掉，只是作为可拆卸模块**。」
- 「**两个智能体肯定两步啊，怎么能合起来**，合起来不就成一个万能智能体了」
- 「**根本不存在段长（操作时间）**，现在智能体架构里已经没有这个语义了」
- 「**A 肯定得基于已经有的帧作为新生长的根**进行延伸，不可能拿未来的薛定谔的帧作为模拟基础。」
- 「**A 没有那个尽量往深处延伸的 KPI**，至少目前不需要，**只需要简单的胜败奖惩**即可，剩余的它自己摸索。」
- 「**节点实际上可以长在整个时间树的任意位置。**」「**不能和某个节点重合，可以处于两个节点之间。**」
- 「**任选 1 帧生长 9 个操作**」+ 4 条合法性（普通帧→建节点分叉 9；叶子→省去建节点；非叶子且新时长≤现有→惩罚；新时长>现有→延伸合法）
- 「**一个 `(节点ID, 相对时间)` 的格式能表示三种语义——生长位置、选的路线、射击帧。**」

### 3.2 树的职责

- 「总之就是**树只模拟「确认的」「很少改变的」内容**，并且**要简洁**，**别做太多辅助，影响智能体感知**。」
- 「**绿死就绿死，AI 自己会感知的**，树只是提升 AI 感知的精度，让 AI 能精确预测【**固定的子弹**】造成的死亡。」
- 「**失效节点不进观测**」——「失效的我觉得智能体根本就不需要能看见它，也没必要让它能被选」
- **射击**：「**每帧都会重新调用 B**……只要 B 的计划稳定，**时间逐步推进，到射击的那一帧的时候，就射击**」
- ★「**我们不考虑薛定谔的子弹**。插入了射击，但实际上子弹还没有出膛，**树里模拟的只有确定的子弹**。
  这些情况，**直接在子弹出现后刷新树即可**。」⟹ **插入射击不需要重算子树**

### 3.3 友伤规则（**经过一次纠正，精确版**）

> 「**碰到东西之前，对发射者不致命。**」

| 武器 | 何时开始对**发射者**致命 |
|---|---|
| 普通弹 / 双管 / 霰弹 / 加特林 | **碰过墙之后**（或碰过别人的护盾之后） |
| **破片** | **首帧就致命** |
| **追踪导弹** | **碰过墙** 或 **2.0 秒之后** |

**设计理由（主人原话）**：「**为了防止追子弹自杀，因为总不能刚射出就炸膛了。**」

⚠️ **但禁令不变**：沙箱里**不许**自己**额外**加"这是自己的弹所以不用判"的豁免。

### 3.4 护盾

> 「**护盾有个特殊的机制，它并不是让坦克无敌，而是真的在坦克周围反弹子弹**
> （当然，**地雷破片碰到就停**），所以这就导致，**带有护盾的坦克其实是可以被杀的**……」
> 「**但貌似，我们不需要考虑过多，因为这涉及薛定谔的子弹（射击事件）。**」

⟹ 施工口径：**已在场的子弹撞盾 → 反弹；破片撞盾 → 停**。
**不要做成"无敌"，也不要为"自己打出的弹反弹打死自己"建模拟。**

### 3.5 帧长

> 「**通常游戏帧率都是稳定的。所以就可以用这个稳定的数值，如果掉帧了，就及时更新矫正。**」

（现有校准器 `calibrateFrameDt` 把"抖动"和"掉帧"当同一回事用 `alpha 0.02` 慢平滑 —— 与之不符。）

### 3.6 开发策略

- 「**先把细节尽可能都搞清楚，直接一次性写对。**」
- 「**先作弊全开地做**」（4 个开关，最后再关）
- 「你查别的地方，总之**都查清楚，防止以后实现乱猜，导致极其隐秘的 bug**」

### 4.2 已确认的关键事实

- **`tick` 里有 8 个会结束本帧的 `return`**（`vantage_tree.js:7129/7131/7143/7217/7375/7397/7544/7552`），
  **其中 6 个会跳过末尾的 `growStep`（`:7558`）**。
- **树上的决策点共 12 处**（D1 生长位置 / D2 生长层数 / D3 节点预算 / D4 选路 / D5 候选过滤 /
  D6 评分 / D7 加成 / D8 段长 / D9 真死回退 / D10 失效重扫 / D11 段末调度 / D12 坍缩重建）。
- **智能体已接线的只有 3 个字段**：`growAt` / `growTimes` / `select`（`vantage_tree.js` 只有 3 个读点）。
- **`Agents` 是全局单例** —— `vantage_` 前缀只决定 `AIs` 里放哪个 Manager，
  **代码里没有任何一行把 `aiId` 映射到 `Agents.use(...)`**。
- **`enforceNonRedPrefer`（不变量②的兜底）唯一调用点被注释掉**（`:6635`，主人要求"别用兜底"）
  ⟹ 不变量②现在靠 `pickBest` 里的**层过滤**在做，**而那条属于评分系统**
  ⟹ **拆评分 = 同时拆掉不变量②的实现载体**。
- **树里没有"射击"这件事**（8,344 行里 `fire` 只出现在一条无关注释）；
  树模式把 `fire` 写死 `false`（`ai_vantage.js:104-111`）。**主人澄清：那是"还没开始实现"。**
- **`SandboxAdapter` 只透出 4 个取数方法**（`getTankState`（只返回 `{x,y,rot}`）/ `getProjectiles` / `getMaze` / `getB2DWorld`）
  —— 而输入规范要的 `getOpponent/getCollectibles/getTraps/getZones/getRoundState/getUpgrades/getWeaponStates/getTeam`
  **一个都没有**（底层方法**全都存在**，只是没转发）。
- **死亡事件有订阅机制**：`RoundModel.addEventListener` + **40 个事件**（含 `TANK_KILLED`、`TRAP_TRIPPED`、`UPGRADE_*`、`ZONE_*`）。
- **子弹弹道不是一条链，是三条不同精度的链**（折线 / track / 融合+Rust 圆弹）；
  **全缺 4 项**：撞墙次数上限、霰弹撞墙减命、激光线段扫掠、导弹制导。
- **JS 有几何回溯补判、Rust 没有** ⟹ 同一局面两边判死不一致，**而选路用 Rust 的结论**。
- **`tree.rs`（1,690 行）是死代码** —— 无 `#[no_mangle]`、无 ABI 调用，**线上跑的树仍是 JS 那棵**。
- **两个差分脚本卡在版本闸门**（判据 `!== 10`，而 `vt_version() = 9`）⟹ `vt_rescore_nodes` / `vt_score_paths` **没有对拍在保**。
- **"录制对局 + 回放"能力目前不存在**（只有决策段级训练 JSONL，**无 fire / 无帧号 / 无地图 / 无种子**）。
  ⚠️ CDP 传输量是硬约束：`collect.js:42` 原注释「**原始记录 400 条 = 30MB，CDP 传不动**」。

## 5. 施工纪律与血泪教训

### 5.1 四条红线

1. **规则版逐帧不变** —— 所有改动必须用 `if (智能体模式)` 包住，规则版路径一行不动。
2. **不许让智能体打分**，也不许算法拿分搜最优路径。
3. **不许有"段长/操作时长"这个语义**（包括 `growTimes`、`segmentFrames` 作为智能体输入）。
4. **每处弹种/判死语义改动，必须 JS track + JS 融合 + Rust 三处同改**，并带一份**能跑通的差分对拍**。

### 5.2 一条核心纪律

> **「生长必须是 tick 里【无条件】的一步，绝不许放在任何『提前返回』之后。」**

**代码级依据**：那 8 个 `return` 里有 6 个会跳过 `growStep`
⟹ **不先把生长前移，A 的 `growAt` 在"提交帧"永远无效。**

### 5.3 AI（我）踩过的坑 —— **别再犯**

| 错误类型 | 具体案例 |
|---|---|
| **从函数名反推语义** | 从 `makeDeadlyToOwner` 反推出"激活前不致命"，被主人指正 |
| **读错方向** | 把霰弹的 `max(timeAlive, MAX−AFTER)` 读成"撞墙**续命**"（实际是**减命**） |
| **过度归因** | 把"绿死"归因于"逐帧采样必然穿透"（**过度推广**，实际要按弹种/几何算） |
| **过早报 bug** | 「什么？都还没开工呢，怎么就 bug 都出来了？」 |
| **没打开目录就断言** | 说"Rust 沙箱完全空白"，实际有 13,281 行 |
| **发明不存在的东西** | 编出一个"闪电"机制（主人：「**根本不存在闪电。**」） |
| **拿旧文档当现状** | 待查清单写于 10-02，之后代码改过 —— **必须去当前代码里核** |

### 5.4 验证纪律

- **必须引用代码原文**，带 `文件:行号`；**不许用 grep 截片段当"读过了"**。
- **严格区分【代码原文】和【我的解释】**；推断一律标 `【未验证】`。
- **`[已核]` vs `[报告引]` 要分清**（前者是自己去代码里核过，后者只是转引）。
- 方向性结论（多/少、加/减、快/慢）**算完要用游戏平衡性常识验一遍**。
- **移动文档会压坏引用它的代码** —— 路径在代码里可能是**拆成多个字符串字面量拼的**，
  搜连续路径搜不到 ⟹ **移文档前必须 grep + 真跑一遍相关脚本**。

### 5.5 环境限制

- **`cargo test` 跑不了**（`link.exe` 链接失败）⟹ **Rust 的 7 组单测一次都没跑过**。
- **`diff_box2d.js` / `diff_rollout.js` / `diff_rescore.js` 同理跑不了**（需要 `cargo run`）。
- **不要批量杀 node 进程**（会杀掉宿主）；只杀 python 或按 PID 杀。

### 7.1 ★ #5 的详情（**最重要**）

**矛盾在这两句话之间**：

| 出处 | 原话 |
|---|---|
| 权威版 §3.4① | 「观测的基本单位 = 节点。**中间帧不发。**」<br>→ 数据量回到 **496 节点 × 16 维 ≈ 7,936 个数** |
| 权威版 §17 表 | 「**B 类 = 每节点一份 = 节点处的帧**」 |

**⚠️ 问题**：**16 维装不下一帧** —— 一帧里有子弹（最多 64）、道具、地雷、毒雾、对手 = **100+ 个数**。

**而现在的 16 维草案里，关于"世界"的只有 `dx/dy/dRot`（自己坦克的位移）**。

**⟹ 那 B 判「这条路安不安全」时，威胁信息从哪来？**

**三个候选**：A 靠全局输入 + B 自己外推（但 B 是网络，做不了精确外推）·
**B 节点 token 扩维塞"威胁摘要"（推荐）** · C 每节点发完整世界快照（数据量会暴涨）。

## 8. 术语速查（**防止把两个东西搞混**）

| 术语 | 含义 | 别搞混 |
|---|---|---|
| **模拟时长** | 固定 **75 帧**（`EVAL_FRAMES`），"一次模拟的时长" | 不是"树的时间上限" |
| **树的时间上限** | **10**（秒？还是别的 —— **单位待确认**） | |
| **~~段长~~** | ❌ **智能体架构里不存在这个语义** | 代码里的 `segmentFrames` 是**规则版遗产** |
| **节点处的帧** | 发给智能体的观测单位（一节点一帧） | 树里"巨量的帧"是数据结构，**不发** |
| **`(节点ID, 相对时间)`** | 办法 2 = `(子节点ID, 反向相对帧)` | **一个格式表示三种语义**：生长位置 / 选的路线 / 射击帧 |
| **`back`** | 反向相对帧，`∈ [0, L)`，`L = 75` 活 / `L = fd−1` 死 | **`back = L` = "不操作" = 禁止** |
| **帧号 / `tGlobal`** | 从树根算起的相对时间 | `tEndSec` 才是绝对量 |
| **`FRAME_DT` / `_frameDtSec`** | **每帧多少秒**（运行时可变） | 与"树的 10 上限"是两回事 |
| **绿死** | 树判"绿"（安全）但实际死了 | 一个长期痛点，**根因未定案** |
| **真死** | `fullDeathFrame ≤ 1` | **不建节点**（"缺席"本身就是标记） |
