**逐字事实**：
- `ratio` 的分母是 `STORM_ZONE_START_GROW_TIME`（=5.0，原文如此），**不是**

- `_rebuildTiles()` 的 `tiles*` 是**局部变量**：只有在 `_expansionSide < 0` 时才把

- 条件里写的是 `j>this._tileBounds.maxY+-tilesBottom`（原文即 `+-`），

- 每个候选格子还要过 `maze.isPositionInsideMaze(position)` 才进 `tiles`。

getStormExpansionSequence: function() {
        var result = [];
        var tileBounds = this.getTileBounds();
        var remainingWidth = (tileBounds.maxX - tileBounds.minX) + 1;
        var remainingHeight = (tileBounds.maxY - tileBounds.minY) + 1;

            var horizontalWeight = remainingWidth / (remainingWidth + remainingHeight);
            if (Math.random() < horizontalWeight) {

                result.push(Math.random() < 0.5 ? 0 : 2);
                remainingWidth -= 1;

【我的解释】由此得到三条**必须由主人/后续实测确认**的结论（我**不敢**当定案）：
1. **前 5 秒毒雾的物理体在迷宫外**（0.4m 宽的边框），对局内坦克**不构成任何威胁**；
2. 之后是 **10 秒一个周期：5 秒静止 + 5 秒平滑生长**，每次生长前 5 秒 `tiles` 就已经报出下一层；
3. `tiles`（AI 威胁表读它）**在"静止那 5 秒"里超前物理体整整一层**。
自检：`STORM_ZONE_EXPANSION_TIME=10`、`START_GROW_TIME=5` 两个常量与"10 秒周期、5 秒生长"对得上；
"第一格要 5 秒后才落地"这个结论**反直觉**，所以我没有直接写进结论栏，而是在 §六列了核对办法。

### 3.6 出生区的时间线（我的算术，原文参数代入）

`dt=0.02`、`lifetime` 从 4.0 递减：

| 时刻 | `_lifetime` | 分支 | `_radius` |
|---|---|---|---|
| t=0 | 4.0 | 都不进（`4.0>2.4`） | 0.3m（建体用 `zone.getField("radius")`） |
| t=1.6s | 2.4 | 进 `<=2.4`：`ratio=min(1,(2.4-2.4)/0.1)=0` | 0.3m |
| t=1.6~1.7s | 2.4→2.3 | 每帧更新体 | 0.3 → 3.7m（**0.1 秒内**线性长完） |
| t=1.7s | 2.3 | 进 `<=2.3`：`_unstable=true` + `ZONE_DESTABILIZED` | 3.7m |
| t=1.7~4.0s | 2.3→0 | `ratio` 被 `min(1, …)` 钳死 ⇒ **恒 1** | 3.7m |
| t=4.0s | 0 | `done()===true` → `RoundController` 销毁 zone → `ZONE_DESTROYED` → `spawnTank` | — |

【我的解释】即："黑洞"在前 1.6 秒是**6px 的小点**，然后在 0.1 秒内暴涨到 74px，之后 2.3 秒保持 74px。
`SPAWN_ZONE_END_GROW_TIME` 与 `START_GROW_TIME` 只差 0.1 —— 这是**跳变**而非平滑生长；
`ratio` 的 `min(1.0,…)` 让"生长"只发生在 0.1s 窗口内。方向自检：`LIFETIME=4.0` 是总时长，
`2.4` 与 `2.3` 分别是"开始长"与"长约完"的**剩余时间**（不是绝对时刻），与代码的 `_lifetime-=dt` 递减方向一致。

**逐字事实 + 我的核对**：
- **没有命中任何 case 的对**：`TRAP|TRAP`（4.4 里说它会碰）—— 落到 switch 之外，
  **既不设 `collisionEvent.data`，也不 `SetEnabled`** ⇒ **纯物理、无事件**；
- 每个 `case` 的比较值都是 `categoryBitsA|categoryBitsB`（`data.contactBits`），
  所以"同一对夹具谁在 A、谁在 B"不影响分支选择，只影响 `getContactData` 里 `tankA/tankB` 的归属；
- `ZONE|TANK` / `ZONE|PROJECTILE` / `SHIELD|ZONE` 三个都用 `data.zone.isPhysical()` 决定是否关接触；
  毒雾与出生区的 `isPhysical()` 都是 `false`（§1.5/§3.1）⇒ **这两个 zone 永不产生物理阻挡**。
