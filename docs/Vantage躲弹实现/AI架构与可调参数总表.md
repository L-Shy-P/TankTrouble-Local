## 一、一句话说清这套 AI 在干什么

每帧（约 50ms 一帧的世界）做四件事：

1. **看**：拿到真实坦克位姿 + 场上子弹（位置/速度/轨迹），算出"哪些子弹会威胁到我、还有几秒"；
2. **想**：维护一棵"操作预测树"——每个节点是一段 3~30 帧的操作（9 种之一），
   用融合世界模拟出这一段走完的轨迹，再逐帧打分（安全分 + 地形分 − 各项惩罚）；
3. **选**：在候选里挑总分最高的操作（`pickBestChildByRolloutTotal`），提交为"当前执行段"；
4. **执行**：`ai_vantage` 每帧把这一段的按键送给游戏；段末对齐真实位姿后进入下一段。

### 1.1 关键机制（改动记录）

| 机制 | 现状 | 何时/为何改 |
| --- | --- | --- |
| **遮蔽分 = 唯一威胁梯度** | `vantage_scoring.js` 逐帧算"子弹遮住了多少安全朝向"（复制区几何；单帧满分 a=(2π)²≈39.478） | 一直是核心；v110 起才明确"它=安全程度" |
| **安全过滤 k** | `b′ = min(a·k, b)`，只截顶、不动危险区间 | v111（主人提的机制） |
| **动作成本** | 只在"这一帧已经安全"时扣，挑最省事的动作 | v110（主人分析） |
| **杀戮场（地形三层场）** | 静态地形表：到最安全地皮步数 40% + 离墙 40% + 基础质量 20% | v103/v104 建；v112 加"等比调整" |
| **空场导航** | 无弹 + 无点击目标时，给一块"最安全地皮"当寻路目标（复用原有寻路通道） | v103 |
| **提交切片** | **v114 起改走 Rust 批量**（`vt_score_paths`），失败/新参数开着才回退 JS | v114（主人同意的 A，卡顿治理） |
| **死亡权威** | 静态 `checkDeath` < **Rust 候选** < **JS 融合世界**（最终）。被选中为执行路线的节点必须 JS 确认 | v77/v78 定稿 |
| **卡墙处理** | 段内 6 帧位移 <3cm 就判卡、拉黑该操作 45 帧、立刻重选 | v106/v108 |
| **录制/性能** | 录制器（环形缓冲 + 死亡自动抓取）、面板分阶段耗时、最慢 12 帧归因 | v106/v103 |

### 1.2 两套评分实现（最容易踩的坑）

同一套评分口径有**两份实现**，必须逐帧一致（差分套件用 1e-9 全等校验）：

| | JS（`vantage_scoring.js`） | Rust（`vt_score_paths` / `vt_rescore_nodes`） |
| --- | --- | --- |
| 用在 | 回退路径、确认死亡、对比实验 | **生长探测（九操作）**、增量重算、提交切片 |
| 认识 **k / 动作成本 / 遮蔽开关** | 认识 | **不认识**（Rust 侧 grep 为空） |
| 速度（9 操作×75 帧，1 颗弹） | ≈10.8ms | ≈1.2ms（9 倍） |

**由此产生一条铁律**：任何**新的评分参数**要么两边都实现，要么像现在这样
`needsJsScoring()` 强制退回 JS——代价是帧率掉一大截。三个"没接完"的参数见第四节。

## 二、可调参数总表（面板 → 状态 → 默认 → 作用 → 代价）

### 2.1 评分类

| 面板控件 | 状态字段 | 默认 | 作用 | 代价 / 备注 |

## 三、改动后负面影响较大的参数（红名单 + 理由）

显红规则：**红标画在控件本体**，从安全值切到危险值时弹一次浮层说明；
改回默认立刻恢复不红。显红**优先于变灰**（标红的控件不会被灰度/半透明盖住）。

| 控件 | 危险取值 | 为什么危险 |
| --- | --- | --- |
| 仅操作时长评分 | 开 | AI 变短视，更晚躲弹 |
| 全局选路 | 开 | 当前版本极明显变呆傻 |
| 死亡不扣分 | 取消勾选 | 评估重新加死亡惩罚，AI 过度保守 |
| Rust 简化选路 | 开 | 只选路不模拟，行为偏差大 |
| Rust 物理预测 | 关 | 退回 JS，决策+性能双降 |
| 预测时长上限 | 关 | 无限叠节点 → 性能雪崩 |
| 无子弹预热 | 关 | 卡顿集中爆发在子弹出现时 |
| 混合选路 | 关 | 只按安全分走，不主动靠近目标 |
| 固定帧数滑块 | <25 或 >200 | AI 变傻或明显变卡 |
| 角度遮蔽评分 | 取消勾选 | 失去唯一威胁梯度（有弹不躲）+ 退回 JS 变慢 |
| 安全过滤 k | < 1.00 | 退回 JS 变慢；且生长路径走 Rust 不认 k → **口径混合、结论不可信** |
| 动作成本 | > 0 | 实战批量分支**未实现**（不改行为），只退回 JS 拖慢帧率 |

**明确不标红（探索参数，随便调）**：每帧生长层数、节点上限、预热上限、
预测时长数值、超上限细化、连续细化、剪枝补偿、回退节点数/帧数、目标分系数、
以及杀戮场全家（杀戮场引导 / 空场安全感知 / 杀戮场权重）。

## 四、已知缺陷与未完成项

1. **3.059m 断崖（实现缺陷，已知未修）**：拷贝区 `R_SEMI = 3.059m` 小于它自己判据
   推出的边界 `hypot(1.75,2.625)=3.155m`，于是 3.06~3.16m 的子弹被当"完全安全"，
   帧分从 9.6 跳到满值 39.5（2 厘米、4 倍）。**不影响死亡判定**（那走融合世界）。
   要真修需在拷贝区外复制一份矩形投影几何（约 80 行），主人已决定先不修。
2. **k 半生效**：生长探测走 Rust 不认 k，只有重算/提交层认 → 开 k 测出的行为是混合口径。
3. **动作成本未实现**：实战批量分支里没有这一项（只有单路径回退分支有）。
4. **两个评分实现必须同步**：新增参数要么两边都写，要么接受退回 JS 的性能代价（见 1.2）。
5. **Rust 候选死亡只确认选中节点**：若 Rust 误报死亡，未选中的候选会被静默剪枝（待录制验证）。
6. **训练模式高压下卡死未定位**；`growStalls` / `perf.worstFrames` 是现成的定位入口。
7. **页面加载失败根因未查**（偶发）。

## 五、出事时怎么查（顺序照做）

1. **先看面板数据区**：
   - 「提交切片 Rust N / JS M」——M 猛涨且没开新滑块 → 多半是 WASM 没加载（看控制台 `Rust init failed`）；
   - 「Rust评分 N 回退M」——生长路径的回退次数；
   - 「生长停」「9op 耗时」「节点数」——卡顿是在生长还是在提交。
2. **导出诊断 JSON**：带 `perf` 字段（整帧/最近 60 帧平均与最慢、
   分阶段 `sig/threat/track/reroute/refresh/commit/grow`、最慢 12 帧的现场）。
3. **导出录制**：`meta` 里记着树版本与四个实验开关（v113 起），能对上"这份录制是哪个设置跑的"。
4. **跑回归**：`game_core/rust/` 下 23 个 `diff_*.js` 套件 + `cargo test`（82 项）。

## 七、⚠ 致命 bug 登记与"数值基准铁律"（每次改代码前先看这一节）

### 7.1 为什么要单独开这一节
有一个 bug **卡了整整三周**，根因是一行"看起来完全合理"的距离比较：

```js
var p0 = threatStartPoint(th);                    // = track[0] = 子弹【发射点】
var maxTravel = th.speed * (nb.t1 - _timeAcc);    // 从【现在】起还能飞的距离
return pointBoxDistance(p0, nb) - maxTravel > CONTACT_MARGIN;   // ← 两个量时间基准不同
```

- 距离从**发射点**量（子弹飞了一半 → 这个值很大）；
- 可飞距离从**现在**算（只剩 0.28 秒 → 这个值很小）。

于是**子弹已经飞到跟前**时，粗筛反而判"打不到"→ 正在执行的节点**被跳过复核** →
坦克沿"预测 75 帧安全"的操作跑完整个段 → **死亡**。

**症状特征（记住它，这是最好的线索）**：
> 树图上是**绿色/橙色节点**（预测能活）却死了——即"预测说没事，实际死了"。

**它为什么难查**：粗筛是"性能优化"，语义上应该只影响**快慢**，不该影响**生死**；
所以所有人（包括我）都往评分/选路/参数上找，没人怀疑"节点根本没进复核名单"。

### 7.2 全部已知"数值基准错配"类问题（同族，一并登记）
| # | 问题 | 错配的两个量 | 修法 | 版本 |
| --- | --- | --- | --- | --- |
| 1 | 新弹剪枝时间轴错位 | 节点盒用**绝对时间**，威胁盒用**相对时间**（rootAbsT 超过 ~9.5s 后永远不重叠） | 统一到绝对时间 | 早期 |
| 2 | **粗筛起点错配（卡三周）** | 距离从**发射点**量，可飞距离从**现在**算 | 用**子弹当前位置**（`threatCurrentPoint`） | v118 |
| 3 | 3.05m 遮蔽断崖 | 拷贝区 `R_SEMI`（未膨胀半径）与它自己的判据边界 `hypot(1.75,2.625)` 不自洽 | 已记录未修（影响感知半径 9.6cm） | v112 记录 |
| 4 | 融合世界几何单位 | 融合世界（可能像素系）vs 我们的米制 | `detectUnitDivisor` 自动量测并换算 | v3(K) |
| 5 | 融合世界缓存键 | 单槽缓存键只认 `(地图, aiId)` 之一，两个 AI 互相挤掉 | 改多槽（键 = aiId） | v36 |

### 7.3 铁律（写代码时逐条对照，违反必出致命 bug）
1. **禁止跨基准比较**：任何"距离 / 时间 / 速度"的判据，必须让参与比较的每个量
   **同基准、同单位、同零点**。写之前先问：*这个距离是从哪个时刻量的？这个时间是从哪个零点算的？*
2. **威胁的时间一律以 `rootAbsT` 为基准**：`anchorOffset` = track[0] 相对 `rootAbsT` 的时刻；
   要把威胁推进到"现在"必须用 `_timeAcc - (rootAbsT + anchorOffset)`。
3. **粗筛（性能优化）不得改变语义**：粗筛只能决定"先算谁"，不能决定"算不算"。
   任何"跳过一个节点复核"的路径，都必须在**执行节点**上留一条兜底（见 v118 安全网）。
4. **新增跨帧/跨局状态，必须写进 `reset()`**（`_stuckOps` 的教训）。
5. **新增缓存，必须写清"键是什么"以及"什么条件下作废"**；
   凡是被多个 AI 实例共用的缓存，键里必须有实例标识。
6. **新增容量上限（如 `MAX_WALLS`），必须按真实地图上限留余量**，
   并且**失败要有声音**（不能静默回退；`MAX_WALLS` 静默回退坑过一次）。
7. **预测与实际不符（绿/橙节点死亡）永远是 bug**，不是"运气差"：
   红色（真死）才是唯一合法的死。见到"预测说活却死了"，先查**复核名单**，
   再查**预测输入**。
