## 一、一句话结论

**"没有 track" 不是"罕见瞬态"，而是【按弹种二值】：白名单 4 种恒有、非白名单 3 种恒无。**

| 弹种（`Constants.WEAPON_TYPES`） | 【实测】threat 帧 | 无 track 帧 | 无 track 占比 |
|---|---|---|---|
| BULLET(-1) | 14590 | 0 | **0.0000** |
| DOUBLE_BARREL(1) | 720 | 0 | **0.0000** |
| SHOTGUN(2) | 2711 | 0 | **0.0000** |
| GATLING_GUN(5) | 0（探针没能让它开火） | — | **未测**（按代码在白名单内，应有 track） |
| **LASER(0)** | 18 | 18 | **1.0000** |
| **HOMING_MISSILE(3)** | 638 | 638 | **1.0000** |
| **MINE 破片(4)** | 3698 | 3698 | **1.0000** |
| 弹已从场上消失但仍挂在 `tree.threats` | 723 | 123 | 0.17（几乎全在"树不 tick"的帧，见 §2.2） |

**两个口径**：

- **【实测·未干预的真实对局】3 局 / 34300 帧：无 track = 0 / 6855 威胁帧 = `0.0000`。**
  但这 0 的原因**不是"那条路不可达"**，而是：**这几局从头到尾没有任何非子弹武器进过场**
  （`projTypesSeen` 全程只有 `t-1`；坦克全程只持有默认弹 `w-1`；地图上刷了激光箱/导弹箱，没人捡 —— 见 §三）。
- **【实测·把武器真打出来】只要激光/追踪导弹/地雷破片出现，它们的 threat 就是 100% 无 track**
  （18/18、638/638、3698/3698；同一份 `game_core`、真实 `spawnCrate` + 真实碰撞拾取 + 真实开火）。

⟹ **给判据用**：
1. 若"生产口径" = **本项目现在能跑的规则 AI 对局**（AI 从不捡武器）⇒ 占比 **0**，**可以不修，只留 TODO**；
2. 但必须写明触发条件：**一旦 AI/玩家开始用非默认武器**（`VantageAI` 自己有捡箱子目标与按武器类型开火的代码路径），
   对这几类弹的占比**立刻 = 100%**（不是"慢慢涨"）；
3. **"永远碰不到"这个说法不成立**：沙箱自己就写了「折线回退」这条活路（§四），
   且**没有任何门槛阻止武器进对局**（箱子每局都在刷，实测地图上长时间躺着 2~3 个武器箱）。

## 二、"没有 track" 的发生条件（【代码原文】）

三条来源，**只有 2.1 与本次缺口真正相关**。

### 2.1 弹种白名单（主因；100% 可复现）

`vantage_sandbox.js:262-270`：

```js
function isBallisticProjectile(pr) {
    if (!pr || typeof pr.getType !== 'function') return true;   // 无类型信息的老对象保守纳入
    var t = pr.getType();
    // LASER(0) 半径 0、不反弹，不进 Box2D 轨迹；制导导弹/地雷另行排除。
    return t === Constants.WEAPON_TYPES.BULLET ||
        t === Constants.WEAPON_TYPES.DOUBLE_BARREL ||
        t === Constants.WEAPON_TYPES.SHOTGUN ||
        t === Constants.WEAPON_TYPES.GATLING_GUN;
}
```

- `simulateBulletTracks`（`:423` 起）**只遍历白名单弹** ⇒ 它返回的 `[{id, frameDt, frames}]` 里
  **永远没有** LASER(0) / HOMING_MISSILE(3) / MINE(4)。
  同处 `:488` 原文：`slot.isShrapnel = false;   // track 白名单里没有破片`。
- 但 **`getProjectilePaths`（`:2292`）不按弹种过滤**（只跳 `done()` / body 未激活 / 折线不健康），
  于是 `computeThreats`（`vantage_scoring.js:1479`）**把这些弹照常 push 进 threats**。
- 树在建树 / 新弹 / 段末提交时，对威胁表调 `ensureThreatTracks`（`vantage_tree.js:1835`）：
  `byId[th.id]` 查不到 ⇒ `th.track` 一直是 `undefined`；
  `snapshotThreatAnchors`（`:1735`）于是记 `trackLen: 0, trackSource: 'path'`。

⟹ **非白名单弹的威胁，从进树那一刻起就没有 track，直到它消失**（对这三类弹 = 100%）。

（补一句"为什么白名单没有它们"：`vantage_sandbox.js:1245-1255` 的 `_projProfile` 原文：
`LASER: bounces 0 / wall 'vanish' / needsSweep`、`HOMING_MISSILE: wall 'bounce' / steers`、
`MINE: 'MINE_SHRAPNEL' / bounces 0 / wall 'vanish' / noSpeedNorm`
—— 都不是白名单那套"寿命 + 反弹"的普通弹步进语义。）

### 2.2 弹已销毁、但仍挂在 `tree.threats`（次因）

【代码原文】清理只在 tick 里做：`removeThreatsByIds`（`vantage_tree.js:1601`），
由 `removedIdsBetween` 在 tick 中调用；而 tick 有 8 条提前 return（AGENTS 已列全），其中两条直接冻结：

- `:7283  if (_frozen) { … return; }` —— v132 死亡定格：只让执行轨迹再走一帧，然后**永久 return**；
- `:7363  if (worldDt <= 0) { … return; }` —— 世界这一帧没 Step（回合切换/暂停/同一真实步重复 tick），树不长不提交。

这些帧里，**已经消失的弹不会被摘掉**，它的威胁条目继续保持 `trackLen: 0`（track 随弹一起断供时）
或带着 `alive:false` 的尾巴（track 还在，但尾巴死了）。

【实测】"弹已消失但仍在树上"的帧共 723，其中：

- 58/61（新·二轮局）、116/174（新·地雷局）落在 `tNow` **不推进**的帧（= 树没 tick）；
- 只有 3~5 帧落在 t 在走的帧。

【我的解释】这类窗口**恰好是树不评分的窗口**（tick 提前 return ⇒ 没有 grow/commit ⇒
没有 rescore/rollout 调用），所以它**不构成本次缺口的暴露面**；
但它是"树威胁表可能陈旧"的独立隐患（`_frozen` 之后 `tree.threats` 会**永久**停在死亡瞬间），建议单列。

### 2.3 v28 兜底短直线（`fallbackPath`）—— **实测 0 次**

`computeThreats`（`vantage_scoring.js:1560-1620`）对"折线被健康校验丢掉、但弹真实存在"的弹
会合成一条短直线并打 `fallbackPath: true`（`:1617`）。

【实测】9 局 / 36000+ 帧里 **一次都没触发**（全部结果 JSON 中 `fallbackPath` 字符串出现次数 = 0）。

⟹ 生产里的"折线回退"**不是**这条兜底，而是 §2.1 的**正常折线 `path`**。
（这一条修正了"折线回退 = v28 兜底"的直觉。）

### 3.4 校验与坑（写给下一个用这套探针的人）

- `idMismatch`（威胁在 `threats` 里但 `threatAnchors` 里查不到）**全 9 局 = 0** ⇒ 锚点表与威胁表同代。

## 四、**path-only 那条路是不是死代码？**

### 结论

**不是死代码 —— 它在 4 个消费端都是活的兜底分支，且【实测】在真实对局里被走到过
（激光 18 帧 / 导弹 638 帧 / 破片 3698 帧，全部是活树、`_frozen=false`、`tNow` 在推进）。**

**但对"子弹族 + 未干预对局"这两条同时成立的场合，它一次都没被走到**（18021 个子弹族威胁帧，0 反例）。

### 四个消费端（【代码原文】）

| # | 位置 | 分支 |
|---|---|---|
| 1 | `vantage_tree.js:1938 threatPosAtTree` | `if (th.track && th.track.length) {…取 track…}`，否则 `return adapter.bulletPosAt(th.path, th.speed, q)` —— **树内取威胁位置** |
| 2 | `vantage_scoring.js:1759 threatBulletPos` | 同上（track 耗尽即 `return null`，否则回退 `bulletPosAt(path, speed, q)`）—— **评分/粗筛取威胁位置** |
| 3 | `vantage_sandbox.js:1566-1640`（融合世界摆弹） | 三档：`src:'track'` → `'path'` → 摆不上的 `approxPlaced`（`:1139` 注释原文：**"无 track/折线可用 → 按真实位姿 + 真实速度前推后摆上"**）|
| 4 | `rescore.rs:290-350 threat_bullet_pos` | `if let Some(track) = &th.track { … }` 否则走折线插值 —— **就是父代理 §1.2 实测差 59/28 的那条** |

### 与"死代码"判断有关的实测事实

1. 非白名单弹**一定**会把 path 分支走到（不是"可能"）：`isBallisticProjectile` 是硬白名单。
2. 这些弹**不是稀有物**：地雷局单帧最多 67 颗弹在场，占该局 threat 帧的 **71%**。
3. 反过来，子弹族威胁 **0.0000** 无 track ⇒ 它们的 path 分支在生产里**没被走过**（0/18021）。
4. `fallbackPath`（v28 兜底合成直线）**0 次**（§2.3）⇒ 生产里的"折线回退"指的是第 1 类，不是兜底。

⟹ 一句话：**路是通的、也真的会被走；只是"当前 AI 对局恰好没人用那三种武器"才让占比落在 0。**

## 五、建议（【我的建议】—— 请指挥官定）

**判据落点**：`占比 ≈ 0 ⟹ 不必修` 只在"规则 AI 互殴、且没人用非子弹武器"这个口径下成立。
本实证**不能支持"缺口永远碰不到"这个更强的结论**。

分档建议：

1. **现在不要动 Rust ABI**（"弹种码 + 已销毁状态跨帧持久"是设计变更，见收尾文档 §1.2）——
   在确认"AI/玩家会用到激光/导弹/雷"之前，先按"不修"记档，**但要把触发条件写进 TODO**：

   > 触发条件 = 任何一次"非白名单弹种（LASER 0 / HOMING_MISSILE 3 / MINE 4）进入对局"。
   > 触发后本缺口的占比对该类弹是 **100%**，不是概率性的。

2. **如果短期内不会让 AI 用这些武器**（当前 AI 实测 34000 帧一次都没捡）：留 TODO 即可；
   同时在 TODO 里补上本文两个数字（未干预 `0.0000` / 武器在局 `1.0000`）与判据来源。
3. **如果要做"廉价护栏"（比 ABI 变更小得多，可先做）**：
   在 JS 侧把"没有 track 的威胁"显式标因（如 `th.trackMissing = 'nonBallisticType' | 'gone' | 'trackGenFailed'`），
   让 **Rust 入口**（`rescore` threat 构造处）**知道这条威胁的弹位是"折线外推"、不是"精确预测"** ——
   要么对这些威胁**只走保守分支**（不许给出"安全/晚死"结论），要么直接标"不可验证"。
   **注意**：这会改死权口径，**需要主人先定**（"宁可误报危险"还是"宁可漏判"）。
4. **如果准备让 AI 真用这些武器**：走设计流程，按收尾文档 §1.2 的
   「ABI 弹种码 + 跨帧销毁状态」施工；并要一并考虑 `HOMING_MISSILE` 的**制导**与
   `LASER` 的**线段扫掠**（沙箱自述里那两条 TODO），否则 track 挂上了也不等于语义对。
5. 附带：`_frozen` 之后 `tree.threats` 永久停在死亡瞬间（§2.2）是**独立**的小隐患，
   建议单列一条待查（它不影响 rescore，因为那一刻起树不再评分）。

## 六、无法判断的（拿不准就不写死）

1. **"生产"到底指哪个口径**：本报告只能给出两个口径的数字
   （规则 AI 对局 = **0.0000** / 武器在局 = 该类弹 **1.0000**）。
   **真人对局里这三类弹占多少 threat 帧，无头环境测不出来**（无头里没有真人，AI 也不捡武器）。
2. **GATLING(5) 完全没覆盖**：探针给了 3 次武器箱、手上持有 18 帧，但**一颗弹都没打出来**
   ⇒ 只能说"按代码它在白名单内、应有 track"，**实测未验**。
3. **`rescore` 在这三类弹的真实场景下会不会真的与 rollout 分叉**：本探针只测"有没有 track"，
   **没跑 Rust**（缺 MSVC）。父代理的反事实实测（path-only 59/28 vs -1）是合成轨迹；
   **真实激光/导弹/破片局的 rescore vs rollout 逐帧对拍尚未做**。
4. **地雷破片的"跨帧销毁复活"缺口在真实破片流下是否触发**：属 Rust 侧，未测。
5. **未干预局的 0 是否等价于"真人对局也是 0"**：不等价（见 1）。
   只能说：**在同一份 `game_core` + 同一套 AI 下，34000 帧里一次都没有非子弹威胁。**
