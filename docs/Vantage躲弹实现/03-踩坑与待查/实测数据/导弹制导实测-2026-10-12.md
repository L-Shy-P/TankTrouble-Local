## 一 五个问题的一句话答案

### ① 制导怎么工作 / 多久内制导？

* **激活门是【严格大于】2.0 s**：`if (this.timeAlive > HOMING_MISSILE_ACTIVATION_TIME)`。
  **【实测】** 激活前**每一帧转向都是 0.0000°**（4 次独立开图）；
  首次出现方向变化的那一帧 `ta` = **2.016 / 2.017**（= 第 121 帧，`121/60 = 2.0167 > 2.0`）；
  且实测到 **ta 恰好 == 2.000 的那一帧【不】转向**（`probe_hm6.log` f300：预测该转向、实测 v 原样不动）⟹ 边界是 `>` 不是 `>=`。
* **激活后一直制导到死亡**，不存在"2 s 后变直飞"。
  **【实测】** 0.8~9 s 全程都能看到逐帧转向（`probe_hm7.log`：末帧 ta=2.916 仍在转；`probe_hm5.log`：ta=8.917 仍在追）。
* 每帧做四件事（**【代码原文】**，`418577fd210ad079ea3d1e5e04050fe0.js:10` 的 `HomingMissile.methods.update`）：
  1. 起点 = 导弹**所在格** `floor(x/10), floor(y/10)`；
  2. 对**全场每一辆坦克**（**含发射者自己**）算 maze BFS 距离，取**最小**；
     平局时 `(currentDistance === shortestDistance && tank !== this.getPlayerId())` ⟹ **优先非发射者**；
  3. 瞄准点：`shortestDistance <= 1` → **坦克真实坐标**；否则 → `maze.getShortestPathWithGraph(start,end)[0]` 的**下一格中心**；
  4. `relativeToMissile = B2DUtils.toLocalSpace(body, aim)`（弹体 `fixedRotation=true` 且从不转向 ⟹ 弹体角度恒 0 ⟹ **本地空间 = 世界轴平移**），然后
     `vx += (rel.x<0?-1:+1)*40*dt`、`vy += (rel.y<0?-1:+1)*40*dt`，最后按条件归一化（见②）。
* **【实测】** 我用游戏自己的 maze API 按上面这套复算 aim 与下一帧速度，
  **逐帧逐分量 bit-exact 命中 164/174（94.2%，`probe_hm8`）与 172/174（98.9%，`probe_hm7`）**；
  残差全部出现在 **ta==2.000 的浮点边界**（`1.9833333+0.0166667` 与 2.0 的比较）与 **rel 分量 ≈0 的符号翻转**上 ⟹
  **【结论】制导是纯确定运算，可 1:1 复刻**（这条是下面施工方案的前提）。

### ② 转向速率是多少？（`ACCELERATION = 40` 是加速度还是角速度？）

* **是加速度**（m/s²，按世界轴分别加减），**不是角速度**。
  `Constants.HOMING_MISSILE.ACCELERATION = 40`（`b714588dc4621fe104113111ba90b1a7.js:1`），乘 `deltaTime`。
* **没有角速度上限**，实际角速度取决于当前速度大小，且**分两个 regime**（都在实测里拍到）：

| regime | 触发条件 | 行为 | **【实测】** |
|---|---|---|---|
| **A 加速 + 归一化**（正常追踪） | 瞄准方向与速度同向占优 | 速度先变大 → 触发 `if (len² − initialSpeed² > 0.01) v *= initialSpeed/len` → **\|v\| 钉回 18**，只有方向微转 | \|v\| 恒 18 时单帧转角 **1.97°（首帧）/ 最大 3.76°**；理论 `2·asin(0.96/36)=3.06°` 量级吻合 |
| **B 减速 → 反向**（目标在背后） | 加速度与速度**反向** | **速度变小**（该归一化条件是 `len² − initial² > 0.01`，**没有 `Math.abs`** ⟹ 变小不归一化）→ 减速到 ~0 → 反向再加速 | **【实测】** `probe_hm6.log`：vx `-18 → -16 → -13.32 → -10.68 → … → 0.0000 → +2.68 → … → 18`，\|v\| 最小 **0.64**，**180° 掉头只用 ~26 帧（0.43 s）**，全程无碰撞 |

* ⚠️ **权威版 §12.16 写"没有归一化，所以速度会持续增大"——这是错的**：
  代码里**有**归一化（只是**只对"速度变大"生效**），实测 \|v\| **从未超过 18**（多轮样本 `max |v| = 18.0000`）。
  【我的解释】正确说法是："**加速沿世界轴施加 + 只在速度变大时拉回初速** ⟹ 等效为**变速跟踪 + 无角速度上限**"。
  **建议回写这一条**（见 §六）。

### ③ 换目标什么时候发生？

* **【代码原文】** 每次 update 都重新算全场最近坦克；`if (targetPlayerId !== this.currentTargetPlayerId)` 就发 `Weapon._EVENTS.HOMING_MISSILE_TARGET_CHANGED`。
  ⟹ 触发条件 = **"最近坦克换人"**：目标死了 / 目标被挪远 / 别的坦克靠得更近 / 出现平局翻转，**都在下一帧立刻发生**。
* **【实测】**（`probe_hm7.log` G 段）：把当前目标挪到远处、再把另一辆挪到导弹旁边一格 →
  **下一帧（Δta=0.017 s）`currentTargetPlayerId` 就从 `tank_b` 变成 `tank_a`**，并连发两条 `targetChanged` 事件
  （f949→tank_b、f974→tank_a；第二条就是这次切换）。
* 目标死了/不可达：`targetPlayerId` 可以为 `null`（此时**不加速**、但仍会发一次 targetChanged(null)），导弹变**直飞**。
  **【实测】** C2 段：三辆坦克都被挪到迷宫外 ⟹ 每帧 `distances===false` ⟹ 目标恒 `null` ⟹ 导弹笔直飞（vx 恒 −18、vy≈0）。
* ⚠️ **树侧没接线**：全仓 `vantage_tree.js` 里 **`homing missile target changed` 出现 0 次** ⟹
  权威版 §10.2 第④条"追踪导弹切换目标 → 刷新"**目前没有任何监听者**（这是施工要补的接线点之一，见施工报告）。

### ④ 寿命 / 反弹语义

* **【代码原文】** `HomingMissile` 只重写 `update`；`hitMaze/hitShield/done` **全继承基类 `Projectile`** ⟹
  撞墙 = 只 push 反弹时间戳、**不改速度不销毁**；fixture `restitution=1.0` ⟹ **镜面反弹、\|v\| 不变**；
  `done()` = `timeAlive>=lifetime || stopped || bounces.length>=5`。
* **【实测】**
  * `lifetime = 10.0`（`HOMING_MISSILE_MAX_LIFETIME:10.0`，弹体上读到 `la:10`）；
  * **无目标场景**（坦克全挪出迷宫）：导弹飞满 **`ta = 10.000000`** 死亡，事件是 **`projectile timeout`**（不是被坦克打死、不是反弹规则）——`probe_hm8.log` C2 段，`bounces.length=1`（撞过一次墙照飞）；
  * 撞墙反弹：`vx -18 → +18`（`nb:0→1`，\|v\| 恒 18），**且撞墙那一帧起 `deadlyToOwner=true`**；
  * 反弹上限（1-2② 那条 35ms/5 次）在导弹上同理不触发：实测相邻撞墙间隔都是几十~几百帧（`nb` 最大只到 1~2）。
* **【实测】友伤语义**（与 AGENTS.md §友伤规则精确版本表逐条对上）：
  * **未碰任何东西之前：打不死发射者。** F 段：把发射者直接挪到导弹正前方，导弹**从它身上穿过去**（最近距离 **0.112 m**），
    发射者**没死**、`deadlyToOwner=false`、事件流空（`probe_hm6/hm7.log` 两次独立复现）；
  * **碰过墙之后（或 2 s 之后）：对发射者致命。** `probe_hm5.log`：导弹先撞墙（f219, ta=0.666, nb=1, dto→true），
    回头在 **ta=1.333**（**2 s 之前**）打死发射者，事件 `tank killed victim=tank_a killer=tank_a`。
  * ⚠️ **实测与 AGENTS.md 第十轮那句"导弹从发射起就能打死发射者"字面冲突**（见 §五）。

### ⑤ `isBallisticProjectile` 白名单 / 要不要让导弹进 track？

* **【代码原文】** `vantage_sandbox.js:262` 的白名单 = `BULLET/DOUBLE_BARREL/SHOTGUN/GATLING_GUN/LASER`，
  **不含 `HOMING_MISSILE(3)`**，注释原文就写着"导弹(3)/破片(4) 被排除**（没有轨迹/停墙语义，不可绘制轨迹）**"。
  ⟹ 导弹**现在 100% 拿不到 track**（与上一轮实测 `638/638` 帧无 track 一致）。
* **【我的解释】修不修得看"能不能复刻"——本次结论是"能"，但这不自动等于"该进 track"**：
  track 是**一条预生成的固定折线**（锚点+偏移复用，见 1-1 三层时间基准 §C），
  而制导弹的轨迹**依赖目标（=我方坦克）自身的未来轨迹**，
  同一条"候选路线"下才可复刻 ⟹ **track 这种"与世界无关的固定折线"在结构上装不下制导**。
  **我的建议：导弹【不进 track 世界】，改在【融合世界逐帧制导】**（详见施工报告 §三 D1~D4 与"需要拍板"）。

## 二 制导语义逐条：代码原文 ↔ 实测

### 2.1 【代码原文】`HomingMissile.update`（`418577fd210ad079ea3d1e5e04050fe0.js:10`，逐字要点）

```js
var HomingMissile = Projectile.subclass().name('HomingMissile');
HomingMissile.fields({ currentTargetPlayerId: null });
HomingMissile.methods({ update: function (deltaTime) {
  this.timeAlive += deltaTime;
  // （bounces 剪枝：与基类同一段"粘性"代码，见 1-2② 实测报告）
  if (this.timeAlive > Constants.HOMING_MISSILE_ACTIVATION_TIME) {
    if (!this.isDeadlyToOwner()) { this.makeDeadlyToOwner(); }        // ★ 激活即对发射者致命
    var tanks = this.roundModel.getTanks(); var maze = this.roundModel.getMaze();
    if (maze) {
      var shortestDistance = null, targetPosition = null, targetPlayerId = null;
      var startPosition = { x: Math.floor(this.x / TILE), y: Math.floor(this.y / TILE) };
      var distances = maze.getDistancesFromPosition(startPosition);
      if (distances !== false) {
        for (var tank in tanks) {
          var endPosition = { x: Math.floor(tanks[tank].getX()/TILE), y: Math.floor(tanks[tank].getY()/TILE) };
          var currentDistance = maze.getDistanceToPosition(distances, endPosition);
          if (currentDistance !== false) {
            if (shortestDistance === null || currentDistance < shortestDistance ||
                (currentDistance === shortestDistance && tank !== this.getPlayerId())) {
              shortestDistance = currentDistance; targetPosition = endPosition; targetPlayerId = tank; } } }
        if (targetPlayerId) {
          if (shortestDistance <= 1) { targetPosition.x = tanks[targetPlayerId].getX(); targetPosition.y = tanks[targetPlayerId].getY(); }
          else { var shortestPath = maze.getShortestPathWithGraph(startPosition, targetPosition);
                 targetPosition.x = (shortestPath[0].x + 0.5) * TILE; targetPosition.y = (shortestPath[0].y + 0.5) * TILE; }
          var relativeToMissile = B2DUtils.toLocalSpace(this.b2dbody, targetPosition);
          var newSpeedX = this.b2dbody.GetLinearVelocity().x, newSpeedY = this.b2dbody.GetLinearVelocity().y;
          if (relativeToMissile.x < 0) newSpeedX -= ACC * deltaTime; else newSpeedX += ACC * deltaTime;
          if (relativeToMissile.y < 0) newSpeedY -= ACC * deltaTime; else newSpeedY += ACC * deltaTime;
          this.b2dbody.SetLinearVelocity(Make(newSpeedX, newSpeedY)); }
        if (targetPlayerId !== this.currentTargetPlayerId) {
          this._emitEvent(Weapon._EVENTS.HOMING_MISSILE_TARGET_CHANGED, TargetChange.create(this.id, targetPlayerId)); }
        this.currentTargetPlayerId = targetPlayerId; } } }
  // ★ 注意：这段【没有 Math.abs】，与基类 Projectile.update 的那段不同
  if (this.b2dbody.GetLinearVelocity().LengthSquared() - this.initialSpeedSquared > 0.01) {
    var velocity = this.b2dbody.GetLinearVelocity(), length = velocity.Length();
    velocity.Multiply(this.initialSpeed / length); }
  this.x = ...; this.y = ...; this.speedX = ...; this.speedY = ...; } });
```

### 2.3 【实测】精确复刻对拍（这是"能不能进沙箱"的硬指标）

探针每帧用**游戏自己的 maze API**按 §2.1 的顺序复算 aim、再按同一公式预测"下一帧游戏会把速度改成什么"，
与下一帧实测速度逐分量比对（撞墙帧剔除）：

| 轮次（日志） | 命中 / 总数 | 残差性质 |
|---|---|---|
| `probe_hm7.log` B 段 | **172 / 174（98.9%）** | 2 帧，d=(0.37~0.58, 0.15~0.51) |
| `probe_hm8.log` B 段 | **164 / 169（97.0%）** | 5 帧，d=(0, 1.28~1.36) 全部在 ta=2.000~2.15 的**激活门边界** |
| `probe_hm6.log` B 段（dt 未修正版） | 133/169 | 差值恒为 ±0.04 ⟹ 就是"16 vs 17 ms"（见下条） |

* 【实测】**游戏帧长不是 1/60 的浮点值，而是整数毫秒**：
  `GameController.update` 用 `new Date()`，虚拟时钟把 `epoch + t`（浮点）塞进 `new Date()` ⟹ **被截断成整数毫秒** ⟹
  每帧 dt **交替是 16 ms / 17 ms**（这也解释了实测 Δv=0.64/0.68 的交替，以及 `ta` 累加出现 **恰好 2.000000**）。
  探针改用 `floor(tExact + 16.6667) - floor(tExact)` 当 dt 后，命中率从 79% 跳到 97~99%。
* 【我的解释】剩下那 2~5 帧的残差**是浮点边界的量级**（激活门的 `>2.0`、rel 分量≈0 时 `rel.x<0` 的真假翻转），
  不是"我理解错了算法"；要在沙箱里复刻时，这些边界必须**按同一顺序、同一比较符**写。

## 三 「追别人直接丢」到底指什么？（出处）

### 3.1 出处：权威版 §12.18 + 主人原话（2026-10-07）

> **§12.18【裁定】导弹追别人 —— 直接丢掉**
> 主人原话：
> 「**导弹追别人直接丢掉吧。树的目的就是精确预测未来，但是导弹追别人是个极其不确定的事情，
> 算的结果价值极低，不如不算，少点干扰，少点性能消耗，智能体自己感知。**」
> → 修正 §12.6 的裁定 b：追别人**不是"粗近似"，是"直接丢掉"**（理由归 §13 总原则：**不确定 ⟹ 不进树**）。
>
> ★ 我的"会不会绿死"顾虑被主人否掉：
> 「**不可能出现追别人且打死 AI 的情况，因为快打死 AI 的时候它就进树了。**」
> 原理：导弹选的是**最近的**坦克（按迷宫距离）⟹ **它一接近 AI，AI 就成了最近的** ⟹ 触发换目标 ⟹ 刷新 ⟹ 它就在树里了。
> ★ 我提的第二个选项（"当普通弹体保留"）也被否掉：
> 「**而如果用普通子弹，有什么必要？轨迹大幅差异，还可能影响本来安全的地方，纯负作用。**」

### 3.2 所以它说的是【沙箱/树的行为】，不是【游戏有丢弃机制】

* **不是**"游戏里导弹会丢弃目标"——**【实测】游戏里没有丢弃：换目标就是换目标，导弹继续飞、继续追**（G 段）。
* **是**"沙箱/树**不进威胁表、完全不模拟**目标不是我方坦克的导弹"。
  **【我的解释】** 施工口径：
  * 建威胁表/模拟时，若 `missile.currentTargetPlayerId !== 我方坦克` ⟹ **整颗丢掉**（不进威胁表、不进融合世界、不进 track）；
  * **不许**"降级成普通圆弹保留"（主人明确否掉：假轨迹会污染本来安全的地方）；
  * 它**一换成我方**就会被 `HOMING_MISSILE_TARGET_CHANGED` 事件刷新进树（该刷新**目前没接线**，见施工报告）。

## 六 对沙箱/四条路径的施工含义（**未施工，先给出结论与决策点**）

> 铁律不变：**JS 融合 / JS track / Rust rollout / Rust rescore 四条路径要么一起改，要么先别改**
> （改一处不改别的 = 白做且更坏）。本轮**没有改任何产品代码**。

### 6.1 数据面：要忠实地算，沙箱缺什么

| 需要的东西 | 现在有没有 | 说明 |
|---|---|---|
| 弹种 = 导弹（kind=4） | ❌ ABI v11 只有 0/1/2/3（`lib.rs:223/627`，4 已预留） | 直接按 1-2③ 同一模式扩 |
| `timeAlive`（判断 2 s 门） | ❌ 现在 ABI 只传部分字段 | 需要新字段（每弹一个 f64） |
| **导弹当前目标**（是不是我方坦克） | ❌ | 建威胁表时从真游戏读 `currentTargetPlayerId`（`vantage_sandbox.js` 的 `computeThreats` 一带） |
| **迷宫连通性**（Rust 要跑 BFS + 最短路） | ❌ Rust 完全拿不到迷宫 | JS 侧 `gc.getMaze()` 现成；Rust 侧必须在 ABI 里加 w/h + tiles（或加"每帧下一格"序列） |
| 其他坦克的**未来轨迹** | ❌ 融合世界只有我方候选 | 这正是"追别人直接丢"的依据；**追我方时**目标轨迹 = 候选轨迹本身 ⟹ 可算 |

### 6.2 四个决策点（**拿不准，请拍板**）

* **D1｜track 世界要不要收导弹？**
  **【我的建议】不收**（`isBallisticProjectile` 保持不含导弹），理由：track 是"锚点+固定折线"，
  制导弹的轨迹**随目标（=我方候选轨迹）逐帧变化**，固定折线必然错；§6.1 的"追别人直接丢"也只对
  "威胁表/融合世界"这句话有意义。若进 track，等于把"错的轨迹"喂给树 ⟹ 与主人"假轨迹纯负作用"的裁定冲突。
* **D2｜"追别人直接丢"要不要**同时**处理"飞行中从别人切到我方"（和反向切换）？**
  定案只说丢弃，没说切换后的时序。**我的建议**：① 建表时 `target !== 我方` → 丢；
  ② 模拟中若发现"按游戏规则本该换成别人"→ **把该弹从本段威胁里摘掉**（等价于"丢弃"，并在 audit 里记一条）；
  ③ 反向（别人→我方）由 §4.5 的 `HOMING_MISSILE_TARGET_CHANGED` 刷新兜底（**但该事件目前树里没监听，要先接线**）。
* **D3｜Rust 侧迷宫怎么传？**（ABI 形状）
  方案 A：传 `W/H + 每格墙体位（u8 位图）`，Rust 内自建 BFS（最忠实，代价 = ABI 增量 + Rust BFS 实现）；
  方案 B：JS 每帧算好"下一格中心"再传（Rust 只做加速+归一化）——**但这会让 Rust 依赖 JS 的每帧调用**，
  与 `vt_rollout_batch` 一次调用跑 75 帧的架构**直接冲突**（JS 不能在 Rust 循环中间插值）⟹ **【我的解释】只能走方案 A**。
* **D4｜0.02 s 固定步长 vs 真游戏 16/17 ms 的相位差**：本次实测 \|Δv\|=0.64/0.68（40×16ms/17ms），
  而沙箱固定 0.02 s ⟹ **每帧转向量会大 18~25%** ⟹ 制导弹的轨迹会比真机"转得快"。
  这属于已登记的 1-1/1-3 时间基准范围（沙箱固定步长是真机 1/60 的 1.2 倍）——**是否在 1-2④ 里一起收口，请拍板**。
