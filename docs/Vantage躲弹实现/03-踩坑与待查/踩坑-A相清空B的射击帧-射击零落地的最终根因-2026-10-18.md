# 🔴 最终根因：**A 相每帧成功 ⟹ 把 B 的 `_agentFirePicks` 清成 null ⟹ 射击覆盖率恒 0**

> **发现者**：父代理自主探针（只在"策略 `fire===1` 的帧"采样，才看见真相）
> **时间**：`2026-10-18` 凌晨
> **状态**：**已批修**（3 行 `game_core`，可 git 回退、无数据损失）

---

## 一、硬数据（决定性）

`VT_FORCE_FIRE=1`，**只在策略 `p.fire===1` 的帧采样**（1 局 × cap600，594 帧里 190 帧策略要开火）：

```
{"f":2,  "acceptedLen":76, "acceptedPicks":[[1,0],[1,0],[1,1]], "agentFirePicksLen":0, "aCalls":23}
{"f":10, "acceptedLen":76, "acceptedPicks":[[9,0],[9,0],[9,1]], "agentFirePicksLen":0, "aCalls":31}
{"f":14, "acceptedLen":76, "acceptedPicks":[[3,0],[3,0],[3,1]], "agentFirePicksLen":0, "aCalls":35}
```

| 观测 | 值 | 含义 |
|---|---|---|
| `acceptedLen` | **76** | ⭐ **桥造了 76 条（路线 + 75 个射击帧），且决策被界面接受** |
| `agentFirePicksLen` | **0** | ⭐ **游戏侧收了却变 0** |
| `aCalls` | 23→31→33→35（**每帧 +1**）| ⭐ **A 相每帧都在成功** |

## 二、根因（代码闭合）

`vantage_tree.js:4581-4587`（`onAgentDecision`）：
```js
if (phase === 'B') {
    tree._agentRoute     = _route;
    tree._agentFirePicks = (dec.picks.length > 1) ? dec.picks.slice(1) : [];   // ← B 写入
} else {                                                                        // phase === 'A'
    tree._agentRoute     = null;                                                // ← A 清路线
    tree._agentFirePicks = null;                                                // ← A 清【B 的领地】
}
```

**⟹ B 写进去的 75 条射击帧，被同一帧的 A 相决策清成 `null`。**

## 三、为什么这修法是对的（语义论证）

1. **`picks: []` 的语义是「本帧不生长」**（`vantage_tree.js:6678` 原注释）—— **树结构没变，B 的选择依然有效** ⟹ **不该作废 B 的决策**
2. **`_agentFirePicks` 是 B 的产物**，**A 相没有任何理由去动它**
3. 只有 **A 真的长出节点**（`dec.picks.length > 0`，树结构变了）时，让 B 的路线失效**才**有道理

## 四、修法（3 行）

```js
} else {                                            // phase === 'A'
    // ★ 修复：只有 A 真的生长了（树结构变了）才让 B 的路线失效；
    //   "本帧不生长" 不得抹掉 B 的路线；_agentFirePicks 属 B 的领地，A 一律不碰。
    if (dec && dec.picks && dec.picks.length > 0) {
        tree._agentRoute = null;
        tree._agentFirePicks = null;
        tree.stats.agentRouteId = null; tree.stats.agentFireFrames = 0; tree.stats.agentFireFirstBack = null;
    }
    ...
}
```

## 五、为什么拖了一整晚（教训）

**所有探针都在"随机帧"上采样** ⟹ 而策略只在 **~2%（190/600 用强制才到 32%）** 的帧说"要开火" ⟹
**采样几乎总落在"没要开火"的帧** ⟹ 看到 `builtLen=1` ⟹ 误判成"桥没造射击帧"。
⭐ **决定性教训**：**探针必须只在"目标事件发生"的帧采样**，否则你会对着"事件没发生"的样本反推原因。
