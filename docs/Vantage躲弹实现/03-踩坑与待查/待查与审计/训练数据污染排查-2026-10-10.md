## 一、结论摘要

**一句话：真正被训练消费的三份 rollout 数据（`_train/rollout.jsonl`、`rollout_v2.jsonl`、`rollout_v3.jsonl`）没有踩中这个 bug——三个 worker 在每个 episode 的 teleport 之前都先泵帧等到 `IN_ROUND`（`__vtReady()`）；两份 `stage1_random.jsonl` 只有"开局一次的移动探测等待"、没有每局复查，属于【有风险但数据里找不到污染签名】，而且它们从未被任何训练脚本读取。**

展开（一句话的三点）：

1. **没问题（低可疑）**：`rollout_worker.js` / `_v2` / `_v3` 的页面内代码里，每个 episode 前都有
   `if (window.__vtReady && window.__vtReady()) { ready = true; break; }`（v1 :286-289），
   而 `__vtReady()` 里显式判 `gc.model.getState() !== GameModel._STATES.IN_ROUND → return false`（v1 :260-262）。
   ⟹ **倒计时内根本发不出 teleport**，与 `match.js` 的漏洞无关（它们不用 `match.js`）。
2. **可疑但未证实（中低）**：`stage1_env.js` / `stage1_rollout.js` 用 `Match.teleport()` / 自己注入的 `__vtSet`，
   **只有开局那一次"给油看动不动"的探测**算等到 IN_ROUND，之后 100+ 局**不再复查**；
   若中途 tank_a 死亡→回合重启→倒计时，期间的 teleport 会被静默丢弃、位姿变成出生点。
   数据侧面检查（§四）**没有**找到出生点堆积/上一局终点残留等签名，但**没有记录"请求的 A"**，无法百分百排除。
3. **不受影响**：`collect.js`（真实树数据 `real_trees.json`）、`record.js`（阶段 0 新录制器）、
   `tools/nn/agent_stage0.py` / `train_stage0.py` / `train_aim.py`（合成树，不跑游戏）都**不调 teleport/setTankState**。

### 四.3 「起点是不是被请求的那个格心」——格心占比

teleport 的目标 `A` 一律是 `mz.reachable` 的格心（`x = tile*10 + 5`，`<worker>:424-426` 与 `stage1_rollout.js:55`）。
所以**成功的 teleport 会把坦克放在格心上**（差值 0），被丢弃时则会落在"上一局终点/出生点+漂移"这种任意位置。

【我的解释】① 三份训练数据 96%+ 的起点**分毫不差地落在格心**，只有"没被丢弃"才可能；
② 剩下那几局偏移也很小（≤2.3），量级与"传送成功后又被 Box2D 顶开/被另一辆车挤开"一致；

## 五、无法判断的（不许猜，如实列出）

1. **stage1 两份文件的"出生点局"无法从数据里排除**。
   出生点的位置和朝向都是**随机**的（`Maze.createRandom` 里第一辆坦克
   `this.tankPositions.push({x:presentTile.x, y:presentTile.y, rotation: Math.random()*2.0*Math.PI, ...})`，
   见 `game_core/js/418577fd210ad079ea3d1e5e04050fe0.js` 压缩单行原文），
   而数据里**只记了"实际起点"、没记"请求的 A"** ⟹ 一次"丢弃→停在出生点"和一次"成功→停在随机格心"
   在数据上**长得一模一样**，无法区分。只能用 §四.4 的"迷宫没换过"间接排除。
2. **根 `stage1_random.jsonl` 里 4 个偏移 >1.2 的起点（1.221 / 1.260 / 1.348 / 2.211）没有定论**。
   候选解释（都【未验证】）：① `pump(4)` 期间漂移比按满速估的 1.06 更大（掉帧/速度常量不是 15.95）；

3. **`stage1_random.jsonl`（根）里 157-162 连续 6 局无数据**（`ep` 跳号）。
   跳号的出口有三个："A-B 太近 `<20` 直接 continue"（`stage1_rollout.js:95`）、"`myTank()` 读到 null（坦克不存在）后 continue"（`:100`）、以及恒不成立的 `if (d < 0) continue`（`:102`），
