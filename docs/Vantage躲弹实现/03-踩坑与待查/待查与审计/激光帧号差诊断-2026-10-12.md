## 一 一句话结论

**这 1049/3776 的帧号差是 v171/v172 激光扫掠的“合并规则不对称”，不是 D4、也不是 c06e60c8 改出来的：JS 融合把扫掠当作“没别的接触才用的 fallback”（`if (!dead[i] && sweepHit[i]>=0)`），Rust 则把扫掠与接触取最早（`if (sweep_hit<death_frame) death_frame=sweep_hit`）。1049 条分歧里 `jsSweepHit` 全部等于 Rust 的 `deathFrame`，而 JS 最终帧全部等于“第一个非 sweep 的接触/几何事件”（更晚）——Rust 报的是激光第一次穿车的帧（对），JS 被更晚的接触拖后了（偏晚，最多 +50）。**
**性质：真 bug（两边语义不一致，且 JS 侧晚）；修法建议 = 把 JS 的 sweep 回溯改成“取更早帧”，与 Rust 对齐（JS-only 一处条件，不必重编 wasm）。**

## 三 方向判定：谁对谁错

- **Rust（sweep 帧）对，JS（更晚的接触帧）偏晚。** 依据：
  1. 激光在 k=3 已经**真实穿过候选坦克的多边形**（JS 自己的 sweep 也记为 3），第一次命中即应判死；k=53 的另一颗弹/更晚接触发生在“坦克早就该死”之后，不能作为死亡帧。
  2. 1-2③ 的验收金标准：5 个真游戏 golden 局面（《激光判死几何实测-2026-10-11.md》+ `_probe_laser_sweep_counterexample.js`）里，真游戏 `gameKill=true`、激光一帧跨过；修复后 sandbox 判 `fd=0`（第一次穿车帧）。真游戏的裁判支持“第一次穿车就死”，而不是“等到更晚的接触”。Rust 的 sweep 帧正是这个语义。
  3. `rustEqSweep=1049/1049` 说明两边对“激光第几帧穿车”**没有分歧**；分歧只在“要不要让更晚的接触覆盖它”——这正是 JS 的 fallback 条件造成的。
- **反向修法不成立**：把 Rust 改成“有更晚接触就丢弃更早 sweep”会退回 1-2③ 之前的“激光跨过不算死/晚死”，与真游戏 goldens 冲突。
- 【推断】绝对帧的边界：sweep 用的是**半径 0 的精确多边形相交**，而 JS 融合世界对半径 0 的激光会退化到 `0.05` 半径；真游戏的有效判死半径可能更大（golden 表里的 `g05/g25`：`miss_almostfull g05=+0.0723` 但真游戏仍判死，`g25=-0.1277`）。在“gap 落在 0 与真游戏有效半径之间”的极边缘擦过里，真游戏可能比半径 0 的 sweep **更早**判死；但本 seed 观测到的 1049 条**全是 JS 更晚**（没有 JS 更早的负差），所以这不影响“JS 偏晚”的方向判定。**这一条是【推断】，需要真游戏边界数据才能定量。**

## 四 D4（0.02 vs 16/17ms）是不是来源

**不是。** 三条证据：

1. **同 dt 对比**：harness 里 `VS.setFrameDtSec(1/60)` 只调一次，JS 融合世界（`FRAME=_frameDtSec`）和 Rust bridge（`setFrameDt`）**都用同一个 dt**；JS−Rust 的帧差是同 dt 下的算法差，D4（沙箱 vs 真游戏的步长差）不在这个比较里。
2. **换 dt 复现**：冻结 v172、`--dt 0.02`（N=200）：

```text
bothDead=1240 diverged=264 (21.3%)
diff js-rust: min=1 p50=1 p90=1 max=61
convergence: rustEqSweep=264 jsEqSweep=0 sweepLtJs=264 sweepGtJs=0 sweepMissing=0 sweepNotEqualRust=0
nonLaserDiv=0
```

  同样的“rustEqSweep=全部分歧、JS 全部更晚”模式在 `dt=0.02` 下原样存在 ⟹ 机制与 dt 无关，只与合并规则有关。
3. **逐帧 trace**：k=3 的 sweep 事件与 k=53 的接触事件是**同一世界内**的事件，与真游戏步长无关。

**D4 仍然是一个独立的、尚未解决的“真游戏帧长 vs 沙箱固定 dt”问题**（1-1/1-3 范围），应保留在“要主人拍板”的清单里；但它**不是**这 1049/3776 帧号差的来源。

## 五 修不修的建议（只建议，未动手）

### 结论：**是 bug，建议修；修法是 JS-only 一处条件**

把 JS 的 sweep 回溯从“fallback”改成“取更早帧”，与 Rust 对齐：

```js
// game_core/js/vantage_sandbox.js —— sweep 回溯（v172 :2186 / 当前中间态 :2354）
// 旧：if (!dead[i] && sweepHit[i] >= 0) { ... }
if (sweepHit[i] >= 0 && (!dead[i] || sweepHit[i] < deathFrame[i])) {
    dead[i] = true;
    deathFrame[i] = sweepHit[i];
    if (audit) audit.sweepFallback = true;
}
```

- **代价**：JS-only，一个条件；**不需要重编 wasm / 不动 ABI**。
- **预期**：`_lfd_frame_diff_probe.js` 的 `diverged` 应从 1049 → **0**（或仅剩数值噪声），`diff max=+50` 消失；`rustEqSweep` 与 `jsEqSweep` 应一致。
- **必须一起跑的回归**：`_lfd_frame_diff_probe`（600 seed 20261011，期望 0）、`20/20` 录放、`diff_rollout_bridge`（0.0）、全量 `diff_*.js`、以及 1-2③ 的激光探针（9/9+5/5、N2/N3、`diff_rescore_laser` 5/5、`_probe_fd0_consumer`）。因为 JS 融合是树确认/执行路线的一部分，帧提前后要确认没有“假绿/假红”翻转。
- **版本**：若此修上门，按项目规则需要同步升 `vantage_sandbox.js?v=` 与可能的 `TREE_VERSION`（树会消费 JS 融合结果）；**本轮只诊断，未升**。
- **协调**：`c06e60c8` 正在改 `vantage_sandbox.js`（当前 md5 已到 `40fcce8c…`，行号漂移），且它把 bridge 推到要求 ABI v12、wasm 还是 v11 的中间态；这个一行修必须由它 rebase/确认，不要并行改同一文件。
- **不要**把 Rust 改成“丢弃更早 sweep、等更晚接触”：那会恢复 1-2③ 之前的漏判/晚判。
- **`geoHit` 另行审计**：`vantage_sandbox.js:2177`（v172）/`:2345`（当前）的 `geoHit` 回溯也是 `!dead[i]` fallback；Rust 没有 geoHit，若直接把 geoHit 也改成“取 min”，可能让 JS 在非激光场景比 Rust **更早**，制造新分歧。本 seed 的非激光分歧 = 0，所以**不建议同 patch 改**；建议单独立项（`_lfd_` 加非激光对照）再定。

### 影响面（供优先级判断）

- 这是**两边都判死**时的帧号差，树/选路/确认拿到的是两套不同的“能走几步”。p50 +1 会让“Rust 早 1 帧”成为系统性偏差；尾部 +50 是“另一颗弹更晚命中”被 JS 当权威帧。若树的 `fullDeathFrame`/选路已有“Rust 早 1 帧”的复判数据（父报告 §①：C 155 次 Earlier=2、Later=0），这个修会把两边对齐，是有收益的。
- 但它是**偏向“更早判死”**的修（对激光的第一次穿车更敏感），对“假绿”方向是**更红**；需按上面回归确认没有把“边缘擦过”从可接受变成立即死。绝对帧的真游戏裁判仍受 D4/有效半径两个未决项限制。
