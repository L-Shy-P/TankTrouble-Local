## 一、两句话结论

> **① 寿命截断型盲区：无害（在"单 vantage AI + 轨迹末端=真游戏 `done()`"两个前提下）。**
> 这类短轨迹**不是重模拟失败**，而是沙箱把弹**模拟到真死**（寿命到期/≥5 次反弹/速度归零 —— 三条都是真游戏
> `Projectile.done()` 的原条件）后自然断供。实测 **893 个"短代"的 `cover0 − 真弹剩余寿命` 全部落在
> `+0.016 ~ +0.034s`（=1~2 帧，方向恒为"轨迹比真弹死得晚"，0 例提前）**，8907 条短轨迹行同结论。
> ⟹ **越界时刻真弹必已消失 ⟹ 正确答案就是"没有这颗弹" ⟹ 粗筛跳过它是【正确】的，不是 bug。**
> ⚠️ 前提是**树时钟 = 游戏时钟**：本轮 `vantCount=1` 实测 **ratio 1.019**（Δ/游戏秒）；而 `vantCount=2` 实测 **ratio 2.039**
> （两个 vantage AI 每帧各 tick 一次，`_timeAcc` 每帧加两次 `dt`）——那个配置下"越界=弹已死"**不成立**（见 §四.3）。
>
> **② "取位 null" 本身一次都没害过人；真正能害人的是【同一套越界条件】的 6 处下游通道（§三.2 表里 #4/#5/#6/#7/#8/#10）。**
> 树里 `trackPosAt` 只有 **2 个调用点，全在 `runDiagnostics`**（`vantage_tree.js:7006` / `:7054`），
> 拿到 null 只是"这颗弹不计入弹差/`px` 记 null"⟹ **诊断失真，不参与任何判定**。
> 但**同源越界**在下游有三种态度：**JS 融合世界钳末帧+近似摆放（保守，不会漏弹）**、
> **JS 评分与 Rust 候选验证把"越界"当"这颗弹不存在"（假绿通道）**、**树内 `threatCoarseBox`/`nodeWindowSig`
> 把时空窗右端压到轨迹末端（跳过重扫的假绿通道）**。
> **实测（v169）**：49,594 条 tick 帧锚点样本里"取位越界而真弹还活着" = **0**；
> **v167 门（上一轮复核的 B2 跑）**该前置条件确实发生过（`px=null` 而真弹位姿非 null = **1249/2642 = 47.3%**），
> 但"**是否真转成了绿/红误判**"——**读代码读不出、本轮也没测到 ⟹ 无法判断**（§五.1 写明需要什么实验）。

## 二、疑点 ①：寿命截断型盲区有没有害

### 2.1 这类轨迹**是什么弹**？—— 答案：**普通弹(BULLET)，被"剩余寿命"截短的轨迹**

**(a) track 只覆盖 4 种弹**：`isBallisticProjectile`（`vantage_sandbox.js:262-270`）只收
`BULLET(-1) / DOUBLE_BARREL(1) / SHOTGUN(2) / GATLING_GUN(5)`
（弹种码表 `WEAPON_TYPES:{BULLET:-1,LASER:0,DOUBLE_BARREL:1,SHOTGUN:2,HOMING_MISSILE:3,MINE:4,GATLING_GUN:5}`）。
本轮 921 个轨迹代 **921/921 全是 `type=-1`（基础弹）** ⟹ 「生命/双管/加特林/霰弹」的短轨迹**一个样本都没有**（见 §五.3）。

**(b) 短轨迹的三个出口 + 一个早停，全部照抄真游戏 `Projectile.done()`**（`vantage_sandbox.js`）：

| 出口 | 行号 | 代码 | 真游戏对应 |
|---|---|---|---|
| 寿命到期 | `:552-555` | `s.lifeLeft -= FRAME; if (s.lifeLeft<=0) active=false` | `timeAlive>=lifetime`（`done()` 第一支） |
| 反弹上限 | `:561-564` | `if (s.bounces.length >= bounceTimeoutCount()) active=false` | `bounces.length>=timeoutBounceCount`（第三支） |
| 速度归零 | `:569-572` | `if (len===0) active=false` | `Projectile.update` 里 `if(length===0) this.stopped=true` ⟹ `done()` 第二支 |
| 全批停 | `:518` | `if (!anyActive) break;` | —（全弹都停后不再空转 Step） |

- 只有 `active` 的弹才被 push 进 track：`:509`；寿命已尽（`lifeLeft<=0`）的弹**连结果都不进**：`:480-483`。
- 真游戏原文（bundle `game_core/js/418577fd210ad079ea3d1e5e04050fe0.js`，Projectile 类）：
  `done:function(){return this.timeAlive>=this.lifetime||this.stopped||this.bounces.length>=this.timeoutBounceCount;}`
  —— 沙箱 `:313-330` 自己就抄了这段原文（可对照）。
- ⟹ **track 的"最后一帧之后"= 沙箱认定的"这颗弹死/消失"的那一刻**，不是"模拟失败"。

**(c) 为什么长度 < `needFrames`**：`needFrames` 由 `trackFramesForTree`（`vantage_tree.js:1844-1854`）**只按树窗口**
（`max(horizon+EVAL, 最深节点+EVAL)` 折算帧 +5）算出，**与弹的剩余寿命无关**；
而沙箱每颗弹在自己的寿命处断供（`:552-555`）⟹ **剩余寿命 < 窗口的弹必然拿到短轨迹**。
> ⚠️ **文档/代码漂移（顺带记一笔）**：`ensureThreatTracks` 的注释（`vantage_tree.js:1930`）和 `:674` 都说
> "沙箱接口 `adapter.getBulletTrackFrames(horizonFrames)` 会按各弹真实寿命取最长"，
> 但**树里从来没有调用过它**（全仓 grep：`getBulletTrackFrames` 只出现在 sandbox 的定义 `:2781` 和这两处注释）。
> 真正的"逐弹寿命截断"是**沙箱内部提前停**造成的，不是这个接口给的。

**(d) 不是"重模拟失败"**——两者的签名完全不同：

| | 重模拟失败（`tracks===null`/抛错） | 寿命截断型 |
|---|---|---|
| 代码路径 | `vantage_tree.js:1943-1950`：**一个锚点都不动**（旧 track + 旧 `anchorOffset` 原样留着） | `:1958-1973`：**换新 track、`anchorOffset=0`**（每次 commit 重模拟） |
| 现象 | Δ 继续线性涨、len 不变 | Δ 锯齿（每次 commit 归零）、**len 随剩余寿命一起递降** |
| 实测 | 本轮没抓到（`ensureEarlyReturn.simNull/simThrow` 未采样） | **549/549、798/798 个短代 `lifeLeft0 < 8s`**；逐代样例见证据 log |

**本轮实测恒等式**（口径：`dumpDiagnostics().liveAnchors[]`；`vantCount=1`；tag Q1,Q2；tick 帧）：

| 量 | 样本 | 结果 |
|---|---|---|
| **短代** `err0 = cover0 − 真弹剩余寿命`(代首帧) | n=**893**（`len0<need0` 或 `cover0<8s`） | **min +0.016 / med +0.0173 / max +0.0337 s** ⟹ **早期截断 = 0** |
| **短轨迹行** `err = cover − Δ − 真弹剩余寿命` | n=**8907** | **min +0.0073 / p10 +0.0143 / med +0.0283 / p90 +0.0327 / max +0.0337 s** ⟹ 提前(<−2帧) **0**，滞后(>+2帧) **0** |
| 短代成因拆分 | 798 个 `cover0<8s` | 100% `lifeLeft0<8s`；100% `type=-1`；797/798 有反弹记录；`stopped=0` ⟹ **出口是"寿命到期"**（若是反弹/停止出口，`cover` 不会恰好等于剩余寿命） |
| （对照）窗口截断代 | 921 代里 28 个 `err0<−2帧` | 逐个看**全是满窗口型被窗口截断**（`len0=481·tdt0.02=9.62` 或 `len0=562·tdt0.01667=9.37`，而 `lifeLeft0≈9.98`）——**那一类是 v167 门的病灶类**，本轮被 v168 门挡住（Δ≤1.0），**不是**寿命截断型 |

### 2.2 深节点越界时，**正确答案应该是什么**？—— **弹已消失（没有这颗弹）**

- 越界判据（产品口径）：`round((t_query − abs0)/trackDt) >= trackLen`（`vantage_tree.js:2024-2036`），
  等价于 `t_query >= abs0 + trackLen×trackDt = 轨迹末端`。
- 轨迹末端 = 沙箱模拟里这颗弹"死/消失"的那一帧（§2.1b）。
- 因此 **「深节点查询越过轨迹末端」⟺「该节点时刻这颗弹早已不在」** ⟹
  **正确的答案 = 这颗弹在该节点不存在**；`threatCoarseBox` 的时间窗右端正好是轨迹末端
  （`:2212` `box.t1 = box.t0 + th.track.length * trackDtOf(th)`），它与该节点的时空窗不相交 ⟹ 跳过这颗弹
  ⟹ **正确，不是 bug**。
- **数值核对**（vant=1，tick 帧，盲区行 7022/10496 = **66.9%**）：
  把越界时刻 `(Δ+horizon)` 按实测 ratio 换算回游戏秒，与真弹剩余寿命比：
  **6750/6785 = 99.5% 满足"越界时刻 ≥ 弹死时刻"**；余下 35 行全部是 ratio=1.019 的 1.9% 换算余量
  （"越界时刻−剩余寿命" med +0.032s、min −0.11s ≈ 6.6 帧），**不是真的越界提前**。
- 另有**纯代数**判据（不依赖换算）：短轨迹行 `err = cover − Δ − lifeLeft ≥ +0.0073 > 0`
  ⟹ `cover > Δ + lifeLeft`；而盲区 ⟺ `Δ+horizon ≥ cover` ⟹ `Δ+horizon > lifeLeft` ⟹ **越界时刻必在弹死之后** ∎

### 2.3 代码怎么处理的？—— **同一件"越界"，四个下游三种态度**

| # | 下游 | 位置 | 越界时行为 | 判定 |
|---|---|---|---|---|
| 1 | 树内取位 `trackPosAt` | `vantage_tree.js:2024-2036` | `return null` | 只进诊断（§三.1） |
| 2 | 树内 `threatPosAtTree` | `:2038-2053` | `return null`（`alive===false` 也 null） | **全仓无调用者 = 死代码** |
| 3 | **JS 融合世界摆弹**（=死亡权威） | `vantage_sandbox.js:1599-1601`（`if (idx>=len) idx=len-1`）+ `:1673-1727`（取不到位 → 真实位姿按 `advFrames` 时间反推**近似摆弹** + `_fusedDropStats` 计数） | **钳到末帧 / 近似摆放 ⟹ 弹不会消失** | **保守，不会假绿**（代价：幻影静止弹=假红方向） |
| 4 | `threatCurrentPoint` | `vantage_tree.js:2275-2296`（`:2281` 钳 `idx∈[0,len-1]`） | 钳末帧 → 幻影静止弹 | 只用于 pending 粗筛 `bulletCannotReach`（`:2590`/`:2755`）⟹ **保守** |
| 5 | `threatCoarseBox` / `nodeWindowSig` | `:2212` / `:4353`（都用 `t1 = t0 + len·trackDt`） | 时空窗右端压到轨迹末端 ⟹ 节点窗不相交 ⟹ `nodePossiblyAffectedByPending`(`:2748-2760`) 判"不受影响" ⟹ `collectStaleForLayer`(`:2921-2932`，注意它的输入 `pendingThreatCoarseBoxes`(`:2790-2798`) **只吃 `_pendingThreats`**=新弹) **跳过重扫**；`nodeWindowSig` 里这颗弹**不进签名** ⟹ `nodeIsStale`(`:4374-4384`) 判"节点没变" ⟹ **不重扫** | **假绿通道**（当且仅当轨迹末端早于真死时才有害） |
| 6 | JS 评分 `threatBulletPos` + 车道分 | `vantage_scoring.js:1764-1785`（`:1773 idx>=len → null`）；车道分 `:1385-1398`（`idx0>=len` ⟹ `pts.length<2` ⟹ `continue`） | 按"**这一帧没有这颗弹**"处理（8 个调用点，见 §三.2） | **评分假绿**；其中 `:2210` 的 `adapter.checkDeath(tank, positions)` 是**静态死判兜底** |
| 7 | **Rust** `threat_bullet_pos` | `rust/vantage_core/src/rescore.rs:291-306`、`scoring.rs:1075-1086`（**idx 越界或 `!s.alive` 都 `None`**） | `verify_death_for_node` 里 `pos_k=None → continue`（`rescore.rs:1171-1174`）⟹ **那颗弹在候选验证世界里根本不摆** | **假绿通道**（但只产 `rust-candidate`；末判在 JS 融合世界，见 §三.3） |
| 8 | Rust 粗筛 chunk | `rescore.rs:474-528` | 只收 `alive` 点、空 chunk 丢弃、q 窗口 ±半帧；注释明写 "frames in that chunk fall back to exact checking" | **保守** |

**一句话**：**"越界该不该当弹消失"这件事，代码里的答案是分裂的** —— 树的粗筛和 Rust 候选验证说"消失"，
JS 融合世界说"还在（钳住）"。所以"取位 null 有害吗"必须**按下游逐个回答**，不能一句话。

### 2.4 结论：**分情况**

1. **无害（覆盖本轮 100% 的样本）**：`len<needFrames` 的短轨迹，**只要它断在真游戏 `done()` 的那三条真死条件上**，
   ⟹ 越界=弹已不在 ⟹ 粗筛/评分/验证"跳过这颗弹"**语义正确**。实测 893 短代 / 8907 短行 **0 例提前**（vant=1）。
2. **有害的窄窗口（条件性）**：
   - **(i) 轨迹末端早于真死**（模型判死太早）⟹ 会变成真·假绿。本轮 **0 例**；【推断】唯一残余风险在
     `bounces>=5`（35ms 粘性剪枝是把真实世界"按接触帧计数"的近似，`vantage_sandbox.js:311-335`）——
     但本轮短代 100% 是"寿命出口"，这一支没被采到（见 §五.3/§五.4）。
   - **(ii) 树时钟 ≠ 游戏时钟**：`cover` 是按**游戏秒**算的剩余寿命（`len = ceil(lifeLeft/_frameDtSec)`），
     而树查询用的是**树秒** Δ。`vantCount=1` 时两者实测 1.019 ✓；`vantCount=2` 时实测 **2.039** ⟹
     越界边界整体前移约一半 ⟹ **"无害"论证不成立**（该配置下本轮实测 `null_now` 仍为 0，但这是运气，不是结构保证）。
3. **⟹ 给主人**：**"越界"本身是对的（弹真的没了）、短轨迹也不是重模拟失败；它的正确性建立在
   「树秒=游戏秒」和「轨迹末端=真游戏 `done()`」两个前提上。前者在"两个 vantage AI 同局"时会翻倍（§四.3），
   后者本轮实测 0 反例。**

## 三、疑点 ②："取位 null" 是否真的导致过假绿/假红

### 3.1 `trackPosAt` 的**直接调用方**（全仓 grep：`trackPosAt` 未导出，只有 2 个调用点）

| 1 | `vantage_tree.js:7006`（`runDiagnostics`：每帧算"锚定轨迹预测位 vs 真实弹位"误差） | `if (!pred) continue;` ⟹ 这颗弹**不计入** `lastBulletError`/`bulletDesyncs` | **诊断失真**：v167 故障时"弹差"会被报成 0（漏报"树看不见活弹"），**不影响任何游戏判定** |
| 2 | `vantage_tree.js:7054`（`runDiagnostics` 填 `anchorProbe[].px/py`） | `px/py = null` | 只进诊断/面板输出 —— **这就是上一轮报"取位 null 344 次"的那个字段** |

  口径同源、**函数不同**；所以"树里 null 有没有害" ≠ "下游 null 有没有害"。

### 3.2 同一套越界条件的下游 —— **逐个判定**（完整清单）

## 四、实测（口径 + 场景 + 数字）

### 4.1 口径声明（数字必须连口径一起引用）

- **Δ / 覆盖 / 取位 / 盲区一律用 `dumpDiagnostics().liveAnchors[]`**（`vantage_tree.js:7976-7994`；AGENTS 2026-10-12 定）：
  - `Δ = _timeAcc − (rootAbsT + anchorOffset)`；`cover = trackLen × trackDt`
  - **取位 null ⟺ `round(Δ/trackDt) >= trackLen`**（与 `:2024-2036` 同式）
  - **深节点越界 ⟺ 存在节点 n 使 `Δ + (n.tEndSec − tNow) > cover`**
- **真弹状态**取自**真游戏对象**（不是树内副本）：`GameManager.getGameController().getProjectiles()[id]` 的
  `lifetime / getTimeAlive() / done() / stopped / bounces.length`。
- 只统计 **tick 帧**（`t.diag.lastCheckAt === tNow`）；**样本 = 帧 × 活锚点**；被冻结的帧**整帧丢弃**。
- 场景：无头 Chrome + 虚拟时钟（16.67ms/帧），`humanIds:['tank_a']`（tag Q/X/V/W 每帧转 0.6 rad + 持续开火；
  A/B1/C 每 20~30 帧转一次），`aiCount:1`，`MAZE_THEMES.RANDOM`，每跑 1200 帧。

- 探针 **v1**（`_probe_blindharm.js`）没滤掉"树冻结但 `lastCheckAt` 仍刷新"的帧，把 `err` 算成 +3s；

## 六、建议（要不要修 / 修哪里 / 还是只记档）

1. **【只记档】寿命截断型盲区不要修。** 它是"弹真的死了 + 树正确地跳过"，实测 893 短代 / 8907 短行 **0 反例**。
   去"修"它只会把正确的跳过改成多余的重扫（假红 + 卡顿）。报告里必须写成
   **"满窗口型归零 / 寿命截断型按设计保留"**（沿用复核报告的"影响面"规矩）。
2. **【记档 + 写规范】每条"盲区/Δ"数字必须带三件套**：① 样本类别（满窗口型 / 寿命截断型）；
   ② **时钟比**（=同局几个 vantage AI）；③ "只算 tick 帧"。建议直接补进 `AGENTS.md` 的"📏 测量口径"节。
3. **【开新调查项】多 vantage AI 同局的"树时钟倍率"**（`:7499` × `ai_vantage.js:93`）：
   `vant=1 ratio 1.019 / vant=2 ratio 2.039`。它会让所有"树秒 ↔ 游戏秒"的换算（`absDeath`、Δ 判据、`cover`）
   整体偏 N×。**建议只读计数**（同局 tick 次数 / 渲染帧数 / `resolveWorldDt` 各分支命中次数）先定位，
   再决定要不要整流（属于时间基准，属于别的清单）。
4. **【先拿证据、后决定】6 处"把越界当弹不存在"的通道，按风险排序**：
   - ① `rust/.../rescore.rs:1171-1174`（`pos_k=None → continue`，**整颗弹不摆**）；
   - ② `vantage_tree.js:4353`+`:2929-2931`（`nodeWindowSig`/粗筛跳过重扫）——建议先加**只读计数**
     （"`t1 < tNow` 的威胁出现了多少次 / 因此跳过了多少个节点"），**不改语义**；
   - ③ `vantage_scoring.js:1773`/`:1385-1398`（评分侧 null）——评分一动就动排名与不变量②
     （`AGENTS`："拆掉评分 = 同时拆掉不变量②"）⟹ **千万不要在没有实测证据前改**。
5. **保留探针** `_tools/headless/_probe_blindharm2.js`（只读）作为以后复跑/复核入口；v1 可删。
