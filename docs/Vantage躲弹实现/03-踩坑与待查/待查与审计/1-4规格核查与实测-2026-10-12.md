## 一、一句话结论

> **三份规格【都不能"照规格一次写对"】。**
> - **护盾 §12.31**：🟡 **骨架对（是反弹不是无敌、破片是停），但缺"半径 4.3 / 圆心=坦克中心 / 不撞墙 / 自己的弹穿过去 / 到期拆夹具 / MINE 型弹与盾的接触被显式禁用"这 6 条关键参数与边界** —— 照 §12.31 现在那 3 行表写，**夹具会建错**（尤其是"破片反弹 vs 破片停"的实现机制）。
> - **毒雾 §12.30**：🟡 **几何部分实测全对（4 条边 ⟺ 一个安全区矩形、出界即死、5.00 s 才开始缩、6.75 s 杀到格心）**，但 **🔴 有一条规格陷阱**：它写"序列来自 `maze.getStormExpansionSequence()`"——**该 API 每调一次就重新抽一条随机序列（实测同帧两次调用结果不同，连长度都不同）**，照写必错；且 **🔴 本地对局（无头/训练/local_patch）根本不会出现毒雾**（BootCampGameMode 没有风暴逻辑 + `storm=false`）。
> - **道具 / 形状改变（§12.4 / §12.5）**：🔴 **规格明显不足一页**（没有 crate 物理参数 / 生成规则 / 队列上限语义 / 拾取用哪个 fixture / 6 种炮管形状 / 形状改变的时刻）。**代码事实我已查清并实测**，但**这些事实【不在规格里】**。
>
> ⟹ **不能照方针 L73「规格已全，照写」执行**；应先补 §五 那 12 条，再施工（顺序见 §六）。

2. **"自己刚打出的弹穿过自己的护盾"要不要进沙箱？** 主人原话是"不要为'自己打出的弹反弹回来打死自己'建模拟"。**但我实测这条规则确实存在，且它决定了"贴墙自杀"到底靠墙还是靠盾** ⟹ 请主人裁：沙箱要不要显式实现"同主人 + 未致命 → 不与盾碰撞"。
3. **护盾到期（6.0 s）时**：要不要把"拆夹具 → 形状签名变化 → 重检死亡"一并做（§12.4b 的机制）？
4. **"最后 2 秒变弱"在物理上什么都不做**（实测/读码）——**请确认**沙箱是否也"只做观测、不做物理"。

**毒雾（§12.30）**
5. **序列来源改口径**：`maze.getStormExpansionSequence()` **每次调用都重抽**（实测）⟹ 请确认规格改成「**从 `RoundState` 的 `ZoneState._expansionSequence` 读**」。
6. **本地对局要不要有毒雾？** 现在本地（含无头/训练）是 `BootCampGameMode + storm=false`，**永远不会有风暴**。请主人定：① 保持现状（沙箱实现毒雾=死代码，只备将来）② 本地也开经典模式/给个 `storm` 开关 ③ 只在沙箱里造合成风暴（那就没法端到端验收）。
7. **"首次生效时间"要不要写进规格**：**出现后前 5.00 s 夹具一动不动**，第 5.00 s 起边界以 `10 m / 5 s = 2 m/s` 内移；**贴墙坦克最早 5.2 s 会被吃**（实测）。
8. **补充"无伤害速率"**：接触即 `destroyTank`、无血量、判定频率 = 每物理帧一次（实测：死前帧刚接触、死亡帧就消失，差 1 帧）。

**道具 / 形状改变（§12.4 / §12.5）**
9. **crate 物理参数**：动态体 `density=0.1 / friction=0 / restitution=1.0 / linearDamping=4.0 / angularDamping=4.0 / allowSleep=false`；box `CRATE 64×64px = 3.2×3.2 m`；GOLD 圆 `r=1.75 m`；DIAMOND 六边形 `44×76px`。**要不要在沙箱里让箱子被推/移动？**
10. **生成规则**（现在 §12.5 标"❓未核"）：间隔 `3.0 + rand*5.0` s、上限 `MAX_CRATES=3`、离坦克 `≥4` 格、类型 = `crateTypes` 随机抽（本地默认 `[0..6]`）。**要不要进树**（§13.3 已裁决"❌不进树"，但那张表与 §12.5 的"❓未核"打架）。
11. **拾取的判定与前置条件**：**任一坦克 fixture 都可**（base 或炮管）；武器箱要"排队中<3"、升级箱要"无同类"、金/钻/旗无条件；**不满足 → 不拾取且箱子不销毁**。**要不要照抄成开关/直接照抄？**
12. **6 种炮管的形状常量表**（弹丸/激光/双管/霰弹/追踪导弹/加特林）+ **两个"形状变没"的分支**（导弹发射后炮管消失、拿地雷无炮管）；以及**形状改变的 3 个触发点**（拾取装填 / 导弹发射 / 武器用尽换下一个）。

## 六、施工顺序建议（**三份规格都补完之后**）

> 前置（不算 1-4 的内容，但按依赖必须先有）：**§12.4b 的"形状签名 + 缓存失效"** —— 护盾与炮管形状**都挂在同一套"候选体重建"机制上**，缺它两样都做不了。

## 七、无法判断的

1. **真破片弹幕（真地雷爆炸）没测**：破片三例用的是"注入真 `Shrapnel`"（走了 `RoundModel.setProjectileState` 的 `case MINE → Shrapnel.create` 真工厂），**没有真埋雷 → 真触发 → 真爆炸的端到端**。⟹ "地雷在脚下炸杀带盾坦克"我**只证明了"破片生成在坦克体内时会杀"**，**没证明真地雷爆炸时破片一定生成在坦克体内**（那取决于埋雷位置与 `MINE.OFFSET`）。
2. **60 s 的风暴出现时间没实测**：本地局拿不到风暴（M4），我只能读码给出"`roundDuration>=60` 且 `this.storm`"。`roundDuration` 从 `initializeRound()` 起算（在 `setState(COUNTING_DOWN)` 之前），⟹【推断】相对 `IN_ROUND` 大概是 **58.5 s**（3 次倒计时 × `COUNTDOWN_DURATION 0.5`），**未实测**。
3. **在线（4399/服务器）局是否真如 `ClassicGameMode` 那样跑**：本仓只有客户端 bundle + `server.py` 的 mock RPC，**服务器端真实现不在仓里** ⟹ 不能排除线上 build 与本仓 `ClassicGameMode` 有差异。
4. **`gameMode.roundController` 是谁设的**：`setRoundController` 全仓**只有定义、没有调用点**，但【实测】`gm.roundController !== null` ⟹ 有别的路径在设它，我没找到。对结论无影响（只影响"经典模式的风暴代码会不会抛异常"这个疑虑——**实测它为 null 为假**）。
5. **护盾对**"对手坦克推挤"**的影响**：护盾 `mask` 含 `TANK`（`SHIELD|TANK` 的 PreSolve：同主人 → `SetEnabled(false)`，**不同主人 → 派发 `TANK_SHIELD_COLLISION`**，物理接触**不**禁用）⟹【推断】带盾坦克会**真的推开别人**（因为盾 fixture `density=10`、坦克 `density=1`）。**未实测**。
