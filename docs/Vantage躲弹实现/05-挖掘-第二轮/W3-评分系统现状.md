#### (a) 单帧"存活分"：`scoreFrameAlive`【代码原文】`scoring:1262-1291`
```js
    function scoreFrameAlive(adapter, tankState, bulletPositions, cfg) {
        cfg = mergeCfg(cfg);
        var geo = occlusionIntervals(tankState, bulletPositions, cfg);
        var frameScore = 0;
        var i;
        for (i = 0; i < geo.freeIntervals.length; i++) {
            frameScore += geo.freeIntervals[i].width * geo.freeIntervals[i].width;
        }
        // v111：安全过滤阈值——把"已经足够安全"的帧分截顶到 a·k。
        // 危险区间（frameScore < a·k）原样保留梯度，只有超过阈值的部分被压平。
        var FRAME_MAX = TWO_PI * TWO_PI;          // a = (2π)² ≈ 39.478
        var k = Number(cfg.safeFilterK);
        if (!isFinite(k) || k <= 0) k = 1;
        if (k > 1) k = 1;
        var cap = FRAME_MAX * k;
        var safeByThreshold = frameScore >= cap - 1e-9;
        var rawFrameScore = frameScore;
        if (k < 1) frameScore = Math.min(cap, frameScore);
        return {
            dead: false,
            frameScore: frameScore,
            rawFrameScore: rawFrameScore,
            occludedRad: geo.occludedRad,
            freeIntervals: geo.freeIntervals,
            sampleCount: geo.sampleCount,
            safeFrame: safeByThreshold || !(geo.occludedRad > 1e-9)
        };
    }
```

#### (g) 顶层公式汇总

`totalScore = Σ_{i=1..N} frameNet_i`；`N` = 死亡帧（含，最后一项是死亡罚）或 `frames`。
`samples[0]` 是父节点末态，**不计分**（`scoring:1744` 注释 + `1826`/`2377` 从 1 开始）。

| 项 | 公式 | 权重/常量 | 出现在哪些函数 |
|---|---|---|---|
| **遮蔽/安全分** | `Σ freeIntervals[i].width²`，再做 `min(a·k, ·)` 截顶，`a=(2π)²` | `safeFilterK`（默认 1）；`occlusionEnabled`（默认 true） | `scoreFrameAlive`，被 `scoreFrame`/`scorePath`/`scorePaths`/`scoreRollout*` 全用 |
| **车道压分** | 每弹 `p = lanePenaltyRatio × (2π)² × (0.5·贴心率 + 0.5·弦率)`；总 `penalty = max(p)` | `lanePenaltyRatio`：评分默认 **0.5**；**树默认传 0**（关） | 四条路径全用 |
| **弹簧绳距离分** | `cap × (1 − Π(1−w))`；`w=clamp((DRef−dSpring)/(DRef−DNear),0,1)`；`w≥1 → cap` | `springRopeEnabled` 默认 **false**；`cap=8.0`，`DNear=4`，`DRef=30` | `scorePath`/`scorePaths`/`scoreRollout` |
| **卡墙罚** | 位姿几乎不变（位移≤`stuckDistEps` 且 \|Δrot\|<`stuckRotEps`）时每帧 `−stuckPenalty` | `stuckPenalty=6.0`、`stuckDistEps=0.08`、`stuckRotEps=0.05` | 同上；**只在 `isMovingInputs` 为真时计** |
| **动作成本** | `−actionCostPerFrame × actionIntensity(inputs)`，`0~2` | `actionCostPerFrame` 默认 0；仅 `safeFrame` 时计 | **只有 `scoreRollout`** |
| **死亡罚** | 死亡帧一次性 `−deathPenalty` 并 `break` | `deathPenalty` 默认 **100000**；**树传 0**（软死） | 四条路径全用 |

### 3.1 遮蔽/安全分（角度分）细节

- 帧分 = `Σ freeIntervals[i].width²`（`scoring:1267-1269`）；一段整圆 `width=2π` ⇒ 满分 `4π²≈39.4784`。
- `safeFilterK`（v111）：`cap = (2π)²·k`，只在 `frameScore > cap` 时压到 `cap`；危险区间保留梯度（`scoring:1270-1279`）。
- `safeFrame = 达到 cap 阈值 或 完全没被遮蔽`（`scoring:1289`）。
- 几何包络 `exactGeom`【代码原文】`scoring:961-979`：
```js
    function exactGeom() {
        var bulletR = Constants.BULLET.RADIUS.m;
        var halfW = Constants.TANK.WIDTH.m * 0.5;
        var halfBack = Constants.TANK.HEIGHT.m * 0.5;
        var halfForward = Math.max(halfBack,
            Math.abs(Constants.BULLET_TURRET.OFFSET_Y.m) + Constants.BULLET_TURRET.HEIGHT.m * 0.5,
            Constants.BULLET.OFFSET.m + bulletR);
        var rectHalfH = (halfForward + halfBack) * 0.5;
        return {
            HALF_W: halfW,
            RECT_HALF_H: rectHalfH,
            EFF_HALF_W: halfW + bulletR,
            EFF_HALF_H: rectHalfH + bulletR,
            R_ABS: halfW + bulletR,
            R_SEMI: Math.sqrt(rectHalfH * rectHalfH + halfW * halfW) + bulletR,
            // 车体中心 → 对称矩形几何中心的偏移（沿朝向朝前，调试器 L109 同公式）
            GEO_OFFSET: (halfForward - halfBack) * 0.5
        };
    }
```

### 3.2 车道压分 `lanePenaltyFrame` 公式

注释里的公式【代码原文】`scoring:1312-1321`：

### 6.5 一句话回答

- **"不要打分选路"也必须保留**：威胁表（`computeThreats`）、逐帧物理 samples、死亡帧、`safeFramesForDeath`、结构不变量/剪枝、刷新调度外壳。
- **"纯为选路服务、可整个拆"**：所有单帧分项（遮蔽/车道/弹簧绳/卡墙/动作成本/死亡罚）、`totalScore/perFrameScores`（作为分数）、`segmentScore/baseExt/rolloutTotal/subtreeBest`、全部 `pickBest*`/回传/加成链、`computeBaseTime`、`scoreRollout*`、`scoreCache`、Rust 两个打分器。
- **真正的耦合点只有三个**：① 评分与"samples+判定死"在同一个返回对象里；② `probeSegment` 用 `perFrameScores` 定段长；③ 选路用 `subtreeBest/rolloutTotal`。**拆评分 = 先把这三个耦合换成新通道，再删分项。**

setter 原文【代码原文】`tree:7827-7834`：

```js
    function setDeathDurationRatio(v) {
        var n = Number(v);
        if (!isFinite(n)) n = 0.5;
        _deathDurationRatio = Math.max(0.1, Math.min(1.0, n));
```

**`safeFramesForDeath` 全文【代码原文】`tree:4090-4105`**
```js
    /** v78/v80：统一"实际执行帧数"口径。
     *  fd<0 → 执行完整计划段；
     *  fd=1 → 只执行 1 帧（真死候选）；
     *  fd>=2 → 不超过"死亡帧的一半"，也绝不超过死亡帧前 1 帧。
     *  v80 起软死操作时长上限 = floor(fd × deathDurationRatio)，
     *  让 AI 更频繁换路，而不是按住一个操作直到接近死亡。 */
    function safeFramesForDeath(tree, fd, planned) {
        if (!(fd >= 0)) return planned;
        // v153：fd 现在数"能走几步"（见 §57.24）。fd=0=起手就撞上、fd=1=走 1 步就死，
        // 两者都是"一选就是死"，都只执行 1 帧。旧写法只认 fd===1，fd=0 会算出 -1。
        if (fd <= 1) return 1;
        var ratio = (tree && tree.cfg && typeof tree.cfg.deathDurationRatio === 'number')
            ? tree.cfg.deathDurationRatio : 0.5;
        if (!(ratio > 0) || ratio >= 1) return Math.min(fd - 1, planned);
        return Math.min(fd - 1, Math.max(1, Math.floor(fd * ratio)), planned);
    }
```

**调用点（全部 6 处）**
| 行 | 所在函数 | 用途 |
|---|---|---|
| `tree:2426` | `invalidateStaleNodes` | 无 box 粗筛分支算 safe frames |
| `tree:2469` | `invalidateStaleNodes` | 新弹提前死亡 → 缩短当前段 |
| `tree:2546` | `applyRolloutScore` | 把评分 `deathFrame` 折算成实际执行帧 |

| `tree:5806` | `splitLongSegmentLeaf` | 细化前缀继承死亡结论 |

**语义要点（代码原文）**：
- `fd < 0`（不死的 rollout 返回 `-1`）⇒ 执行完整计划段；
- `fd ≤ 1` ⇒ 无论 ratio 多少，**只执行 1 帧**；
- `fd ≥ 2` 且 `0 < ratio < 1` ⇒ `min(fd−1, max(1, floor(fd×ratio)), planned)`：**同时**受"死亡帧前 1 帧"和"死亡帧的一半"两个上限；
- `ratio ≥ 1` 或非正 ⇒ **只保留 `fd−1` 上限，"减半"不生效**。
【我的解释，未验证】所以"死亡时把可执行帧数压到一半"只在 `fd≥2` 且 ratio 默认 0.5 时成立；`fd≤1` 的真死是"只走 1 帧"，不是"一半"。

## 八、【解释】（全部是我的推断，未验证）

1. **接口面判断**：【我的解释，未验证】最小可行的"去评分"编辑面 = `vantage_tree.js` 的 8 个函数（A1-A11）+ `vantage_sandbox.js` 的 3 个 Rust 评分包装（D1/D4/D5）+ `vantage_rust_bridge.js` + Rust 的 `vt_score_paths`/`vt_rescore_nodes`；但这**不能只删调用**，因为 samples/死亡帧藏在评分返回里（M2/M3）。更现实的顺序是先加"纯模拟/纯判死"返回通道，再逐项删分项与选路器。
2. **动作成本疑似"接线失效"**：【我的解释，未验证】`actionCostPerFrame` 只在 `scoreRollout`（`scoring:1850-1852`）里扣；树实际走的是 `scorePath`/`scorePaths`，两者都**没有**这项（`scoring:2399,2501`）。而 `needsJsScoring()`（`tree:1371`）在 `_actionCostPerFrame>0` 时只是把 Rust 快路踢回 JS——JS 路径也不扣。⇒ 开关打开后疑似对树的最终分数没有影响。**我没有运行验证，只读代码得出。**
3. **`computeBaseTime` 是孤儿**：【我的解释，未验证】树不读（`grep baseTime vantage_tree.js` 无命中），`ai_vantage.js:29` 只写 `this.vantageBaseTime`，全仓库无读取者（检索过）。只有 testbench 调它。⇒ 拆评分时它基本可整块移走；但 `ai_vantage` 那段"只算+存"的注释与现状一致（不算驱动树）。
4. **`scoreRollout`/`scoreRolloutCached` 是孤儿**：【解释，未验证】两者都无调用者（§二），`node.scoreCache` 也**永远为 null**（所有写入点都在赋 null，§五）。v54 的增量缓存机制在当前 v162 已不在主路径上。
