## 二、接口层完整实现

### 2.1 `Invariants`（`vantage_tree_interface.js:34-77`）

**`isTrueDead(node)`**（`:29-32`，也在 `:320` 被单独导出）

```js
function isTrueDead(node) {
    return !!node && typeof node.fullDeathFrame === 'number' &&
           node.fullDeathFrame >= 0 && node.fullDeathFrame <= 1;
}
```
注释口径（`:26-27`）："真死 = 执行一步就会死（完整 75 帧模拟里死亡帧 ≤ 1）。"

**`canGrowAt(node)`**（`:38-42`）—— 不变量一

```js
canGrowAt: function (node) {
    if (!node) return false;
    if (node.invalid) return false;
    return !isTrueDead(node);
},
```
注释（`:37`）："不变量一：禁止在真死的节点上生长。"

**`checkSelect(chosen, candidates)`**（`:59-70`）—— 不变量二

```js
checkSelect: function (chosen, candidates) {
    if (!chosen) return { ok: false, reason: 'no-choice' };
    if (!isTrueDead(chosen)) return { ok: true };
    var hasAlive = false;
    for (var i = 0; i < (candidates || []).length; i++) {
        var c = candidates[i];
        if (!c || c === chosen || c.invalid || c.exhausted) continue;
        if (!isTrueDead(c)) { hasAlive = true; break; }
    }
    if (!hasAlive) return { ok: true, reason: 'all-true-dead' };  // 全真死，不干预
    return { ok: false, reason: 'picked-true-dead', hasAlive: true };
},
```
它的注释明确写了设计边界（`:47-55`）：
> ⚠️ 本函数【不替智能体改选】—— 主人 2026-10-02 定案：
>    "不要取'第一个'非真死的，那是遗漏的问题，非真死依旧由智能体选择。"
>    改选依据必须来自智能体，不能由接口凭空给一个"第一个"。
>    所以本函数只【报告】，不做替换

**`enforceSelect(chosen, candidates)`**（`:72-76`）—— 已废弃，**恒等函数**

```js
/** @deprecated 已废弃——它会替智能体改选。保留仅为兼容，内部改为只报告。 */
enforceSelect: function (chosen, candidates) {
    var r = Invariants.checkSelect(chosen, candidates);
    return r.ok ? chosen : chosen;   // 一律原样返回，不再替换
}
```
【代码原文事实】三元表达式的两个分支都是 `chosen`，所以无论 `r.ok` 真假都原样返回。
【解释，未验证】它现在的唯一作用是"顺带调一次 `checkSelect`"，调用方拿不到任何信息（返回值与入参相同），实际等于无操作。

### 2.2 `Agents` 注册表（`vantage_tree_interface.js:295-307`）

```js
var Agents = {
    _cur: new RuleAgent(),
    _all: {},
    register: function (a) { if (a && a.name) this._all[a.name] = a; return a; },
    use: function (name) {
        var a = (name === 'rule') ? new RuleAgent() : this._all[name];
        if (!a) { console.warn('[TreeAgent] 未注册的智能体，回退规则版:', name); a = new RuleAgent(); }
        this._cur = a;
        return a;
    },
    current: function () { return this._cur; }
};
Agents.register(new RuleAgent());
```

要点（全部是代码事实）：
- 注册键 = `a.name`；没有 `name` 的智能体**静默不入册**（`register` 只是 `return a`，不报错）。
- `use('rule')` **每次新建一个 `RuleAgent` 实例**，不走 `_all['rule']`。
- `use('不存在的名字')` → `console.warn` + 回退 `RuleAgent`（`:301`）。
- 初始 `_cur` 就是 `RuleAgent`（`:296`），且加载时又注册了一个（`:307`）。
- 没有"注销 / 列举"API。

**实测**（Node 加载未改动文件）：

```

[TreeAgent] 未注册的智能体，回退规则版: does-not-exist
use(unknown) -> rule
```

### 2.3 `validateDecision` / `validateBundle`

**`validateDecision(d)`**（`:113-123`）—— 白名单 + 夹紧

```js
function validateDecision(d) {
    if (!d) return null;
    var out = {};
    if (Array.isArray(d.growAt)) out.growAt = d.growAt;
    if (typeof d.growTimes === 'number' && d.growTimes > 0) {
        out.growTimes = Math.min(8, Math.floor(d.growTimes));
    }
    if (d.select !== undefined && d.select !== null) out.select = d.select;
    if (d.memory && typeof d.memory === 'object') out.memory = d.memory;
    return out;
}
```
- `d` 为假值 → `null`。
- 接受的 4 个键：`growAt` / `growTimes` / `select` / `memory`；**其它键一律丢弃**。
- `growTimes` 上夹到 8（自测页 `vantage_selftest.html:102` 断言 `99 → 8`）。

**`validateBundle(d)`**（`:133-149`）—— "格式层"整包校验

```js
function validateBundle(d) {
    if (!d || typeof d !== 'object') {
        return { ok: false, illegal: ['<整包>'], reason: 'no-output', clean: {} };
    }
    var illegal = [], clean = {};
    // 记忆：不透明，任何对象都收（树不解释内容）
    if (d.memory && typeof d.memory === 'object') clean.memory = d.memory;
    // 生长：必须是节点编号数组
    if (d.growAt !== undefined) {
        if (Array.isArray(d.growAt)) clean.growAt = d.growAt;
        else illegal.push('生长');
    }
    // 选路：单个节点编号
    if (d.select !== undefined && d.select !== null) clean.select = d.select;
    return { ok: illegal.length === 0, illegal: illegal,
             reason: illegal.length ? ('格式非法: ' + illegal.join('/')) : '', clean: clean };
}
```

#### ★ 2.3.2 【代码原文事实】**`growTimes` 在真实路径上必被丢弃**

**实测**（Node 加载未改动文件）：

```

validateDecision(clean) = {"growAt":[1,2],"select":7,"memory":{"a":1}}
直接 validateDecision(raw) = {"growAt":[1,2],"growTimes":5,"select":7,"memory":{"a":1}}
```

后果（【代码原文事实】）：树侧的 `growTimes` 消费分支 `if (... tree._agentDecision && tree._agentDecision.growTimes)`（`vantage_tree.js:5982-5985`）**永远拿不到值**。

```js
                if (!n) { illegal.push('生长'); reason = '节点编号不存在'; break; }
                if (!VantageTreeInterface.Invariants.canGrowAt(n)) {
                    illegal.push('生长'); reason = '在真死/失效节点上生长'; break;
                }
            }
        }
        // 选路：必须是当前决策点的候选之一，且不是真死
        if (!illegal.length && clean.select !== undefined) {
            var kids = (tree.commitNode && tree.commitNode.children) || [];
            var hit = null;
            for (var j = 0; j < kids.length; j++) if (kids[j] && kids[j].id === clean.select) { hit = kids[j]; break; }
            if (!hit) { illegal.push('选路'); reason = '不在当前决策点的候选里'; }
            else {
                var chk = VantageTreeInterface.Invariants.checkSelect(hit, kids);
                if (!chk.ok) { illegal.push('选路'); reason = chk.reason; }
            }
        }
```
→ **`select` 的合法域被钉死为 `tree.commitNode.children`**。`vantage_pose_agent.js:45-46` 的注释独立印证了这点：
> 只考虑【根的直接子节点】—— checkBundleSemantics 要求 select 在
> commitNode.children 里，选深层节点会被判非法。

## 四、规则模式不变性是怎么保证的

### 4.1 三重保险

**① 默认即规则 + `use('rule')` 新建实例**

## 八、【解释】

> 本节全部是推断，不是代码事实。

1. 【解释，未验证】**"智能体"的注册与"Vantage"的分流是两个互不相干的系统**。`vantage_` 前缀只决定 `AIs` 里放哪个 Manager；`Agents.use(name)` 决定树里跑哪个智能体。代码里**没有任何一行**把 `aiId` 映射到 `Agents.use(...)`（`ai_vantage.js` 全文无 `Agents`；`local_patch.js` 的 Vantage 分支终点是 Manager）。所以"给每辆 Vantage 车配不同的智能体"目前没有现成接线。
2. 【解释，未验证】`vantage_tree.js` 里 `agentSeam` 的位置（任何提前 return 之前，`7336-7368`）说明设计上要求"智能体每 tick 至少被问一次"；这与 AGENTS.md 里"生长必须是无条件的一步"是同一类修正。
3. 【解释，未验证】§2.3.2 的 `growTimes` 丢失大概是**两个校验函数各自演化**造成的：`validateBundle` 是后来加的整包格式层，加它时没同步加 `growTimes` 白名单。
4. 【解释，未验证】`Modules` 是一套"设计好了但没接线"的槽位表；从 `MODULE_SLOTS` 的 6 个名字看，它的意图是"让智能体只接管 6 个机制中的某几个"。
5. 【解释，未验证】`isReady()` 返回 false 时不清 `_agentDecision`（`vantage_tree.js:3918`）与"每帧清残留"的设计意图冲突；对比规则分支 `3915` 明确写了"切回规则时清残留"。
6. 【解释，未验证】`PoseTargetAgent` 的存在说明接线是被真实验证过的（它注册、被 debug 页切换、并被 `checkBundleSemantics` 的 `commitNode.children` 约束反向影响了实现）。
7. 【解释，未验证】`local_patch.js` 的 V1（`:166`）与 V3（`:369`）是两套判定：前者建 `AIs.ais[id].isVantage`，后者同时接受 `cfg.isVantage` 与 `aiId` 前缀。写新东西时应以 V3 为准（因为 `AIs.addAIManager` 已被 V4 替换为 V3 所在函数）。
