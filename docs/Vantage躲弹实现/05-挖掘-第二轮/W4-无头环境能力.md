## 二、能力清单（★ 核心）

### 2.1 浏览器 / 页面层（`cdp.js`）

【原文】`cdp.js:2-5`
> `极简 CDP 驱动 —— 用 Node 24 自带的 WebSocket，零 npm 依赖。` / `只做我们需要的：启动浏览器 → 开标签页 → 注入脚本 → 导航 → evaluate。`

具备的能力：

1. **自动找浏览器**：按固定路径找 Chrome / Edge，找不到抛 `找不到 Chrome / Edge`（`cdp.js:11-21`）。
2. **无头启动**：`--headless=new` + 一组反节流/静音/隐藏滚动条/允许 file 访问/SwiftShader/窗口尺寸参数，随机端口 `9300 + Math.floor(Math.random()*400)`，临时 `--user-data-dir`（`cdp.js:142-161`）。**不用管道**：`stdio: ['ignore','ignore','ignore']`，并注明"某些沙箱环境下 spawn 用 `stdio:'pipe'` 会 EPERM"（`cdp.js:164-165`）。
3. **等 CDP HTTP 就绪**：轮询 `/json/version`，默认 25s（`cdp.js:25-35, 167`）。
4. **事件 API**：`on(method, cb, sessionId)`、`waitFor(method, timeout, sessionId)`（会先查最近 500 条事件缓存以躲竞态，`cdp.js:61-62, 91-103`）；`'*'` 监听所有事件（`cdp.js:65-66`）。
5. **新开/关闭标签页**：`Target.createTarget` + `Target.attachToTarget(flatten)`（`cdp.js:105-111`）。
6. **页面求值**：`Runtime.evaluate`，默认 `awaitPromise: true` / `returnByValue: true` / `userGesture: true`；页面异常包装成 `页面异常: ...` 抛出并带 `pageError`（`cdp.js:113-129`）。
7. **截图**：`Page.captureScreenshot`（由 `match.js:300-304` 调用落 PNG），本文件不直接封装。
8. **收尾**：关 WS、`proc.kill('SIGKILL')`、删临时 profile（`cdp.js:131-136`）。

### 2.2 虚拟时钟层（`clock.js`）

见 §三（细节单独展开）。一句话：**手动泵帧 + 时间/随机数可控**，让"跑多快都不影响游戏内时间"，并提供 `__vtRng` 记录/回放原语。

### 2.3 对局环境层（`match.js`）

`Match` 类把整条链路串起来：

- **跳过登录/大厅**：`bootstrapSrc` 直接 `Constants.setMode(CLIENT_LOCAL)` → `GameController.create(BootCampGameMode.create(), ...)` → `addPlayer` → `AIs.addAIManager` → `ph.state.start('Game', ...)`（`match.js:54-93`）。
- **真实游戏内核**：文件头声明跑的是真 `game_core`：真 Box2D、真子弹/武器/道具/迷宫、真 Laika AI（`match.js:6-10`）。
- **资产加载与泵帧**：`Page.addScriptToEvaluateOnNewDocument` 注入 `CLOCK_SRC + PAGE_HELPERS`（`match.js:157`），导航后先 `pumpUntilState('Menu')`，造局后再 `pumpUntilState('Game')` + 30 帧（`match.js:166-177`）；资产阶段必须"推进几帧 → 让出真实时间"交错（`match.js:18-21, 165-173`）。
- **控制/传送/读状态**：见 §四 API 表。
- **CLI 自检**：`node match.js [--frames 600] [--verbose] [--shot]`，打印 `openMs / simMs / framesPerSec / bootstrap / stateLog / before / after / virtualT / vtStats / pageErrors`（`match.js:316-358`）。

### 2.4 数据采集 / rollout

- **真实树输入分布采集**：`collect.js`（`--max/--every/--frames/--ai/--out/--no-dump`），钩子由 `game_core/js/vantage_tree.js:3888-3911` 实现（v163），只在 `window.__vtCollect` 存在时工作；采集字段 `{nodes, rootId, commitId, nodeCount, tank, threatCount, time}`（`vantage_tree.js:3899-3907`）。
- **阶段 1′ 采集**：`stage1_env.js`（随机策略验证）、`stage1_rollout.js`（JSONL 落盘）。
- **PPO rollout**：三个 `rollout_worker*.js`，页面内 MLP 前向 + 采样 + 奖励，多 page 并行，输出 JSONL（§五）。

### 2.5 训练驱动（不在 `_tools/headless` 内，但它决定了这些工具怎么被用）

- `tools/nn/stage1_ppo.py`：`WORKER = .../rollout_worker.js`（`stage1_ppo.py:27`），每轮 `export(net, WEIGHTS)` → `node worker --pages/--episodes/--steps/--seg/--temp/--weights/--out` → 读 JSONL 训练 PPO（`stage1_ppo.py:87-119`）。
- `tools/nn/stage1p_ppo.py`：`WORKER = .../rollout_worker_v3.js`（`stage1p_ppo.py:24`），并按指标自动切阶段 A/B/C/D/E（`stage1p_ppo.py:33-44`）；每轮把 `cfg`（W_FIELD/W_POSE/USE_DF/W_DENSE/...）通过 `--cfg` JSON 传给 worker（`stage1p_ppo.py:88-90, 167-173`）。
- 两个 trainer 都要求 worker stdout 里有一行 `RESULT {...}` 才算成功（`stage1p_ppo.py:94-100`；`rollout_worker_v3.js:508`）。

### 2.6 验证 / 诊断 / 探针（§一里已逐个列名）

能力上分四类：**接口探查**（`probe_*`）、**时间基准诊断**（`diag_dt*`、`_verify_dt.js`）、**端到端验收**（`test_*`、`verify_*`）、**性能/对照**（`parallel_bench.js`、`demo_shot.js`）。

接管 `Date` 构造函数的原因在代码注释里写得很明确：

【原文】`clock.js:42-48`

### 3.2 没接管哪些（★ 关系到可复现性）

【解释】`clock.js` 只覆盖了上表这些入口；以下都**没有**被接管，仍走真实语义：

### 3.3 帧推进语义

【原文】`clock.js:122-150` 的 `__vtStep(n)` 顺序：

1. 跑 `window.__vtBefore` 里所有回调（每帧推进**前**）；
2. `state.t += state.dt;`（`clock.js:132`，`dt = 1000/60`，`clock.js:14`）；
3. 取出并清空 `state.queue`，逐个执行 rAF 回调，**回调参数是 `state.t`**（`clock.js:133-140`）；
4. 跑 `window.__vtAfter` 里所有回调（每帧推进**后**）；
5. `state.steps++`（`clock.js:147`）。

`__vtBefore` / `__vtAfter` 是**开放数组**（`clock.js:117-119`），任何脚本都可以 `push`，用于"喂输入"和"采样观测"。

### 3.5 `__vtRng`：`Math.random` 的记录 / 回放

**为什么不做种子化**（原文引用主人的话）：

【原文】`clock.js:71-79`
> `为什么不做"种子化"：主人 2026-10-07 定案——` / `「种子化最好不要改变地图生成逻辑，否则那就更麻烦了。」`
> `地图生成里 Math.random() 散落各处（_createRandomMaze 直接调、对称迷宫还会把块生成跑两次），想改成可播种就得动生成器本体。`
> `这里换成"记录取值序列"：只替换 Math.random 的【来源】，不动调用方。`
> `· record：跑一遍真实对局，把每次返回值按顺序记下来` / `· play ：按同一条序列吐回去 → 地图、出生点、弹道散布逐位复现`
> `序列用尽时返回常数 0（绝不再引入新的真实随机），并计数以便发现发散。`

**实现**（`clock.js:81-93`）：

【原文】
> `const rng = { mode: 'off', seq: [], idx: 0, max: 2000000, overflow: 0 };`
> `Math.random = function () {`
> `  if (rng.mode === 'play') { if (rng.idx < rng.seq.length) return rng.seq[rng.idx++]; rng.overflow++; return 0; }`
> `  const v = RealRandom.call(Math);`
> `  if (rng.mode === 'record' && rng.seq.length < rng.max) rng.seq.push(v);`
> `  return v;`
> `};`

【解释】三种模式：`'off'`（默认，纯透传真实随机，不记录）、`'record'`（透传并记录，超过 `max` 后不再记录但仍返回真实随机值）、`'play'`（按序列吐值；用尽返回 0 且 `overflow++`）。注意 `RealRandom` 是**注入时刻**捕获的 `Math.random`（`clock.js:81`）。

**API 用法**（`clock.js:95-113`，全部为【原文】语义）:

| 方法 | 签名 | 行为 |
|---|---|---|
| `record(max)` | 清空 seq/idx/overflow；`max` 给了就改成 `max|0`；`mode='record'`；返回 `'recording'`。 |
| `stop()` | `mode='off'`；返回 `seq.length`（已录条数）。 |
| `play(seq, startAt)` | 复制传入数组；`idx = clamp(startAt, 0, len)`；`overflow=0`；`mode='play'`；返回序列长度。`startAt` 的注释原文：`用于"从某一帧开始回放"（跳过已消耗部分）`（`clock.js:103`）。 |
| `dump()` | **返回内部 `rng.seq` 本身**（不是拷贝）。 |
| `state()` | 返回 `{mode, len, idx, overflow}`。 |

**当前有没有人在用？** 没有。

【解释】全仓库 grep `__vtRng` 只命中两处：`clock.js:95` 的定义，和 `docs/.../智能体版-初步实现方案-2026-10-07.md:353` 的文字规划。`match.js`、`run.js`、三个 rollout worker、`collect.js`、`stage1_*` **都没有调用** `record/stop/play/dump`。所以这是一件"造好但没接线"的工具。

### 3.6 可复现性小结（哪些是确定的）

- **时间确定**：只要走 `__vtStep(n)`，游戏看到的 `performance.now` / `Date.now` / `new Date()` 都是"帧号 × 16.667ms"，与机器快慢无关（`clock.js:14, 37-62, 122-150`）。
- **随机数可选确定**：只有显式 `__vtRng.record()` / `play(seq)` 之后才确定；**默认 `'off'` 不记录也不回放**（`clock.js:82`）。
- **I/O 不确定**：网络/图片加载仍受真实时间影响；`match.js:18-21` 的原话是"虚拟时钟会把真实 I/O 一起冻住"，所以加载阶段要放真实时间。
- 【解释，未验证】游戏里是否还有其它未接管的随机/时间源（例如 Box2D 内部、AI 的 setTimeout），本次未逐处排查。

## 六、录制/回放能力现状与缺口（★ 主人最关心）

### 6.1 结论

**`_tools/headless/` 目前没有"录制整局对局 + 回放"的能力。**

### 6.3 缺口清单（要做到"导出 → 导入正常游戏回放"，按数据链顺序）

1. **逐帧输入记录（所有玩家）**：现在没有任何逐帧输入日志。
   - rollout 的 action 空间只有 9 个移动操作，`__vtAct` 只写 `fwd/back/left/right`，**不写 `fire`**（`rollout_worker_v3.js:120-127`）；
   - 记录粒度是"每个决策段一步"（`v3:248` 的 `traj.push({obs,a,logp,v,r,done})`），不是每帧；
   - 只记录 `tank_a`（`window.__vtTankId`，`v3:142`）。
2. **初始条件导出**：没有统一打包地图/主题/玩家列表/初始位姿/回合设置的函数。
   - `Match.maze()` 能**读**迷宫（`match.js:259-266`），但没有配套的"写出"；
   - worker 造局时写死 `MAZE_THEMES.STANDARD`、两个玩家 `tank_a/tank_b`（`v3:408-412`），`Match.open()` 造局用 `MAZE_THEMES.RANDOM`（`match.js:67`）；这些参数目前不在 JSONL 里；
   - episode 里只有 `ax0/ay0`（`v3:257`），没有目标 `B` 的显式字段（只能从 `obs[4..7]` 反推）。
3. **随机序列导出**：`__vtRng.dump()` 存在但没人调用（§6.2）；训练时也从未 `record()`。
4. **帧号/时间基准**：`traj[]` 里没有帧索引或 `__vt.t`；`clock.js` 的 `state.steps` 也没有随数据导出。回放时无法知道"这条 action 从第几帧开始、持续几帧"（虽然可以按 `--seg` 约定推断，但数据里没有写）。
5. **统一容器格式与版本号**：rollout JSONL 没有 schema 版本、没有 obs 维度标记、没有生成它的 worker 版本；JS 与 Python 各写一份布局（`v3:35-56` vs `stage1p_ppo.py:31, 57-58`）。
6. **回放播放器**：正常游戏里没有任何"读轨迹文件 → 逐帧喂输入"的代码；没有回放入口/UI。
   - 可行的注入点是现成的：`GameController.setInputState({getPlayerId, getForward, getBack, getLeft, getRight, getFire})`——`clock.js:167-174` 就是这么驱动 `tank_a` 的；
   - 但要注意游戏自己会丢弃无效时段的输入：
     【原文】`rollout_worker.js:248-249`
     > `★ 回合就绪检测：回合有时间限制，结束后 setInputState 会被整段丢弃` / `(setInputState 第一行 if (!this.model.getStarted() || !this.model.getMaze()) return;)`
     【原文】`stage1_env.js:45`
     > `★ 自适应等回合开始：倒计时期间 setInputState 会被游戏直接丢弃`
     → 回放必须先保证"回合已 started 且 maze 存在"，否则前几秒的输入不会被吃进去。
7. **入口复刻**：训练环境是用 `GameController.create(BootCampGameMode.create(), ...)` + `addPlayer(...)` 直接造对局（`match.js:63-89`），正常游戏走大厅/服务器；回放要么复刻同一入口，要么提供一个"导入式"的本地对局引导。
8. **确定性的边界**：只有注入了 `clock.js` 并显式使用 `__vtRng.play()` 的页面才有时间与随机数的确定性；正常游戏不注入 `clock.js`，`setTimeout` 等真实定时器也没被虚拟化（§3.2）。因此"同样输入跑出同样过程"目前只是**有条件**成立。
9. **落盘路径与体积**：逐帧录制需要新的文件格式/分片/上限（参考 `collect.js:42` 的 30MB 教训）。
10. **回放与"正常游戏"的边界**：主人要的是"导入正常游戏能播放"，但"正常游戏"是哪个入口（`index.html` 的大厅流程？还是像 `_make_debug_page.py` 那样从 `index.html` 复制一个注入页？）——**代码里没有答案**。
