## 零、绝对规则

### 🚫 绝不杀 node 进程

```powershell
Get-Process node | Stop-Process -Force      # ❌ 会杀掉 DSH 自己（DSH 跑在 node 上）
taskkill /F /IM node.exe                     # ❌ 同上
```

**后果**：工具调用刚被记录 → harness 自杀 → 结果无法落盘 → 日志显示
`The tool call was interrupted... its outcome is unknown`。

**而且会形成恶性循环**：崩溃留下孤儿子进程 → 去"清理孤儿" → 再杀 node → 再崩。

**安全做法**：只清 python / chrome。

```bash
taskkill //F //IM python.exe     # ✅ 安全
taskkill //F //IM chrome.exe     # ✅ 安全
```

## 一、★★★ 物理不动：`new Date()` 未被虚拟时钟接管

### 症状

动作序列完全正常（真的有 8 种不同操作），但坦克位移 ≈ 0，奖励恒在 ±0.01。

### 根因

```js
// GameController.update()（game_core/js/ce217c9b090cc73ce0e1faa13d20ca15.js）
update: function () {
    var time = new Date();                        // ← Date 构造函数，不是 Date.now()
    var deltaTime = (time - this.lastUpdate) / 1000.0;
    this.lastUpdate = time;
    ...
    this.roundController.update(deltaTime);       // → b2dworld.Step(dt, 10, 10)
}
```

旧版 `clock.js` 只接管了 `Date.now()` / `performance.now()`，
**没接管 `Date` 构造函数** → `new Date()` 走真实墙钟 → **物理 dt = 两帧之间的真实耗时**。

- 一次 evaluate 里紧循环 `__vtStep(1)`：帧间真实耗时≈0 → **dt≈0 → 坦克不动**
- 每帧 CDP 往返 / `setTimeout` 让出：真实时间流逝 → 会动，但**速度由真实时间决定，非确定**

### 修复（`_tools/headless/clock.js`）

```js
const RealDate = Date;
function VirtualDate() {
  if (!(this instanceof VirtualDate)) return new RealDate(state.epoch + state.t).toString();
  if (arguments.length === 0) return new RealDate(state.epoch + state.t);
  return Reflect.construct(RealDate, arguments);
}
VirtualDate.prototype = RealDate.prototype;
VirtualDate.now = () => state.epoch + state.t;
VirtualDate.parse = RealDate.parse;
VirtualDate.UTC = RealDate.UTC;
try { window.Date = VirtualDate; } catch (e) {}
```

### 效果（实测）

| 操作（20 帧） | 修复前 | 修复后 | 理论值 |
|---|---|---|---|
| 前进 | 1.55 | **5.31** | 5.317 |
| 左转 Δrot | -0.270 | **-1.665** | -1.667 |
| 吞吐 | 9.7 步/秒 | **315.6 步/秒** | — |

### ⚠️ 教训

**虚拟时钟必须同时接管：`performance.now` / `Date.now` / `Date` 构造函数。**
只接管前两个是不够的 —— 代码里可能用 `new Date()` 取当前时间。

### ❌ 错误修法（我做过的绕路）

「每帧 `await setTimeout` 让出事件循环」——它**碰巧**提供了真实时间所以坦克会动，
但：
- 物理 dt 由真实时间决定 → **非确定、跟机器快慢相关**
- 吞吐慢 10 倍（9.7 vs 315.6 步/秒）

**不要用这个。**

## 二、沙箱边界：`spawn` 用管道会 EPERM

### 症状

```
WORKER FAILED: Error: spawn EPERM
    at ChildProcess.spawn
```

### 根因

受限沙箱模式下**程序无法打开命名管道**，而 Node 的 `child_process.spawn` / `exec`
**默认用 `stdio: 'pipe'`** → EPERM。

### 修复（两处，均已改）

**`pyserver.js`**：Python 服务器的 stdout 改重定向到临时文件，轮询文件找端口：

```js
const logFile = path.join(os.tmpdir(), `ttsrv-${process.pid}-${Date.now()}.log`);
const fd = fs.openSync(logFile, 'w');
const proc = spawn(exe, ['-u', 'server.py'], { stdio: ['ignore', fd, fd], ... });
// 然后 setInterval 读 logFile 找 /http:\/\/127\.0\.0\.1:(\d+)/
```

**`cdp.js`**：启动 Chrome 时不用管道（Chrome 的 stderr 我们不需要）：

```js
const proc = spawn(exe, args, { stdio: ['ignore', 'ignore', 'ignore'], windowsHide: true });
```

## 三、回合有时间限制（60 秒）

`BootCampGameMode` 的回合持续 60 秒，结束后进入
`BETWEEN_ROUNDS(8s) + COUNTING_DOWN(2s)`，**期间 `setTankState` / `setInputState` 会被静默丢弃**。

### 修复

每次 episode 前等回合就绪，跨过间歇期：

```js
var ready = false;
for (var w8 = 0; w8 < 1800; w8++) {
  if (window.__vtReady && window.__vtReady()) { ready = true; break; }
  window.__vtStep(4);
}
if (!ready) { e--; continue; }
```

### ⚠️ `__vtReady` 曾经是坏的

旧代码查 `gc.model.getStarted/getMaze`，但 **`gc.model` 是 `GameModel`，没有这两个方法** →
两个 `typeof` 检查全部落空 → **永远返回 true** → 回合结束后的输入被静默丢弃。

正确写法：

```js
var gc = GameManager.getGameController();
if (!gc.getTank(window.__vtTankId)) return false;      // 坦克没了 = 回合结束
var rm = gc.roundController && gc.roundController.model;
if (rm && typeof rm.getStarted === 'function' && !rm.getStarted()) return false;
if (window.GameModel && GameModel._STATES && gc.model && gc.model.getState) {
  if (gc.model.getState() !== GameModel._STATES.IN_ROUND) return false;
}
```

## 四、输入在倒计时期间被丢弃

`GameController.setInputState` 第一行：

```js
if (!this.model.getStarted() || !this.model.getMaze()) return;
```

**开局必须自适应预热**（一边给前进信号一边看车动不动）：

```js
let started = false;
for (let i = 0; i < 30; i++) {
  const a = await m.myTank(); if (!a) break;
  await m.setControl({ fwd: true }); await m.pump(8, { yieldMs: 4 });
  const b = await m.myTank();
  if (b && Math.hypot(b.x - a.x, b.y - a.y) > 0.5) { started = true; break; }
}
```

## 五、指标陷阱：`moved`（净位移）不能用来判断"坦克有没有动"

随机初始化策略每步换方向，**净位移天然被抵消成几像素** —— 这不是没动，是绕回去了。

**正确的指标**（`RESULT` JSON 里都有）：

| 指标 | 含义 | 健康值 |
|---|---|---|
| `avgStepPx` | 平均每步位移 | 15~18 像素（满速上限 34.6）|
| `avgPath` | 平均每局路径长度 | 越长越好 |
| `avgNetMoved` | 净位移 | 随机策略下接近 0 是正常的 |
