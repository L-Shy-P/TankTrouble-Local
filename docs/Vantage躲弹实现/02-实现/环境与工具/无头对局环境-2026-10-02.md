# Vantage 无头对局环境（headless）— 2026-10-02

> 这是 Vantage 从「算法」走向「物理精算 + 神经网络决策」的地基。
> 没有它，所有训练数据都只能来自合成任务；有了它，数据才和真实对局同源。

---

## 一、headless 是什么

**headless = 「无头」= 不画画面。**

| | 有画面 | headless |
|---|---|---|
| 一局耗时 | 被 60fps 钉死 | 想跑多快跑多快 |
| 并行 | 基本没法 | 一台机器能开几十局 |
| 自动化 | 手点 | 一条命令跑 2000 局 |
| **物理是否同源** | — | ✅ **同一份 game_core，一行没改** |

**关键在最后一行**：这不是「另写一个简化版游戏」，而是**同一份代码，只是不画**。

实测：`_tools/headless/match.js --frames 6000` → **19 倍实时**（100.9 秒游戏时间 / 5.17 秒真实时间），开局 2.3 秒。

## 三、架构：三层

```
Node 侧（零 npm 依赖）
  cdp.js       用 Node 24 自带 WebSocket 驱动 Chrome DevTools Protocol
  serve.js     简易静态服务器（备胎）
  pyserver.js  拉起 game_core/server.py（正式用这个，见下）
  clock.js     虚拟时钟（注入到页面，在所有脚本之前）
  match.js     环境门面：open / pump / fast / snapshot / screenshot / close
```

### 虚拟时钟（`clock.js`）—— 整个方案的核心

接管页面的 `requestAnimationFrame` / `performance.now` / `Date.now`，
只有外部调 `window.__vtStep(n)` 才推进，**每帧固定 16.667ms**。

→ **确定性**：同样帧数，结果每次一致，与机器快慢无关
→ **可加速**：物理不依赖真实时间，想跑多快跑多快

**⚠️ 唯一的坑（踩了很久）：虚拟时钟会把真实 I/O 一起冻住。**

一口气 `__vtStep(120)` 只要 10ms，本该 2 秒的 120 帧 10ms 就跑完了 ——
图片还没下完，游戏永远卡在 `Boot` 的 `preload` 阶段。

**规则：资产加载阶段必须「推进几帧 → 让出真实时间」交错进行；
资源就位后（进了 `Game`）才可以全速空转。**
`Match.pump(n,{yieldMs:8})` vs `Match.fast(n)` 就是这个区别。

### 跳过登录/大厅

`Menu` 状态要 WebSocket 登录（`ws://127.0.0.1:8000`，Python 服务器没有 WS），
所以不进 `Menu`，直接照 `UILobbyState._createLocalGame` 造一局：

```js
Constants.setMode(Constants.MODE_CLIENT_LOCAL);
var ttGame = GameController.create(BootCampGameMode.create(), false,false,false,

ttGame.addPlayer('tank_a');

ttGame.addPlayer(aiId);
GameManager.setGameController(ttGame);
GameManager.getGame().state.start('Game', true, false, ttGame);
```

## 四、顺手修掉的真实 Bug：`server.py` 单线程

**这不是无头环境的问题，是正常玩也会中的问题。**

`HTTPServer` 默认 **单线程 + `request_queue_size = 5`**，
而 `index.html` 有 **62 个 `<script>`**，浏览器每 host 并发 6 连接 → 第 6 个起被 RST。

而 **`<script src>` 加载失败时浏览器不报错**，只继续往下执行，
于是 `eval(mod_pagespeed_xxx)` 拿到 `undefined` 抛 `ReferenceError`。

实测：单线程时 **361 个 mod 变量只有 169 个到位**、加载 **21 秒**；
改 `ThreadingHTTPServer` + `HTTP/1.1` 长连接 + `request_queue_size=256` 后
**361 个全到位、零错误、2.3 秒**。

改动（`game_core/server.py`）：
- `HTTPServer` → `ThreadingHTTPServer`，`request_queue_size = 256`、`daemon_threads`
- `GameHandler.protocol_version = 'HTTP/1.1'`（长连接）
- `do_OPTIONS` 补 `Content-Length: 0`（1.1 长连接必须，否则浏览器死等）
- 支持 `TT_NO_BROWSER=1` 环境变量（无头时不弹真浏览器）

## 五、怎么用

```bash
# 跑一局，打印前后局面 + 速度
node _tools/headless/match.js --frames 6000 --verbose

# 截一张图看画面
node _tools/headless/match.js --frames 600 --shot

# 原始探针（开发用）
node _tools/headless/run.js --server py --frames 60 --chunk 2 --yield 6 \
     --script scripts/s12_world.js
```

代码里：

```js
const { Match } = require('./_tools/headless/match');
const m = new Match();
await m.open();                        // 2~3 秒，自动起服务器+浏览器+开局
console.log(await m.snapshot());       // 紧凑局面（坦克/弹丸/武器/分数）
await m.fast(2400);                    // 全速跑 40 秒游戏时间
await m.close();
```

`snapshot()` 返回紧凑数字，**不含 Classy 的 `__class` 元数据**：

```js
{ stage, players, tanks:[{id,x,y,rot,fwd,back,left,right,fire,locked}],
  projectiles:[{id,owner,x,y,rot,type}],
  weapons:[{id,owner,type,bullets,pulled,fired,alive}],
  collectibles, scores:[{playerId,type,value}], virtualT }
```

## 六、还没做的

0. **确定性只到一半 ⚠️**
   帧内推进是确定的（同样帧数 → 同样虚拟时间 → 同样的物理步进），
   但**开局是随机的**：`Constants.MAZE_THEMES.RANDOM` 选地图、出生点也随机，
   两次跑同一帧数会得到不同局面（实测已验证）。
   → 训练想要**多样性**，这正是好事；
   → 想要**可复现**，在 `clock.js` 里把 `Math.random` 换成带种子的 PRNG 即可（约 5 行）。
1. **自己控制坦克** —— 现在 `tank_a` 是站桩傀儡。
   下一步接 `GameController.setInputState` / `setTankState` 走输入通道，
   让 `VantageAI` 或 NN 驱动 `tank_a`，同时读回真实物理反馈。
2. **多局并行** —— `cdp.js` 支持多 target，可以一个浏览器开 N 个页面；
   或开 N 个浏览器进程。预计单机 8~16 局并行。
3. **胜负判定自动化** —— 现在要自己读 `getScores()` / `getRoundState()`。
4. **把「实际发生了什么」喂回树** —— 这是 A/B 双智能体的记忆接口。
5. **预留输入类型**（房间总坦克数、地图配置、物理常量）—— 用户明确说「以后的事，先验证普通环境能跑」。

## 七、踩坑清单（省下次的时间）

| 现象 | 真因 | 修法 |
|---|---|---|
| 页面卡「加载中」，`Phaser` 未定义 | `server.py` 单线程 + backlog 5，脚本被 RST | `ThreadingHTTPServer` + HTTP/1.1 |
| 卡在 `Boot` 的 `preload` | 虚拟时钟冻住了图片 I/O | 交错泵帧（推进+让出真实时间）|
| 卡在 `Menu` | 等 WebSocket 登录 | 跳过 Menu/Lobby，直接造本地对局 |
| 服务器日志为空 | Python 输出缓冲 | `python -u server.py` |
| Phaser 图片对象找不到 | 存在 `file.data` 不是 `file.image` | 读对属性 |
| `getTanks()` 用不了 `.map` | Classy 集合不是数组 | `__vtArr()` 统一转换 |
| 快照巨大无比 | Classy 对象带 `__class` 元数据 | 只取字段，别整个序列化 |

## 八、已实测打通的接口（2026-10-06 补）

### 8.1 开我们的车

游戏里 `tank_a` 没有真人在键盘上，没人调 `setInputState`，所以输入是**每帧挂钩子喂**的
（`clock.js` 的 `__vtBefore`）：

```js
// 一次性装钩子
window.__vtInstallControl('tank_a');
// 每帧改这个对象
window.__vtCtrl = { fwd, back, left, right, fire };
```

游戏侧（`GameController.setInputState`）只调用 6 个 getter，传鸭子类型对象即可：

```js
gc.setInputState({ getPlayerId, getForward, getBack, getLeft, getRight, getFire });
```

**坑**：`setInputState` 第一行是
`if (!this.model.getStarted() || !this.model.getMaze()) return;`
—— **倒计时期间喂的输入被直接丢弃**。预热必须自适应（一边给前进信号一边看车动不动）。

实测：前进 9.87 格/40 帧、左转 Δ-1.71、右转 Δ+1.705、开火弹数 0→1。

### 8.2 传送坦克（免重开回合）

```js
gc.setTankState(TankState.withState(playerId, x, y,
    false, false, rotation, false, false, false, false), false);
```

- `TankState` 是**全局类**，不是 `tank.constructor`
- **坐标必须是合法格心**（每格 10 单位，合法值 5/15/25/35/...）。
  传到墙里会被 `verifyAndCorrectTankState` 推开
- 传到别的坦克头上会被挤开
- 这是训练阶段 1/2/3 的核心：**传送比重开回合快四个数量级**

### 8.3 回合行为（实测）

- 回合**会自动重开**（`roundId` 变化、坦克复活）
- 但**太慢**：一回合 ≈94 秒游戏时间，**回合间还有 25 秒空档**
- → 训练不要依赖被动重开，用传送代替

### 8.4 迷宫数据与热切换

```js
gc.getMaze()                                   // 迷宫对象
gm.getMaze(['tank_a','tank_b'], theme)         // ← 第一个参数是玩家ID【数组】
gc.setMaze(newMaze)                            // 热切换，不重置回合
```

实测：w=7,h=5 → w=8,h=5，`stage` 仍为 `Game`，坦克都在，**武器 alive 计时连续**
（证明没重置回合）。

**坑**：`MAZE_THEMES.RANDOM`(4) 是"随机选主题"的枚举，本身没有主题配置，
传进去会炸 `Cannot read properties of undefined (reading 'FLOOR_CONFIG')`。要传 `STANDARD`(0)。

**迷宫自带的能力（免费送，不用自己实现）：**

| 方法 | 用途 |
|---|---|
| `getRandomUnusedPosition()` | 阶段1「随机给可达位姿」 |
| `getDistancesFromPosition(pos)` / `getDistances()` | **距离场 → 天然的奖励信号** |
| `getShortestPathWithGraph(...)` / `getGradientPath()` | 最短路 / 梯度路径 |
| `getPathAwayFromWithThreats(...)` | 带威胁的逃离路径 |
| `isTankStateInsideMaze(pos)` | 合法性判定 |
| `getTankPositions()` / `getReachable()` / `getTankSpawnPosition()` | 位姿集合 |

### 8.5 无 AI 双人局（阶段 1/2/3 的底座）

至少 2 个玩家才开局（1 人局 `GameController` 会被清空）。所以：

```js
new Match().open({ humanIds: ['tank_a','tank_b'], aiCount: 0 })
// → 回合正常起，但没有对手
```

实测 `players: ["tank_a","tank_b"]`，两辆车在场。

**硬件实测**：i7-13620H，8 物理核 / 16 逻辑核，31.7 GB 内存（14.5 GB 可用）。
