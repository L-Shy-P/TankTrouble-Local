# 阶段 1′ 奖励重设计：距离场 + 位姿相似度（2026-10-07 第二版）

> 用户指令：
> 1. 「可以先**距离场 + 精确贴合**，因为只有距离场的话它**只知道走到同一格，不知道摆角度**」
> 2. 「你的**欧式我觉得完全没用**，因为没法处理**精密位置和角度的评分**」
> 3. 「在终点附近需要一套算法来计算**当前位姿和目标位姿的相似度**」
> 4. 结束条件：「检测到坦克与目标位姿**产生相交**后，坦克**单次连续静止半秒以上**，就算结束」

---

## 一、第一版为什么错（记录教训）

第一版奖励只有一个项：

```js
var rw = (prevD - d) / 10;      // prevD/d 都是【欧氏直线距离】
```

**三个致命缺陷：**

### ① 欧氏距离完全无视墙

目标在墙后面时：

```
欧氏距离：很近（直线 20 单位）   → 奖励说"继续往前冲" → 撞墙
距离场：  很远（要绕墙走 8 格）  → 奖励说"先绕过去"
```

**欧氏距离会把智能体引到墙角上蹭。** 这是全局路径问题，必须有距离场。

### ② 欧氏距离完全无视角度

任务是「贴合**位姿**」= 位置 + 朝向。但 `Δd` 里**一个角度项都没有**。

后果：坦克开到了目标点，但朝向完全不对，奖励照样给满分。
**智能体永远学不会「摆角度」这件事**——而这恰恰是用户指出来的核心。

### ③ 没有终点定义

`done` 永远是 0（除非坦克死掉）。到达目标也继续跑满 24 步，
后面的步数奖励全是 0，纯浪费。

## 二、新设计：两个势能项，各管一段

```
r = W_FIELD · Δ(距离场)          ← 全局：绕墙走到目标格
  + W_POSE  · Δ(位姿相似度)       ← 局部：终点精确贴合（位置+角度）
  + r_reach                        ← 终局：到达
```

**两项都是「势能差」，所以都不会扭曲最优策略**（Ng et al. 1999 的势能塑形理论）。
关键是**它们各自在正确的尺度上起作用**：

| 项 | 有效范围 | 处理什么 | 为什么不能互相替代 |
|---|---|---|---|
| `Δ(距离场)` | 全程 | **绕墙** | 它是图距离，墙后面就是远 |
| `Δ(位姿相似度)` | 终点附近 | **精密位置+角度** | 它是连续量，能分辨 0.1 单位 / 0.05 弧度 |

## 三、距离场项

### 3.1 取哪几个 API

```js
var mz = gc.getMaze();
// 两点间图距离（瓦片跳数，整数）
var md = mz.getDistanceBetweenPositions(
    { x: Math.floor(ax / TILE), y: Math.floor(ay / TILE) },   // 坦克所在格
    { x: Math.floor(tx / TILE), y: Math.floor(ty / TILE) });  // 目标所在格
// md === false 表示不可达
```

**`TILE = MAZE_TILE_SIZE.m`**（坦克坐标 → 瓦片坐标要除它）。

其他可用的（备选/调试）：
- `mz.getDistancesFromPosition(pos)` —— 从某点出发的整个距离场
- `mz.getGradientPath(...)` —— 梯度路径（沿距离场下降）
- `mz.getShortestPathWithGraph(...)` —— 最短路

### 3.2 奖励项

```js
W_FIELD = 0.5
r_field = W_FIELD * (mdPrev - md)      // 靠近一格 +0.5，远离一格 -0.5
```

**注意**：`md` 是整数，所以在**同一格内移动时 `Δ(md) = 0`**——
这正是「只知道走到同一格，不知道摆角度」的来源，必须靠第二项补上。

## 四、位姿相似度（终点附近的精密评分）

### 4.1 算法

```js
function wrapPi(a) { while (a > Math.PI) a -= 2*Math.PI; while (a < -Math.PI) a += 2*Math.PI; return a; }

// 位置误差（单位，1 格 = TILE = 10）
var dPos = Math.sqrt((tx-ax)*(tx-ax) + (ty-ay)*(ty-ay));

// 角度误差（弧度，绝对值差 —— 注意不是相对朝向）
var dAng = Math.abs(wrapPi(tRot - aRot));

// 高斯相似度：光滑、有界 [0,1]、可导
var SIM_P = 6.0;      // 位置尺度：6 单位 = 0.6 格
var SIM_A = 0.45;     // 角度尺度：0.45 rad ≈ 26°
var sim = Math.exp(-(dPos*dPos)/(2*SIM_P*SIM_P))
        * Math.exp(-(dAng*dAng)/(2*SIM_A*SIM_A));
```

**为什么用两个高斯的乘积**：
- 位置对了角度不对 → 仍然低分（乘积会压下来）
- 角度对了位置不对 → 仍然低分
- **只有两者都对才接近 1** → 正好表达「位姿贴合」

**尺度选择理由**：

| 参数 | 值 | 含义 |
|---|---|---|
| `SIM_P` | 6.0 单位 | 半格多一点。比坦克尺寸（3×4）大，留出靠近的余地 |
| `SIM_A` | 0.45 rad (26°) | 坦克炮管很窄，26° 已经算"朝向明显不对" |

**这两个数是本设计里唯一的可调参数**，需要实测标定。

### 4.2 用距离场门控（关键！）

`sim` 用的是欧氏距离,所以**墙后面会误判**（直线近但要走很远）。
必须用距离场把它锁在"终点附近"：

```js
var gate;
if (md <= 0)      gate = 1.00;    // 已经在目标格
else if (md === 1) gate = 0.50;   // 相邻格
else if (md === 2) gate = 0.20;
else               gate = 0.05;   // 还远，位姿项几乎不参与

var simG = sim * gate;
```

**这样欧氏距离只在它能正确工作的范围内（同一格/相邻格）生效。**

### 4.3 奖励项

```js
W_POSE = 2.0
r_pose = W_POSE * (simG - simGPrev)     // 相似度提升才给分
```

## 五、结束条件（用户设计）

> 「检测到在坦克与目标位姿**产生相交**后，坦克**单次连续静止半秒以上**，就算结束」

**这个设计比"距离阈值"好**——它不依赖人为容差，用的是**几何事实 + 行为事实**：

| | 容差法 | 相交+静止法 |
|---|---|---|
| 判定依据 | 人为距离阈值 | **几何相交 + 行为静止** |
| 「到了还乱动」 | 判成功 | ❌ 不判（还在动）|
| 「蹭到边缘停下」 | 判成功 | ✅ 判成功（确实停住）|
| 可调参数 | 要调 tol | **零参数**（半秒是行为定义）|

### 5.1 相交判定

目标点在坦克的**定向包围盒**内（坦克 3×4）：

```js
// 把目标点转到坦克局部坐标系
var dx = tx - ax, dy = ty - ay;
var ca = Math.cos(-aRot), sa = Math.sin(-aRot);
var lx = dx*ca - dy*sa;
var ly = dx*sa + dy*ca;
var overlap = (Math.abs(lx) <= TANK_W/2 + MARGIN) && (Math.abs(ly) <= TANK_H/2 + MARGIN);
```

⚠️ **待核实**：游戏里坦克尺寸常量的确切名字/单位、以及 `rot` 与坐标系朝向的对应关系
（实测 `rot=0` 朝 -y，`rot=π/2` 朝 +x）。

### 5.2 静止判定

```js
STILL_EPS  = 0.3;    // 单位：一段位移小于 0.3 单位算"没动"
STILL_NEED = 30;     // 帧：0.5 秒 @60fps

if (movedThisStep < STILL_EPS) stillFrames += seg; else stillFrames = 0;   // 单次连续，断了就重数
```

### 5.3 触发

```js
if (overlap && stillFrames >= STILL_NEED) {
    r += 8.0;        // 到达奖励
    done = 1;        // 立即终止，不空跑剩下的步
}
```

### 5.4 ⚠️ 需要用户拍板的一个点

「相交」如果**只判位置**，那么「位置重叠但朝向完全相反」也会算成功。

**两种选择：**
- **(a) 只判位置相交**（严格按用户原话）→ 角度只靠 `r_pose` 引导，不参与成功判定
- **(b) 相交 + 角度在容差内** → 成功判定也包含朝向

**建议 (b)**，因为任务是「贴合**位姿**」（位姿含朝向）。但这是用户定的，需确认。

## 六、课程（脚手架逐步拆除）

用户在上一轮提出的三段式，和本设计天然吻合：

| 阶段 | 训练进度 | 距离场权重 | 位姿项 | 意图 |
|---|---|---|---|---|
| **A 引导期** | 0~30% | `W_FIELD = 0.5` | 关（`W_POSE = 0`）| **只用距离场**：先学会绕墙走到目标格 |
| **B 过渡期** | 30~65% | `W_FIELD = 0.2` | `W_POSE = 1.0` | 引入角度和精确位置 |
| **C 严格期** | 65~100% | `W_FIELD = 0.0` | `W_POSE = 2.0` | **完全拆掉距离场**，只靠位姿相似度 |

**为什么 A 期要关掉位姿项**：早期坦克离目标很远，`sim ≈ 0` 且几乎不变化，
`Δ(sim)` 是纯噪声，会干扰距离场的学习信号。

**为什么 C 期要完全拆掉距离场**：
- 距离场是「拐杖」——它用了迷宫的全局信息，智能体本身看不到
- 留着它 = 喂了一部分"规则答案"
- 完全拆掉后，智能体必须只靠**局部观测 + 位姿相似度**完成任务
- 这与用户架构哲学一致：**不喂规则的答案，只喂模拟的事实**

## 七、完整奖励公式

```js
// 每步
var r = 0;

// 1) 距离场（按阶段给权重）
r += W_FIELD * (mdPrev - md);

// 2) 位姿相似度（门控后）
var simG = sim(ax, ay, aRot, tx, ty, tRot) * gate(md);
r += W_POSE * (simG - simGPrev);

// 3) 时间成本（对应任务要求"尽可能短时间"）
r -= 0.005;

// 4) 终局
if (overlap && stillFrames >= 30) {
    r += 8.0;
    done = 1;
}
if (tank died) { r -= 5.0; done = 1; }
```

## 十、★★ 非线性：完美必须值钱（2026-10-07 第三版修正）

> 用户定案：「**距离场和位姿都应该是非线性奖励的，1 次完美得到分能顶很多次大误差**」

### 10.1 第一版为什么是"平的"

| 项 | 第一版形状 | 问题 |
|---|---|---|
| 距离场 | `Δ(md)` **线性** | 每靠近一格都是 0.5，**走到最后一格和中间任何一格一样值钱** |
| 位姿 | 高斯 `exp(-d²/2σ²)` | **在 d=0 处导数 = 0** → 越接近完美，边际收益越小 |

**高斯在 0 附近是平的**，这是最反直觉的地方：

```
d 从 σ → 0     sim 收益 0.393
d 从 3σ → 2σ   sim 收益 0.124
                 比值 = 3.2x        ← 完美只比"粗糙"值 3 倍
```

**结果**：智能体在「大致靠近」的区域就能拿到接近完美的收益，
**没有动力去追求最后的精确度** —— 而"精密位置 + 角度"恰恰是任务的核心。

### 10.2 修正一：距离场用**亚线性幂函数**

```js
Phi_maze(md) = -Math.pow(md, P_FIELD)      // P_FIELD = 0.7（< 1 才是亚线性）
r_field = W_FIELD * (Phi_maze(mdPrev) - Phi_maze(md));
```

`md^0.7` 是**凹函数**，所以靠近 0 时边际收益**递增**：

| 转移 | 收益 | 说明 |
|---|---|---|
| 10 → 9 | +0.35 | 远处，一格便宜 |
| 3 → 2 | +0.52 | |
| 2 → 1 | +0.62 | |
| **1 → 0** | **+1.00** | **最后一格最值钱** |

**完美/粗糙 = 1.00 / 0.35 ≈ 2.9x**

`P_FIELD` 越小越极端：`P_FIELD=0.5` 时 1→0 值 1.0、10→9 值 0.22（**4.5x**）。

### 10.3 修正二：位姿改用**拉普拉斯核**（指数，非高斯）

```js
// 旧：高斯，0 附近平
sim = Math.exp(-(dPos*dPos)/(2*SP*SP)) * Math.exp(-(dAng*dAng)/(2*SA*SA));

// 新：拉普拉斯，0 附近梯度非零
sim = Math.exp(-dPos/SP - dAng/SA);
```

| 转移（dPos 变化，角度=0）| 高斯收益 | **拉普拉斯收益** |
|---|---|---|
| 3σ → 2σ | 0.124 | 0.085 |
| σ → 0 | 0.393 | **0.632** |
| **比值** | **3.2x** | **7.4x** |

**拉普拉斯把"完美"的相对价值提高了 2.3 倍。**

**可选加码**：`sim = Math.pow(sim, K)`（K=2~3）进一步锐化，
但 K 太大梯度会消失（远处全是 0），**建议 K=1 起步，用实测决定**。

### 10.4 修正三：终局奖励**必须跨过位姿门槛**

光是 `overlap && still` 还不够 —— 位置重叠但朝向完全不对也算成功，那"完美"就白设计了。

```js
if (overlap && stillFrames >= 30) {
    // 按相似度给**分级**终局奖励，而不是一刀切
    var bonus = 2.0 + 8.0 * sim;          // sim=0.3 → 4.4；sim=1.0 → 10.0
    if (sim < SIM_MIN) { bonus = 1.0; }   // 位姿太差，只给一点点
    r += bonus;
    done = 1;
}
```

**这样"完美贴合"比"勉强相交"多拿 2~5 倍**，直接体现用户要求。

### 10.5 完整非线性公式

```js
// ---- 每步 ----
var r = 0;

// 1) 距离场：亚线性幂，最后一格最值钱
r += W_FIELD * (Math.pow(mdPrev, P_FIELD) - Math.pow(md, P_FIELD));   // P_FIELD=0.7

// 2) 位姿：拉普拉斯核 + 距离场门控
var sim  = Math.exp(-dPos/SP - dAng/SA);          // SP=6.0, SA=0.45
var simG = sim * gate(md);
r += W_POSE * (simG - simGPrev);

// 3) 时间成本
r -= 0.005;

// ---- 终局 ----
if (overlap && stillFrames >= 30) {
    r += (sim < SIM_MIN) ? 1.0 : (2.0 + 8.0 * sim);   // 分级：完美 ≈ 10，勉强 ≈ 1
    done = 1;
}
if (tankDied) { r -= 5.0; done = 1; }
```

### 10.6 新增可调参数

| 参数 | 建议初值 | 作用 | 调大的效果 |
|---|---|---|---|
| `P_FIELD` | **0.7** | 距离场的非线性度 | 越小，最后一格越值钱（0.5 → 4.5x）|
| `SP` | 6.0 单位 | 位置尺度 | 越大越宽容 |
| `SA` | 0.45 rad | 角度尺度 | 同上 |
| `SIM_MIN` | 0.35 | 终局最低位姿门槛 | 越高越严格 |
| `K`（可选）| 1 | `sim^K` 锐化 | 越大越"完美主义"（太大会梯度消失）|

### 10.7 验证指标（必须能看出"完美值钱"）

训练日志里要能直接读到：

| 指标 | 含义 | 期望 |
|---|---|---|
| `avgFinalSim` | 终局位姿相似度 | **持续上升** |
| `reachRate` | 到达率（相交+静止触发）| 上升 |
| `perfectRate` | `sim >= 0.9` 的比例 | **后段应显著上升**（证明"完美"这条路走得通）|
| `avgBonus` | 终局奖励均值 | 应随 perfectRate 一起上升 |

**如果 `reachRate` 升但 `perfectRate` 不升** → 说明非线性不够，要调小 `P_FIELD` / `SA` / 加 `K`。

## 十一、★★★ 时间必须从奖励里拿出去（2026-10-07 第四版修正）

> 用户定案：
> 1. 「**注意时间，不能作为额外的奖励项**。不然它开局朝着靠近的方向走几格停下，
>    用时少，奖励高。」
> 2. 「**时间应该是一种参数**」
> 3. 「或者，**刚开始就不加时间，防止它刷分**，等到它能**精确到目标位置后，再加时间**」

### 11.1 第三版错在哪

第三版里我写了：

```js
r -= 0.005;      // ❌ 每步时间成本
```

**这制造了一条刷分路径：**

```
走 3 格靠近目标  →  距离场给 +1.05
然后原地不动     →  剩下步数 Δ(md)=0、Δ(sim)=0，只付时间成本
净收益 = +1.05 − 0.005×19 = +0.955

  对比：继续往前冲 → 可能撞墙/走错方向 → 距离场给负分 → 反而更低
```

**结论：「少做事」成了局部最优。** 这和任务要求（尽可能短时间贴合）方向完全相反。

**根本问题**：per-step 惩罚是**线性累积**的，而"探索的收益"是**有风险的**。
当时间成本 > 探索的期望收益时，agent 就会学会"走几步就停"。

### 11.2 正确的做法：时间作为 **参数**，不是奖励项

**① 时间作为终止参数**（超时 = 失败，不是每步扣分）

```js
// 不是 r -= k，而是硬性上限
if (stepIndex >= MAX_STEPS) {
    r += 0;                       // 不加不减
    done = 1;
    timedOut = true;              // 只记录，不进奖励
}
```

**② 时间作为课程参数**（随训练收紧）

| 阶段 | `MAX_STEPS` | 意图 |
|---|---|---|
| A 引导 | 60 | **完全不管时间** —— 先学会"走过去 + 摆角度" |
| B 过渡 | 40 | 略收紧 |
| C 严格 | 30 | |
| **D 加速**（能精确到达后）| 20 → 15 | **这时才引入时间压力** |

**③ 时间作为评估指标**（进日志，不进奖励）

```
avgStepsToReach     到达时平均用了多少步
avgTimeToReach      换算成秒
reachRateAtMaxSteps 在时限内到达的比例
```

### 11.3 加时间的唯一正确时机与方式

**时机**：用户说的 ——「等到它能**精确到目标位置后**，再加时间」。
触发条件是 **`perfectRate`（sim≥0.9 的比例）稳定在高位**，不是训练进度。

**方式**：**只在成功时按速度分级给奖励**（终局奖励，不是每步惩罚）

```js
if (overlap && stillFrames >= 30) {
    var speed = 1.0 - Math.min(1.0, stepIndex / MAX_STEPS);
    // speed: 用了一半步数 → 0.5；极限快 → 接近 1
    r += (2.0 + 8.0 * sim) * (1.0 + TIME_BONUS * speed);
    done = 1;
}
```

- `TIME_BONUS = 0` 时完全无时间压力（阶段 A~C）
- `TIME_BONUS = 0.5` 时，快速到达比慢到达多拿 50%

**为什么这样不刷分**：
- **没到达 = 一分钱都拿不到** —— 停下不动 = 0 奖励，不是"少扣分"
- 奖励只跟**成功时的速度**挂钩，不跟"用了多少步"线性挂钩
- 想拿时间分，唯一的路是**又快又准地到达**

### 11.4 修正后的完整公式

```js
// ---- 每步（无任何时间项）----
var r = 0;
r += W_FIELD * (Math.pow(mdPrev, P_FIELD) - Math.pow(md, P_FIELD));  // 距离场，亚线性
var sim  = Math.exp(-dPos/SP - dAng/SA);                             // 拉普拉斯核
var simG = sim * gate(md);
r += W_POSE * (simG - simGPrev);                                     // 位姿

// ---- 终局 ----
if (overlap && stillFrames >= 30) {
    var speed = 1.0 - Math.min(1.0, stepIndex / MAX_STEPS);
    r += (sim < SIM_MIN ? 1.0 : (2.0 + 8.0 * sim)) * (1.0 + TIME_BONUS * speed);
    done = 1;
} else if (stepIndex >= MAX_STEPS) {
    done = 1;              // 超时，不加不减，只记录
}
if (tankDied) { r -= 5.0; done = 1; }
```

**注意每一步里已经没有任何时间项。**

### 11.5 新增参数

| 参数 | 阶段 A~C | 阶段 D | 作用 |
|---|---|---|---|
| `MAX_STEPS` | 60 → 40 → 30 | 20 → 15 | 时限（终止参数，不是奖励）|
| `TIME_BONUS` | **0** | 0.3 → 0.5 | 到达时的时间加成（只在成功时）|

### 11.6 验证（防止又刷分）

训练日志必须能看出「没有刷分」：

| 指标 | 健康表现 | 刷分的表现 |
|---|---|---|
| `avgStepsToReach` | 随训练**下降** | — |
| `reachRate` | 上升 | — |
| `avgPath / avgNetMoved` | 路径 ≈ 净位移（走得直）| **路径长但净位移小**（来回蹭）|
| `timeoutRate` | 下降 | 上升（说明在磨）|

**如果看到 `timeoutRate` 升 + `avgPath` 大 + `avgNetMoved` 小 → 在刷分或原地打转。**
