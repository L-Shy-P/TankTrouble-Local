# 单世界融合沙箱实施方案 · 2026-08-16

## 2026-08-23 状态更新

- 本方案是死亡检测的最终正确形态，**重新成为主线**。
- 当前代码 v19 为绕开幽灵弹把子弹移出融合世界，死亡检测退回静态重叠 checkDeath，
  违反“游戏唯一权威”。下一阶段将按本方案恢复共享子弹体 + 传感器 + CCD。
- 幽灵弹的历史根因（只摆未来位置不摆未来速度、槽位半径混用）是实现错误；
  恢复时必须在摆放子弹时同时设置速度，并使用每颗弹自己的真实半径。

> 目标：在不把子弹计算提出 Box2D、不放弃 Box2D 死亡检测的前提下，用一个常驻私有世界同时模拟 9 种操作 + 一套共享子弹，以内存换 CPU。
> 旧实现保留，新旧路径通过开关对照。

## 一、红线（不违反）

1. 子弹继续放在 Box2D 世界里飞行、撞墙、角弹，CCD（bullet=true）保留。
2. 死亡判定继续用 Box2D 原生接触；极快子弹不靠手写几何判定。
3. 旧 `simulateTankClone` 和旧 `checkDeath` 全部保留，通过开关回退。
4. 真实游戏世界绝不 Step，只读真实位姿/速度。

## 二、总体结构

新建一个与旧 `_cloneCache` 并存的 `_fusedCache`：

```
_fusedCache = {
  mazeRef,
  world,                 // 常驻私有 Box2D 世界
  candidates: [9],       // 9 个候选坦克体
  candidateFixtures,     // 每个候选的 normal/sensor 夹具
  bulletSlots,           // 子弹体池，复用
  round,                 // 池轮次
  tempVectors,           // 预分配向量池
}
```

世界内物体：

1. 一套墙（B2DUtils.createMaze 原样）；
2. 9 个候选坦克体，每个车体+炮塔正常夹具；
3. 每个候选坦克体上另挂一套传感器夹具（车体矩形 + 炮塔矩形，isSensor=true）；
4. 一套共享子弹体（最多 20 个，池化）；
5. 第一版不放入对手坦克体（纯躲弹边界；记录为与旧路径的已知差异，后续可加碰撞组）。

## 三、碰撞过滤设计

| 夹具 | category | mask | groupIndex | 作用 |
|---|---|---|---|---|
| 候选正常夹具 | TANK | MAZE | 0 | 候选坦克只和墙碰撞，候选之间、候选与子弹都不碰撞 |
| 候选传感器夹具 | TANK | PROJECTILE | 0 | 与子弹产生 isSensor 接触，不反弹、不阻挡 |
| 子弹夹具 | PROJECTILE | TANK|MAZE|SHIELD|ZONE | 0 | 与传感器接触；与墙正常反弹，CCD 角弹 |
| 墙夹具 | MAZE | TANK | 0 | 正常阻挡候选坦克 |

实现时在 `B2DUtils.createTankBody` 创建候选体后，遍历夹具修改 filter：
- 正常夹具 mask 改为仅 MAZE；
- 追加两个传感器夹具（形状与游戏车体/炮塔完全一致，isSensor=true）。

## 四、核心算法：九操作同世界推进

输入：`state, operations[9], durationFrames, opt`

1. 取/建 `_fusedCache`；
2. 9 个候选体摆到同一 `startPose`，速度角速度清零；
3. 子弹池按当前 `projectiles` acquire/park，并按 `opt.tGlobal` 用折线插值摆位置（与旧逻辑一致），速度取真实速度；
4. 逐帧：
   - 对每个候选操作，借用真实 Tank 实例算速度/转速（快照/恢复）；
   - 写入 9 个候选体速度、角速度；
   - `world.Step(FRAME_DT, 10, 10)` 一次；
   - 读取 9 个候选位姿，写入 samples；
   - 遍历接触链表，只处理“候选传感器 × 子弹”接触，标记对应操作的死亡帧；
5. 返回 9 组 `{samples, hitWall, dead, deathFrame}`。

复杂度：每轮 9 操作 75 帧只做 **75 次 Step**，死亡检测不另开世界。

## 五、评分层适配：`scorePaths` 批量评分

新增 `VantageScoring.scorePaths(adapter, parentSimState, operations, frames, threats, cfg)`：

1. 调用 `adapter.simulateTankBatch(...)` 拿到 9 组轨迹和死亡帧；
2. 子弹位置每帧只计算一次，9 操作共享；
3. 存活帧用“跳过 checkDeath 的遮蔽角/车道压分”计算；
4. 死亡帧由批量世界结果判定，不再逐操作调 `adapter.checkDeath`；
5. 批量接口不存在或开关关闭时，回退为逐个调用旧 `scorePath`。

## 六、树层接入

- `rolloutNine`：开关开启时改用 `scorePaths` 一次拿 9 结果；
- 预览切片：`stepExpandSlice` 每 tick 只取部分操作，调 `scorePaths` 的批量模拟；
- 提交切片：`stepCommitSlice` 同样改用批量模拟。

## 七、对照开关

在 `VantageSandbox` 暴露：

```
VantageSandbox.fused = { enabled: true }   // 可 console 改 false 回旧路径
VantageSandbox.useFused() → bool
```

评分/树层每次调用前判断。旧函数一个不删。

## 八、验证计划

1. `node --check` 全部相关文件；
2. 离线构造 1 弹 / 5 弹 / 贴脸场景，分别跑旧路径与融合路径：
   - 9 操作 samples 误差：无对手坦克碰撞场景应逐点一致（允许浮点尾差）；
   - 死亡帧一致；
   - 分数/argmax 一致；
3. 真实对局人工验证：同场景切换开关，AI 行为一致；
4. 性能对比：记录旧/新 9×75 耗时，霰弹枪场景帧时间。

## 九、已知差异与风险

1. 第一版候选坦克之间、候选与对手坦克之间不碰撞（纯躲弹边界，旧路径有坦克互撞）。若黄金测试发现依赖坦克碰撞，下一版用碰撞组补回。
2. Box2D 单世界多体可能有 solver 迭代分配差异；使用与旧路径相同 `Step(0.02, 10, 10)`。
3. 传感器接触对极快子弹依赖 Box2D CCD；保持 bullet=true，不降级。
4. 性能提升预估值：内层 rollout 6~12 倍；整体 FPS 1.5~3 倍，需实测修正。
