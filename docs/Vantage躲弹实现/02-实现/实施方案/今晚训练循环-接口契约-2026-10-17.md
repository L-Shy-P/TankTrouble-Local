## 一、传输（谁在什么时刻把什么交给谁）

```
浏览器/Node 采集器（P0-1/P0-2）
   │  每局结束 ⟹ 一局 = 一行 JSON（UTF-8，⛔ 不要 pretty-print，⛔ 不要换行）
   ▼  stdin
train_ppo_online.py（--mode stdin）
   │  stdout = 【每行一个事件 JSON】（协议，⛔ 人类日志一律走 stderr）
   │  事件：episode_accepted / episode_rejected / cycle_start / cycle_done / trainer_exit / error
   ▼
 每满 min_episodes 局 ⟹ 一个 cycle：PPO 更新 → 存 D:/vt_run/ckpt/{last.pt,model_latest.pt}
                              → 追写 metrics/metrics.jsonl → 抽样 dump → 清空 RAM
```

- 采集器也可以**直接 `import`**（同进程）：
  ```python
  import importlib.util
  spec = importlib.util.spec_from_file_location("vt_buffer", r"<repo>/_tools/training/vt_buffer.py")
  vb = importlib.util.module_from_spec(spec); spec.loader.exec_module(vb)
  vb.append_episode(ep_dict)        # ← ⭐ 一局结束调一次；也可先 vb.decode_episode(ep_dict) 自检
  ```
- **帧的编码（`obs` 段）二选一，⛔ 不许混用**：
  - 小 `N`/调试：嵌套 `list`
  - ⭐ 采集器快路：`{"b64": "<原始字节 base64>", "dtype": "float16"|"float32", "shape": [rows, cols]}`（**C 序、小端、连续**）
    —— `N=685` 时 `node` 段 `fp16` = `13.7 KB/帧`，`list` 方式 ≈ `5×` 且要 `json` 解析数万字符。
- **绝不许**：① 发档位填充的 `node` 行（必须**只发真实 `N` 行**）② 发 `act.nodeId ≥ N` ③ 发非有限的 `lp/v`。

## 二、buffer 格式（**逐字契约**）

### 2.1 局级（一行 JSON）

| 字段 | 类型 | 必填 | 含义 / 口径 |
|---|---|---|---|
| `ep` | `int` | ✅ | 局号（全局递增；采集器自己保证唯一） |
| `scene` | `dict` | ✅ | 本局场景（**放局级**；放帧级也接受但只读第一帧，两者都给则各校验一次） |
| `scene.players` | `int` | ✅ | 场上坦克数 `2~8`（**我方 `1` 个 `Vantage` + 其余 `Laika`**） |
| `scene.mapW` / `scene.mapH` | `int` | ✅ | **实际**迷宫宽高（用来核对"人数 ⟹ 尺寸"联动；照方案 §二） |
| `scene.storm` | `bool` | ✅ | 毒雾开/关 |
| `scene.crates` | `list[int]` | ✅ | 本局可用道具类型集（关 = `[]`） |
| `frames` | `list` | ✅ | 该局**所有帧**（时间升序，`t` 严格递增；⛔ 不许跳帧/丢帧） |
| `win` | `0/1/null` | 可选 | 局结果（`null` ⟹ `unknown`，评测器**不算负**） |

### 2.2 帧级（`frames[i]`）

| 字段 | 类型/形状 | 必填 | 含义 / 口径 |
|---|---|---|---|
| `t` | `int` | ✅ | 局内帧号（严格递增） |
| `N` | `int` | ✅ | **真实节点数**（动作候选数就是它；`1 ≤ N ≤ 1000`） |
| `obs.node` | `(N, 10)` | ✅ | 节点段；行数**必须 = N** |
| `obs.opp` | `(1, 15)` | ✅ | 对手段（固定 1 行，缺则补零） |
| `obs.bullet` | `(64, 6)` | ✅ | 子弹段（**固定 64 行**，不足**补零**——服务端 `mk()` 就是这个容量） |
| `obs.item` | `(8, 6)` | ✅ | 道具段（固定 8 行，不足补零） |
| `obs.global` | `(1, 38)` | ✅ | 全局段 |
| `obs.mem` | `(4, 256)` | ⚠️ **可省** | **缺 ⟹ 训练侧补零**（与推理侧一致，见 §三·3）；省了会在 `stats.mem_absent_frames` 计数 |
| `act.nodeId` | `int` | ✅ | 执行的动作：**节点 token 下标 ∈ `[0, N)`**；越界 ⟹ 训练器**拒收整局**（`P0-0` 体检闸门） |
| `act.fire` | `0/1` | ✅ | 是否开火（`picks[1..]` = 射击帧） |
| `act.picks` | `list` | ✅ | 页面执行的动作包；`picks[0].nodeId` 必须 = `act.nodeId` |
| `lp` | `float` | ✅ | 采集时该动作的 `log` 概率（服务端 `out[3]`，**只作 `ratio` 基准**） |
| `v` | `float` | ✅ | 采集时价值（服务端 **`out[0]`** 的池化标量） |
| `v_next` | `float` | ⚠️ 可选 | **只在"截断局"需要**：局末帧仍 `done=False` 时，填"下一帧的 `v`"（见 §三·4） |
| `r.total` / `r.result` / `r.survive` / `r.legal` | `float` | ✅ | 奖励分项（**四个都要给**；`result`：胜 `+1`/负 `-1`/双死 `-0.25`/超时 `0`；`survive`：每帧存活；`legal`：非法罚） |
| `done` | `bool` | ✅ | 局末帧 `true` |

**dtype 建议**：`node` → `fp16`（省一半 RAM，网络入口本来就是 `float32` 转换）；其余段 `float32`。
**单位**：全部用 `VantageObserve.encode` 的**归一化后**口径（照 `阶段2-3观测字段表-定稿`），采集器**不要**在这里再改尺度。

### 2.3 训练器对 buffer 的**硬闸门**（不达标 ⟹ 显式报错/拒收，⛔ 绝不静默）

| 闸门 | 判据 | 理由 |
|---|---|---|
| `nodeId < N` | 每帧 | `P0-0`：推理侧曾用"档位大小"当候选集 ⟹ 采到填充位（`今晚持续训练方案:105-147`）|
| `N == node 行数` | 每帧 | 同上（发档位填充 = 另一种形态的脏数据）|
| `lp/v` 有限 | 每帧 | 品质闸门 `lp_finite = 100%`（`G4 §2.6`）|
| `picks[0].nodeId == act.nodeId` | 每帧 | 契约 `C2`；不一致说明"选的动作"和"执行的动作"不是一个 |
| `t` 严格递增 | 每局 | 帧序错 ⟹ `GAE` 时序错 |
| 段容量 = `1/64/8/1/4` | 每帧 | 服务端 `mk()` 固定容量；训练侧必须同形，否则 `ratio` 失真 |

## 三、喂给网络时的**口径**（训练 ⟷ 推理必须逐条一致）

1. ⭐ **动作空间 = 只在前 `N` 个 `node` token 上**：`out[3][:, :nmax]` 之后再 `log_softmax` 一次（**重归一化**）。
   `78` 个上下文 token（`opp 1 / bullet 64 / item 8 / global 1 / mem 4`）**不参与动作**。
   与 `policy_server_graph.py:99-100` 的做法逐字一致（`softmax` 平移不变 ⟹ 等价于只在前 `N` 个原始分数上做 softmax）。
   **自证**：烟测里"前 `N` 个概率和 − 1"的最大偏差 = `2.98e-07`。
2. ⭐ **`mask` 语义（`True` = 填充/无效）**：训练侧**只把 `[N, nmax)` 的 `node` 行置 `True`**，其余 5 段全 `False`（有效）。
   —— 与服务端 `mk()` 现状对齐。
   ⚠️ **给 `P0-0` 修复子代理的请求**：修完请确认服务端也是"`mask` 只在 `[N, 档位)` 的 `node` 行置 `True`、
   其余 78 个上下文 token 全 `False`、动作 softmax 只取 `[0, N)`"——否则**训练/推理两套输入分布**，`ratio` 必失真。
3. ⭐ **`mem` 恒为全零**：服务端 `mk()` (`policy_server_graph.py:20`) 把 `mem` 建成零，且 `:68-71` 只覆盖载荷里出现的段
   ⟹ **推理侧恒零**。`train_loop_v1.py:13-27` 那套"由网络逐帧生成"需要 **`mem_writer` 头 + 服务端同步生成**，
   而 `net_v2_fixed.py` **没有这个头**（只有 4 个输出）。
   ⟹ **今晚训练侧也喂零**（`mem_mode=zeros`）；⚠️ **若训练侧生成、推理侧喂零，同一帧的输入就变了 ⟹ `ratio`/`advantage` 全是错的**。
   （这与 `G4 文档 §2.1` 契约 `C6` 的写法**有意偏差**，理由如上；要改必须**网络 + 服务端 + 训练器同批改**。）
4. ⭐ **截断局的 `V(s')`**：末帧 `done=True` ⟹ `next_v = 0`；末帧 `done=False` ⟹
   **必须**有 `v_next`，否则训练器**抛错**（`--bootstrap zero` 才显式当终止，并在 `metrics.bootstrap_tails.zeroed` 计数）。
   —— 采集器若**只发完整局**（`P0-2` 的设计就是"等 `ROUND_ENDED`"），则**不需要** `v_next`。
5. ⚠️ **已知的批间偏差（不改网、只记账）**：`net_v2_fixed.py:23` 用**批内 `real.max()`** 归一位置编码
   ⟹ 同一帧在不同 batch 组成下 `pos` 会差一点。本训练器用"**按 `N` 排序装桶**（`minibatch=32`）"把批内长度拉齐来压这个偏差。
   ⭐ 一行修复建议（**需网络 + 服务端同批改**，⛔ 本轮没改）：`:23` 的 `real.max()` → `real`（逐样本归一）。
6. **`value` 头 = `out[0]`**（`head_node` 池化标量）—— 父代理 `2026-10-17` 拍定；服务端 `policy_server_graph.py:107` 同取 `out[0]`。

## 九、⭐ 算力实测（本轮，`2026-10-17` 夜）——**这条会改变今晚的计划**

**方法**：`--mode episodes` 喂 `128` 帧（`N=900~1000`，真尺度）+ `minibatch=32` + `epochs=1`，跑两遍取两次一致的数。
⚠️ **同机负载**：本任务之外另有 `2` 个 `node` 进程在跑（`tasklist`），`GPU` 已用 `2272 MiB/8151 MiB`（含别的子代理）；
**机器不静默 ⟹ 这个数是"下限"**（`AGENTS.md` 有"整夜跑要机器静默"的纪律）。

| 项 | 实测 | 口径 |
|---|---|---|
| `PPO` 更新吞吐 | **`90.1` / `94.8` 帧/s**（两次） | `minibatch=32`、`d=256·L=3`、`≈1078 token/样本`、1 个 epoch |
| 参照 | `138.9 样本/s`（`AGENTS.md:1357-1373`，同构网） | 本次偏低 ⟹ 与"同机负载"有关，⛔ 不能当"性能回退"结论 |
| 单帧上限检查 | `N=900~1000`、`minibatch=32` **不 OOM**（`EXIT=0`） | 真尺度可跑 |

**推算（按实测 `92` 帧/s、`3158` 帧/局、采集 `17.5 s/局` 出自 `今晚…方案:203`）**：

| 方案 | 每局耗时 | 一晚（`8 h`）能跑 |
|---|---|---|
