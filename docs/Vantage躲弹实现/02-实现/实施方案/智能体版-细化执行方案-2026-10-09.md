# 二、S0 基线（**最重要的阶段，别跳**）

## S0.1 为什么必须先做

**现状是：没有基线。** 后面每改一步，**没有任何东西能告诉你"是不是改坏了"**。
而本项目的血泪史（`AGENTS.md` 的「AI 踩坑复盘」）就是"修一个坏一个"。

## S0.2 要做什么

| # | 做什么 | 具体 |
|---|---|---|
| **0-a** | **接线 `__vtRng`** | ⚠️ **它现在【没有任何调用方】**（`clock.js:95-113` 定义 + 一份规划文档，`match.js`/三个 worker 全没调）<br>⟹ **必须在对局开始前 `__vtRng.record()`，结束时 `dump()` 落盘** |
| **0-b** | **逐帧记录 `opName`** | 现在 `__vtAct` **只写 `fwd/back/left/right`，不写 `fire`** ⟹ 要补 `fire`；<br>而且**要记 `tank_a`（AI）和 `tank_b`（对手）两边** |
| **0-c** | **记录初始条件** | 地图 / 主题 / 玩家列表 / 初始位姿 / 回合设置 —— **现在全都没打包**（§20.2 #2） |
| **0-d** | **落盘格式** | ⚠️ **`collect.js:42` 的教训**：「原始记录 400 条 = **30MB，CDP 传不动**」<br>⟹ **必须在页面内累积、分片导出**，不许 `Runtime.evaluate` 一次返回整局 |

## S0.3 验收标准

- ✅ 同一份录制回放**两遍**，逐帧 `opName` **完全相同**（`__vtRng.play()` 保证 `Math.random` 一致）
- ✅ 两遍的**坦克位姿逐帧误差为 0**（虚拟时钟下应当完全确定）

## S0.4 ⚠️ 已知的确定性边界（别指望"绝对可复现"）

| 没被虚拟化 | 后果 |
|---|---|
| **`setTimeout` / `setInterval`** | 资产加载必须「推进几帧 → 让出真实时间」交错（`match.js:18-21` 原注释） |
| `fetch` / `XHR` / `Image` | 真实 I/O |
| 微任务时序 / `performance.mark` / Worker / WebAudio / CSS | 未接管 |
| ⚠️ **`cancelAnimationFrame` 被换成空函数** | 有代码依赖"取消 rAF"时**取消不掉**（未验证游戏是否调用） |

## S1.4 ★ 帧长校准器（**主人已裁定**）

> **主人原话**：「**通常游戏帧率都是稳定的。所以就可以用这个稳定的数值，如果掉帧了，就及时更新矫正。**」

**现状的毛病**：`calibrateFrameDt` 把**抖动**和**掉帧**当同一回事（都 `alpha 0.02` 慢平滑）。

**要改的**：

| 改什么 | 改成 |
|---|---|
| 慢平滑 `alpha 0.02` | **用稳定值**（帧率稳时不平滑） |
| 钳位 `[0.015, 0.03]` | 🔴 **不钳**（或钳很宽）—— 真实掉到 <33fps 时必须跟 |
| 抖动/掉帧一视同仁 | **抖动忽略（±5%）+ 连续 K 帧持续偏离则立即切中位数** |
| 校准源 = 弹的 `timeAlive` | ★ **换成 `gc.lastUpdate` 墙钟差分**（`resolveWorldDt:1480` **已经在用了**）<br>训练模式用 `rm._ttStepCount` / `rm._ttLastStepDt`（**精确步数表**） |

**⟹ 换校准源的意义**：**修掉"场上没弹就不校准"那个洞**（现在校准源就是弹的 `timeAlive`）。

**⚠️ 别破坏这个保护**：`resolveWorldDt` 里的

```js
if (seen === _lastSeenWorldStep) return 0;   // 世界没 Step 的 tick ⇒ 树时钟不前进
```

**这是"树时钟不能比世界快"的关键。**

## S1.5 清理"两套帧长"的不一致

| 位置 | 现状 | 要改成 |
|---|---|---|
| Rust 桥的样本时间戳 | **硬编码 `frame * 0.02`**（`vantage_sandbox.js:1319`、`:2347`） | **和 JS 融合一样用 `k * FRAME`**（`:1617` 的写法） |
| `_frameDtSec` vs `worldDt` | 两个来源不同（§7.10G） | **统一走同一个 `FRAME`** |

## S1.6 验收

- ✅ 新方法**全部返回真实数据**（用一个已知局面**逐个打印核对**）

# 四、S2 树侧改造（**智能体接管决策**）

## S2.1 ★★ 第一步：**把"生长"提到任何 `return` 之前**

**为什么必须先做这个**（W1 的结论，§22.3⑤）：

> `tick` 里有 **8 个**会结束本帧的 `return`（`:7129/7131/7143/7217/7375/7397/7544/7552`），
> **其中 6 个会跳过末尾的 `growStep`（`:7558`）** ⟹
> **不先移，A 的 `growAt` 在"提交帧"永远无效。**

**⟹ 这就是 `AGENTS.md`「生长必须是无条件的一步」那条纪律的代码级依据。**

**怎么做**：
1. 把 `growStep(tree, adapter, tree.threats || evalThreats)` 的调用**上移到 `agentSeam` 之后、所有 return 之前**；
2. **但要保留"这次 tick 该不该长"的判断**（跳过预算/熔断）—— 那是 `growStep` **内部**的事，不是靠不调用；
3. ⚠️ **注意 `_frozen` 分支（③）**：死亡定格时**不该长**，这是例外（保留 return）。

**验收**：在"提交帧"（`segmentEndDue` 为真的帧）里 **`growStep` 确实被调用了**（打点验证）。

## S2.2 节点建在死前 + 真死不建（§4.1/§4.2）

| 改动 | 规则 |
|---|---|
| **节点 = 一次 75 帧模拟的终点** | 死了就在 `d−1` 建节点 |
| **真死（`fd ≤ 1`）不建节点** | 标记为"缺勤"，**"缺席"本身就是信号**（不给它发任何字段） |
| **`samples[0]` 是父节点状态**，`samples.length = durationFrames + 1` | §7.7 的"差 1"陷阱 |
| **智能体版彻底不碰 `segmentFrames`** | 它是规则版遗产 |

## S2.4 两次调用（§4.5）

**A、B 必须**：
- **同一 tick**（之间世界不推进）
- **在 `tick` 的两类提前 return 之前**
- **全有或全无**（B 失败则 A 的产出也作废，本帧回规则兜底）

**调用点顺序**：`agentSeam` 现在在 `:7362`（所有 return 之前 ✓），要扩成**两次调用**。

## S2.5 ★★ 不变量②**必须重新实现**

**这是拆评分带出来的连锁后果**（§17.4①）：

- `enforceNonRedPrefer`（不变量②的兜底）**唯一调用点被注释掉**（`:6635`，**主人要求的"别用兜底"**）；
- 现在不变量②靠 **`pickBest` 里的层过滤（绿 > 橙）**—— **而那条属于评分系统**；
- ⟹ **智能体版拆掉评分的同时，也把不变量②的实现拆掉了。**

**⟹ 必须自己做**：例如做成**智能体输出上的合法性过滤**（过滤掉"有非真死路线却选真死"的 `select`）。

**⚠️ 但要做成"过滤"还是"否决"，要你定** —— 主人说过「**尽可能不用兜底**」，
所以可能是"**在契约层拒绝**"（返回非法 ⟹ 本帧走规则兜底），而不是"**选完再改选**"。

### ③ 射击帧怎么落到"当前帧"

```
节点 = 一次 75 帧模拟的终点（或死前的帧）
      ⟹ 它的帧范围 = [tEnd − L, tEnd]（L = 75，或死时 L = fd − 1）
(节点ID, back) ⟹ 命中时刻 = tEnd − back   （back ∈ [0, L)）
执行层每帧：当前帧 ∈ B 的射击帧集合？ → 是则 fire = true
```

### ⑤ 0 帧自杀（**检测要做、过滤可选**，§五 已降级）

**主人定案（2026-10-07 第五轮）**：

> 「那个主要是为了**过滤自杀的失误情况**，**如果不好搞，其实不搞也行**，
> **训练够了它就不失误了**……**只知道检测个 0 帧死**，
> 也就是**坦克还没开始动就死了**，**很容易检测**。」

| 事项 | 状态 |
|---|---|
| **检测**「0 帧死」 | ✅ **要做** |
| **过滤**（从候选里划掉） | ⚠️ **做不了可以先不做**（主人「想不出什么很有效的过滤办法」） |
| **不做会怎样** | 主人判断：**训练够了它就不失误了** |

**⚠️ 精确语义（**必须钉死**）**：

> `双智能体 §10.1④` 原话：「**不能实现成"段帧号 0"**，否则把自爆安排在第 1 帧就绕过了不变量三。」
> → 正确定义：**子弹射出瞬间就命中自己**（**炮管贴墙发射、立刻反弹回来**），
> **不是"第 0 帧"这种帧号约定**。

**⟹ 检测方式的三个选项**（**我倾向 A**）：

| 选项 | 怎么做 | 代价 |
|---|---|---|
| **A（几何，推荐）** | 判**炮口点是否落在墙里 / 极近处有墙** ⟹ 子弹一生成就在墙里 ⟹ 立刻反弹 | 简单、**不违反薛定谔原则**；但只是**近似**（反弹后是否命中自己还跟墙法线有关） |
| **B（模拟）** | 临时往融合世界加一颗子弹，看是否 `fd ≤ 1` | **最准**，但**违反"树里只模拟确定的子弹"**（不过它只是**检测**、不进树，**可以讨论**） |

# 五、S3 沙箱保真度（**树能不能信的地基**）

## S3.1 判死世界缺的东西（§11.6⑤ / §18.5）

**现状缺**：对手坦克 · **护盾夹具** · **陷阱** · **道具** · **风暴区** · **武器炮塔形状** · **激光扫掠** · **导弹制导**

**🔴 最关键的一句**：**"没模拟" ≠ "不会死"**。
**如果风暴/陷阱/对手撞击能致死，而树只报"绿"，那和"子弹漏判"是同一种事故。**

**⟹ 按 §13 三条判据（确定的 / 很少改变的 / 简洁）逐项裁定"进 / 不进"，并把裁定写进接口。**
