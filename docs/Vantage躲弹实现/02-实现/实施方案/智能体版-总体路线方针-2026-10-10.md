## 一、总施工纪律（**违反任何一条 = 白做**）

1. **规则版逐帧不变**：一切改动用 `if (智能体模式)` 包住。
2. **不许让智能体打分**，不许算法拿分搜路径；不存在规则版显式评分（智能体直接感知输出路线）。
3. **没有"段长/操作时长"语义**，不许以任何形式复活（包括拿规则版实测的"13 帧"说事）。
4. **弹种/判死语义改动必须 JS track + JS 融合 + Rust 三处同改** + 一份能跑通的差分对拍。
5. **生长是 tick 里无条件的一步**；**禁止分散到多帧计算（切片）**；树满禁止生长（机械判定，不问智能体）。
6. **实测 ≠ 设计**：引用任何实测数字必须带配置（"段长 13 帧""496 节点"是把规则版实测当设计事实的幻觉，已被主人点名）。
7. **不许从函数名反推语义**；方向性结论（多/少、加/减）算完用游戏平衡性常识验一遍。
8. **根只在误差 ≥ 1 帧操作量时对齐**（缓存不失效）；**晚 1 帧是设计**（游戏逻辑→智能体→下帧执行，不是错位）。
9. **每个阶段结束必须跑通"规则版零回归"对拍**，跑不通不许进下一阶段。

### 阶段 1 · 沙箱保真度 🔴 极易出错区，每小步都要对拍

> 树能不能信的地基。原则：**先时间、再弹种、后世界内容**（时间基准错位会放大一切误差）。

| 序 | 内容 | 为什么这个顺序 / 怎么躲坑 |
|---|---|---|
| 1-1 | **时间基准统一** —— ⚠️ **它有【三层】，不是一层**（2026-10-11 补记，详见下方"1-1 补记"） | 一切判死/弹道都乘在时间轴上；错位 1 帧 = 判反擦边 |
| 1-2 | **弹种四缺项**（每项三处同改 + 差分对拍）：① 霰弹撞墙减命（≤0.7s）② 反弹上限实测（先无头长走廊数真实反弹，再定 `BOUNCE_TIMEOUT_WINDOW=35` 语义）③ 激光线段扫掠（先裁决反弹与否）④ 导弹 2s 制导/换目标（追别人直接丢） | ①② 是纯实现（**已落地 v166**）；③④ 要动 ABI，放后；每项配 `diff_*.js` 对拍，**改一项验一项**。⚠️ ③④ 还要**一并**把"给激光/导弹/破片挂 track"做掉（见 1-1 补记 §C） |
| 1-3 | **JS/Rust 判死统一** —— ⚠️ **audit 已跑（2026-10-11），结论推翻了原方向**：原写"给 Rust 补几何回溯"，但实测**分歧的 85% 是「起点即接触 `df=0`」（JS 抓到、Rust 漏）**，与几何回溯无关；几何回溯那类只占 **0.056%~≤1.2%**。而且**方向和我原先以为的相反**：两边都判死时 **JS 晚 1 帧（更迟钝），不是更保守**。**新口径：① 先修「起点接触」（两侧同改）→ ② 视界最后一帧口径差（⏳ 待主人定，改它会少判死）→ ③ 查 `lanePenaltyRatio` 静默回退** | ⚠️ **别建议把 JS 几何补判拿掉**（会造新绿死）。对"选路"的实际影响很小：树自己的选中路线复判 **646 次仅 3 次翻转**，两轮无偏采样 **`0/249`、`0/260`** |
| 1-4 | **护盾 fixture**（反弹子弹/停破片，不做"无敌"）、**毒雾**（§12.30 规格已完整，安全区=4 条边）、**道具/形状改变**（炮管 fixture 切换 + 拾取模拟） | 全是"确定且很少改变"的内容，照规格一次写对；写不进规格的不做 |

> 调试工具要求：每个弹种语义改完，差分对拍容差 1e-9（范本 `diff_shrapnel_wall_stop.js`）；
> 修本机 cargo/链接器环境或把 Rust 单测改到 wasm 目标跑（B29/B30 两个差分脚本卡在版本闸门，`vt_version()=9`）。

> ### ★★★ 1-1 补记（2026-10-11）：**"时间基准统一"其实有三层，只做了第一层就要出事**
>
> **这一节是"1-1 被当成一层做过一次、结果漏掉后两层"的血泪记录。** 后续任何"时间"相关的活，先读这里。
>
> | 层 | 内容 | 状态 |
> |---|---|---|
> | **A · 帧 ↔ 秒** | 帧长校准器（用稳定值+掉帧及时矫正，校准源换 `performance.now()` 自分差而非 `gc.lastUpdate`——整数毫秒会偏 +3%）；清掉 Rust 样本时间戳硬编码 `frame*0.02`；两份 ABI 的帧长钳位对齐 | ✅ **已完成**（v163~v165） |
> | **B · 「现在」vs「节点起点」** | 同一个"时间偏移"概念有**两套基准**：**`qLife`/`q` = 从【节点起点】起算**（轨迹取位用）、**`qAge` = 从【现在】起算**（寿命扣减用）。变量名不区分 ⟹ 历史上反复踩。**凡涉及时间，先问：这个量从哪起算？** | ✅ **已完成**（v165 的 S1/S4 + **v167 的 S3/S8/S7**） |
> | **C · 「锚点」的年龄** | 威胁轨迹的锚点会被**复用**。**门 `shift <= 1.0` 检查的是"本次 commit 间隔"，而注释的本意是防"累计偏移过大"** ⟹ 对"跑满窗口型"的长命弹这道门**等于不存在** ⟹ 实测 Δ 涨到 `20.99s` 而轨迹只覆盖 `9.37s` ⟹ **深节点盲区 72.5%** | ✅ **已完成**（v168 改成对 `|newOffset|` 的界） |
> | **C 的尾巴** | 还有**一条不吃这道门的旁路**（`hasKids===false` 分支 → `ensureThreatTracks` 在 `simulateBulletTracks` 返回假值时的早退 `if (!tracks) return;`）—— 1/6 次跑出现、未复现 | 🔵 **定位中** |
>
> **⚠️ 另外两条已登记的关联缺口**（**不要忘了**）：
> - **激光 / 导弹 / 破片【永远拿不到 track】**（`isBallisticProjectile` 是硬白名单 4 种）—— 当前 AI 恰好不用这三种武器，**一旦捡到就是 100% 无 track**。⟹ **合并进 1-2③④ 一起做**（反正要动同一个 ABI）。
> - **视界最后一帧的口径差**（JS `geoHit` 会补判到 `k = durationFrames`，Rust 不会）—— 量级 0.056%~≤1.2%。

|---|---|

### 阶段 3 · 树侧改造 🔴 时序高危区，稳重地写

> 顺序就是依赖链，一步一验：

| 序 | 内容 | 坑 |
|---|---|---|
| 3-0 | **拆评分的代码耦合**（D12 重述版，2026-10-11 外部审查后恢复）：`applyRolloutScore` 的守卫是评分字段 `r.perFrameScores`（`vantage_tree.js:2542`），而死亡缩短 / `simState` / `tGlobal` / `fullDeathFrame` / 状态写入**全包在这一个函数里**——不评分它直接 `return false`，节点拿不到死亡处理。⟹ 先造**只返回物理结果的模拟通道**（权威版 §21.5 第一步），把函数拆成「物理应用」（守卫 `samples/dead/deathFrame`，智能体版用）与「评分应用」（`segmentScore/subtreeBest`，规则版专用） | 不拆 = 无分数通道下**静默 return false**，又是本项目最痛的那种坑 |
| 3-1 | **生长前移**到所有提前 return 之前（`_frozen` 分支除外） | 不移，A 的 growAt 在提交帧永远无效 |
| 3-2 | 节点建在死前 / 真死不建（"缺席即标记"）；智能体路径彻底不碰 `segmentFrames` | `fd≤1` 时 `d−1` 算出 0/−1，必须走"不建"分支 |
| 3-3 | 接口契约：`picks: [Pick,...]`（每次 1 帧，预留多帧=多次调用 A）；删 `growTimes`（含 selftest 假绿）；修 `growAt` 只消费 `[0]` 与 `expandLeaf` 拒绝非叶的矛盾 | validateDecision/validateBundle/语义校验**三处同步改**（血泪教训：漏一处 = 死字段） |
| 3-4 | **两次调用同 tick**：A → 生长 → B，全有或全无；生长禁止切片 | B 必须看到 A 本帧刚长的完整节点 |
| 3-5 | **执行层**：每帧滚动执行 B 路线首操作；fire 解开写死 false，射击帧按 (节点ID, back) 落到帧；**输入只在该帧有效，不锁存** | 点射变长按 = 加特林废掉 |
| 3-6 | **预算闸门**（规则系统侧）：冻结点 B 定的形式；树满（机械判定）禁止生长、不调用 A；根滞后对齐（≥1 帧操作量才对齐） | 无闸门 = 9⁷ 最坏爆炸 |

> 验收：`Agents.use('nn')` 但 decide 返回 null 时与规则版**逐帧一致**（用阶段 0 的基线）；
> 非法输出被契约层拒绝且不静默；B 计划射击时执行层真在对应帧按下。
