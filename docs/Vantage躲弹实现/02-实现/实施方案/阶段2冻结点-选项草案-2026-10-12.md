## 三、逐个开口的选项表

### A1 · 树时间上限「10」的单位与取值

**已知事实**：代码里**没有**"10"这个常量；时间视界现成机制是 `_horizonSec = 8.0` 秒（`tree:818`、`TREE_DEFAULTS.horizonSec` `tree:1293`，面板可调 1~15 秒，setter `tree:8257`）。"10"只有两条文字来源：主人原话「时间限制 10 秒，也就是游戏中生命周期最长的子弹」（`双智能体…:644-651`）+ 常量 `BULLET_MAX_LIFETIME:10.0`（常量 bundle`:1`；`HOMING_MISSILE_MAX_LIFETIME` 也是 10.0）。
**帧长是运行时可变**：`FRAME_DT ∈ [0.015, 0.03]`（`权威版:535`）⟹ 10 秒 = **333~667 帧**，不固定。

| 选项 | 具体取值 / 形式 | 代价（量化） | 安全？ |
|---|---|---|---|
| **A1-O1（推荐）** | **10 = 秒**；把 `_horizonSec` / `TREE_DEFAULTS.horizonSec` 从 **8.0 改成 10.0**；**观测里的时间一律用"秒"**（`tRel / 10` 归一化），**不用原始帧号** | 不新增机制（只改 1~2 个常量）。轨迹长度公式 `trackFramesForTree`（`tree:1895`）= `(horizonSec + 75×FRAME_DT)/FRAME_DT + 5`：8 s → **480 帧/颗**，10 s → **580 帧/颗**（+21%）；树级 threats 上限 64 颗（`tree:1556`）≈ **2.7 MB → 3.3 MB** | ★**最安全**：上限是配置（1~15 s）；以后缩回 6/8 s 不用推翻编码器；观测用秒 ⟹ 60 fps 机器（0.0167）与 50 fps（0.02）输入语义一致 |
| A1-O2 | **10 = 500 帧**（等于冻结 `FRAME_DT=0.02`，`_frameDtCalibEnabled=false` `tree:856`） | 深度固定、观测形状固定；但真机 60 fps 时 `FRAME_DT≈0.0167`（`权威版:534`）⟹ 500 帧只覆盖 **8.35 s < 最长弹 10 s** ⟹ **8.3~10 s 的弹看不到**（盲区、偏绿）；且冻结校准后树时钟与游戏时钟可差 ~20%（`权威版 §7.8`） | ✗ 语义与"最长子弹寿命 10 秒"不再对齐；不推荐 |
| A1-O3 | **10 = 秒，再加层数上限 7 层**（`ceil(10 / 1.5s)` = 7） | 需新增层数判据（现在没有）；与 D6「只限时间上限」冲突；本质是把 A2 的活做两遍 | 不推荐单独立；若 A2 选了数量闸门，这条多余 |
| A1-O4（**排除**） | `horizonCapEnabled = false`（`tree:817`），完全不限时 | 与 A2-O2 叠加 = 树**没有任何上界**；track 长度无限增长 | ✗ 直接排除 |

**推荐理由**：两条独立来源（主人原话 + 代码常量）互证"秒"；改动量最小（现成滑块）；把"单位"和"观测口径（秒）"一起定掉，正好吸收 `FRAME_DT` 可变。

### 4.3 子弹 token 的宽度（最省多少维）

**关键发现**：`Projectile` 的字段表里**没有独立的"角度"**（`418577…js:4`：`id / playerId / type / x / y / speedX / speedY / lifetime / timeoutWindow / timeoutBounceCount / timeAlive / deadlyToOwner / initialSpeed / stopped / bounces[]`）⟹ **角度 = `atan2(speedY, speedX)`，与速度冗余 ⟹ 不单独占维**。

| 字段 | 代码来源 | 取值范围（代码依据） | 量化步长 | 定点位宽【估算】 |

## 六、无法判断 / 需要主人一句话的（**不许编**）

1. **浏览器内整 tick 耗时**（含 JS 融合确认 + 观测编码器）——**需要实测**。本次同机复跑 1.65→5.6 ms 波动太大（另一代理在跑东西），**不能当设计依据**；A2-O1 的上限值最终要不要从 500 抬到 2000，最好等一次空载无头实测。
2. **`10` 没有单一代码真源**：代码里是 `_horizonSec=8.0`（`tree:818`），"10"只在文档（`双智能体 §13.4`）与 `BULLET_MAX_LIFETIME:10.0` 里。需主人一句："**确认 10 = 秒，并把 `horizonSec` 改成 10.0**？"
3. **D6 vs A2（数量上限）**：字面执行 D6 = 6.5 GB / 717 万维（§三 A2-O2）。需主人裁"维持 D6 字面"还是"允许数量/内存闸门"。
4. **操作类型字段**：10-07 说"不需要"（`权威版:217`、`AGENTS.md:521`），10-10 说"得加"（`设计审查…:30`）。{推断}按后者（较晚）。若主人确认**不加**，A3 节点 token **12 → 10 维**。
5. **子弹 token 的时刻口径**：已定"传全场"，没定"哪一刻的弹"。本草案按**现在**（root）。若要"节点所在未来时刻的弹"，数据量变成 N×M（A3-O3 级别）——**需主人一句**。
6. **上帧计划的 `K_fire` 上限**（本草案暂取 4）没有实测的"每帧射击点数分布"；超限**截断规则**（超了怎么办）也没定——"不许规则层挑观测"和"定长张量"在这里会撞。**需要实测 + 主人裁**。
7. **观测是否带 `FRAME_DT`**（`权威版 §7.8` 的方案 c）：带 = +1 维换"策略知道当前帧值多少秒"；不带 = 少 1 维但时间语义依赖外部常量。**未拍**。
