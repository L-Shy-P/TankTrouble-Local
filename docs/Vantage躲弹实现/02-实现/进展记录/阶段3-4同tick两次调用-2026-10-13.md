## 二、拆成了什么样（六步顺序 + 两次调用的位置 + B 移出闸门）

### 2.1 tick 里的顺序（v185）

```
① 规则系统维护（推进物理 / 增量失效 / 段末重锚 / 节点预算 / 性能闸门）   —— 原样
② A.decide：ctx.phase='A'，picks=生长位置
   ├─ 位置：`vantage_tree.js:8135`，仍在 `canAddTreeNodes(tree,9)` 数量闸门**之内**
   └─ 成功 → tree._agentDecision（A 槽）；失败 → 清 A 槽，本帧无生长指令
③ growStep：消费 A 的 picks[0]/growAt[0]（3-1 已前移的那一次）
   └─ ★ 生长禁止切片：`while (tree._expandSlice) stepExpandSlice(...)`（`:8182-8189`，
      guard=64；跑不完记 `recordStructure('grow-slice-unfinished')` 响亮暴露）
④ B.decide：ctx.phase='B'，picks[0]=选的路线、picks[1..]=射击帧
   ├─ 位置：`vantage_tree.js:8199`，在**数量闸门之外**（`if (agentModeCurrent(tree) && …)`）
   └─ 成功 → tree._agentDecisionB（B 槽）+ tree._agentRoute/_agentFirePicks
⑤ commit / emergency / 段末：**原样**；选路消费 B 的路线
   └─ `agentSelectOverride`（`:4207-4216`）：优先 `_agentDecisionB.picks[0].nodeId`（旧 `select` 兼容）
⑥ 执行本段：原样
```
* **两次调用都在 `if (tree._commitSlice)` / `if (emergency)` 两条提前 return 之前**，同一 tick、
  **同进同出**；中间**没有**世界推进（`ctx.time` 相等已实测）。
* **没有改规则版路径**：B 的调用被 `agentModeCurrent(tree)`（非 rule 智能体）门住 ——
  规则模式下 A 照旧返回、B **根本不调**（探针 P5：规则模式 decide 0 次）。

### 2.3 失败语义（每相独立、同 tick 同进同出）

* **A 失败**（重试超限）→ 本帧无生长指令（A 槽清空）；下次 tick 重新调 A。
  （`growStep` 在 A 槽空时**不会**退回规则 `pickGrowLeaf` —— 见 3-3 的 B3/B4 语义；树满 A 不调时同样。）
* **B 失败** → 清 B 槽 + `_agentRoute/_agentFirePicks`；本帧路线/射击帧交回**规则逻辑**（`agentSelectOverride` 返回 null）。
* **A、B 的失败互不牵连**（B 跑不跑只看接口/agent 就绪与是否非 rule；D11 要求树满也要跑 B）。
* **threats 用哪一刻**：A、B 都用**调用时刻**的 `evalThreats`（本 tick 开头算的，
  `threats || tree.threats`）；生长用 `tree.threats || evalThreats`；新弹的 `attachNewThreats`
  在 B **之后**才发生 ⟹ **A/B 都只看"它们被调用那一刻"的观测**（权威版 §7.4："开始调用那一刻不会
  出现任何新事件"；3-1 登记的 emergency 顺序问题按"决策时观测"定，见 §六-3）。

## 三、⭐ 三条证明 + 假阳率

### 证明 1：B 看到 A 本帧刚长的完整节点

* 同一 tick，调用顺序 `["A","B"]`，各 1 次；
* `ctxA.time === ctxB.time`（中间世界不推进）；
* `ctxA.nodes=19`，`ctxB.nodes=28`，**delta=9**；A 新长的 9 个子节点 id **全部**在 B 的
  `ctx.nodes` 里（`inCtxB=9/9`）；树 `nodeCount 19→28`。
* ⭐ 这同时证明"**生长禁止切片**"：B 看到的是完整 9 支，不是半个切片。

### 证明 2：全有或全无（B 失败）

* A 合法（`picks:[{leaf,0}]`）→ **A 调 1 次**；B 非法（路线不在候选里）→ **B 重试 3 次后放弃**；
* A 的生长**在**（叶子 9 个子节点，树一致）；**B 的路线不生效**（`agentRouteUsed` 不增）、无崩溃。
* **为什么不需要回滚（本步的说明，见 §六-1 登记）**：
  1. **生长是独立的机械展开**：它只消费 A 的生长位置 + rollout 结果（3-2 的真死不建、3-3 的 picks），
     **不编码 B 的路线**；B 失败不影响这批节点的合法性/一致性（父链、计数、leaves 均自洽）。
  2. B 失败后的落点是**规则兜底选路**——这正是引入智能体之前的行为；没有"半 B 状态"残留
     （B 槽/路线/射击帧都清了）。
  3. 回滚成本高且危险：一次 A 生长可能含多层/细化（拆长段会改已有节点的时长），
     回滚要反演这些结构操作；权威版 §7.4 绑定的是"两次调用同帧"，没有要求"B 失败回滚 A"。
  * ⚠️ 如果主人要**严格原子**（B 失败 → A 的生长必须消失），那是一次明确的语义升级
    （需要"生长结果缓冲/回滚"设计）——**本报告停下不拍**。

### 证明 3：D11 —— 树满时 A 不调、B 照调

* 造树满：`tree.cfg.maxNodes = tree.nodeCount` ⟹ `canAddTreeNodes(tree,9)=false`；
* 该 tick：**A 相 decide 0 次**，**B 相 decide 1 次**，`tree.stats.agentSkippedFull +1`；
* 说明 B 的调用确实在数量闸门之外（`vantage_tree.js:8199`）。

## 六、未解决（含两条"设计选择，停下报告"）

1. ⚠️ **两次调用的是同一个 agent 对象（用 `ctx.phase` 区分），不是两个注册智能体**：
   当前接口只有一个 `Agents.current()`；A/B 的相位通过 `ctx.phase`/`role` 传进去，
   智能体内部自己分派（NN 可以做成两头）。**若主人的本意是"两个独立 agent（两个模型/两个注册名）"**，
   那是接口层的设计选择（`Agents` 注册表要不要支持 A/B 两个槽、ctx 怎么分），**本步没拍**。
2. ⚠️ **B 失败不回滚 A 的生长**（§三-2 给了"不需要回滚"的理由）；**若要严格原子（B 失败→生长消失）**，
   需要"生长结果缓冲/回滚"的新设计，**本步没拍**。
   另：**B 的空 `picks`** 本步读作"本帧不给路线/射击帧 → 规则兜底"；若另有含义，需拍。
3. **`threats` 用哪一刻**：本步按"A/B 只能基于调用时观测"定死 = 两次调用都用 tick 开头算的
   `evalThreats`，新弹 `attachNewThreats` 在 B 之后；3-1 登记的 emergency 顺序问题由此收口
   （文档没有相反说法）。
4. **`Pick.back` 的执行语义**（哪一帧、执行几帧）与 **B 的射击帧执行**（什么时候开火/加弹）
   都只做到"校验 + 存储"，真正执行在 **3-5**。
5. `_expandSlice` 抽干 guard=64：超出会记 `grow-slice-unfinished`（响亮）但不会强跑完；
   默认融合批量路径同步，不会走到。
6. 3-3 登记的两处 HTML 假绿（`vantage_selftest.html` / `flywire_debug.html`）仍未改（范围外）。
