## 二、改了什么（带行号）

### 2.1 `picks: [Pick,...]` 契约（三处同步）

| 层 | 位置 | 改动 |
|---|---|---|
| 接口·格式 | `vantage_tree_interface.js:148-190` `validateBundle` | 新增 `picks` 白名单：必须是数组；逐项校验 `nodeId` 非空、`back` 为非负整数；**非法项逐项报**（`生长picks[0].nodeId` / `生长picks[1].back`）；非数组报 `生长picks` |
| 接口·归一 | `vantage_tree_interface.js:117-140` `validateDecision` | `out.picks` 原样保留（**不截断多元素**，契约允许"多给"）；**`growTimes` 块整段删除**；`growAt`/`select`/`memory` 兼容保留 |
| 树·语义 | `vantage_tree.js:4228-4260` `checkBundleSemantics` | **`picks[0]` 优先于 `growAt[0]`**；校验：节点存在 + `Invariants.canGrowAt` + **必须是叶**（见 2.3） + `back ∈ [0, L)`；`L` 由新 `pickLOf(n)`（`:4218`，`validFrames` → `fullDead/fullDeathFrame` 推，**不碰 segmentFrames**）给出 |
| 树·消费 | `vantage_tree.js:6428-6478` `growStep` | 只消费 **`picks[0]`**（没有则旧 `growAt[0]`）；`picks: []` = 本帧不生长（沿用 `growAt: []` 的既有定案）；多给的**忽略**并记 `tree.stats.ifacePickExtras`/`ifaceGrowAtExtras` + `recordStructure('pick-extras-ignored')` |

* `Pick = { nodeId, back }`；`back ∈ [0, L)`（§7.7）：`back=0` → 目标 = `samples[L]`（节点自己）；
  `back=L−1` → 只执行 1 帧；`back=L` = 不操作 → 禁止。
* **每次 1 帧 / 预留多帧 = 多次调用 A**（权威版 §7.5）：本步把"多给"定义成**忽略 + 记账**，
  不报错、不重试（"多给"是合法契约）；真正"多处生长"要靠 3-4 起的多次 A 调用。
* ⚠️ **一个过渡语义**（本步拍的，登记）：A/B 还没拆，`picks[0]` 当前被消费为 **A 的生长位置**；
  B 的 `picks[0]=路线 / picks[1..]=射击帧` 是 3-4 之后的事，本步仍用旧的 `select` 选路。

### 2.2 删 `growTimes`（含 selftest 假绿的成因）

* **接口**：`validateDecision` 的 `growTimes` 分支整段删除（`:117-140`）；文档头同步改。
* **树**：删除 `growStep` 里"智能体指定本帧长几次"的覆盖块（原 `:6460-6470`，现 `:6516` 只留删除注释）；
  层数继续由 `tree.cfg.growLayersPerTick` 决定（规则/智能体一致）。
  `_ifaceStats` 的 `growTimes` 计数换成 `picks/pickExtras/growAtExtras`（`:4275` 一带）。
* **那个 selftest 为什么是假绿（两层原因，都说清）**：
  1. **测试打错入口**：`game_core/vantage_selftest.html:100-102` 注册假智能体返回
     `{growAt:[1,2], growTimes:99, select:7, junk:1}`，然后**直接**调
     `I.validateDecision(I.Agents.use('selftest').decide({}))` —— **绕开了 `validateBundle`**。
     所以它验证的是"`validateDecision` 的夹紧"，而不是"契约管道真的把 `growTimes` 送到树里"。
  2. **真实管道里字段早就死了**：`validateBundle` 的 `clean` 白名单**从来不含 `growTimes`**
     （§17.4② 记的那个坑）⟹ 树里 `tree._agentDecision.growTimes` 的消费代码**永不可达**。
  * **删掉后的行为**：旧断言 `check('…growTimes 99 → 8', d.growTimes === 8)` 现在会拿到
    `undefined` ⟹ **会 FAIL**。也就是说：这次删除把"假绿"变成了"真红"——这正是
    方针 §静默失效型要求的"响亮失败"。**该 HTML 不在本步允许改动范围，只查证、没改。**
  * 另一处 `game_core/flywire_debug.html:470` 仍返回 `growTimes:2`（调试页；现在会被忽略）——登记。

### 2.3 `growAt` 只消费 `[0]` + 非叶矛盾

* **只消费 `[0]`**：`growStep` 本来就只取 `_agentWantsGrow[0]`；本步把**语义校验也只查 `[0]`**
  （旧代码会遍历整个数组逐个校验 → 第 2 个非法会触发整帧重试，可它根本没被消费）。
  多给的忽略并记 `ifaceGrowAtExtras`。
* **`expandLeaf` 拒绝非叶的矛盾**：旧链路 = `checkBundleSemantics`（`canGrowAt` 只查 invalid/真死）
  放行非叶 → `expandLeaf` 记一笔 `expand-has-children` 静默失败 → 智能体以为长成功了。
  本步在语义层**响亮拒绝**：`growAt[0]`/`picks[0]` 指向有子节点的节点 → `illegal:['生长']`，
  `reason='… 在非叶节点上生长（expandLeaf 会拒绝）'` → 帧内重试 3 次 → 规则兜底。
  * ⚠️ 完整的"在某一帧分叉 / 时长延伸"语义（主人 2026-10-07 提的方向）**不在本步**
    —— 本步只把静默失败改成响亮失败（方针 3-3 的原文就是"修这个矛盾"）。

## 四、⭐ A/B 现在是怎么调的、3-4 该拆成什么样（为下一步铺路）

### 4.1 现在（v184 实测/源码）

* **只有 1 个 `agentSeam` 调用点**：`vantage_tree.js:8060`
  `agentSeam(tree, adapter, tree.root.simState, evalThreats, VantageSandbox.OPERATIONS)`，
  它包在 v179 的**数量闸门** `if (canAddTreeNodes(tree, 9)) { … } else { tree._agentDecision=null; }` 里。
* 一次 `decide()` 返回**一包**：`picks`/`growAt`（A 的生长位置）+ `select`（B 的选路）+ `memory`（同一接口）。
* 消费点：
  * **A 的生长**：`growStep` 读 `tree._agentDecision.picks[0]` / `growAt[0]`（`:6428-6478`，3-1 已前移到提前 return 之前）；
  * **B 的选路**：`agentSelectOverride` 读 `tree._agentDecision.select`（`:4178` 一带），
    被 `pickBest`/`pickBestChildByRolloutTotal` 在 commit/选路时调用。
* 所以现在 **A 和 B 是同一次 `decide()`**（这正是 3-0 报告里点过的事实）。

### 4.2 3-4 该拆成什么样（**已定案，不是本步拍的设计**）

权威版 §7.4 + 初步实现方案 §4.5 原文：

```
帧开始
 ① 规则系统维护（推进物理 / 增量失效 / 段末重锚 / 节点预算 / 性能闸门）
 ② 摊开【当前树】→ A 决策 → 记录生长位置
 ③ 执行生长（growStep）
 ④ 摊开【更新后的树】→ B 决策 → 记录 route + fire
 ⑤ 段末 commit（消费 B 的 route）
 ⑥ 执行本段
```

**三条硬约束**（3-4 实施时必须满足）：
1. **两次调用强绑定在同一帧**（权威版 §7.4：开始调用那一刻不会出现新事件；新子弹下一帧才更新）；
2. **两次调用都必须在 `_commitSlice` 与 `emergency` 两条提前 return 之前**，且**同进同出**
   （不许"A 调了、B 没调"）；
3. **B 的调用必须移出 `canAddTreeNodes(tree,9)` 数量闸门**（v179 注释里的 D11：
   "停止生长 ≠ 停止工作"；A 可以因树满不调，B 仍要工作）。

> 本步**只做了契约层**（`picks`/`growTimes`/`growAt[0]`/非叶响亮拒绝），
> **没有**动 A/B 拆分 —— 那属 3-4；拆法在文档里已定，不需要新的设计选择。
