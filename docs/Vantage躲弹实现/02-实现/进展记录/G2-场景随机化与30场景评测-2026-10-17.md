## 一、三条硬判据（全过）

### ① 多 `Laika` 实例（`1 vs 3`，`players=4`）

- `out.aiIds = ["laikaX_1","laikaX_2","laikaX_3"]` —— **3 个不同 id** ✓
- 都在动 + 都在开枪（`_g2_scene_probe.js`，采样 `480` 帧）：

| id | 位姿变化帧 | 不同位姿 | 累计位移 | `_bulletsFired` |
|---|---|---|---|---|
| `laikaX_1` | `71` | `78` | `13.87` | `0 → 2` |
| `laikaX_2` | `91` | `131` | `23.13` | `0 → 4` |
| `laikaX_3` | `115` | `148` | `30.37` | `0 → 1` |

- 做法：**用 `laikaX_i` 前缀**（`laika_*` 会被 `local_patch.js:1106-1112` 折回 `6148530`），
  并**逐 id 在 `AIs.ais` 放一份 `6148530` 的 config 副本**，再 `AIs.addAIManager` + `ttGame.addPlayer`；
  **每个调用都检查返回值，失败即 `aiErr` 抛错**（⛔ 不静默）。
- ⭐ **附带发现（口径要清）**：raw 常量 `Constants.CLIENT.MAX_PLAYERS = 3`（**每条连接**上限），
  但 `local_patch.js:29 applyLocalLimits()` 在运行时把它改成 `LOCAL_MAX_TANKS = 8`
  （实测 bootstrap `maxActivePlayerCount = 8`）⟹ **原代码在页面里其实也拿到 `8`、并不是 `4/8` 人局的拦路虎**。
  本轮仍把 `maxActivePlayerCount` **显式写成 `max(players, CLIENT.MAX_PLAYERS)`**，是为了不依赖运行时补丁
  （raw 的每局上限常量是 `GAME.MAX_ACTIVE_PLAYERS = 8`，出处 `game_core/js/b714588dc4621fe104113111ba90b1a7.js`；
  `local_patch.js:15,29` 是 8 的另一个出处）。已改，且默认调用路径行为不变（已真跑回归）。

## 四、⚠️ 未解决 / 必须带警告读的东西

1. 🔴🔴 **多对手观测进不了网络（本轮最大口径缺口）**：
   `vantage_observe.js` 的 `oppTok` 是**每个对手 `15` 维**拼接（`1v1=15 · 4人=45 · 8人=105`；
   `OPP_FIELDS=[ox,oy,orot,...,oAlive(7),...]`），而 `net_v2_fixed.py` 的 `opp` 槽是 **`(1,15)`** ⟹
   **`8` 人局服务端对每条请求都以"段 opp 超容量"显式拒绝**（实测修前 `lp_finite 0/2999`）。
   本轮跑局器的处理：**显式取"离自车最近的存活对手"那一个 `15` 维块**喂网络，
   并在每局结果里记 `opp_input="nearestAlive(N->1)"` / `opp_adapted_frames`（**⛔ 不是静默降级**）。
   ⟹ **`4/8` 人胜率的读法**：策略看的是"单对手"输入分布（与训练分布一致），
   **不是权威的多对手观测**。要出权威的 `4/8` 人胜率，必须先拍板"网络 `opp` 槽扩到 `8×15` / 或编码器改聚合"（**网络+服务端+训练器三处同批**）。
2. ⚠️ **`rngSeq` 还没接** ⟹ 清单只能保证"五元组 + `expect` 区间"固定，**地图每次会变**（可比性降一级：看趋势，不做严格对照）。
   清单里的 `seed` 字段跑局器**没有消费**（`match.js` 只支持 `rngSeq/epoch`）；本轮只传了 `epoch`。
3. ⚠️ **评测权重是"活动靶"**：并发训练器在本轮期间把 `D:/vt_run/cyc_1/ckpt/model_latest.pt` 从 `step=6` 写到 `step=9` ⟹
   本轮**冻结** `eval_ckpt_frozen.pt`（`step=9`，`md5 fa64273c88f280b9bd7132100d79bb03`）。
   下一轮评测要**再冻结一次**并把 md5 写进报数。
4. ⚠️ **`9/30` 截断**（`3600` 帧 = `60s` 上限）：`8` 人局占多数（`6/9`），因为 `Laika` 们打不完。
   截断记 `unknown`（`win=null`），**不算负** —— 总胜率的分母是 `16`（`5+11`），不是 `30`。
5. ⚠️ **`Vantage` 一枪未发**（沿 `G1 §四`）：射击帧 `picks[1..]` 仍由策略给不出 ⟹ 它只会躲；
   `8` 人局能赢基本靠"对手互相打死 + 自己活到最后"。
6. ✅ **`chrome` 收工口径说明**：本任务自己的浏览器进程为 `0`；收工时 `tasklist` 里另有 `10` 个
   `chrome.exe` 属于**并发在跑的采集器子代理**（`node _tools/headless/_collect_tmp.js`，PID `3792`，
