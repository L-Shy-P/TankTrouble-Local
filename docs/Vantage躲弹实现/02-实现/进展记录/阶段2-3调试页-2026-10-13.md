## 三、⭐ 判据：「左边画的是 token 解出来的世界」

### 3.1 **结构上不可能"另取一份"**

我把「token → 世界」做成了一个**纯函数**：**`VantageObserve.buildScene(enc)`**
——**它的唯一入参就是右边那份 `enc`**，函数体内**只读 `enc.nodes.tokens` / `enc.bullets.tokens` / `enc.rootPose` / `enc.mapSize`**：

```js
// 节点：token 的 dx/dy/dRot 是【相对根】的 ⟹ 绝对 = rootPose + token
nodes.push({ ..., x: rp.x + t[6], y: rp.y + t[7], rot: rp.rot + t[8], ... });
// 子弹：token 的 x/y/θ 本来就是绝对量 ⟹ 直接用
bullets.push({ x: b[0], y: b[1], theta: b[4], ... });
// 分叉：按 parentIdx 收 slot
```

页子的绘制路径是 **`enc = encode(...)` → `scene = buildScene(enc)` → `draw(scene)`**：
**`draw()` 的入参里没有 `gc`、没有 `adapter`** ⟹ **它想"另取一份"也拿不到句柄**。
🔎 **自查**：`grep -n "getTank(\|getProjectiles()\|getCollectibles()" vantage_observe_debug.html` = **只有 1 处命中，且是第 89 行的注释**（写着"绝不碰"）⟹ **绘制路径 0 处游戏取数**。

### 3.2 **数值上逐位相等**（**真开一局实测**，探针 `_probe_2_3_debug_page_path.js`）

场景：真 `vantCount:1` + 360 帧 + 每 3 帧注入真子弹；**90 个采样帧**，取 `N=82` 的那一帧：

| 判据 | 实测 | 判定 |
|---|---|---|
| 根 token 解回 `rootPose` | `rootBad = 0` | ✅ |
| **逐节点** `scene.x === rootPose.x + token[6]` | **`xBad = 0` / N=82** | ✅ |
| **逐节点** `scene.y === rootPose.y + token[7]` | **`yBad = 0`** | ✅ |
| **逐节点** `scene.rot === rootPose.rot + token[8]` | **`rotBad = 0`** | ✅ |
| **逐子弹** `scene ≡ token`（`x,y,vx,vy,θ,type,lifeLeft` 全等） | **`bBad = 0` / M=3** | ✅ |
| `θ` 约定 = `atan2(speedX,-speedY)`（唯一真源） | `atan2(speedX,-speedY)` | ✅ |

**真样例（token → 画面坐标）**：
```
节点 idx=1  token=[uid 10, parentIdx 0, slot 0, depth 1, tRel 0.004333, L 2,
                   dx -0.015396726717405329, dy 0.12652307175288335, dRot 0.05, hasGrown 0]
   rootPose.x = 55
   ⟹ scene.x = 55 + (-0.015396726717405329) = 54.984603273282595   ← 探针逐位比过，相等
```

### 3.3 ⚠️ **一个例外的如实说明：墙不在 token 里**

**token 的 10+7 维里【没有墙】**（字段表里也没有）。
⟹ 左画布的背景墙**只能**从 `VantageSandbox.getFusedWallShapes(gc, aiId)` 取（**只读**）。
**我把它明确标注在图例里**（"墙（来自 adapter，token 里没有）"）＋ 画布底部一行字，
**⛔ 不假装它是 token 来源**。**这不违反判据**：判据要的是"**坦克/节点/子弹**"不能另取一份（那才是会被"人眼核对"骗到的东西），而墙是**静态背景**、不随 token 变。

### 3.4 为什么必须加 `rootPose`（**一处必要的小改**）

节点 token 存的是**相对根**的位移（字段表 N7/N8/N9，这是主人"照相机跟着根走"的设计），
**光靠 token 画不出绝对坐标** ⟹ 我在 `encode()` 的返回里加了 **`rootPose`**（**与节点 token 同一次调用的产物**，取自 `encodeNodes` 已经找到的那一行根）。
⛔ **没有**让画布去问 `gc.getTank()` 要一次 —— 那样就正好踩了要防的坑。

## 四、两个"替代信号"的可视化

### 4.1 ① **缺 `slot`（= 那一支真死）** —— ✅ **真信号**

* 页子里：**把"同一 `parentIdx` 的节点收齐、看少了哪个 `slot`"**，把该父的连线**标红**，并在右表第 3 节列出「在的 slot / **缺的 slot**」。
* 读法出处：权威版 `:3142`「**把同一父的收齐、看缺哪个槽位即可**」。
* **第二步实测过的真实样例**（`_probe_2_3_observe_selfproof.js`，223 个采样帧）：
  `grownByChildCount = { "9": 1957, "8": 8, "7": 9 }` ⟹ **确实存在只有 8 / 7 支的父** ⟹ **"缺 slot"是可读的**。
* ⚠️ **本步的探针（90 帧）没复现**（`nMissing=0`）—— **如实记为"本局未复现"**（见 §六），**没有**为了变绿去改判据。

### 4.2 ② ⚠️ **`L=1` —— 我第二步说错了，本步更正**

**第二步报告 §4.6 我写过**：「真死子节点的 `L` 恒为 `1`（实测 `{"1":9}`）⟹ 可当过渡口径的真死候选」。

**🔴 本步实测把它否掉了**：跨帧累计 **`L=1` 占全部节点 `982/1260 = 77.9%`**。
⟹ **`L=1` 只是"短枝"**（`back ∈ [0,1) = {0}`，这一段本来就只切了 1 帧 —— 规则版 `probeSegment` 的 `tMin` 造成的），**与"真死"没有充分关系**。

**我当时犯的错 = 本项目最经典的"单向检查"**：我只看「**真死的节点里 `L` 是多少**」，**没看「`L=1` 的节点里有多少是真死」**（没算假阳率）⟹ **`P(L=1 | 真死) = 1` 被我当成了 `P(真死 | L=1) = 1`**。
**这正是 `AGENTS.md`「探针 PASS 时要能说出它为什么 PASS」和"假绿通道"同族。**

**⟹ 处置**：
1. **页子里把它降级**：图例改标「**L=1 节点（短枝；⚠️ 不是真死判据 —— 实测占 77.9%，非特异）**」；第 4 节明确写出更正；
2. **`缺 slot` 仍是**真信号**；
3. ⭐ **这条更正反而【支持裁决 (a)】**：**今天 token 里确实没有可用的"真死"信号** ⟹ **等阶段 3-2（真死不建节点）** 是对的，⛔ **不许现在加字段**。
