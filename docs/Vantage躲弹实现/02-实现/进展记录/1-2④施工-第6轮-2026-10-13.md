## 三 ABI v12 原子落法与 wasm 自证

* **原子批次**（同一批落，不留中间态）：A（lib.rs）→ B → C → D(0) → E（bridge）→ F/G →
  `bash game_core/rust/build_wasm.sh` → 版本三处戳（`TREE_VERSION v174` / `index.html ?v=174` /
  `diff_tree_low_eval_frames.js:11`）+ **三个被改 JS 的 script 标签缓存戳**（sandbox 70→71 / scoring 40→41 /
  bridge 16→17）——理由与 wasm 的 `?v=18→19` 完全相同：不提升就吃浏览器旧缓存。
* **为什么必须原子**：`vantage_rust_bridge.js` 的调用点实参个数与 `lib.rs` 尾参一一对应；
  只改源码版本号不同步 bridge/wasm 会得到「wasm 12 + bridge 按 11 传参」⟹ 尾参 `undefined`
  ⟹ Rust 快路**静默**掉回 JS（回归全绿也查不出来）。本轮 E 与 wasm 同批落，不存在这个窗口。
* **自证**：`rm target/.../vantage_core.wasm && bash game_core/rust/build_wasm.sh` 后

* **最终产物上的复跑**：最后一次重编只来自 `lib.rs` 的**注释更正**（行为不变）；

## 四 顺手修：sweep 合并规则不对称（JS 偏晚）

（诊断全文：`03-踩坑与待查/待查与审计/激光帧号差诊断-2026-10-14.md`，md5 `fabf4429…`）

* **根因**：JS 融合把 sweep 当 fallback（`if (!dead[i] && sweepHit[i]>=0)`）——`dead[i]` 已被**另一颗弹**
  的接触置 true 时，**更早的 sweep 帧被丢掉**；Rust 是取 min。⟹ JS 偏晚（1049 条分歧里
  `jsSweepHit` 全等于 Rust 帧且全早于 JS 最终帧）。
* **修法**（`vantage_sandbox.js:2526` 一带，一行条件；**Rust 不动**）：
  `if (sweepHit[i] >= 0 && (!dead[i] || sweepHit[i] < deathFrame[i])) { … }`
* ⚠️ `geoHit`（几何补判）那处的同类 `!dead` **没动**（Rust 没有 geoHit；改了会让 JS 在非激光场景比 Rust 更早）——

## 八 未解决项（诚实清单）

1. **导弹专属 `vant=2` 整局基线**：现有基线场景无导弹（grep 0 命中）。要重录一个"AI 捡到 HOMING_MISSILE 并发射"
   的 600 帧基线（需要给录放 harness 加固定武器注入），本轮未做；已用的替代证据见 §六。
2. **导航表一次性建表 117ms（16×10）**：是「第一次见到制导弹」那一刻的一次性卡顿。
   可选优化：后台/切片建表、或在换图时就建好（把卡顿挪到换图瞬间）；本轮只给数字、不改。
3. **`geoHit` 的同类合并不对称**：与 sweep 同形（`!dead` fallback），但 Rust 没有 geoHit，
   改了会让 JS 在非激光场景比 Rust 更早；本 seed 非激光分歧 0 ⟹ 另立项。
4. **"模拟中换目标"无法在融合世界判定**：已按批准口径只做"**本段摘掉**"——
   建表/摆位一刻按 `currentTargetPlayerId` 判，`null`（未激活）保守保留；
   真正的"逐帧换目标"需要别人未来轨迹/位置，Rust 融合世界连别的坦克都没有 ⟹ 明确不做。
   B2 生产者对 `node.startT > anchorOffset` 的深未来节点也有一个明确近似（锚点到节点起点那段把目标冻结在
   `samples[0]`），已写在代码注释里。
5. **`_i3_scorepath_fd0_guard.js` 的 md5 钉被更新**：`vantage_scoring.js` 因 D2 追加而 md5 变化
   （`3705a14e… → 5b1f2a99…`）；16 条语义断言全过。若守卫作者希望 md5 固定，需要把 D2 挪出 scoring
   （但威胁表 D2 是已批准设计，见 §一-F）。
6. **`hidden` 哨兵拆分**（含 `q.fps`/`pg`/`tf`/`lu` 实时量）：仍按"单独标注、不当回归失败"处理，本轮未拆。
7. **`rollout_trace` CLI 没有 `vt_set_maze` 入口**：用 CLI 跑制导弹场景前必须先装表；
   已在 CLI 注释里写明（本轮的制导弹验证都走 bridge/部署 wasm，不受影响）。
