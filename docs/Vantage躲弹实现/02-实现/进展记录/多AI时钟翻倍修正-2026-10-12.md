### 1.2 `vant=1` 的 1.019/1.02 是什么：**headless 虚拟时钟的整数毫秒截断偏差**（不是"每帧余量"）

推导（headless 下 `clock.js` 接管时钟）：

- `window.__vt.t = n × 1000/60`（**浮点**）；`Date.now` 被换成 `() => epoch + state.t`（**浮点**）；
- 但 `new Date()` 走的是 `VirtualDate` → `new RealDate(epoch + state.t)`，**Date 只能存整数毫秒** ⟹ `gc.lastUpdate.getTime()` 是 `floor(t_{n-1})`；
- 于是旧算式的逐帧样本是
  `raw_n = Date.now() − luMs = t_n − floor(t_{n−1}) = dt + frac(t_{n−1})`；
- `frac(t)` 以 `{0, 1/3, 2/3}`（60fps 下）循环 ⟹ **均值 = 16.6667 + 0.3333 = 17.0 ms = +2.0%**。

**实测三种值正好是那三个**（改前 `tickRawWallMs` min/max/med = `16.6667 / 17.3333 / 17.0`，mean=17.0）。
这不是"合理的每帧余量"，而是一个**只在 headless 成立的系统性 +2% 漂移**：
真机 `Date.now()` 与 `new Date()` 同为整数毫秒，逐帧差的和会望远镜抵消【推断】；但**我们所有训练/回归/评测都在 headless**，
所以它会把一切"树秒↔游戏秒"的换算抬 2%，并且让 §三 的接受指标永远到不了 1.0。

**修法**：回退分支改用 `Math.floor(Date.now()) − luMs`（与游戏自己 `new Date()` 的口径一致）。
floor 后样本 ∈ `{16,17,17}`，**均值精确 = 16.6667ms**（改后 `ratioAcc=0.999958`，见 §三）。

> `1.019` 与 `1.02` 的 0.1% 差：盲区报告的 ratio 是"轨迹代内 `Δdelta/ΔlifeAge`"（两侧增量阈值、首末取点），
> 本探针是"`ΣΔ_timeAcc / ΣΔt`"直接测。两者是同一机制的两个采样口径，**不是第二处漂移**。

## 二、改动（带行号）

### 2.1 `vantage_tree.js`：回退分支按"游戏帧身份"去重（L1512-L1526）

```js
if (luMs !== null) {
    // v170：游戏帧身份 = gc.lastUpdate 的时间戳。
    if (luMs === _lastSeenWorldClock) return 0;   // ← 新增：同一帧第 2 个 AI 返回 0（同训练分支语义）
    _lastSeenWorldClock = luMs;                    // ← 新增：消费掉本帧
    var raw = (Math.floor(Date.now()) - luMs) / 1000.0;   // ← 改：整数毫秒口径（原为 Date.now()）
    if (raw > 0 && raw <= cap * 1.5) w = Math.min(raw, cap);
}
```

配套：

| 位置 | 改动 |
|---|---|
| `vantage_tree.js:1437` | 新增模块级状态 `var _lastSeenWorldClock = null;`（与 `_lastSeenWorldStep` 并列） |
| `vantage_tree.js:8080` | `reset()` 清 `_lastSeenWorldClock = null;`（v139 跨局纪律同款） |
| `vantage_tree.js:1486` | **保护行原样未动**（`if (seen === _lastSeenWorldStep) return 0;`） |

**为什么用 `gc.lastUpdate` 时间戳当"游戏帧身份"**：非训练模式没有步数计数器；而
`GameController.update()` 每帧只做 `var time=new Date(); ...; this.lastUpdate=time;`（bundle 原文，压成一行），
`lastUpdate` 恰好就是"最近一次世界 update"的身份证。暂停时它不变 ⟹ 重复 tick 返回 0；世界真的又走了一帧 ⟹ 它变化 ⟹ 放行一次。
testbench 的暂停递进（`vantage_testbench.js:283-286`）也会每步改写它 ⟹ 每步恰好消费一次。

## 六、`_lastWorldDt` guard（裁决 #2，已做；**不升版**）

`vantage_tree.js:7514-7520`：

```js
var worldDt = resolveWorldDt(ai, dt);
```

`vant=1`（唯一生产配置）里 `worldDt` 本来就 >0 ⟹ 本行是 no-op。

**中立性实测（不是推理）**：
