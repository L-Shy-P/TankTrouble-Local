## 一 完整链条：为什么“无条件也不返回”、`pos_k=None` 只是误读

### 1. 先澄清两个误判

- **`pos_k` 不是 None。** 临时把被 verify 的 `k` 与 `threat_bullet_pos` 结果编码返回过：small-step 是 `pos_k=(1,5) → pos_k1=(4.6,5)`，center 是 `(5,5)→(5,5)`，都在坦克上。
- **“无条件 `laser_hit=true` 也不返回”不是流程没走到**：`verify_death_for_node` 确实在 k=0 返回了 `Ok((0, 1))`；但返回 0 后，调用方把它丢了。之前用 9999/8888 哨兵能看见，是因为哨兵 >0 恰好穿过了那个 sink；把返回值换成 0、或把 `laser_hit` 改无条件，返回值仍是 0，所以看起来“没生效”。

### 2. 链条（按代码逐段）

1. `danger_frames_for_samples_with_chunks`（`rescore.rs:1021`）对每个 threat 算 `radius = envelope + bullet_radius + DANGER_MARGIN + speed*dt`，给 `flags[i]`（i=1..samples-1）打危险帧。
2. `verify_death_for_node`（`rescore.rs:1101`）：`max_steps = node.frames.min(node.samples.len()-1)`；只对 `danger_flags[k+1] != 0` 的 k 做验证。
3. 对每个 k：`p0=node.samples[k]`、`p1=node.samples[k+1]`；`threat_bullet_pos(th, t_k)/(t_k1)` 给出弹位；`if th.is_laser` 用 `sweep_hits_tank_pose(p0/p1, pos_k, end)` 做线段×sensor 多边形；命中 `laser_hit=true`。
4. Step 后 `verified_frames += 1; if laser_hit { return Ok((k as i32, verified_frames)); }` —— **这里确实返回了 `(0, 1)`**（修前也一样；哨兵证明 `th.is_laser=true`）。
5. **断点就在调用方 `rescore_nodes`（修前 `rescore.rs:1361`，最终 `:1365`）**：
   ```rust
   let (death_frame, verified_frames) = verify_death_for_node(...)?;
   if death_frame > 0 {              // ← fd=0 在这里被当成“没死”
       ... out.death_frame = death_frame; out.per_frame_scores = [-penalty];
   } else {
       out.verified_frames = verified_frames;   // 只写了 verified，death_frame 仍是默认 -1
   }
   ```
   所以 `vt_rescore_nodes` 的 `out_death[i]` 是 -1，`out.per_frame_scores` 还是整段活帧 —— 桥上看到的就是 `deathFrame=-1`。
6. **第二断点（JS bridge）`vantage_rust_bridge.js` rescore 输出映射**：`actualFrames = df > 0 ? df : Math.min(nodeFrames, samples-1)`。即使 Rust 已回 0，`df=0` 也会被当成“没死”去读满 `frames` 条分数（而 Rust 只写了 1 条：`[-deathPenalty]`）。
7. **第三断点（JS sandbox）`vantage_sandbox.js:2715 / :2888`**：`dead: r.deathFrame > 0` / `dead: rn.deathFrame > 0`，fd=0 仍被标成“活”。

### 3. 修复

- `rescore.rs:1365`：`if death_frame >= 0`；`death_idx = death_frame.max(0)`；取前缀用 `saturating_sub(1)`，fd=0 → `per_frame_scores=[-death_penalty]`、`total_score=-death_penalty`、`death_frame` **原样保留 0**（⛔ 不改写成 1）。
- `vantage_rust_bridge.js` 两处：`actualFrames = df >= 0 ? Math.max(1, df) : ...`（rescore 与 scorePaths 各一处；fd=0 只读 1 条）。
- `vantage_sandbox.js` 两处：`dead: deathFrame >= 0`。
- `score_paths.rs` 的 `>=0` 是上一轮已修，本轮未动。

### ② N2/N3 墙反例：`_probe_laser_wall_cases.js`（N2 PASS，**N3 FAIL，真缺口**）

- 场景：水平墙 `y∈[-0.1,0.1]`；激光 `(1.5,0.5)`、速度 180 沿 `(1,-1)/√2`；N2 坦克 `(4,-2)`（墙下、直射本来会命中但墙先反射走）；N3 坦克 `(4,2)`（反射后同帧命中）。
- oracle：独立 JS 实现“射线×墙最早命中 + 镜面反射 + 线段×真坦克多边形”，最多 4 段。

```text
  PASS  N2_wall_blocks             oracle=false rustDead=false rustFd=-1 expect=false/-1
  FAIL  N3_same_frame_reflect      oracle=true  rustDead=false rustFd=-1 expect=true/0
N2/N3 PROBE FAILED (1)
```

**诊断（这是真缺口，不是构造错）**：Rust/JS 的 sweep 都只吃 `Step 前 → Step 后实际位置` 这一段。N3 里 Box2D 的 bullet CCD 在墙上就把弹截停了（post 在墙面附近），`sweep_segments_against_walls` 拿到的实际位移段在墙处就用完了，没有“剩余距离”可反射，反射后的线段根本没生成；oracle 用的是解析的整步轨迹，所以 oracle 命中而 wasm 不命中。
**修法方向（未在本轮做）**：sweep 除了实际 pre→post 段，还要**并行**测一条“意图段” `pre + v_start*dt`（v 取 Step 前槽速度），再做墙裁剪/反射；两条都测可同时覆盖“弹被墙截停”和“弹已物理反弹”两种 Box2D 行为。JS `simulateFusedBatch` 与 Rust `run_rollout_batch` 需同步改 + 重编 wasm。
**影响**：N3 是激光特有的同帧反射命中；不修会让“墙后反射打死”的候选在 rescore/rollout 里偏绿。建议下一轮优先。

### ③ 性能实测

**(a) 新增 `_probe_laser_perf.js`：9 op × 75 帧、7 轮 × 120 次取中位（部署 wasm）**

```text
  case            ms/call   µs/op·frame   vs A(中位)
  A 无弹             2.217          3.284        0.00%
  B 1 普通弹          2.484          3.680       12.06%
  C 1 激光弹          2.743          4.064       23.75%
  D 5 激光弹          2.994          4.435       35.06%
```

- 读法：一次 `rolloutBatch` = 9 条候选路线 × 76 采样 ≈ 675 op·帧；激光在场比无弹多约 `0.53ms/次`（1 颗）到 `0.78ms/次`（5 颗），约 `+24%~+35%`。多次运行有 ±0.3ms 抖动；这是**候选路线批量评估**的数字，不是浏览器里整棵树的 tick。
- **(b) 既有 `_probe_perf_paths.js`（v172 重跑）**：`9 op × 75 帧` 单次、真适配器：
  `laser radius 0: JS评分路径 1.03ms / Rust全包 1.15ms（0.9x）`；对照 `crossing bullet 12.73ms / 1.39ms`、`far bullet 11.87ms / 1.75ms`。→ 激光一帧跨过时 Rust 路径反而比 JS 评分路径略快，扫掠本身不是瓶颈。
- **树 tick 整棵未单独测**：headless 里最接近的是上面 9 条候选路线；如需浏览器实测 `VantageTree.getDesiredOperation` 一 tick，需另开 headless 计时脚本（列 §六）。

3. **3 个 CLI 型 diff 环境不可跑**（缺 MSVC），需在有 VC Tools 的机器补跑。
4. **N2/N3 目前只测了 Rust wasm + 解析 oracle**，没有把“JS 融合世界”在同一自定义墙场景下对拍；JS 侧墙裁剪(RayCast)的同类 N3 缺口尚未取数（很可能同因）。
5. 性能数字有 ±0.3ms 抖动；如需稳定基线可在空闲机器上跑更多轮。

## 结论

**`rescore` 激光路径闭环了**：不是 `pos_k=None`，而是 `rescore_nodes` 的 `death_frame > 0` 把 `verify_death_for_node` 已经返回的 `(0,1)` 丢掉，叠加 bridge `actualFrames` 与 JS `dead>0` 两处同款 sink；三处修为 `>=0` 且不改写 fd 后，新差分 `diff_rescore_laser.js` 在同一份脚本上完成 **修前 4/5 FAIL → 修后 5/5 PASS（scoreDiff=0）**。三件小的：fd=0 消费层反例 PASS；性能给了真数字（1 颗激光约 +0.53ms/675 op·帧，约 +24%）；N2 墙挡住 PASS，但 **N3 同帧反射命中 FAIL，是本轮新暴露、需要下一轮优先修的 sweep 缺口**。
