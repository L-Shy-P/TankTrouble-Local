## 三、面板上的四件事（都已真跑）

### 1) 智能体模式 → 神经网络（真接我们的策略）
- 面板：`#vt-agent-rows` 的 `select[data-act="vt-agent-mode"]`（`rule` / `nn`）。
- 决策桥：**原样复用** `_tools/headless/inject_fire.js`（服务器 `/vt_inject_fire.js` 下发，`game_core/server.py:417`）——
  `__b.step(nodeId,fire)` 读观测、`__b.build()` 当帧沿树按 slot 重走取新鲜节点 id、`__b.setFireBack('now')`。
- 推理：观测 JSON POST `/vt_policy`（`game_core/server.py:433`），由 `_tools/training/policy_server_graph.py`
  一问一答（`VT_CKPT` 权重，stderr 逐行回显，⛔ 不 DEVNULL）。
- **实测**（`D:/vt_run/evidence/panel_nn_e2e.json`，真游戏路径）：
  `served=2079 次策略调用 / err=0 / 服务端延迟中位 8.0ms / 树节点 1000 / N=838`，
  采样 `nodeId = [57,60,69,79,75,34,37,57,90,122,48,28,80,88,98,86]`（**每帧在变**，不是规则版）。
- ⚠️ 权重是 `D:/vt_run/seed/ckpt/last.pt`（`step=3`）；策略**开火头输出 logit≈-176 ⟹ fire=0**
  （服务端 `FIRE_DIST n=200 fire1=0`）。所以现在是「会走会选路、但不开枪」，这是**权重**问题，不是面板问题。

### 2) 三个开关（互不联动，唯一落点 `window.__vtConfig`）

   `fireErr="拿不到游戏游标 agentFrame（undefined）"`、`giveUpB` 偏高（另一代理在改 `inject_fire.js`，本单不碰）；
3. 决策覆盖率 ~70-85%（一问一答单飞，`inflight` 时跳过；GPU 上策略单请求 ~8ms）；
