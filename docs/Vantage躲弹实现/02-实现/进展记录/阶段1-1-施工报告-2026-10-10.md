## 一、改了什么（带 `文件:行号`）

### 1. `vantage_tree.js`：校准器重写（L7093–L7194）

**旧实现**（改动前 L7086–L7124）：
`弹.getTimeAlive()` 逐帧差分 → `alpha 0.02` 慢平滑（~50 tick）→ 钳 `[0.015,0.03]` → "离 0.02 不到 0.001 就维持常数"。

**新实现**（现在的行号）：

| 位置 | 内容 |
|---|---|
| `vantage_tree.js:7094-7110` | 新注释 + 常量：`FRAME_DT_JITTER_RATIO = 0.05`（抖动带）、`FRAME_DT_SWITCH_RUN = 4`（连续 K 帧，K **【推断】**取 4，文档给 3~5） |
| `vantage_tree.js:7112-7116` | `medianOfNumbers()`（中位数，偶数取中间两数均值） |
| `vantage_tree.js:7119-7126` | `syncFrameDtToSandbox(adapter)`：`FRAME_DT → adapter.constants.FRAME_DT → VantageSandbox.setFrameDtSec()` 一次对账 |
| `vantage_tree.js:7132-7164` | `sampleRealFrameDt(ai)`：**训练模式**读 `rm._ttStepCount/_ttLastStepDt`（与 `resolveWorldDt:1447-1466` 同源同序），否则读 `gc.lastUpdate` 墙钟差分（`Date.getTime()` 或 number 都兼容；`raw <= cap*1.5`、`min(raw,cap)` 与 `resolveWorldDt:1481` 同口径）。**场上没有弹也照样出样本** |
| `vantage_tree.js:7167-7185` | `applyFrameDtSample()`：`|adv−FRAME| ≤ 5%×FRAME` ⇒ 清样本串、**一个数都不改**；连续 4 帧持续偏离 ⇒ `FRAME_DT := 这 4 帧中位数`、清样本串、同步 |
| `vantage_tree.js:7187-7194` | `calibrateFrameDt()`：每次 tick 先 `syncFrameDtToSandbox` 对账，再采样/应用 |

**没有做的事**：没有"平均/平滑"，没有 0.02 锚点，**没有任何 `[0.015,0.03]` 钳位**。
保留的唯一上限是 `maxDeltaSec()`（= 本 build 的 `Constants.MAX_DELTA_TIME = 0.1`）：因为游戏自己
`deltaTime = Math.min(deltaTime, MAX_DELTA_TIME)` 之后才 Step，**物理每步最多 0.1s**，树跟它才是对的（§三.1 20fps 取 0.05、>0.1 时取 0.1）。

### 2. `vantage_tree.js`：跨局清理 / 诊断（L1173–L1178、L7806–L7816、L8215–L8222）

- `reset()`：清 `_frameDtRun / _frameDtSampleKey / _frameDtLastAdv / _frameDtSwitches`，并改用 `syncFrameDtToSandbox(_lastAdapter)`（原来手写的两行同步）。
- `setFrameDtCalibrationEnabled(false)`：同样清理，冻结 0.02 后**真的写进沙箱**（原来那行是空调用）。
- `exportRecord().meta` 增 `frameDtMeasured / frameDtLastAdv / frameDtSwitches`（**只记录，不参与决策**），给探针/录像看"矫正了几次"。
- 删掉旧状态 `_lastGameClock / _lastGameClockId`（消费者已重写；全仓已无引用）。

### 3. `vantage_sandbox.js`：同步入口补洞 + 值域（L1032–L1060、L2694–L2699）

- 🔴 **根因**：树里三处 `global.VantageSandbox.setFrameDtSec(FRAME_DT)` 但模块级导出对象里**没有** `setFrameDtSec`
  （只有 `createAdapter()` 返回的实例对象上有）⟹ 判断 `if (global.VantageSandbox && global.VantageSandbox.setFrameDtSec)` 永远为假，
  **`_frameDtSec` 永远是 0.02**。实测：改前 `laika` 场景树 `FRAME_DT=0.016`、沙箱 `0.02`（§三.1 "沙箱=" 列）。
- 修：`vantage_sandbox.js:2698-2699` 在模块导出里补 `setFrameDtSec/getFrameDtSec`。
- `setFrameDtSec` 合法范围 `[0.005,0.2] → [0.001,1.0]`（`vantage_sandbox.js:1038-1057`），并且**拒绝时 `console.warn` 一次**
  （旧版静默忽略 = "树以为改了、沙箱还在旧值"这种静默失效，正是本项目最痛的坑）。
- 顺带把两处"预测帧数（0.02s/帧）"的过期注释改成"每帧 `_frameDtSec` 秒"。

### 4. `vantage_tree.js`：`resolveWorldDt` 墙钟回退死代码（L1482–L1498）—— **这一处是额外修的，请审**

**发现**：指令说"实战用 `gc.lastUpdate` 墙钟差分，`resolveWorldDt:1480` 已经在用了"。读了之后发现它**没在用**：

```js
// 改动前（v41 起一直如此）
} else if (typeof gc.lastUpdate === 'number') {       // ← 本 build 的 lastUpdate 是 new Date()
    var raw = (Date.now() - gc.lastUpdate) / 1000.0;
    if (raw > 0 && raw <= cap * 1.5) w = Math.min(raw, cap);
}
```

- 游戏原文（`game_core/js/ce217c9b090cc73ce0e1faa13d20ca15.js`，**压成一行，无行号可引**）：
  `update:function(){var time=new Date();var deltaTime=(time-this.lastUpdate)/1000.0;this.lastUpdate=time;...}`
- 探针每帧读回：`lastUpdateType=object getTime=true`（`prof/_p1_1_before_dt_all.log`）。
- ⟹ 这条墙钟回退**从未生效**，`_timeAcc` 一直吃调用方传的 `physicsElapsedMS`（Phaser **固定 60fps**）；
  而 `calibrateFrameDt` 校出来的 `FRAME_DT` 现在会跟到真实帧长（20fps=0.05）⟹ 权威版 §7.10 G.1 说的
  "`_frameDtSec` 与 `_timeAcc` 不一致就错位"在 30/20fps 下真实存在。

**实测量级**（同一条 RNG 带、同一张图，只切换这一分支，见 §三.2）：
`bulletErr`（树预测弹位 vs 真实弹位）在 30fps 末/20fps 末：**1.2m / 12.558m**（回退死）→ **0.054m / 0.2521m**（回退活）。

**改动**：把类型判断换成和 `calibrateFrameDt` 同一个读法（Date 取 `getTime()`，兼容 number）；其余（`cap*1.5` 拒绝大间隔、`min(raw,cap)`）原样。
**保护行 `if (seen === _lastSeenWorldStep) return 0;`（`vantage_tree.js:1466`）一字未动**，训练模式精确步数表的优先级也没动。

> **【请拍板】** 这一处不在《细化执行方案 §S1.4》逐条清单里，但没有它，"时间基准统一"只统一了一半
> （沙箱步长对了、树时钟在 30fps 下仍是世界的一半）。如果你认为超出 1-1 范围：回退就是把 `vantage_tree.js:1482-1498`
> 换回 `} else if (typeof gc.lastUpdate === 'number') { ... }` 三行，**代价是 12.5m 的弹道误差回来**。

### 2.3 规则版决策：受控对照（同 RNG = 同一张图/同一个世界）

**这不是"旧代码 vs 新代码"的逐字节对拍**（旧代码已改掉、且探针当时没存 RNG 带）。
做法：用**新代码**、同一条 Math.random 带，只切换"校准开 / 校准关（冻结 FRAME_DT=0.02）"。
`--calib-off` 是项目现成的 v140 调试开关，冻结 0.02 正是旧校准器在"场上没弹"时的行为。

```

node _tools/headless/_probe_p1_1_dt.js --case laika --tag final_rule_off --rngseq prof/_p1_1_rng_laika_final.json --calib-off
node _tools/headless/_probe_p1_1_rulediff.js prof/_p1_1_dt_laika_final_rule_on.jsonl prof/_p1_1_dt_laika_final_rule_off.jsonl
```

```

首个 op 分歧帧 = null ; 首个 commitNode 分歧帧 = 29 ; 首个位姿分歧帧 = null
```

**怎么读**：

- **外部操作（`getDesiredOperation().opName`）200/200 帧一致、坦克位姿 0.0000m 差** ⟹ 在这个（偏静止的）场景里，

- **不是意外副作用**：位姿 0 差、op 0 差说明没有"把规则版改坏"；差异集中在"时间账本"上，正是本阶段要动的量。

## 四、没解决 / 拿不准 / 需要确认

1. **【请拍板】`resolveWorldDt` 那一处改动（§一.4）** 不在 §S1.4 的逐条清单里。我判断它属于"时间基准统一"的必要一半
   （G.1 明说两个帧长不一致就错位），且不动保护行；但若你认为越界，可按 §一.4 末尾的一行回退，代价是 12.5m 弹位误差回来。
2. **【推断】K=4**：文档给"K 取 3~5"，我选 4（两次"帧长跳变→矫正"的实测响应都是第 4 帧到位）。要改只是常量 `FRAME_DT_SWITCH_RUN`（`vantage_tree.js:7106`）。
3. **【实测偏差，属 5% 带内】整数毫秒量化让稳定值偏 +3%**：虚拟/真实时钟的 `Date` 只有 1ms 分辨率，
   60fps 下逐帧差在 `16/17/17.33ms` 之间跳；4 帧中位数 = **0.01717**（真值 0.016667，+3%）。它落在 5% 抖动带内，
   所以按主人裁定"不再矫"。**【推断】可接受**（比旧版 0.02 的 20% 误差好一个量级）；若以后要求更紧，建议
   "中位数窗口拉长到 8~16 帧"或"用平均"，**但这会偏离文档的 K=3~5 口径，需你定**。
4. **【事实纠正】权威版 §7.10 G.5 说 `MAX_DELTA_TIME = 1.0`，本 build 是 `1.0/10.0 = 0.1`**
   （`game_core/js/b714588dc4621fe104113111ba90b1a7.js`；阶段0 header 里也记着 0.1）。
   本次 `cap` 取的是运行时 `maxDeltaSec()`（=0.1），与游戏自己的钳制一致。
5. **【未解】Rust 侧值域 clamp 与 JS 侧不一致**：Rust `set_frame_dt` 只收 `0.005..=0.2`
   （`game_core/rust/diff_rust_frame_dt_sync.js` 断言），我把 JS 沙箱放宽到了 `0.001~1.0`。
   本 build 游戏自己 cap 0.1，**高侧永远够不着**；但 **>200fps（如 240Hz，dt≈4.17ms）时 JS 会用 0.00417、Rust 会忽略**，
   而桥的 `setFrameDt` 返回 true（不会察觉）→ 又是"两套帧长"。**本轮没动 Rust**（铁律：动 Rust 要三处同改 + 对拍）；建议后续给桥加"读回 Rust 实际值"或统一值域。
6. **【残留】突然掉帧瞬间，已经生成的弹道 track 仍按旧帧长摆位**，`bulletErr` 会瞬时抬升
   （修完树时钟后 20fps 峰值 0.2521m）。轨迹重建/弹种四缺项是 1-2 及以后的事，没在本阶段动。
7. **【未做】版本号没升**：`TREE_VERSION` 仍是 `v162`。因为 `game_core/index.html:537` 的 `?v=162` 与
   `diff_tree_low_eval_frames.js` 断言 `VERSION==='v162'` 要一起改，超出"只改俩 js"的范围。**建议**下一次施工
   统一升 `v163` 并同步 `index.html`。
8. **【覆盖面】规则版决策只在"idle 场景 + 200 帧 + 一张图"做了受控对照**，没有做"有弹幕、需要换操作"的场景矩阵；
   结论"op 不变"**不能外推**到所有局面（段末时序变了是事实）。如果要更强的零回归结论，建议用阶段0 的录制基座
   加一局"有 vantage 对手 + 固定 RNG"的长对拍。
9. **【未做】真机（非 headless 虚拟时钟）实测**：所有证据都来自 `--remote-debugging` 无头 + 虚拟 60fps 时钟；
   "真机掉帧"用的是探针改 `__vt.dt` 模拟。真机 30/20fps 的 `Date` 抖动特性**未实测**。
10. **【口径】"持续偏离"没要求同方向**：按文档字面，任何 4 连帧 `|adv−FRAME|>5%` 就切中位数（中位数天然兜底；
    实测 ±交替抖动也不会误切——它会切回同一个数而 `switches` 不增加）。若要"同向才切"，改 `applyFrameDtSample` 一处。
