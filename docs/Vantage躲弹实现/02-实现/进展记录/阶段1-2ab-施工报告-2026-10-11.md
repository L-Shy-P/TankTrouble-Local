## 三、① 霰弹撞墙/撞盾**减命**（剩余寿命 ≤ 0.7s）

### 3.1 依据（全部是代码原文，不是从函数名猜的）

- **游戏**（bundle `418577fd210ad079ea3d1e5e04050fe0.js`）：
  ```js
  Shotgun.methods({
    hitShield: function () { this._super(); this.timeAlive = Math.max(this.timeAlive, Constants.SHOTGUN_MAX_LIFETIME - Constants.SHOTGUN_LIFETIME_AFTER_MAZE_HIT); },
    hitMaze:   function () { this._super(); this.timeAlive = Math.max(this.timeAlive, Constants.SHOTGUN_MAX_LIFETIME - Constants.SHOTGUN_LIFETIME_AFTER_MAZE_HIT); } });
  ```
  ⟹ **撞墙是"减命"**（把 `timeAlive` 抬到 ≥1.3s ⟹ 剩余 ≤0.7s），**不是"续命"**。
  这正是 `AGENTS.md`「第十轮复盘」第 2 条更正过的那条 —— 方向反了就是平衡性事故。
- **常量**（`b714588dc4621fe104113111ba90b1a7.js`）：`SHOTGUN_MAX_LIFETIME: 2.0`、`SHOTGUN_LIFETIME_AFTER_MAZE_HIT: 0.7`。
- **建弹**（`46989e393ad0e356ac8a0c6c53b362f9.js`）：`Shotgun.create(state, Constants.SHOTGUN_MAX_LIFETIME, 35, 5, …)`
  ⟹ 霰弹的 `lifeTotal` **恒等于 MAX=2.0**。

### 3.2 三处同改（本次全部就位）

| 处 | 位置 | 写法 |
|---|---|---|
| JS track | `vantage_sandbox.js:543`（`simulateBulletTracks` 的接触帧） | `s.lifeLeft = clampShotgunLifeLeftAfterHit(s.lifeTotal, s.lifeLeft)` |
| JS 融合 | `vantage_sandbox.js:1915`（`simulateFusedBatch` 的接触帧） | 同上 |
| Rust | `rollout.rs:920-984`（Step 后的接触枚举 → `:979-981` 调用） | `slots[si].life_left = clamp_shotgun_life_left_after_hit(...)` |
| 共用公式 | `vantage_sandbox.js:388` / `rollout.rs:81` | 见下 |
| ABI | `vantage_rust_bridge.js:396,1365` 发码；`lib.rs:217-218` 解码 | `b.isShotgun ? 2 : (b.isShrapnel ? 1 : 0)` |

**公式的"逐字对齐"**：JS 是原式 `剩余 = lifeTotal − max(lifeTotal − lifeLeft, MAX − AFTER)`；
Rust 侧 ABI **只带 `lifeLeft`（不带 lifeTotal）**，而霰弹 `lifeTotal ≡ MAX`，于是原式代数等价于
`剩余 = min(lifeLeft, AFTER)` —— 我用的是**化简式**，注释里标明了这是等价而不是另立语义（`rollout.rs:69-82`）。
`AFTER` 在 Rust 侧是常量 `SHOTGUN_LIFETIME_AFTER_MAZE_HIT_SEC = 0.7`（游戏同名常量同值）。

其他两条纪律（都照抄了原版）：
- **只在真的发生 hit 的那一帧才钳**（`rollout.rs:976-982`）。无条件钳 = 霰弹永远活不过 0.7s，**方向又反了**。
- **破片不吃这条**（`Shrapnel.hitMaze` 完全覆盖、不调 `super`）。

**新增对拍** `game_core/rust/diff_shotgun_wall_lifetime.js` → **PASS**（完整输出见证据日志 §A）：

## 四、② 反弹去抖上限（`Projectile.done()` 第三支）

### 4.1 语义（**不是**"总共弹 5 次消失"）

- **【代码原文】**（bundle `418577fd…js`）：
  ```js
  Projectile.update: var currentTimeout = new Date().getTime() - this.timeoutWindow;
                     for (var i = 0; i < this.bounces.length; ++i) {
                         if (this.bounces[i] >= currentTimeout) { this.bounces.splice(0, i); break; } }
  hitMaze/hitShield: this.bounces.push(new Date().getTime());
  done:              this.timeAlive >= this.lifetime || this.stopped || this.bounces.length >= this.timeoutBounceCount;
  ```
  `HomingMissile.update` 里**自己复制了一份剪枝循环**（导弹不走基类 `update`）。
- **常量**：`PROJECTILE_BOUNCE_TIMEOUT_WINDOW: 35`（**毫秒**）、`PROJECTILE_BOUNCE_TIMEOUT_COUNT: 5`。
- ⟹ **语义 = 「最近 35ms 窗口内累计 ≥5 次撞墙/撞盾接触」的去抖保护**（弹被挤在墙体几何里 / 出生就压墙），
  触发后按 `PROJECTILE_TIMEOUT` 归类销毁。
  **正常飞行永不触发**：实测长走廊 600 帧 **21 次**撞墙、`bounces.length` 最大只有 **1**、弹活满 10.0s。
- **剪枝是"粘性"的**：只在**找到一条 35ms 内的记录**时才删前缀，**全过期时一条都不删**
  （实测单条记录能撑到 467ms 才被删）。`rollout.rs:88-100` 与 `vantage_sandbox.js:341-349` 都逐字照抄。
- ⛔ **绝没有写成"总共弹 5 次消失"** —— 那样长走廊的弹会被提前判死（与游戏不一致）。两个新对拍的静态断言里都钉了这条。

### 4.2 三处同改

| 处 | 位置 | 要点 |
|---|---|---|
| JS track | `vantage_sandbox.js:527`（接触枚举）→ `:560-561`（剪枝 + ≥5） | 与融合共用 `forEachProjectileWallContact` |
| JS 融合 | `vantage_sandbox.js:1895` → `:1932-1933` | 同上；破片不 push、不吃 ② |
| Rust | `rollout.rs:920-976`（枚举 + push `:973-975`）→ `rollout.rs:1008-1016`（剪枝 + ≥5） | `bounces: Vec<f64>` 时间戳 |
| 共用 | `bounceTimeoutWindowSec()` `vantage_sandbox.js:332` / `pruneBounceStamps` `:341` ↔ `rollout.rs:60/64/97` | 35ms→0.035s、count=5 |

顺序**照原版**：`push → 剪枝 → done 判定`（不是先判定再剪枝）；`push → 钳寿命`（① 在同一个接触块里，先 push 再钳）。
槽位按 `last_round` 轮询复用 ⟹ **摆位时必须清空上一轮的 `bounces`**（`rollout.rs:824-827`，与 JS `acquireFusedBullet` 的 `slot.bounces = []` 同口径；不清空会把新弹提前判死，§14 同类教训）。

### 4.3 证据

**新增对拍** `game_core/rust/diff_bounce_timeout_window.js` → **PASS**（完整输出见证据日志 §B）：

| 场景 | 期望 | 实测 |
|---|---|---|
| **内角夹死**（弹种在两面墙内角，2 次接触/帧） | 帧1=2、帧2=4、帧3=**6≥5** ⇒ **第 3 帧销毁** | JS/Rust 都活（59 帧外的坦克没被打死）；JS track 轨迹**只到第 2 帧就断供**；`JS↔Rust maxPos=0` |
| **反事实**（只改 JS `COUNT=99`） | 弹不销毁 ⇒ 坦克该死 | JS 第 **24** 帧打死坦克 ⇒ (A) 的"活"确实来自 ≥5 规则 |
| **贴墙滑行**（1 次接触/帧、连续 60 帧） | 稳态只剩最近 3 条（0/16.7/33.3ms）⇒ **永不触发** | JS/Rust 都在第 **60** 帧打死坦克；JS track 活满 76 帧。**任何"不剪枝/按总接触数"的实现都会在第 5 帧自杀**（那坦克就会活） |

- 【实测·存量对照】实测报告里长走廊 600 帧 21 次撞墙 `bounces.length` 最大=1 —— 本条规则永不误杀正常弹。
