## 四、⭐ "闸门真的生效"的证据

**探针**：`_tools/headless/_probe_p2_gate_full.js`（本次新建，落盘后未再改，md5 `5a0a8eb5…`）。headless 真局、`vantCount:1`、`growWithoutThreats=true`（让树快速长）、1 帧采样 80 点。

```
== §① 产品默认值 ==
  PASS  VERSION=v179 / TREE_DEFAULTS.maxNodes=1000 / TREE_DEFAULTS.horizonSec=10.0
== §② 活树默认（被 vantage_testbench.js 覆盖）==
  PASS  cfg.maxNodes=500 / nodeCapEnabled=false / refineBeyondLimits=true / horizonSec=8
== §③ 控制组：显式 cap=true、refine=false，maxNodes=3000 ==
  PASS  tickOk 69→71，nodeCount 37→55
== §④ 实验组：maxNodes=100 ==
  PASS  树满点 nodeCount=100 maxDepth=11
  PASS  起点满且终点仍满的 1 帧间隔 = 67 个
  PASS  这些间隔内 tickOk 全部冻结（violated=[]）
  PASS  nodeCount 全程 ≤100（末值 100）
  PASS  tickSkippedFull 55→126；tree.stats.agentSkippedFull 0→71
  PASS  恒等式 tickOk+tickSkippedFull+tickErr==tickCalls = 80+126+0=206
== §⑤ 反向：maxNodes 抬回 1000 ==
  PASS  tickOk 80→100；nodeCount 100→244（A 恢复）
P2-GATE-FULL PROBE PASSED
```

**锯齿（为什么长窗口里 tickOk 会有一点点增长）**：commit 会把 `nodeCount` 降回 91，随后 A 被允许再长 1 层（9 个）回到 100，再冻结。80 tick 里这种"解冻→填满"只发生 4 次；**每一个"仍满"的 1 帧间隔都是 0 次调用**。这是"树满禁止生长、不满可长"的正常语义，不是漏判。

**反向验证**：同一局内把 `maxNodes` 抬回 1000，A 立刻恢复、nodeCount 越过 100 —— 证明冻结确由闸门造成，不是智能体挂了 / 树不再 tick。
