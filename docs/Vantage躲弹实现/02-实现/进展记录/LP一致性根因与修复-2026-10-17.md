# ⭐⭐ `ratio` 爆炸的根因：**采集与训练用了两份不同的随机权重**（`2026-10-17` `05:5x`）

> **父代理亲手定位 + 亲手验证 + 亲手修复**。这条把"链路通"变成了"训练有效"。

---

## 一、症状
首轮真数据 PPO：`ratio_max = 47.26` · `kl = 8.605` · `grad_norm = 29562` · `clip_frac = 0.931`
⟹ **训练侧重算的 `logprob` 与采集时服务端给的 `lp` 不一致** ⟹ **这轮更新学的是错的**。

## 二、定位过程（三条，逐条排除）
1. **先排除"填充长度影响位置编码"**（我的头号假设）：
   `net_v2_fixed.py:23` 的 `pos = arange(n)/real.max()` 理论上依赖填充长度。
   **实测**：同一帧，`pad=N` 算得 `lp=-21.185493`、`pad=tier` 算得 `lp=-21.185495` ⟹ **差 `2e-6`、可忽略** ⟹ **假设作废** ✓
   （原因：`real = 未屏蔽 token 数 = N+78` 在两种填充下相同，且节点区下标都是 `0..N-1`）
2. **再排除"记录值本身是脏的"**：换一帧 `lp` 有值的：
   ```
   记录 lp_rec      = -2.096267        （采集时服务端算的）
   我用新建网络重算 = -43.592197        ⚠️ 差 41.5
   服务端（重起一次）= -2.309950        ⚠️ 与记录值也不等
   ```
   ⟹ **两次服务端的 `lp` 都不相等** ⟹ **嫌疑落到"权重"** ✓✓
3. ⭐⭐ **确认根因**：**服务端每次启动都是 `nv2.NetV2()` 随机初始化**（除非给 `VT_CKPT`），
   **而训练器也自己 `NetV2()` 随机初始化** ⟹ **两边是两份不同的权重** ⟹ `logprob` 当然对不上 ✓✓✓

## 三、决定性验证（同一份权重 ⟹ 对上）
```
① 造一份 ckpt（`torch.save({'model': NetV2().state_dict(), ...})`）
② 用 VT_CKPT=<该 ckpt> 起服务端，喂一帧真观测 ⟹ server lp = -1.888059
③ 本地加载【同一份 ckpt】、同一帧、同一 pad ⟹ local lp = -1.888115
   ⟹ |diff| = 5.6e-05  ✓✓ 完全对上
```

## 四、修复（**纯协议层，零代码改动**）
⭐ **采集与训练必须用【同一份 `ckpt`】**：
1. **训练器先产出一份 ckpt**（`--mode smoke` 或任何一次 `cycles` 都会写 `ckpt/last.pt`，**含 `optimizer` 状态**）
2. ⭐ **采集时**：`VT_CKPT=<该 ckpt> node _tools/headless/_collect_tmp.js`
3. ⭐ **训练时**：`--resume <同一份 ckpt>`
4. **每轮循环**：训练完写出新 `ckpt` ⟹ 下一轮采集用**新** `ckpt`（`model_latest.pt` 就是给服务端用的那个）

⚠️ **两个坑**（都实测踩过）：
- **手工造的 ckpt 若 `opt=None` ⟹ 训练器 `--resume` 会崩**（`AttributeError: 'NoneType' has no attribute 'copy'`）⟹
  **要用训练器自己产出的 ckpt** ✓
- **训练器会拒绝"命令行覆盖 ckpt 超参"**（如 `--bootstrap zero`）⟹ 要显式加 `--allow-cfg-override`（**好纪律，别绕过它**）✓
