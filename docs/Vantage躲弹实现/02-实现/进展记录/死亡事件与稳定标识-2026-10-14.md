## 二、`E1` 真 bug 的修法 + 证据（给数字）

**旧代码**（`:383`）：`g.push(last ? num(last.victimPlayerId, -1) : -1, …)`，而 `num()` 只认数字 ⟹ `num("tank_a",-1)` **恒 −1**。
**修法**：新增 `stablePlayerIndex(adapter)`（模块级，P4），死亡事件的 victim/killer **只走索引**：
```js
var vIdx = (rec.victimPlayerId != null && pIdx.idxOf[String(rec.victimPlayerId)] !== undefined)
    ? pIdx.idxOf[String(rec.victimPlayerId)] : -1;
```

**证据（Node，同一份 `getDeaths()` 记录）**：
```
记录: {victimPlayerId:'tank_a', killerPlayerId:'tank_b', deadlyType:-1, x:5, y:6, rot:0.5}
索引表: {tank_a:0, tank_b:1, tank_c:2}
token 死亡 7 维 = [0, 5, 6, 0.5, 1, -1, 0]
                   ↑victimIdx=0（= tank_a = 自车）✓ 不再是 −1     ↑killerIdx=1 = tank_b ✓
```
⟹ **`victim ≠ −1` 且与记录对得上** ✓（验收项达成）

## 四、`P3`：`dT` 定的口径 + 依据

**定案口径：`dTAge` = 树时钟秒 ÷ horizon**（= 与 `tRel`、`rootLag` **完全同一基准**），并写进字段表（字段名 `dTAge`）。

**依据（读码，不是拍脑袋）**：
- `tRel` = `n.tGlobal / horizon`（`:189`）；
- `rootLag` = `lag / horizon`，`lag = d.tNow − d.rootAbsT`（`:254-256`，`d = tree.dumpDiagnostics()`）；
- ⟹ 观测里两个"时间量"**都是"树时钟秒 ÷ horizon"**；`dT` 若用「帧基年龄」或墙钟毫秒 ⟹ **第三个基准** = 本项目已付过多次代价的老坑。
- 实现：`encode()` 从 `lagRes.tNow` 取**树时钟"现在"（秒）**透传进全局段；死亡事件按 `victimId@tWallMs` 记**首次被观测到的 tNow**，`dTAge = (tNow − 首见tNow) / horizon`。
- ⚠️ 语义与近似：这是"**该死亡距今多久**"，**首帧 = 0**；因为打戳发生在"观测器第一次看到这条死亡记录"那一刻，**误差 ≤ 1 个观测 tick**（比混用墙钟毫秒好得多，且**不新增时钟**）。

**对拍（同一致局、同一套 opts）**：把 `tNow` 推 +3 s ⟹ `dTAge` 由 `0` → **`0.3`** = `3 s / horizon(10 s)` ⟹ **与 `tRel`/`rootLag` 的单位一致** ✓

## 五、`P4`：稳定索引表 + 跨帧不变证明

**表规则**（`stablePlayerIndex()`）：自车 = **0**；对手 = **1..N**；**索引按 id 字典序一次性分配、只追加、永不移位/永不复用**；`oppIds`（对手段的顺序）按索引升序 ⟹ 不再依赖 `keyList(tanks)` 的对象键顺序。
**同时用于**：死亡事件（P1/P2）＋ **对手段排序（E6 的"靠数组顺序认人"）**。

**证据（60 帧，中间让对手 `tank_b` 死亡 15 帧再复活 15 帧）**：
```
idx_frames = 60
idx_unique_signatures = ["{tank_a=0, tank_b=1, tank_c=2}"]   ← 60 帧里**只有一种签名**
opp_order_now = ["tank_b","tank_c"]                          ← 按稳定索引升序
```
⟹ **连续 60 帧索引不变；对手死亡（从 getTanks 消失）与复活（回来）期间也不变** ✓（验收项达成）
