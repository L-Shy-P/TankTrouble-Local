## 四、④ `wpn` 是不是"假哨兵"？—— **实测：是**（对非 BULLET 弹种）

### 4.1 实测（探针 `_tools/headless/_i4x_vx_wpn_check.js`，`_i4x_prof/_i4x_vx_wpn_check.json`）

做法：真局里逐个注入**真武器状态**（`XXXWeapon.createInitialWeaponState(...)` → `roundController.setWeaponState(ws)`，
与 `training_mode.js:applyEmitterWeapon` 同一入口），再**逐字照抄 `record_page.js:206-210` 的三元组**读 `wpn`：

```
wout.push([w.playerId, w.type, f._numBullets, f._bulletsFired, f._timeAlive == null ? null : +(+f._timeAlive).toFixed(4)]);
```

| 场上武器（注入后） | `wpn` 行（JSON 化 = 落到哨兵里的样子） | `fieldsJSON` 真键 | 判定 |
|---|---|---|---|
| BULLET（type −1，默认） | `["tank_a",-1,5,1,2.05]` | `_bulletsFired,_numBullets,_timeAlive,_triggerPulled` | ✅ **三字段都有值** |
| SHOTGUN（2） | `["tank_a",2,3,null,null]` | `_numBullets,_reloadTime,_triggerPulled` | 🟡 只剩"剩余弹数" |
| GATLING（5） | `["tank_a",5,20,null,null]` | `_newBurst,_numBullets,_timeSinceFire,_triggerPulled,_weaponCharge` | 🟡 只剩"剩余弹数" |
| LASER（0） | `["tank_a",0,null,null,null]` | `_fired,_timeSinceFire` | 🔴 **三字段全空** |
| HOMING_MISSILE（3） | `["tank_a",3,null,null,null]` | `_activationTime,_launched` | 🔴 **三字段全空** |
| MINE（4） | `["tank_a",4,null,null,null]` | `_numMines,_triggerPulled` | 🔴 **三字段全空**（连 `_numMines` 都没进哨兵） |

**最关键的一枪（导弹发射前后，`wpn` 完全看不见）**：

| | `_launched`（真值，来自 `fieldsJSON`） | `wpn` 行 |
|---|---|---|
| 发射前 | `false` | `["tank_a",3,null,null,null]` |
| **真开火发射后** | **`true`**（`_activationTime=1.917`） | **`["tank_a",3,null,null,null]`（逐字不变）** |

（同一时刻 `wpnJSON` 整体"变了"是**别的行**在变：BULLET 那行 `_timeAlive` 从 `2.15` 走到 `2.233` —— 与导弹无关。
⟹ 这正说明"`wpnChanged` 绿了 ≠ 导弹那格被盯住了"。）

### 4.2 严重性判断（**不夸大**）

| 结论 | 说明 |
|---|---|
| 🔴 **对 LASER / HOMING_MISSILE / MINE 是"空哨兵"** | 整行只携带 `(playerId, type)`：**"激光已开火 / 导弹已发射激活 / 地雷剩余数"这些真会漂移的量，它一个字都不盯** |
| 🟡 对 SHOTGUN / GATLING 只有**一项**有效 | 只剩"剩余弹数"（`_numBullets`）；装填/连发相位（`_reloadTime`/`_timeSinceFire`/`_weaponCharge`/`_newBurst`）不盯 |
| ✅ 对 BULLET **仍有效** | 三字段齐 ⟹ 开局默认弹种的 `hs.wpn` 是真哨兵 |
| ⚠️ 影响面（"少了什么、没少什么"） | **少的是**"武器**内部状态**漂移"这类回归（例：`_launched` 该 true 却 false、`_numMines` 少扣一个、`_reloadTime` 相位不同）。**没少的是**弹飞出去之后的轨迹 —— 仍被 `hs` 的别的字段（b2d/fixtures）、帧字段 `projs`（x/y/type）、`rn`、`drive` 覆盖 ⟹ **不是"整局没有哨兵"，而是"决定性哨兵里少了一格"** |
| ⚠️ 真风险 | `wpn` 属**决定性**（`det`）：两边**都**是 `null` ⟹ **恒等** ⟹ **不会假 FAIL，只会静默漏检** —— 正是"回归全绿、其实没盯"那一类 |


### 4.3 修法建议（**只建议，未动手**）

> 前提：`record_page.js` 有 `VERSION` 纪律 + 一堆 md5 钉（`hidden哨兵分析-2026-10-12.md:21` 等）；要改**必须连"升 VERSION"一起定**。

1. **方案 A（推荐）**：把 `wpn` 从"固定三字段"改成**按弹种取该弹种自己的字段**：
   ```js
   // 每个武器一行 = [playerId, type, "k=v,k=v,…"]（键排序后拼串，长度可控）
   wout.push([w.playerId, w.type,
              Object.keys(f).sort().map(function(k){ return k + '=' + f[k]; }).join(',')]);
   ```
   ⟹ 覆盖**所有**弹种与**所有**字段（含以后新增的弹种），一个武器约 40~80 字符。
2. **方案 B（更省心）**：对 `fieldsJSON` 做**规范化**（`JSON.parse` → 键排序 → 序列化）后入哨兵；等价于 A。
3. **必带动作**：`VERSION` 升一级，并在 `hidden哨兵分析-2026-10-12.md` / `hidden哨兵拆分-验收-2026-10-12.md` 注明
   "**`hs.wpn` 含义变更 ⟹ 旧录制不能与新录制对拍**"。
4. **顺带**：保留"最多 16 个武器"的上限（防哨兵膨胀），但把**被截断条数**也记进哨兵（否则"少一个武器"也看不见）。
5. **可选加固**：单列一个 `wstate`（只放按弹种的关键状态：`launched`/`fired`/`numMines`/`reloadTime`），便于只对关键状态做硬对拍。
