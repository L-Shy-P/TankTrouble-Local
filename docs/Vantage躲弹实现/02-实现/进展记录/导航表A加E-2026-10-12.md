## 四 ★ E 的语义：停用制导后，制导弹**按什么飞**？（你要我说清的那条）

**答：本批**不模拟它**（"不进这一步的模拟"），**不是**"按直飞"** —— 这不是我新定的语义，而是**既有路径**：

* `vantage_sandbox.js:2109-2115`（既有代码，本轮未改）：
  ```js
  var navTables = missileSlotCount ? getMazeNavTables(gameController.getMaze()) : null;
  if (missileSlotCount && !navTables) { ... mns.active = false; parkHomingCopies(mns); ... }
  ```
  紧跟 `:2111` 的既有日志也写着「**制导弹在场但拿不到迷宫导航表（buildNextTileTable 失败）→ 本批制导弹全部停用（不直飞）**」。
* 内核 Rust 路（`:1685-1690`）拿不到表时直接 `return null` ⟹ 该批**回退到 JS 融合世界**（既有行为）。

**⚠️ 但我必须把它的后果挑明（这属于语义影响，供你和主人判断）**：
停用 = **这颗制导弹对树完全不可见** ⟹ 若它其实会打中我方，树**不会预判到**（**假绿**方向）。
另一种语义（"按直飞继续模拟"）会让它**至少以直飞轨迹参与判死**（**假红/保守**方向）。
按项目"宁假红不假绿"的一贯口径，**停用**是**偏危险的那一侧**；不过它只在"迷宫大到超预算"时发生
（当前游戏尺寸 5 929 格位 ≪ 12 000 ⟹ **现网不会触发**）。
【我的建议】**要么保持现状（超预算=极罕见，且已有响亮告警）、要么把超预算改成"按直飞继续模拟 + 响亮告警"** ——
**这是设计选择，我没有自己动**。

   再用 `格对×格子/4000` 预估 ms 后判预算（已写进代码注释）。**本轮按最小改动只做代理量。**
2. **§四 的语义选择**（停用 vs 直飞继续模拟）—— **待你和主人拍**；我没有自己动。

   ⟹ 那种配置下仍是"懒建"（极罕见：生产默认走 Rust 路）。
4. 状态位是**"最近一次导航表动作"**的全局值（不是 per-maze 的字典）⟹ 多迷宫来回切时读到的是最后一次；
