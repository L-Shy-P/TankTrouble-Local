## 三、前移做了什么（+ NaN 隐患处理）

### 3.1 生长前移（**仅智能体路径**）

`vantage_tree.js:7927-7933`（插在 `tree._commitSlice` 判断之前、`agentSeam` 之后）：

```js
var _didEarlyGrow = false;
if (agentPathActive(tree)) {          // 3-0 造的分派口：非 rule 且本帧真有 A 决策
    perfEnd('grow');
    growStep(tree, adapter, tree.threats || evalThreats);
    perfEnd('grow');
    _didEarlyGrow = true;
}
```

`vantage_tree.js:8122-8128`（原末尾那句被守住，防双长）：

```js
if (!_didEarlyGrow) {                 // 规则版 _didEarlyGrow 恒 false ⟹ 与改造前一致
    perfEnd('grow');
    growStep(tree, adapter, tree.threats || evalThreats);
    perfEnd('grow');
}
```

* **§5 铁律**：只在 `agentPathActive(tree)`（接口存在 + `Agents.current().name !== 'rule'`
  + `tree._agentDecision` 非空）时前移；规则版/`decide→null` 时 `_didEarlyGrow` 恒 false
  ⟹ 末尾调用与改造前**同一句、同一顺序**。
* **例外与依据**：#1/#2 无世界状态、#3 `_frozen`（方针明示）、#4 世界没 Step（错轴）；
  见 §二表。
* **同一 tick 只长一次**：`_didEarlyGrow` 守卫；探针 S5 实测 `growStepCalls` 增量=1（不是 2）。

### 3.2 `buildCandidate` 的 NaN 隐患（3-0 登记，本步处理）

`vantage_tree.js:4392-4397`：

```js
child.segmentScore = (probe && probe.cum && probe.cum[opIdx])
    ? probe.cum[opIdx][Math.min(actualFrames, probe.cum[opIdx].length - 1)]
    : (typeof r.totalScore === 'number' ? r.totalScore : 0);   // ← 都缺时落 0
child.baseExt = (r.totalScore || 0) - child.segmentScore;
```

* 旧写法的 `: r.totalScore` 在 `probe.cum` 与 `r.totalScore` 都缺时得到 `undefined`
  ⟹ `baseExt = 0 - undefined = NaN`，会顺评分字段扩散。
* **规则版行为不变**：现行规则/智能体路径里，JS 评分（`scorePaths`）必给
  `perFrameScores`+`totalScore`，Rust 快路不齐会回退 JS ⟹ 该分支现行**不可达**；
  本修是给 3-2「不评分通道」的**防御性预埋**。验证=源码断言（探针 S0）+ 逐值语义推导。

### 3.3 诊断计数（只读、不参与决策）

`growStep` 入口 + `expandLeaf`/切片成功点各加 1 个只读计数：
`tree.stats.growStepCalls` / `tree.stats.growExpands`（`vantage_tree.js:6240/6381/6395/6413`）。
* 为什么要加：**`nodeCount` 不能当"生长发生了"的信号** —— 提交切片本身也会创建 9 个候选节点
  （探针实测：规则版提交帧 `growStepCalls=0` 但 `nodeCount=10`）。这两个计数只读数、不改变任何分支。

## 四、⭐ "前移真的生效"的证据 + 假阳率

**探针**：`_tools/headless/_probe_3_1_grow_forward.js`

> 单看 `ifaceGrowAt` 会假阳：目标节点不是叶 / `expandLeaf` 失败时它照样 +1 却没长出节点；
> 单看 `nodeCount` 会假阳：提交切片也会造节点。所以必须"函数被调到 + 真的长出节点"两量同时。

| 场景 | 帧性质 | v181 冻结树 | **v182 产品树** |
|---|---|---|---|
| S1 提交帧（`!commitNode` → startCommitSlice）| 规则版 | `growStepCalls=0`（旧行为，预期） | **`growStepCalls=0`、`growAt=0`、`expands=0`（规则路径没被碰）** |

| S2 新弹 emergency 根层重选帧 | 智能体路径 | `calls=0 / expands=0`（旧坑） | **`calls=+1 / expands=+1`** |
| S3 `_frozen` 帧 | 智能体路径 | 不长（预期） | **`calls` 不增、`expands` 不增（方针例外）** |
| S4 空闲帧（`worldDt<=0`）| 智能体路径 | 不长（预期） | **`calls` 不增、`expands` 不增（时间轴没走）** |

**假阳率（`AGENTS.md:136`）**：
* 不该长的 3 帧（规则版提交帧 / `_frozen` / 空闲）复合信号 **一次都没响 = 假阳 0/3**；
* 该长的 1 帧（智能体提交帧）复合信号响了 = **假阴 0**；
* 反例记录：探针第一版用 `nodeCount` 当信号，规则版提交帧 `nodeCount=10` 被判成"长了"
  ⟹ 当场改成 `growStepCalls`+`growExpands`（这就是"信号本身要有特异度"的现场证据）。

## 六、未解决

1. **新弹 emergency 且"不重选根"那条路的行为差异（智能体路径专属）**：
   改造前该路会走到末尾，用**追加新弹之后**的 `tree.threats` 长；前移后用**追加之前**的
   threats（= A 本帧决策时的观测）长。**这符合"生长只消费 A 的决策"**，但 3-4
   「A→生长→B 全有或全无」的最终顺序需要拍板：若要"长用新弹 threats"，需显式重排
   （不是本步能擅自定的）。已登记。
2. **真实页面里"会决策的探针智能体"集成验证未做**：本步证据是 VM + 真接口 + mock adapter +
   真 `VT.tick` 的 20 条断言；浏览器里注册一个真会返回 `growAt` 的智能体跑 N 帧的验收，
   留给 3-4/3-5 的端到端。
3. `buildCandidate` NaN 修是**防御性**的：现行调用路径下 `probe.cum` 与 `r.totalScore`
   不会同时缺（JS 评分总会给；Rust 快路不齐回退 JS）⟹ 3-2 接通"不评分通道"时才会真正走到，
   届时需补一条**能走到**的功能性断言（本步只有源码断言 + 语义推导）。
4. 3-0 报告 §六登记的三处"机械操作仍由评分排名/段长驱动"（`pickGrowLeaf` / 选路 /
   `probeSegment`）**本步没动**（属 3-3/3-4）。
5. `growStepCalls`/`growExpands` 两个只读诊断计数是本步为验证加的；若 3-4 有更好的
   统一埋点，可平替删除（不影响任何决策）。
6. `_frozen` 帧**只走一帧执行轨迹**（v132）——本步不动；前移块在它之后才可能执行，
   已实测不长（S3）。
