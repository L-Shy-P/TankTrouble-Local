# 「不呈现」开关：实现 + 实测（`2026-10-17`）

> **一句话结论**：**开关已做成（默认关、可运行时开关、已验证只关绘制、已提交 `9119cb6`）**；
> **但在无头采集链路上「不呈现」【量不出可复现的收益】**。
> ⭐ **主指标（配对交错，只报相对差：`2` 会话 × `5` 对 × 三臂；同机另有 `18~20` 个 `python/node/chrome` 进程）**：
> **`canvas 1×1+隐藏` vs 关：`pump` 中位 `-4.3%`（`7/10` 对为负）；`full`（再加 render 置空）vs 关：`-12.3%`（`7/10` 对为负）、`total` `-10%`（`7~8/10` 对为负）**。
> ⚠️ **但逐对相对差散布 `±10%~±70%`、`3/10` 对符号为正 ⟹ 效应淹没在噪声里，不足以判"有效"**。
> ⭐ **机制上限**：`renderer.render(stage)` 单次只要 **`0.06 ms`** ⟹ **"不呈现"理论顶多省 `~1%`**。
> ⛔ **早先那条 `-47%`（`6.53 → 3.46`）与本轮两次顺序测的 `-34%/-55%`：撤下、不采信**（见 §三，顺序/负载伪影）。

## 三、机制（为什么"不可能省 `47%`"）

| # | 实测 | 值 |
|---|---|---|
| ① | `renderer.render(stage)` 单次成本（30 次/批 ×3，扣 `CDP` 往返 `0.47ms`） | **`0.055 / 0.059 / 0.082 / 0.057 ms`** |
| ② | 置空 render 后同一批量 | `0.003 ms`（= 空函数，符合预期）✓ |
| ③ | canvas `940×705` vs `1×1 隐藏` 的单次 render 成本 | `0.059` vs `0.082`（无差别） |

⟹ **一帧里"绘制"只占 `~0.06ms`**（`pump` 段 `2.2~9ms`）——
**把绘制整个删掉，也顶多省 `0.1%` 量级**；`-47%` 在机制上**不可能**来自"不呈现"。

**伪影来源（推断，非实测）**：早先那条 `-47%` 的探针（`_tools/headless/probe_norender2.js`）
是 **`BASE → DISPLAY_NONE → 1×1_NONE → REMOVED` 单向顺序**、**没有对照臂** ⟹ 机器负载/预热随时间的漂移会**全部**记成"优化收益"。
本轮反向顺序测（`ORDER=C_full,B_canvas,A_off,D_off2`）直接看到**单调漂移与相位顺序一致**：
`pump 6.79 → 8.00 → 9.06 → 10.05`（开关顺序是"开/开/关/关"，收益却随**时间**走）。

## 四、结论与建议（默认值）

- ⭐ **建议：开关默认值保持【关】**，理由三条：
  1. **机制上限只有 `~1%`**（一次 `renderer.render` = `0.06 ms`）；
  2. **配对实测 `-4%~-12%`、`7~8/10` 对为负但逐对散布 `±10~70%`**（同机重活污染）⟹ **达不到"可复现收益"的门槛**；
  3. **开了以后画面全黑**（截图/录屏失效），**对"要画面的活"是负收益**。
- ⭐ **复测建议**：**机器静默时**用
  `ORDER=A_off,B_canvas,C_full INTER=1 K=5 M=40 node _tools/headless/_slowframe_norender_tmp.js`
  + `node D:/vt_run/perf/analyze_pair.js <log>`（只读相对差）；
  ⭐ **若静默复测 `full` vs 关的 `pump` 中位 ≤ `-5%` 且 `≥9/10` 对为负**，再考虑接入采集（一行：`open({noRender:true})` 或 `VT_NO_RENDER=1`）。

## 五、边界

- `mode='full'`（render 置空）下：**截图/录屏会是空白/停更**（canvas 本来就隐藏+`1×1`），别在需要画面的脚本里开。
- 本轮所有日志在 `D:/vt_run/perf/`（`C:` 盘只剩 `1.9G`，未往仓库写日志）。
- **未做**：把开关接进 `rollout_worker*.js` 采集器（那在别的子代理手上；**且实测没有收益，暂不建议接**）。
