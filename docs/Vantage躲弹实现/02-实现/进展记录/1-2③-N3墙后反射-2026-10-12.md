## 一 最初假设的“CCD 截断导致反射段消失”代码链（最终被证伪）

### JS 融合（修前/回滚后都是这条）

- `game_core/js/vantage_sandbox.js` 的 `simulateFusedBatch`：
  - Step 前只快照**位置**：`var swPP = swPre.body.GetPosition(); swPre.sweepPrevX = swPP.x; swPre.sweepPrevY = swPP.y;`
  - Step 后取**实际后位置**：`var swP = swB.body.GetPosition();`
  - 扫掠线段完全来自实际位移：`var swSegs = fusedSweepSegments(fc.world, swB.sweepPrevX, swB.sweepPrevY, swP.x, swP.y, 4);`
- 若 Box2D 的 CCD 把弹截停在墙上，`swP` 就在墙面附近，`swSegs` 在墙处就用完，**反射后的段不会生成**。

### Rust rollout

- `game_core/rust/vantage_core/src/rollout.rs`：
  - `sweep_pre: Vec<Option<(f64, f64)>>`（只存位置），Step 前 `sweep_pre[si] = Some(fc.world.body_position(slots[si].body));`
  - Step 后 `let post = fc.world.body_position(slots[si].body);`
  - `let segs = sweep_segments_against_walls(&input.walls, pre.0, pre.1, post.0, post.1, 4);` —— 同样只吃实际位移。
- 这条链在“弹被 CCD 截停”的前提下成立；`_probe_laser_wall_cases.js` 的 N3 FAIL 一开始被我误当成它的证据。

## 三 真相：探针把“每帧位移”当“速度”

### 代码对照

1. 探针 `_probe_laser_wall_cases.js` 的 `scene()`：
   - `const p1 = { x: p0.x + v * dt * inv, y: p0.y - v * dt * inv };`（`dt=0.02`），因此 `p1-p0 = 180*0.02/√2 = 2.5456`，这是**一帧的位移**。
   - 调 bridge 时却把它当速度传：`bullets: [{ ..., vx: c.p1.x - c.p0.x, vy: c.p1.y - c.p0.y, ... }]`（2.5456）。
2. bridge 的 API（`vantage_rust_bridge.js` 文档）：`bullets: [{x,y,vx,vy,radius,lifeLeft,active,isShrapnel}]`。
3. Rust 实现：`rollout.rs:996` `fc.world.set_body_linear_velocity(body, (bullet.vx, bullet.vy));`，随后 `fc.world.step(frame_dt(), ...)`。所以弹每帧实际走 `vx*dt = 2.5456*0.02 = 0.0509 m`，比 oracle 的 2.5456 m **少 50×**。
4. 结论：N3 里 Rust 的弹根本走不到墙，更别说反射后命中坦克 → `dead=false`；oracle（用 p0→p1 一整帧）说 true。N2 也是同一个“弹几乎没动”导致的 false，所以看起来 PASS。**这是探针自身口径不自洽，不是产品 sweep 缺反射段。**
