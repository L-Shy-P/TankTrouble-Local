## 二、接口扩成了什么样（带行号）

### 2.1 接口层：`Agents` 的 A/B 分工槽（`vantage_tree_interface.js:335-380`）

```js
var Agents = {
    _cur: new RuleAgent(),                 // 默认槽（规则版/旧单智能体，行为不变）
    _all: {},
    _byRole: { A: null, B: null },         // ★ v186：两个独立分工槽（生长 / 选路）

    register: function (a, role) {         // role 省略 = 默认槽；'A'/'B' = 分工槽
        if (!a || !a.name) return a;
        this._all[a.name] = a;
        if (role === 'A' || role === 'B') this._byRole[role] = a;
        return a;
    },
    use: function (name, role) {           // role 省略 = 旧用法（默认槽）
        var a = (name === 'rule') ? new RuleAgent() : this._all[name];
        if (!a) { console.warn(...); a = new RuleAgent(); }
        if (role === 'A' || role === 'B') {
            this._byRole[role] = a;
            if (!this._cur || this._cur.name === 'rule') this._cur = a;   // 进入智能体模式
        } else { this._cur = a; }
        return a;
    },
    current: function (role) {
        if (this._cur && this._cur.name === 'rule') return this._cur;     // ★ §5 硬门
        if ((role === 'A' || role === 'B') && this._byRole[role]) return this._byRole[role];
        return this._cur;                                                 // 槽空 → 回退默认（单智能体兼容）
    }
};
```

* **两个槽各自是独立对象**（不同实现、将来不同模型/权重）；`ctx.phase` 只是传进去的上下文。
* **规则版语义**：默认槽 = rule 时，`current('A')/current('B')` **直接返回 rule**（硬门），
  分工槽一律忽略 ⟹ 规则版路径与 v185 完全一致。
* **兼容**：`register(a)` / `use(name)` / `current()`（不带 role）语义与旧版**逐字一致**；
  只注册一个默认 agent 时 A/B 两相都回退到它（旧单智能体模式）。

## 三、⭐ "两个真的独立"的证据 + 假阳率

**探针**：`_tools/headless/_probe_3_4b_two_agents.js`（17/17 PASS，真 interface + 真 tree + mock adapter + 真 `VT.tick`）。

| 场景 | 结果 |
|---|---|
| **P1 两个不同实现** | `grow-net` 与 `route-net` 是**两个不同对象**；分别注册/使用到 A/B 槽；tick 后：**A 只在 A 相被调**（phases 全 `'A'`）、**B 只在 B 相被调**（全 `'B'`）；**A 的输出被采纳**（指定叶子长出 9 个子节点）；**B 的输出被采纳**（路线命中，`agentRouteUsed 0→1`）；`current('A')===grow-net`、`current('B')===route-net` |
| **P2 旧单智能体兼容** | 只注册一个默认 agent → A/B 两相各调它 1 次（`["A","B"]`），`current('A')===current('B')===同一个对象` |
| **P3 §5 硬门** | 注册 A/B 槽后再 `use('rule')`：`current('A')/current('B')` 都返回 rule；tick 里 A/B 两相**都不调**（0 次）；树照常生长/提交（`nodeCount>0`） |
| **P4 假阳率**（信号：`current('A') !== current('B')`） | 不该响：单智能体模式（同一对象）→ **false**；两个槽注册**同一对象** → **false**；该响：两个不同实现 → **true** ⟹ **假阳 0/2、假阴 0** |

> 说明：信号"两个对象不同"只证明**注册槽里放的是两个不同实现**；
> "各自被调用/各自被采纳"由 P1 的调用相位 + 生长/路线落点分别证明。

## 六、未解决

1. **`Agents.use(name, role)` 的"进入智能体模式"是隐式的**：首次 `use(name,'A'/'B')` 时若默认槽还是
   `rule`，会**顺带把默认槽也切到该 agent**（否则 §5 硬门会把分工槽忽略掉，两独立模式进不去）。
   这是我选的口径（向后兼容、避免新增显式模式开关）；**若主人想要显式的"切两智能体模式"API**，
   属接口设计选择，需再拍。**未阻塞**：当前 `use('rule')` 可随时切回、规则版行为不变。
2. **两个"独立"目前是"两个独立注册的实现/对象"**，还不是"两个独立加载的模型/权重"
   （模型加载/序列化/训练管线不在本步；接口已允许任意两个实现）。
3. `VantageTreeInterface.VERSION` 仍是 `1.0.0-interface`（本步只扩了 API、没有改版本串）——
   如果接口版本要做语义化，需要另定。
4. 3-4 登记、主人先记档的两条仍然有效：**B 失败不回滚 A 的生长**（按"全有或全无=(a)"理解）；
   `Pick.back`/射击帧**执行语义**在 3-5。
5. 3-3 登记的两处 HTML 假绿（`vantage_selftest.html` / `flywire_debug.html`）仍在允许范围外未改。
