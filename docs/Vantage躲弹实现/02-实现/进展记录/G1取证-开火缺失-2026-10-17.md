## 二、根因（已定位到接口层）

**我们的桥接只送了"走哪"，从来没送"开火"。**

`_tools/headless/inject_sarl2.js:24` 逐字：
```js
window.__b.bundleA = { picks: [{ nodeId: nodeId, back: 0 }], memory: {} };
```
- ⭐ **`picks` 是"树生长 picks"**（`_probe_3_3_contract.js:121` 断言"树侧 `growStep` 只消费 `picks[0]/growAt[0]`"）
- ⭐ **`Vantage` 的【输入】（forward/back/left/right/**fire**）不是由 `bundle` 直接给的**，
  而是由 `VantageAIManager` 按 `plan` 每帧 `setInputState(InputState.withState(id, f, b, l, r, fire))` 提交
  （见 `外接AI接入方案-Hybrid.md §八` 的契约描述）
- ⭐ 而**服务端目前也只返回 `{lp, v, nodeId, mode, payload}`** —— **`out[1]`（`head_fire`）根本没有被用到**
  （`policy_server_graph.py` 主循环只取 `out[3]` 的动作分布与 `out[0]` 的价值）✓

**⟹ 现在这个桥只驱动"路线选择"，**开火这一路（`out[1]`）**从头到尾没接**。

**⚠️ 一条重要旁证**：我们早先见过游戏报错
`skipped="B:重试超限(0帧自杀(炮口贴墙) picks[1])"` ⟹ **`picks[1]` 确实与"开火"有关**
（**说明契约里存在"第二个 pick 表示开火"的用法，需要查清确切格式**）✓

## 三·五、🔴🔴 更深的问题（`03:5x` 追加实测）：**NN 的决策大多【被拒】、桥根本没通**

**证据**（`window.__vantageIface` 实测，`CAP=120`）：
```
IFACE {"calls":51,"callsA":28,"callsB":23,
       "skipped":"B:重试超限(picks[0] 节点编号不存在)",
       "giveUpA":118,"giveUpB":127,
       "lastCtx":{"nodes":748,"root":28,"commit":38,"bullets":3,"phase":"B"},
       "lastDecision":{"picks":[{"nodeId":41,"back":0},{"nodeId":41,"back":0}],"memory":{}}}
```

**⟹ 三条结论**
1. ⭐⭐ **拒绝原因是"`picks[0] 节点编号不存在"** ⟹
   **NN 在帧 `t` 读观测、选了一个节点 `id`；而该决策在帧 `t+1` 才被消费 —— 这一帧里树可能【重建/重摆】**，
   于是那个 `id` 在新树里不存在 ⟹ **bundle 判非法 ⟹ 重试 ⟹ 放弃 ⟹ 回退规则版** ✓✓
2. ⭐ **`giveUpA=118 / giveUpB=127` 远大于 `calls=51`** ⟹ **放弃次数极多** ——
   **说明"NN 驱动"只在少数帧真正生效**，其余时候跑的是**规则版 `Vantage`** ✓✓
3. ⚠️ **由此**：**我们此前所有"NN 在跑"的印象都要打折** —— **`laikaMoveFrames`、`lp` 那些数是真的，
   但"Vantage 的动作来自 NN"这一点【大部分不成立】** ✓✓

**⭐ 修法方向（待实现）**：**把"NN 选的节点"翻译成"从 root 出发的 `slot` 序列"**，
**在 `decide()` 被调用的【当帧】沿当前树重走该 slot 路径、取到【新鲜的】节点 id** 再提交
（`slot` 在节点 token 里、`NODE_FIELDS[2]`）——
这正好对上裁决①"路线目标 = 任意可达节点"、且**不依赖 id 跨帧稳定** ✓✓
（树变了就让前缀尽量匹配；匹配不足则回退，但**要计数上报**，⛔ 不许静默）
