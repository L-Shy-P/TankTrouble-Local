## 二、根因（已定位到接口层）

**我们的桥接只送了"走哪"，从来没送"开火"。**

`_tools/headless/inject_sarl2.js:24` 逐字：
```js
window.__b.bundleA = { picks: [{ nodeId: nodeId, back: 0 }], memory: {} };
```
- ⭐ **`picks` 是"树生长 picks"**（`_probe_3_3_contract.js:121` 断言"树侧 `growStep` 只消费 `picks[0]/growAt[0]`"）
- ⭐ **`Vantage` 的【输入】（forward/back/left/right/**fire**）不是由 `bundle` 直接给的**，
  而是由 `VantageAIManager` 按 `plan` 每帧 `setInputState(InputState.withState(id, f, b, l, r, fire))` 提交
  （见 `外接AI接入方案-Hybrid.md §八` 的契约描述）
- ⭐ 而**服务端目前也只返回 `{lp, v, nodeId, mode, payload}`** —— **`out[1]`（`head_fire`）根本没有被用到**
  （`policy_server_graph.py` 主循环只取 `out[3]` 的动作分布与 `out[0]` 的价值）✓

**⟹ 现在这个桥只驱动"路线选择"，**开火这一路（`out[1]`）**从头到尾没接**。

**⚠️ 一条重要旁证**：我们早先见过游戏报错
`skipped="B:重试超限(0帧自杀(炮口贴墙) picks[1])"` ⟹ **`picks[1]` 确实与"开火"有关**
（**说明契约里存在"第二个 pick 表示开火"的用法，需要查清确切格式**）✓
