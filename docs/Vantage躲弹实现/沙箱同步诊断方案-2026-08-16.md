# 沙箱同步诊断方案 · 2026-08-16

> 背景：AI 出现“第二三发子弹开始无视”“躲完部分子弹后站桩”“虚影与真实不一致”等表现。
> 不再靠猜补丁，先建立数据同步的观测手段，定位 AI 世界与真实世界的分叉点。

## 一、目标

找出以下任一问题：

1. 真实子弹存在，但树 threats 里没有（漏弹）；
2. 树 threats 有子弹，但锚定折线预测位置与真实位置偏差过大（折线/物理不一致）；
3. 树预测坦克轨迹与真实轨迹偏差过大（运动沙箱不一致）；
4. 弹集合变化时，树的锚点没有正确切换（时间/签名不一致）。

## 二、已加工具

### 1. 运行时同步诊断（vantage_tree.js）

每 tick 自动执行：

- 比较锚定 threats 折线预测位置 vs 真实子弹位置；
- 记录“真实存在但树未锚定”的子弹 id；
- 比较当前执行节点 rollout 预测位姿 vs 真实坦克位姿；
- 逐帧记录每颗子弹的真实位置/速度与折线预测位置（每弹最近600帧）；
- 超过阈值写事件日志：`desync`（树图黄色 D 标记）。

读取：

```js
VantageTree.dumpDiagnostics()
VantageTree.getBulletTracks('子弹id')   // 只看某颗弹
```

返回结构：`{actual:[{t,x,y,vx,vy}], predicted:[{t,x,y}]}`。

### 2. 面板诊断行

树详情新增一行：

- 弹差（米）
- 车差（米）
- 最近弹差事件
- 缺失子弹数量

### 3. 节点虚影预览

树图点击节点 → “渲染该节点 / ◀ / ▶”：

- 显示该节点 rollout 的坦克轨迹与锚定 threats 的子弹位置；
- 可逐帧对比真实画面，定位哪一帧开始分叉。

## 三、标准测试流程

### 测试 A：漏弹测试

1. 开树模式，面板开树详情；
2. 一管 5 发，以约 300ms 间隔逐发射击；
3. 观察诊断行：
   - `缺弹 N 颗`：说明新弹没进 tree.threats，查 threatIds/threatDirty；
   - `弹差 Xm`：说明子弹在，但折线时间/位置错；
4. 每发射一发后暂停，执行：
   ```js
   VantageTree.dumpDiagnostics()
   ```
   确认 threats 是否包含该弹 id。

### 测试 B：时间锚点测试

1. 静态场景只打一发，暂停；
2. 用节点虚影逐帧递进；
3. 比较虚影子弹与真实子弹位置：
   - 第 0 帧应重合；
   - 之后每帧误差应 < 0.5m；
4. 若第 0 帧就不重合，是 rolloutStartT/threats 锚点错；
5. 若逐步漂移，是折线采样或物理角弹差异。

### 测试 C：运动轨迹测试

1. 暂停，点击当前 commitNode；
2. 逐帧递进，观察坦克虚影与真实坦克：
   - 位置应基本重合；
   - 车差应 < 0.5m；
3. 若突然跳变，检查是否中途 freshRoot/新弹重建导致执行节点与显示节点不同。

### 测试 D：顺序射击复现

1. 同一初始局面，按两种顺序射击：
   - 先远后近；
   - 先近后远；
2. 每发之间暂停并 dumpDiagnostics；
3. 对比 threatIds 顺序和 threats 锚点是否一致。

## 四、判定标准

| 现象 | 定位 |
|---|---|
| `缺弹 >0` 持续 | 新弹签名/锚点未更新 |
| `弹差` 持续增长 | 折线预测与真实物理不同步 |
| `弹差` 只在某类角弹出现 | 折线计算与 Box2D 角弹规则不一致 |
| `车差` 持续增长 | 运动沙箱与真实驱动不同步 |
| 虚影第 0 帧不重合 | 节点时间基准错误 |
| 节点预览子弹比实际少 | 节点 threats 没有随树保存/更新 |

## 五、后续修复顺序

1. 先跑测试 A/B，确定是漏弹还是时间错；
2. 若是漏弹：修 threatIds/threatDirty 和新弹 anchor；
3. 若是弹差：比较 `positionOnProjectilePath` 与融合世界物理路径，决定统一数据源；
4. 若是车差：比较候选坦克驱动公式与真实 Tank.update；
5. 每修一处，重跑四组测试并记录 diff。
