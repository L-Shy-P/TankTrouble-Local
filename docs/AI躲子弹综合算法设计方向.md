# AI 躲子弹算法设计

## 核心问题

坦克在迷宫中运动，子弹碰壁会镜面反弹（极端情况角弹），AI 需要实时躲避子弹。

**关键约束：**
- 移动路径上**任何一帧踩红区即死亡**，不能只检查终点
- 子弹在迷宫中持续反弹扩散，像"波"一样，必须穿过波才能安全
- 地形对躲弹策略影响极大：开阔地灵活，死胡同必须冒险穿过
- 不能一味后退，一味后退会进入死胡同

---

## 核心洞察

### 1. 精度分层

顶尖玩家之间的博弈，操作精度也精确不到帧级别，但能躲掉绝大多数子弹。**计算太精确必要性不大，极端情况太少。**

参考：另一个人做的效果不错的人机，搜索间隔0.2秒，只预测5次。以帧为单位预测精度太高。

### 2. 增量预测（时间复用）

```
预测公式：n = (fps - 1) × t

n = 预测的时间倍数（预测到多少秒后）
fps = 帧率
t = 每帧预测耗时（秒）

例：每帧预测未来11帧（有效10帧），6帧就能预测到1秒后
    给它1秒，就能预测10秒后的情况
```

**原理：** 下一帧复用上一帧的预测结果，只需计算新增的1帧，而不是重新预测全部。

### 3. 组合爆炸的解决（2026-08-07 主人修正）

**主人修正（2026-08-07）：分层决策不是组合爆炸的出路，搜索是分层的其中一层；超级函数是完全的假想，与分层不兼容。**

组合爆炸（每帧从 |A| 个操作选一个，N 帧共 |A|^N 种组合）的出路在「预测树搜索方案」章节：动态基准时间 + 延伸率函数（近密远疏）+ 回退率 + 树的坍缩（主干优先）共同把搜索规模压到可控范围。

# 理论A：四层决策架构

## 四层架构

### 最高层：战术决策（暂不实现）

- 决定需要躲还是走、需要打还是等
- 需要对局势有深刻理解
- 躲弹场景暂时不需要

### 次高层：方向决策

- 对决策的细化执行
- 决定应该移动到哪块地形、大致什么角度
- **核心功能：** 衡量不同地形，进行"穿"和"避"的数值配比，影响执行层评分
- 需要对地形、玩家有深刻理解
- 决定了能否躲掉老版算法看似无解的子弹

**地形分类（需寻路算法）：**
- 开阔房间：灵活度高，参数A
- 走廊：受限，参数B
- 死胡同：必须冒险穿过，参数C

**穿 vs 避：**
- 开阔地：以"避"为主，灵活闪躲
- 死胡同：以"穿"为主，冒险穿过子弹波
- 子弹波像乒乓球波，只有穿过它让它走到背后才安全

### 粗略执行层（重点）

**关键修正：** 粗略层不是"粗略躲弹"，而是**为精细躲弹寻找并移动到正确的起点位置**。

- 精细躲弹需要在子弹到达前很久就预测并移动到合适的起始位置
- 如果让精细层做这件事，预测距离太远，计算量巨大且不现实
- 粗略层负责**提前走位、摆好角度**，让精细层能在合适的时机接管

**核心能力：**
- 识别并走到"躲弹起点"（精细躲弹路径的大致起点）
- 判断该往左、往右、向前还是等待
- 计算可以大幅简化，但方向不能错

**与执行层关系：**
- 并列同级，不同时执行
- 粗略层把坦克放到合适位置后，执行层接管精细操作
- 执行层发现起点错误/局势变化 → 触发粗略层重新规划

### 执行层

- 在上一层已经做好的基础上，精确落地决策
- 帧级别的精确操作
- 只在粗略执行层不够用时启用

## 预测树搜索方案（执行层与粗略执行层的具体实现 · 2026-08-07 交流精华）

本章是**执行层和粗略执行层的具体实现方案**：粗略执行层负责粗模拟延伸（找起点、提前走位），执行层负责精验证落地（帧级精确操作），本方案把两层统一到一棵预测树上。取代旧的「搜索策略」章节，旧搜索策略（保持当前操作 + 增量树维护）已被本方案吸收与扩展，旧描述不准确的部分不再作为设计依据。

### 总体架构：粗层候选 + 前缀验证（DSpark 式无损）

类比 DSpark（小模型预测 + 大模型验证）：

- 粗模拟 + 简单树 = 小模型 → 算出粗树最优路径
- 高精度模拟 + 复杂树 = 大模型 → 算出精树最优路径
- 对比两条路径的**最大公共前缀**：
  - 前缀一致部分 → 粗模拟可信 → 接受并继续
  - 第一个分叉点 → 粗模拟在此处不可靠 → 精树纠正
  - 基于纠正位置继续粗模拟
- **验证的本质是"两棵树最优路径的对比"**，不是任何单个评估器。安全区（遮蔽角）是评分器，不是验证器。

### 操作类型：9 种

1. 保持静止（含「试图移动但卡墙」合并；不同操作线算出完全一样的情形直接合并）
2. 前、后、左、右（4 种单键操作）
3. 前左、前右、后左、后右（4 种双键组合操作）

killfield 的 10 种 = 9 种移动 + 1 种原地开火（它是对战 AI 才有开火）；纯躲弹只需 9 种。

### 动态基准时间

- 过长 → 远处粗模拟不准，预测频繁错误回退
- 过短 → 预测延伸缓慢，只看眼前
- **核心原则（主人拍板 · 2026-08-09）**：基准时间与"时间"挂钩最多——时间远的子弹影响小，时间近的子弹即使距离稍远也绝对更影响当下决策。距离感知交给评分（遮蔽角），基准时间只做纯时间
- 超远距离子弹影响微乎其微，但**不排除**（旧的「排除远子弹」理论错误）

#### V6 模型（2026-08-09 · 纯时间定稿 · 主人拍板，V5 已废弃）

**V5 废弃原因**：V5 的"沿延伸方向估算威胁区间 + 机动余量 + 方案 A/B/C 权衡"表述模糊、无法落地；后续尝试让距离参与基准选取（有效威胁时间 = 倒计时 ÷ 威胁程度）也被主人否决——距离一旦掺和基准排序就喧宾夺主，违背"时间优先"。

**每颗子弹的两个量（第1层输出）**：

```
倒计时   = 沿轨迹线（反射折线）飞到"离坦克最近位置"的时间
          计算时坦克以净速度移动（前进速度 − 后退速度，缓慢前移）——平衡坦克速度的影响
最近距离 = 轨迹线到坦克的最近距离（注意：不是"子弹飞过来的距离"，是轨迹线隔坦克多近）
```

**计算流程（纯时间）**：

```
① 外圈过滤：
  最近距离 > 外圈半径 → 不算威胁，不参与基准时间计算
  外圈取值（粗略过滤即可）：大多数情况坦克可主动追击子弹，假威胁子弹少见；
    太大 → 超远子弹的短倒计时会压短基准时间（本来可以多操作一会，效率下降）
    太小 → 漏掉"追击后能碰到"的真威胁
  待标定

② 基准子弹 = 圈内倒计时最小的子弹（纯时间，不做任何距离修正）
  基准倒计时 = 它的倒计时

③ 密集权重（其他圈内子弹，纯时间）：
  密集权重 = a · e^(b · (基准倒计时 − 该子弹倒计时))
  时间接近基准 → 权重接近 a；时间越远 → 指数衰减趋近 0（无边界、不突变）
  含义：其他子弹与基准子弹"威胁时间相近" = 挤在一起 = 场面复杂、需精细模拟

④ 基准时间 = 基准倒计时 ÷ (1 + 密集权重和)
  单颗子弹 → 权重和为 0 → 基准时间 = 基准倒计时
  多颗挤在一起 → 权重和增大 → 基准时间缩短（密集 → 更短，主人定论）
  钳制：下限 1 帧，上限 3 秒

⑤ 无子弹在圈内 → 基准时间 = 固定默认值（约 1~2 秒，待标定）
  用于正常预测探索（未雨绸缪）
```

**设计要点（为什么这样）**：

- 纯时间：密集权重与基准选取都不掺距离量 → 参数微调连续不突变，数值波动可控（主人原则：复杂化反而可能造成意想不到的数值波动）
- 压缩方向是除法（密集 → 更短），与"同样需要精密操作"的定论一致
- 倒计时隐含距离：轨迹线远的子弹路径天然长、倒计时天然大、影响自动小；但"倒计时短 + 最近距离远"的假威胁子弹需要外圈兜底
- 回退机制兜底：基准时间估算偏差可由回退 + 换路线补救，不追求极端精确
- 接入点：每帧开始时计算一次基准时间（驱动本帧预测深度）；节点级可重算（滚动时域，延伸时按当前节点状态再算）

**待数值标定**：外圈半径、密集权重系数 a、b、无威胁默认值（1~2 秒）、上下限（1 帧 ~ 3 秒）。

### 时间步长 dt(t)：物理模拟精度

**作用**：决定每个时间层的物理模拟步长（帧级细 vs 大步长粗）。这是**模拟精度**，与延伸率（分叉数量）是两回事。

**驱动**：由物理常量决定（见「动态基准时间」第四步）——坦克转速 ω、坦克移速 v_t、子弹移速 v_b。这些常量决定"模拟需要多精细"：

```
精细度需求 = h(ω, v_t, v_b)
  ω 小（转向慢）→ 需精细规划转向 → 步长细
  v_t 大（移动快）→ 位置敏感 → 步长细
  v_b 大（子弹快）→ 威胁变化快 → 步长细

时间步长：
  dt(t) = dt_min + (dt_max - dt_min) · (1 - 遮蔽角占比(t))
  威胁大的时刻步长细，威胁小的时刻步长粗（遮蔽角占比 = 解析威胁区间内为高、外为低）
```

### 延伸率（分叉数量）：b(t)

**作用**：决定每个时间层的**分叉数量**，即每个节点**模拟哪些操作**。这是延伸率（主人纠正：延伸率处理分叉数量，不是时间步长）。

**主人纠正（V5）**：指数函数是用来**描述树的形状**的；延伸率用于控制**叶子分布更相似树形相对比例**——即延伸率**基于具体某个节点**，让整棵树的叶子分布贴合理想的树形（指数形状）。这类似统计学的**回归模型**（离散的节点实际分布 拟合 目标曲线）。并且为了控制性能，**不是每次模拟都要让所有叶子生长，只需要发展最有用的那些节点**。

#### V5.1 模型（2026-08-08 · 树形状修正：中间宽 · 主人观察后重写）

**主人观察（重要修正）**：树的形状是**中间宽、两侧窄**的（左侧=树根 1 个节点，右侧=最远未来），不是单调衰减：

```
        o o
     o o o o o
 o  o o o o o o o o
 o  o o o o o o o o o o o
 o  o o o o o o o o
     o o o o  o
        o o
      （左=根，右=最远未来）
```

**为什么中间宽**（三个机制叠加）：

```
① 增长段（近处）：分叉累积
   每个节点分叉 b>1 个 → 节点数指数增长：n(t+dt) = n(t)·b(t)
   树根 1 个 → 第1层 9 个 → 第2层更多……

② 平台段（中间）：预算饱和
   每轮模拟总次数有上限（性能控制），节点数不能无限增长
   增长到预算上限后 → 平台（中间最宽）

③ 衰减段（远处）：延伸率收缩
   远处分叉少（b(t)<1）→ 节点数下降 → 右侧最窄
```

**树的形状函数（钟形/纺锤形，三种候选）**：

```
候选1（高斯钟形）：n(t) = n_max · exp(-(t-t_peak)² / (2σ_tree²))
候选2（分段）：    t < t_peak:  n(t) = n_max·(t/t_peak)^α（增长）
                   t ≥ t_peak:  n(t) = n_max·exp(-(t-t_peak)/τ_tree)（衰减）
候选3（预算推导）：n(t) 由"分叉累积 × 预算截断 × 延伸衰减"直接算出（最准，最复杂）

t_peak = 节点数峰值时刻（分叉累积 = 预算上限的平衡点）
```

**延伸率 e(node) 的新定义**（拟合中间宽形状）：

```
每轮模拟后统计各时间层的实际节点数 n(t)
与目标形状（钟形）比较 → 缺口：
  某层 n(t) < shape(t)（太疏）→ 该层节点优先发展（补分叉）
  某层 n(t) > shape(t)（太密）→ 该层节点少发展/回收
e(node) = clamp(目标该层节点数 / 当前该层节点数 × 平均分叉, 1, 9)
```

**待数值标定**：t_peak、σ_tree/τ_tree、α、n_max（= 预算上限）。

### 回退率

- 新增变量：根据评分计算回退率
- 根据回退率回退不同的时间尺度重新模拟
- **回退发生在延伸和分叉评分过低的情况下**，精准回退必须用到延伸/分叉的评分参数（主人纠正：不是孤立公式）

#### V6 模型（2026-08-09 · 两条独立判定 · 主人修正后重写，V5.1 已废弃）

**V5.1 废弃原因**：旧的"固定阈值 s_thr 检测"被死亡扣分污染——死亡扣 10 万分后总分必低于任何合理阈值，导致"9 种操作里只要有一个死亡分支，整节点就被判回退"，违背本意。

**主人发现（重要）**：回退判断不能看"9 种总分"（被死亡扣分污染），要把"死没死"和"活得好不好"分开判。

```
回退判定（两个独立条件，任一满足就回退）：
  条件1（多数安全吗）：9 种操作里死亡分支 ≥ 6 个 → 回退
    死亡用游戏碰撞检测判定（游戏是唯一权威）
  条件2（活着的有质量吗）：存活分支的平均分 < 存活满分的 1/3 → 回退
    只统计存活分支的分（死亡扣分不参与）；取平均分而非最高分（主人指定）

回退动作 = 往前回退一定时间 Δt（不是回退完整节点——节点 9 种已算过，回退完整节点=重复计算）
  Δt = 上一轮延伸到该节点的基准时间的一半（向下取整帧）
  不足一帧 → 放弃该节点，在父节点重新选择
```

**为什么死亡扣 10 万不污染回退判断**：条件1 只看死亡个数，条件2 只看存活分支平均分——两个判断都不含"9 种总分"，死亡扣分天然不介入。

**待数值标定**：条件2 的阈值系数（1/3）、回退时间比例（1/2）。

#### V5 模型（2026-08-09 · 每帧求和定稿 · 主人拍板，V4 已废弃）

**V4 废弃原因**：V4 的"安全存量积分 + 剩余角中心度 + 末端安全"加权版被"大道至简"取代——死亡检测既然必须每帧，剩余角也可以每帧求和，就用一套逻辑统一，不搞多个加权项。

**评分定稿（一套逻辑）**：

```
每帧：先用游戏碰撞检测死亡（游戏是唯一权威，不用角度遮蔽判死亡）
  死 → 路径标记死亡，扣 100000 分，停止延伸该节点
    （不丢弃：所有路线都死=死局，死亡路径之间也要排序找相对最优）
  没死 → 算单帧分

单帧分 = Σ(全圆所有剩余角区间的弧度)²
  · 遮蔽角 = 被挡住不能碰的危险角；剩余角 = 2π − 遮蔽角 = 安全角（用剩余角）
  · 全圆所有剩余角都算：不能只用坦克所在区间——万一两颗子弹左右夹住坦克，
    只算所在区间会漏掉外部威胁（外面加多少子弹都检测不到）
  · 平方加权求和：单个大区间（0.8²）优于等大的散落小区间（4×0.04）→ 奖励集中安全区
  · 坦克朝向必然落在角内（没在角内就死了）
  · 角度遮蔽把坦克视为矩形 → 剩余角双轴对称，取一边即可
  · 单帧分上限 ≈ π² ≈ 10（连续完全安全 1000 帧才接近 1 万）

路径总分 = 各帧单帧分求和（帧数多自然分高）
死亡比较与存活同一套逻辑：每帧求和 + 死亡扣 10 万
路径选择：比较路径总分（死亡最晚的路线积累帧多、分自然高）
```

**权衡说明（主人定稿时讨论的取舍）**：

- 死亡扣 10 万：采用全圆 2π 范围后安全分上限提高，10 秒安全 ≈ 1 万分，扣 10 万确保死亡路径永远垫底（防万一）
- 短时高分 vs 长时中分：直接每帧分数和、不除帧数——1 帧完全安全 vs 10 秒比较安全，选 10 秒（总分高）
- 距离感知的真正舞台在评分：基准时间纯时间化后，遮蔽角（评分）承担全部距离信息——子弹一靠近遮蔽角自然变大、分自然降

**未来增强（待主人确认）**：威胁临近扣分——把第1层的威胁倒计时喂给评分，预测路径上离威胁时刻越近的帧扣越多分，让远距离也有区分度（评分不再全满分）。当前先不启用，靠纯躲实验看表现。

**待数值标定**：死亡扣分 100000（已定）；未来增强的临近扣分参数。

### 树的坍缩（每帧）

- 每帧执行一条路径，未执行的分支直接作废 → 每帧最多坍缩 90%
- 树 = **主干优先**：主干（当前执行路径的延伸）占 80% 预算，探索分支占 20%
- 增量复用的真正价值：沿主干的免重复计算，不是保留全部分支

### 贴脸并行策略

- 超近距离时：并行扩展预测树（可降低性能）+ 执行 killfield 算法（硬编码侧移兜底）

### 每帧预测流程（执行层与粗略执行层的具体实现 · V6 详细版）

#### 数据结构定义

```
节点 Node：
  t            — 节点时间（距当前时刻，秒）
  tankState    — 坦克状态 {x, y, 朝向θ, 当前操作类型}
  opType       — 到达此节点的操作（9 选 1）
  parent       — 父节点引用（null 为树根）
  children     — 子节点列表
  score        — 安全性评分（见「评分」）
  status       — alive / dead / pending
  depth        — 节点所在层数（第几层）

树 Tree：
  root         — 根节点（当前真实状态）
  leaves       — 存活叶子节点列表
  budget       — 本帧剩余模拟预算
  fullLevels   — 短期全量层数（默认 3，掉帧减一层，见性能控制）

储备库 reservePool：
  短期全量层的叶子节点列表（= 换路线的候选起点池，评分降序）
```

#### 帧循环（每帧执行一次，共 6 大步）

**第 1 步：更新子弹状态**

```
输入：上一帧子弹状态、帧时间间隔 dt_frame
算法：用子弹波函数（反射折线解析式）推演每颗子弹当前位置（结果缓存，全帧复用）
输出：当前所有子弹状态
```

**第 2 步：树初始化检查**

```
if 树为空 或 树根与真实坦克状态偏差过大：
    建根节点（t=0，当前状态，当前操作），leaves=[root]
else：
    复用上一帧坍缩后的树，根对齐到当前真实状态（防漂移）
```

**第 3 步：循环模拟（预算用尽停止）**

```
子步骤 3.1 短期全量补层（每帧只补新增的最深层）：
  目标：近 fullLevels 层保持全量（每节点分 9 个，9^L 组合）
  当前树深度不足 fullLevels 层 → 逐层补齐：
    第2层 81 个，第3层 729 个（每帧只补当前缺的那层）
  全量层的叶子 → 加入储备库 reservePool（评分降序）
  每帧只补一层（约 9^L - 9^(L-1) 个），不是每帧重建全部

子步骤 3.2 中远期单线延伸（全量层之外）：
  沿当前路线（储备库中评分最高的叶子）继续：
    延伸 = 当前操作 1 个分支（低成本单线）
    评分正常 → 继续延伸（每帧延伸一层）
    评分低 → 不延伸，转 3.5 换路线

子步骤 3.3 评分（每个新叶子，见「评分」V5 定稿）：
  每帧：游戏碰撞检测死亡？
    死 → 标记死亡，扣 100000，不延伸
    活 → 单帧分 = Σ(全圆剩余角弧度)²
  路径总分 = 各帧单帧分求和（死亡路径扣 10 万）
  写入叶子.score

子步骤 3.4 回退检测（两条独立判定，见「回退率」V6）：
  if 9种操作死亡分支 ≥ 6 个 → 回退
  if 存活分支平均分 < 存活满分/3 → 回退
  回退 = 往前回退基准时间的一半（不足一帧 → 放弃节点，父节点重选）
  删坏分支，从回退目标重新发展

子步骤 3.5 换路线（低分且回退后仍低）：
  从储备库 reservePool 选评分最高、且不在当前路线上的叶子 → 新起点
  从新起点重新单线延伸（换路线 = 搜索重启，排序+去重+重选）
  若储备库全在路线上 → 扩展储备库（补一层）再选

子步骤 3.6 更新预算与叶子列表：
  预算 -= 本次模拟节点数
  新存活叶子加入 leaves
  if 预算 ≤ 0 → 跳出循环
```

**第 4 步：选路径（后向DP）**

```
从叶子向根回溯：value = 自身评分 + max(子节点 value)
根沿 value 最大路径回溯 → 最优路径（全局最优，非贪心）
```

**第 5 步：坍缩（逻辑必然，非性能取舍）**

```
本帧执行第1层的选定操作，根节点已确认 → 其他操作的分支逻辑上永远不会被应用
保留 2 层储备（第2、3层的全量节点），作废其余
（下帧从第2层当新根，补新的第3层）
```

**第 6 步：输出操作**

```
输出最优路径第一段操作（本帧执行）
```

#### 性能控制（全量层数是主旋钮）

```
1. 全量层数 fullLevels：3层=729节点(≈2.6ms物理)、2层=81节点(≈0.3ms)、4层=6561(≈23ms危险)
   掉帧就减一层（每层是上一层的9倍节点量，减一层省9倍）
2. 保留2层+补1层：每帧只补9^L-9^(L-1)个，不重建
3. 中远期单线延伸：只沿当前路线1个分支，成本极低
4. 回退回收：坏分支删除不重复模拟
5. 子弹波预计算缓存：每帧一次，全帧复用
6. 真实成本估算：每帧约 3~5ms（含物理+评分+DP），占40ms预算10%左右
```

## 神经网络决策层（未来方向 · 2026-08-09 主人提出）

### 动机：手写延伸/回退策略的局限

- 树延伸"跟着评分走"有效率（省去无效随机延伸），但**评分不完美 → 树一直跟高分走 → 局部最优**（高分陷阱：一路躲到墙角）
- 手写"如何存活"的剪枝/信号都是表面功夫——延伸决策本质是"在不确定性下决策"，手写启发式无法根治
- 结论：把"延伸/回退决策"从手写规则换成**神经网络决策**，树 + 沙箱只做精确执行

### 架构：分层控制

```
高层（神经网络）——做所有"决策"：
  选择延伸哪个节点 / 是否回退 / 回退到哪 / 是否换路线
  输入：树节点特征（评分、深度、生死、位置、时间）+ 预测数据
        （威胁倒计时、基准时间、子弹状态等）
  甚至：基准时间、评分也可以交给神经网络（几乎干了所有决策相关的事）

低层（树 + 沙箱模拟）——做精确执行：
  按 NN 决策延伸节点、逐帧沙箱物理模拟、碰撞检测、评分计算
```

### 训练目标与数据

- **训练目标**：让神经网络尽可能**减少回退、增加预测效率**（奖励 = 每帧的预测效率/回退情况，密集奖励）
- **训练方式**：先用手写策略在沙箱里批量生成"状态 → 决策 → 结果"数据（行为克隆起点），再强化学习微调
- **训练量比端到端训练游戏人机小得多**（主人判断，理由）：
  1. 奖励密集：每帧有即时反馈（回退没、效率高没），不是等一局结束
  2. 状态紧凑：输入是树节点特征（低维、信息密集），不是完整游戏状态
  3. 可离线生成数据：沙箱 + 手写策略批量造数据，监督学习即可起步

### 开发路线（主人拍板顺序）

1. **先开发手写版**（当前设计：树 + 沙箱 + 评分 + 基准时间 + 回退 + 换路线），有问题不管，先看实际结果
2. 手写版运行时**记录决策数据**（每帧：节点状态 → 延伸/回退决策 → 结果）→ 即 NN 的训练数据集
3. 手写版当 NN 的**基线**（NN 学得比基线好 = 成功）

## 子弹波理论（粗略层的核心模型）

### 基础直觉

在管道（长条形走廊）地形中，子弹沿镜面反射轨迹运动，可以近似看作**波**：

- **波速**：子弹在管道方向上的前进速度
- **频率**：子弹在两侧墙壁间反弹的周期
- **侧点**：子弹刚好位于坦克侧边中线、与坦克对称的时刻，此时威胁最小
- **重合点**：多颗子弹同时到达侧点的时刻，此时最容易一次性穿过多个威胁

### 单子弹基础案例

场景：长条管道，一颗子弹从斜前方射来。

**情况1：子弹与管道夹角小（近似平行于墙壁）**
- 子弹横向移动慢，会在管道一侧停留较长时间
- 策略：站在管道另一侧，等子弹过去

**情况2：子弹波速慢、频率高**
- 子弹横向来回快，窗口期短
- 站在原地等待可能蹭到坦克尾巴
- 策略：在子弹到达侧点之前提前向前走
- 极端情况：子弹刚离开前方遮挡，立即向前移动，使尾巴不被蹭到

### 多子弹基础案例

两颗子弹在管道中：

**情况1：频率差距大**
- 通过等待，两颗子弹因波速不同而逐渐分离
- 然后一颗颗躲过
- 缺点：耗时太长

**情况2：寻找重合点**
- 两颗子弹的侧点会在某个时刻重合
- 此时多颗子弹等价于一颗子弹
- 直接穿过，最常用

### 对粗略层的启示

粗略层不需要模拟每一帧的操作，而是可以：

1. **将每颗子弹抽象为波**
2. **计算每颗子弹的侧点时刻序列**
3. **寻找多颗子弹侧点的重合窗口**
4. **根据当前地形，选择一个安全侧点作为"躲弹起点"**
5. **从当前位置移动到该起点**

**关键：** 这不是路径搜索，而是基于波的相位匹配。

### 理论模型（待完善）

设管道宽度为 W，子弹速度为 v，入射角为 θ（相对于管道方向）。

- 管道方向分量：`v_parallel = v * cos(θ)`
- 横向分量：`v_perp = v * sin(θ)`
- 反弹周期：`T = 2W / v_perp`
- 侧点时刻：子弹横向位置达到极值的时刻

多颗子弹时，需要找到一组时刻 t，使得所有子弹同时处于侧点附近。

**待解决：**
- 复杂地形（非管道）如何应用波理论？
- 角弹如何建模？
- 如何从"侧点"推导出"躲弹起点"的位置？

## 四种基础穿弹方法（玩家实战总结）

### 1. 直穿

**适用场景：** 频率几乎一样、相位相反（一个子弹在一侧时，另一个刚好在另一侧）的子弹。子弹频率越高越难。

**操作方式：** 以近乎平行墙壁的方向向前移动。

**起点位置：** 可在侧边和中间，几乎任意。

**特点：** 最简单，依赖子弹相位差。

---

### 2. 外翻

**适用场景：** 坦克中心在子弹反弹线外侧，有空间做外翻动作。

**操作方式：**
1. 先转向与子弹几乎平行的方向
2. 等到子弹到达侧点时，向前移动（平行于子弹侧点反弹后的轨迹）
3. 接近侧点时开始旋转移动至平行于墙壁
4. 到达侧点后旋转移动至与侧点反弹前的轨迹

**轨迹特征：** 坦克整体划出一个与子弹反弹轨迹类似的 **V 字形**，坦克中心移动轨迹在子弹反弹轨迹**外侧**。

**本质：** 相当于坦克起点在中间时的侧穿，主要靠移动。

---

### 3. 内过

**适用场景：** 坦克中心在子弹反弹线内侧，没有空间外翻的情况。

**操作方式：**
1. 先转向与子弹反弹前平行的方向
2. 等到子弹到达侧点后，后退然后转向至子弹反弹后的方向平行

**轨迹特征：** 坦克移动较少，主要靠平行于子弹来让它自己经过。坦克中心划出一个小 **V 字形**，与子弹反弹轨迹开口方向**相反**，移动轨迹在子弹反弹轨迹**内侧**。

**本质：** 主要靠旋转，移动较少。

---

### 4. 侧跃

**适用场景：** 极端情况。坦克在侧边，平行墙壁，子弹已经在自己面前到达侧点，即将反弹蹭到坦克边缘时。

**操作方式：**
1. 微微抬起坦克
2. 向前移动走过子弹
3. 再转回角度，防止坦克尾部被蹭到

**轨迹特征：** 整体轨迹是一个开口方向与子弹轨迹开口**相反**的 V 字。与内过不同的是，它的轨迹与子弹轨迹**相交**，坦克 V 把子弹侧点扣在里面。

**使用频率：** 通常不是必要的，因为可以后退等待子弹下一个周期。一般用于快速冲刺或者退无可退时。

---

### 四种方法对比

| 方法 | 主要操作 | 轨迹特征 | 适用场景 |
|------|----------|----------|----------|
| 直穿 | 移动 | 平行于墙壁 | 相位相反的子弹 |
| 外翻 | 移动+旋转 | V字，在反弹线外侧 | 有空间外翻 |
| 内过 | 旋转+后退 | 小V字，在反弹线内侧 | 无空间外翻 |
| 侧跃 | 微抬+前进+转回 | V字扣住侧点 | 极端情况/冲刺 |

**核心区别：**
- 外翻 vs 内过：外翻主要靠移动，内过主要靠旋转
- 外翻/内过：坦克中心轨迹在子弹反弹线外侧/内侧
- 侧跃：轨迹与子弹轨迹相交，把侧点扣在里面

### 对粗略层的意义

这四种方法是**基础操作原语**，粗略层需要根据当前局势选择合适的穿弹方法：

1. **识别子弹相位关系** → 选择直穿/外翻/内过/侧跃
2. **计算侧点时刻** → 确定操作时机

## 数学建模

### 符号定义

```
坦克状态：S = (x, y, θ, vx, vy, ω)
  x, y     = 坦克中心位置
  θ        = 坦克朝向角
  vx, vy   = 坦克速度
  ω        = 角速度

子弹状态：b_i = (x_i, y_i, vx_i, vy_i)
  x_i, y_i     = 子弹位置
  vx_i, vy_i   = 子弹速度（含反射后的方向）

墙壁集合：W = {w_1, w_2, ..., w_m}
  w_j = (p1, p2) 线段端点

操作空间：A = (a_fwd, a_rot)
  a_fwd ∈ {-1, 0, 1}  前进/停止/后退
  a_rot ∈ {-1, 0, 1}  左转/不转/右转
```

### 运动学模型

**坦克运动：**
```
dx/dt = v_max * a_fwd * cos(θ)
dy/dt = v_max * a_fwd * sin(θ)
dθ/dt = ω_max * a_rot
```

**子弹运动（含反射）：**
```
dx_i/dt = vx_i
dy_i/dt = vy_i
碰撞墙壁时：法向速度分量取反
```

### 碰撞检测

**坦克-子弹碰撞（圆-圆近似）：**
```
C_tank_bullet(S, b_i) = (x - x_i)^2 + (y - y_i)^2 < (R_tank + R_bullet)^2
```

**坦克-墙壁碰撞（矩形-线段）：**
```
C_tank_wall(S, W) = 坦克矩形与任意墙壁线段相交
```

**综合安全条件：**
```
Safe(S) = ¬C_tank_wall(S, W) ∧ ∀i, ¬C_tank_bullet(S, b_i)
```

### 四层决策的数学形式

#### 次高层输出

次高层输出一个**目标区域和穿避配比**：
```
次高层输出：(target_region, λ_pass, λ_avoid)
  target_region ⊂ ℝ^2   目标移动区域
  λ_pass ∈ [0,1]         穿弹权重
  λ_avoid ∈ [0,1]        避弹权重
  λ_pass + λ_avoid = 1
```

#### 粗略执行层任务

给定次高层输出，从 7起点 × 4操作 = 28种候选中选出最优：

```
max_{(start_k, mode_p)} Score(start_k, mode_p)

约束：
  1. 从当前状态可达 start_k
  2. 在 start_k 执行 mode_p 的整条路径安全
  3. 路径上每帧都满足 Safe(S(t))
```

#### 执行层任务

给定粗略层选定的 (start_k, mode_p)，执行帧级精确操作：

```
每帧选择 a ∈ A 使得：
  Safe(S(t+1)) = true
  且 a 最接近 mode_p 的期望操作
```

### 操作模式的轨迹参数化

每种操作模式可以参数化为坦克中心的时空轨迹 (x(t), y(t), θ(t))：

#### 直穿轨迹

```
参数：v（前进速度，归一化到 [-1, 1]）
轨迹：
  x(t) = x_0 + v * v_max * t
  y(t) = y_0
  θ(t) = θ_0（近似平行墙壁）
```

#### 外翻轨迹

```
参数：(v, t_turn, ω)
轨迹：
  阶段1 [0, t_turn)：
    x(t) = x_0 + v * v_max * cos(θ_0 + ω*t) * t 的积分
    y(t) = y_0 + v * v_max * sin(θ_0 + ω*t) * t 的积分
    θ(t) = θ_0 + ω * t
  阶段2 [t_turn, T]：
    反向旋转，θ 回到 θ_0 + Δθ
```

#### 内过轨迹

```
参数：(v_back, t_turn, ω)
轨迹：
  阶段1 [0, t_turn)：
    后退 + 旋转
    x(t) = x_0 - v_back * v_max * cos(θ(t)) * t
    θ(t) = θ_0 + ω * t
  阶段2 [t_turn, T]：
    前进 + 反向旋转
```

#### 侧跃轨迹

```
参数：(δ_lift, v, t_lift, t_return)
轨迹：
  阶段1 [0, t_lift)：微微抬起（横向微移 δ_lift）
  阶段2 [t_lift, t_return)：向前走过子弹
  阶段3 [t_return, T]：转回角度
```

### 可行性检查的核心计算

**对每种操作模式，需要验证整条路径的安全：**

```
Check(mode_p, params, bullets, walls):
  生成轨迹 (x(t), y(t), θ(t)) for t ∈ [0, T]
  
  对每个关键时间点 t_k：
    S_k = (x(t_k), y(t_k), θ(t_k))
    
    计算危险角度：
      blocked = wallBlockedIntervals(S_k.pos, walls)
              ∪ bulletBlockedIntervals(S_k.pos, bullets(t_k))
    
    检查 θ(t_k) 是否在安全角度内
    
  返回：所有关键时间点都安全 = true
```

**关键时间点选取：**
- 不需要每帧检查
- 只在操作模式的**状态转折点**检查
- 例如：直穿检查 t=0, T/2, T；外翻检查 t=0, t_turn, T

### 起点安全性的新定义（4 维 · 主人已确认）

**绝对危险起点**：任何由"前进"延伸出的操作（前、前+左、前+右之一）都会在未来某个时刻、某个位置、某个角度碰到子弹。

**半危险起点**：存在某些由"前进"延伸出的操作，使得坦克在未来不会碰到子弹。

**安全起点**：所有由"前进"延伸出的操作，都不会在未来碰到子弹。

**"原地旋转"不算"开始躲"**：
- 原地旋转消耗时间，不改变位置
- 时间消耗 = 起点位置的时间窗口缩小 = 等同于"重新选择起点"
- 所以"开始按前进键"才是真正的"开始躲"

### 扇环的几何（修正版）

**操作 = 匀速直行 + 恒定旋转**（角速度 5 rad/s 恒定）

**ICR（瞬时旋转中心）**：
- 在匀速 + 恒定角速度时，ICR 是**固定的**
- 距离：v / ω（v = 16 m/s，ω = 5 rad/s，距离 = 3.2 m）
- 位置：坦克中心 + (v/ω) × 朝向旋转 -90°

**扫过区域 = 扇环**：
- 内半径 = 矩形近端到 ICR 距离
- 外半径 = 矩形远端到 ICR 距离
- 角度范围 = ω × T（T = 操作时长）
- 中心角 = 初始朝向方向

**注意**：坦克矩形有 4 个顶点，扫过 4 段圆弧；4 条边扫过 4 段"扇环带"
严格几何 = 由 4 段外圆弧 + 4 段内圆弧 + 2 端面围成的复杂区域
近似为"扇环"（主人的命名）

### 窗口期计算办法（主人提出）

**步骤**：
1. 画出扇环
2. 找出子弹反弹后轨迹和扇环相交的位置（**外交点**：子弹反弹后移动了更远的距离）
3. 坦克在扇环轨道上移动到这里，坦克边角刚好擦着交点
4. 交点 = 子弹的位置
5. 计算子弹在此处的时刻
6. 计算坦克从初始位置移动到此处所需的时间
7. **子弹时刻 - 坦克移动时间 = 最晚出发时刻**
8. 反弹前的轨迹交点用于计算**最早出发时刻**

# 理论B：超级函数

## 核心思想

超级函数是一个从初始状态直接生成操作函数的映射：

```
S(B₀, T₀, T) = f

输入：
  B₀ = {b₁, b₂, ..., bₙ}  初始子弹状态
  T₀ = (p_t, θ_t, v_t)    初始坦克状态
  T                       预测时长

输出：
  f: [0, T] → A           操作函数
                          A 是操作空间（按键映射）
```

**关键：** 不是搜索离散的操作序列，而是直接生成连续的操作函数。

### 操作空间 A

```
A = { (a_forward, a_rotate) | a_forward ∈ {-1, 0, 1}, a_rotate ∈ {-1, 0, 1} }
```

或连续版本：

```
A = [-1, 1] × [-1, 1]
```

### 为什么能解决组合爆炸

**传统方法：**
- 每帧从 |A| 个操作中选择一个
- N 帧共有 |A|^N 种组合
- 指数爆炸

**超级函数：**
- 操作函数 f 被限制在低维参数化函数族 F_param 中
- F_param = ∪_{p∈P} F_p
- P 是有限的操作模式集合
- 每个 F_p = { f_p(·; α) | α ∈ ℝ^{d_p} }
- d_p 很小（1-5 维）

**优化维度从 |A|^N 降到 max d_p。**

如果允许组合 K 个模式段，维度为：

```
dim = K × (log|P| + 1 + max d_p)
```

当 K 很小（3-5），维度仍然可控。

### 三元函数视角

超级函数可以分解为三个更基础的函数：

1. **子弹波函数：** 给定子弹初始状态，输出任意时刻子弹位置
   ```
   b_i(t) = W_b(b_i(0), t)
   ```

2. **安全区函数：** 给定坦克状态和子弹状态，输出是否安全
   ```
   safe(tank, bullet) ∈ {0, 1}
   ```

3. **操作函数：** 给定操作输入，输出坦克状态随时间变化
   ```
   tank(t) = W_t(T₀, f, t)
   ```

三者结合：

```
Safety(f, t) = ∏_i safe(W_t(T₀, f, t), W_b(b_i(0), t))
```

目标：找到使 Safety(f, t) = 1 对所有 t∈[0,T] 成立的 f，并最大化某个评分。

### 超级函数的数学形式

```
max_{f ∈ F_param} J(f)

约束：∀t ∈ [0, T], ∀i, C(W_t(T₀, f, t), W_b(b_i(0), t)) = 0
```

其中：
- C(·,·) 是碰撞检测函数
- J(f) 是评分函数（生存时间、位置质量、前进距离等）

### 参数化操作模式

#### 直穿模式

```
f(t) = (v, 0),  t ∈ [0, T]

参数 α = {v}
v ∈ [-1, 1] 表示前进/后退速度
```

#### 外翻模式

```
f(t) = {
  (v, ω₁),  t ∈ [0, t₁)
  (v, -ω₂), t ∈ [t₁, t₂)
  (v, 0),   t ∈ [t₂, T]
}

参数 α = {v, ω₁, ω₂, t₁, t₂}
```

#### 内过模式

```
f(t) = {
  (v₁, ω₁),  t ∈ [0, t₁)
  (v₂, -ω₂), t ∈ [t₁, t₂)
  (0, 0),    t ∈ [t₂, T]
}

参数 α = {v₁, v₂, ω₁, ω₂, t₁, t₂}
```

#### 侧跃模式

```
f(t) = {
  (v, ω₁),  t ∈ [0, t₁)   微微抬起
  (v, 0),   t ∈ [t₁, t₂)   向前走过子弹
  (0, -ω₂), t ∈ [t₂, T]   转回角度
}

参数 α = {v, ω₁, ω₂, t₁, t₂}
```

### 求解流程

#### 单颗子弹的安全参数域

对固定操作模式 p 和参数 α，定义安全条件：

```
Safe_p(α) = ∀t ∈ [0, T], C(W_t(T₀, f_p(·;α), t), W_b(b(0), t)) = 0
```

对固定 p 和固定子弹 b，允许参数集合：

```
A_{p,b} = { α | Safe_p(α) 成立 }
```

#### 多颗子弹的公共可行域

模式 p 对所有子弹安全 ⟺

```
α ∈ ∩_{i=1}^{n} A_{p,b_i}
```

#### 最优模式选择

```
对每个操作模式 p ∈ P:
  计算公共可行域 F_p = ∩_i A_{p,b_i}
  如果 F_p ≠ ∅:
    在 F_p 内选择使 J(f_p(·;α)) 最大的 α_p
  否则:
    标记 p 不可用

最终选择：
p* = argmax_{p: F_p ≠ ∅} J(f_p(·;α_p))
```

### 直穿模式的解析求解

#### 坐标系与运动方程

设管道沿 x 轴，宽度 W，墙壁在 y=0 和 y=W。

**子弹运动：**
- 横向位置 y_b(t) 是周期为 2W/v_perp 的三角波
- 每个半周期内，y_b(t) 是线性函数：y_b(t) = a_k * t + b_k
- 其中 a_k = ±v_perp

**坦克运动（直穿模式）：**
- x_t(t) = x_t0 + v * v_max * t
- y_t(t) = y_t0

**碰撞约束（简化为圆-圆）：**
- R = r_tank + r_bullet
- 安全条件：(x_t(t) - x_i(t))^2 + (y_t0 - y_b(t))^2 > R^2

#### 分段二次不等式

在第 k 个半周期 [t_k, t_{k+1}] 内：

```
x_i(t) = x_i0 + v_parallel * t
y_b(t) = a_k * t + b_k
```

代入安全条件：

```
[(v*v_max - v_parallel) * t + (x_t0 - x_i0)]^2 + [y_t0 - a_k*t - b_k]^2 > R^2
```

令：
- Δv = v*v_max - v_parallel
- Δx0 = x_t0 - x_i0
- Δy0 = y_t0 - b_k

展开为二次不等式：

```
(Δv^2 + a_k^2) * t^2 + 2(Δv*Δx0 - a_k*Δy0) * t + (Δx0^2 + Δy0^2 - R^2) > 0
```

对每个半周期求解该不等式，得到使不等式成立的 t 区间。
如果所有半周期的解区间并集覆盖 [0, T]，则该 v 值安全。

#### 单颗子弹的安全 v 集合

对每个 v ∈ [-1, 1]，用上述方法判断安全性。
所有安全 v 的集合即为 A_{p,b}。

由于 v 只出现在 Δv 中，且 Δv 是 v 的线性函数，二次不等式的系数是 v 的多项式。
因此 A_{p,b} 通常是一个或几个区间，可以用数值方法（如二分法）精确求解边界。

#### 多颗子弹的公共 v 集合

```
V_safe = ∩_i A_{p,b_i}
```

对每个操作模式 p，计算 V_safe。
如果 V_safe ≠ ∅，则直穿模式 p 可行。

### 外翻/内过模式的解析求解

外翻和内过模式中，坦克 y_t(t) 也是分段线性的（V 字轨迹）。
因此安全条件仍然是分段二次不等式，可以用同样的方法求解。

**外翻模式：**
- 第一段：y_t(t) 以斜率 m1 变化
- 第二段：y_t(t) 以斜率 m2 变化（反向）
- 第三段：y_t(t) 保持不变

每段分别建立二次不等式，求解安全参数域。

### 与增量预测结合

超级函数可以增量计算：

```
第 k 帧：
  1. 复用上一帧的超级函数结果 f_{k-1}
  2. 去掉已执行的部分
  3. 在末尾添加新预测的时段
  4. 如果当前路径仍然安全，继续执行
  5. 如果不安全，重新求解超级函数
```

这样每帧只需要做少量计算，而不是从头开始。

# 通用部分

## 近距离才选择操作

### 核心观察

- 坦克离子弹很远时，任何操作都安全
- 只有进入"威胁半径"后，才需要认真选择操作
- 威胁半径可以动态调整，取决于子弹速度和方向

### 数学表达

```
R_threat = min_i R(b_i, T₀)

其中 R(b_i, T₀) 是子弹 i 对当前坦克的威胁半径
      = v_b * T + R_safe
```

粗略层只在 `min_i dist(坦克, b_i) < R_threat` 时激活。

### 远距离子弹的处理（2026-08-07 修正：不排除）

- **旧的「距离 > R_threat 的子弹不纳入当前求解」理论已废弃**（错误）
- 超远距离子弹影响微乎其微，但不排除：全部子弹都纳入威胁密度聚合，按距离衰减权重
- 威胁密度 → 基准时间的输入之一（见「预测树搜索方案」章节）
